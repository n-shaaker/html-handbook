## ۱) شروع کلاس؛ مسئله قبل از تعریف

### مسئله کلاس (اول بگو)

«sidebar ثابت ۲۴۰px و main باید **بقیه عرض** را بگیرد؛ یک item کوچک نباید کل ردیف را له کند.»


اول با **مسئله** شروع کن — نه با لیست property.

«تا اینجا ویژگی‌ها را روی ظرف می‌نوشتیم تا همهٔ آیتم‌ها با هم جابه‌جا شوند. flex-basis ، flex-grow و flex-shrink روی خود آیتم نوشته می‌شوند و تعیین می‌کنند آن آیتم، بعد از چیده شدن در محور اصلی، با فضای کم یا زیاد چه کند. مرورگر اول به هر آیتم یک اندازهٔ پایه می‌دهد، بعد اگر جا اضافه ماند آن را بین آیتم‌هایی که اجازهٔ رشد دارند تقسیم می‌کند، و اگر جا کم آمد آیتم‌هایی را که اجازهٔ جمع شدن دارند کوچک می‌کند.»

«پیش‌فرض همه flex-grow: 0 است، یعنی بزرگ نمی‌شوند. جعبه ۲ با flex-grow: 1 کل فضای خالی را برمی‌دارد:»

«این همان ترفند «جعبه جست‌وجو» در نوار بالای فروشگاه‌هاست: لوگو و دکمه اندازه خودشان را دارند و کادر جست‌وجو بقیه فضا را پر می‌کند.»

«فضای خالی به نسبت عددها تقسیم می‌شود. اینجا جعبه ۲ دو برابر جعبه ۱ و ۳ از فضای خالی سهم می‌گیرد. (دقت کنید: «فضای خالی» دو برابر می‌شود، نه لزوماً کل عرض جعبه.)»

**روی جزوه این عناوین را دنبال کنید:** *۹) رشد، جمع شدن و اندازه پایه* · *مثال ۱: flex-grow: 1 روی یک آیتم* · *مثال ۲: سهم‌های متفاوت* · *مثال ۳: flex-basis — اندازه اولیه*

**چرخه این بخش:** نشان بده → دانشجو حدس بزند → یک خط کد → refresh.

«پیش‌فرض همه flex-grow: 0 است، یعنی بزرگ نمی‌شوند. جعبه ۲ با flex-grow: 1 کل فضای خالی را برمی‌دارد:»

«این همان ترفند «جعبه جست‌وجو» در نوار بالای فروشگاه‌هاست: لوگو و دکمه اندازه خودشان را دارند و کادر جست‌وجو بقیه فضا را پر می‌کند.»

## ۳) Live Coding — مرحله‌به‌مرحله

«فایل live جدا می‌سازم تا index پروژه قاطی نشود — مثلاً `تدریس/live/` در همین ماژول.»

**مرحله 1 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```css
.box-2 {
  flex-grow: 1;
}
```

**مرحله 2 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```css
.box-1 { flex-grow: 1; }
.box-2 { flex-grow: 2; }
.box-3 { flex-grow: 1; }
```

**مرحله 3 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```css
.box-1 { flex-basis: 100px; }
.box-2 { flex-basis: 200px; }
.box-3 { flex-basis: 30%; }
```


**در حین تایپ بگو:** «الان فقط یک تغییر — save — refresh — چه فرقی دیدید؟»

**اشتباه عمدی (یک بار):** یک selector اشتباه یا property روی فرزند نادرست — خطا را با کلاس debug کنید.

## پیوست: نکات تکمیلی از جزوه (برای مدرس)

«flex-basis مثل width است (در حالت row )، ولی مخصوص Flexbox. مقدار پیش‌فرضش auto است، یعنی «از width یا محتوای خودت استفاده کن».»

«هر سه جعبه flex-basis: 300px دارند، یعنی جمعاً ۹۰۰ پیکسل؛ ولی ظرف فقط ۵۰۰ پیکسل است. پیش‌فرض همه flex-shrink: 1 است، پس به یک اندازه کوچک می‌شوند. جعبه ۱ را با flex-shrink: 0 از کوچک شدن معاف کرده‌ایم:»

«جعبه ۱ همان ۳۰۰ پیکسل ماند و کمبود جا بین جعبه ۲ و ۳ تقسیم شد. این برای عکس پروفایل یا آیکون‌هایی که نباید له شوند خیلی کاربردی است.»

«اشتباه رایج: فکر می‌کنیم flex-grow: 2 یعنی «دو برابر پهن‌تر». flex-grow فقط فضای اضافه را تقسیم می‌کند. اگر محتوای دو جعبه از اول اندازه متفاوتی داشته باشد، نتیجه دقیقاً دو برابر نمی‌شود. برای تقسیم دقیق، flex-basis: 0 بگذارید (درس بعد).»


**نکته مدرس:** بعد از هر save یک ثانیه مکث کنید تا کلاس خروجی را ببیند.

**نکته مدرس:** یک بار property را عمداً غلط بگذارید و با DevTools پیدا کنید.

**نکته مدرس:** از دانشجو بخواهید قبل از refresh پیش‌بینی بگوید.

**نکته مدرس:** DevTools → Elements → راست‌کلیک → Scroll into view برای آیتم‌های off-screen.

**نکته مدرس:** در RTL جهت main axis را با overlay Flex روی صفحه نشان دهید.
