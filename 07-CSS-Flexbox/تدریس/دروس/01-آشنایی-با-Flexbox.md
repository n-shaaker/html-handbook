## ۱) شروع کلاس؛ مسئله قبل از تعریف

### مسئله کلاس (اول بگو)

«navbar دارید: لوگو، لینک‌ها، دکمه ورود — HTML درست است ولی همه **زیر هم** افتاده‌اند. قبل از حفظ property، ببینیم block layout چه می‌کند — بعد **یک خط** CSS منو را افقی می‌کند.»


اول با **مسئله** شروع کن — نه با لیست property.

«قبلاً برای کنار هم چیدن جعبه‌ها از float یا inline-block استفاده می‌کردیم؛ هم کد زیادی لازم داشت و هم وسط‌چین کردن یا هم‌قد کردن ستون‌ها سخت بود. Flexbox (جعبه انعطاف‌پذیر) دقیقاً برای همین ساخته شده: چیدن چند آیتم در یک ردیف یا یک ستون ، تقسیم فضای خالی بین آن‌ها و تراز کردنشان، فقط با چند خط CSS.»

«یادآوری Block: div پیش‌فرض بلوکی است → زیر هم می‌آید. Block / Inline · display»

«عنصر div به‌طور پیش‌فرض display: block است. هر بلوک عرض موجود را کامل می‌گیرد و عنصر بعدی را به خط بعد می‌فرستد، برای همین سه جعبهٔ زیر، بدون هیچ چیدمان اضافه‌ای، زیر هم دیده می‌شوند نه کنار هم.»

«چیدمان را روی خود جعبه‌ها عوض نمی‌کنیم. فقط به عنصر پدر ، یعنی همان عنصری که این سه جعبه فرزند مستقیم او هستند، display: flex می‌دهیم. از این لحظه پدر ظرف فلکس می‌شود و فرزندانش را در یک ردیف، از شروع خط، کنار هم می‌چیند.»

**روی جزوه این عناوین را دنبال کنید:** *۱) آشنایی با Flexbox* · *مثال ۱: بدون Flexbox و با Flexbox* · *مثال ۲: ظرف (Container) و آیتم (Item)* · *مثال ۳: محور اصلی و محور فرعی*

**چرخه این بخش:** نشان بده → دانشجو حدس بزند → یک خط کد → refresh.

## ۳) Live Coding — مرحله‌به‌مرحله

«فایل live جدا می‌سازم تا index پروژه قاطی نشود — مثلاً `تدریس/live/` در همین ماژول.»

**مرحله 1 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```css
.box {
  padding: 10px;
  /* هیچ چیدمان خاصی نداریم */
}
```

**مرحله 2 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```css
.parent {
  display: flex;
}
```

**مرحله 3 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```html
<div class="parent">          <!-- ظرف فلکس -->
  <div class="box">۱</div>    <!-- آیتم -->
  <div class="box">           <!-- آیتم -->
    <span>نوه</span>          <!-- آیتم نیست -->
  </div>
</div>
```


**در حین تایپ بگو:** «الان فقط یک تغییر — save — refresh — چه فرقی دیدید؟»

**اشتباه عمدی (یک بار):** یک selector اشتباه یا property روی فرزند نادرست — خطا را با کلاس debug کنید.

## ۵) سؤال کلاسی

- «کدام عناصر flex item می‌شوند — نوه‌ها یا فقط فرزند مستقیم؟»  
  **پاسخ:** فقط **فرزند مستقیم** container؛ نوه‌ها item نیستند مگر والد میانی هم `display: flex` داشته باشد.
- «با `display: flex` روی والد، جهت پیش‌فرض چیدمان چیست؟»  
  **پاسخ:** `flex-direction: row` — itemها در ردیف افقی (در RTL از سمت راست شروع می‌شوند).
- «Flex برای layout دو‌بعدی کل صفحه کافی است؟»  
  **پاسخ:** برای اسکلت کامل صفحه معمولاً **Grid** راحت‌تر است؛ Flex برای نوارها، ردیف‌ها و ستون‌های داخل یک ناحیه عالی است.

## پیوست: نکات تکمیلی از جزوه (برای مدرس)

«فرزندها کنار هم نشستند، چون ظرف حالا آن‌ها را در محور اصلی، پشت سر هم، می‌چیند. هر کدام فقط به اندازهٔ محتوای خودش پهن است، زیرا مقدار پیش‌فرض flex-grow صفر است و آیتم فضای خالی را برنمی‌دارد. این رفتار را در درس رشد و جمع‌شدن عوض می‌کنیم؛ فعلاً مهم است ببینید display: flex به‌تنهایی آیتم‌ها را هم‌عرض نمی‌کند.»

«در Flexbox همیشه دو نقش داریم: عنصری که display: flex می‌گیرد ظرف فلکس است، و فرزندان مستقیم آن آیتم‌های فلکس هستند. نوه‌ها آیتم نیستند و مثل قبل رفتار می‌کنند.»

«قاعده ساده: ویژگی‌هایی مثل display: flex ، flex-direction ، justify-content و gap روی پدر نوشته می‌شوند؛ ویژگی‌هایی مثل flex-grow ، order و align-self روی فرزند .»

«هر ظرف فلکس دو محور دارد: محور اصلی (main axis) جهتی است که آیتم‌ها پشت سر هم چیده می‌شوند (در حالت عادی افقی)، و محور فرعی (cross axis) عمود بر آن است (در حالت عادی عمودی). بیشتر ویژگی‌های Flexbox می‌گویند «در کدام محور» چه اتفاقی بیفتد.»


**نکته مدرس:** بعد از هر save یک ثانیه مکث کنید تا کلاس خروجی را ببیند.

**نکته مدرس:** یک بار property را عمداً غلط بگذارید و با DevTools پیدا کنید.

**نکته مدرس:** از دانشجو بخواهید قبل از refresh پیش‌بینی بگوید.

**نکته مدرس:** DevTools → Elements → راست‌کلیک → Scroll into view برای آیتم‌های off-screen.

**نکته مدرس:** در RTL جهت main axis را با overlay Flex روی صفحه نشان دهید.
