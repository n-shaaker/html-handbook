# مبحث ۶ — ذخیره و بازیابی با localStorage

📖 بخش مرتبط پروژه: [صفحه منوی نارنج](../../../index.html) (سبد سفارش بعد از رفرش باقی می‌ماند) — در [`js/app.js`](../../../js/app.js) توابع `loadOrder` و `updateCart`.

> HTML و CSS آماده است (پوشه `starter`). پوشه `starter` را کنار همین پوشه کپی کنید و فقط `ex-n.js` را بنویسید. داده‌ها را در DevTools ← **Application** ← **Local Storage** ببینید و برای آزمون عمداً خرابشان کنید. بهتر است با Live Server اجرا کنید. پاسخ نمونه در پوشه `solution` است.

---

## تمرین ۱ — سفارش به نام شما ⭐

**هدف:** ذخیره یک **متن ساده** هنگام تایپ و برگرداندن آن هنگام باز شدن صفحه.

**صورت مسئله:** مشتری‌های همیشگی «نارنج» نمی‌خواهند هر بار نامشان را برای سفارش بیرون‌بر تایپ کنند.

**الزامات:**
- با رویداد `input` روی `#customer`، نام (بعد از `trim`) با کلید `naranj-customer` ذخیره شود؛ اگر خالی شد، کلید با `removeItem` پاک شود.
- هنگام باز شدن صفحه، نام ذخیره‌شده در کادر نوشته شود.
- `#greeting`: با نام ← «سفارش به نام: سارا»؛ بدون نام ← «نام خود را بنویسید تا دفعه بعد یادمان بماند.»
- دکمه «پاک کردن نام» کادر و حافظه را خالی کند.

**تست‌ها:**
- تایپ «سارا» ← «سفارش به نام: سارا»
- رفرش (F5) ← کادر هنوز «سارا» است
- «پاک کردن نام» و رفرش ← کادر خالی و پیام راهنما

## تمرین ۲ — غذاهای محبوب ⭐⭐

**هدف:** ذخیره یک **آرایه** با `JSON.stringify` و خواندن امن آن با `JSON.parse` + `try...catch`.

**صورت مسئله:** هر کارت یک دکمه قلب (`.fav-btn`) دارد. مهمان غذاهای محبوبش را علامت می‌زند و دفعه بعد که منو را باز می‌کند، قلب‌ها پر مانده‌اند.

**الزامات:**
- تابع `loadFavorites()` که آرایه نام‌ها را از کلید `naranj-favorites` بخواند؛ اگر نبود، خراب بود یا آرایه نبود ← `[]`.
- کلیک روی قلب: اگر نام در آرایه بود حذف و وگرنه اضافه شود؛ بعد ذخیره.
- دکمه قلب محبوب: متن «♥»، `aria-pressed="true"`؛ غیرمحبوب: «♡»، `aria-pressed="false"`.
- `#fav-count`: «۲ غذای محبوب: میرزاقاسمی، دوغ محلی» یا «هنوز غذای محبوبی انتخاب نکرده‌اید.»
- هنگام باز شدن صفحه، وضعیت همه قلب‌ها از روی آرایه درست شود.

**تست‌ها:**
- قلب میرزاقاسمی و دوغ ← «۲ غذای محبوب: میرزاقاسمی، دوغ محلی»
- رفرش ← دو قلب هنوز پر هستند
- کلیک دوباره روی قلب دوغ ← «۱ غذای محبوب: میرزاقاسمی»
- در DevTools مقدار کلید را `[خراب` کنید و رفرش ← همه قلب‌ها خالی، بدون خطای قرمز

## تمرین ۳ — به خاطر سپردن جستجو و فیلتر ⭐⭐⭐

**هدف:** ذخیره یک **شیء تنظیمات** و **اعتبارسنجی** داده خوانده‌شده قبل از استفاده.

**صورت مسئله:** صاحب رستوران روی تبلت آشپزخانه همیشه دسته «غذای اصلی» را باز می‌کند. می‌خواهد صفحه با همان فیلتر و همان متن جستجوی دفعه قبل باز شود.

**الزامات:**
- شیء `settings = { filter: "all", search: "" }` با کلید `naranj-menu-settings` ذخیره شود (هر بار که فیلتر یا جستجو عوض شد).
- تابع `loadSettings()`: داخل `try...catch`؛ `filter` فقط اگر یکی از `"all"`، `"starter"`، `"main"`، `"dessert"`، `"drink"` بود پذیرفته شود؛ `search` فقط اگر رشته بود. در غیر این صورت مقدار پیش‌فرض.
- یک تابع `applyFilters()` که هر دو شرط (دسته و جستجو در نام) را اعمال کند و `#no-result` را مدیریت کند.
- هنگام باز شدن صفحه: کادر جستجو و دکمه فعال (`active` و `aria-pressed`) از روی تنظیمات درست شوند و `applyFilters()` اجرا شود.

**تست‌ها:**
- «دسر» + جستجوی «فالوده» و رفرش ← دکمه «دسر» فعال، کادر «فالوده»، ۱ کارت
- مقدار کلید را `{"filter":"pizza","search":5}` کنید و رفرش ← «همه» و کادر خالی، ۸ کارت
- مقدار کلید را `abc` کنید و رفرش ← همان حالت پیش‌فرض، بدون خطای قرمز

## اشتباه‌های رایج این مبحث

- ذخیره آرایه یا شیء بدون `JSON.stringify` (`"[object Object]"` ذخیره می‌شود).
- `JSON.parse` بدون `try...catch`.
- اعتماد کامل به داده ذخیره‌شده؛ کاربر یا نسخه قدیمی برنامه ممکن است مقدار عجیبی گذاشته باشد. قبل از استفاده بررسی کنید.
- فراموش کردن ذخیره بعد از **حذف**.
- استفاده از کلیدهای کلی مثل `"data"`؛ کلید با پیشوند پروژه (`naranj-...`) با برنامه‌های دیگر قاطی نمی‌شود.
