# مبحث ۹ — باز یا بسته؟ (کار با Date)

📖 بخش مرتبط پروژه: [سربرگ صفحه منو](../../../index.html) (نوشته «الان باز هستیم») — در [`js/app.js`](../../../js/app.js) بخش وضعیت باز/بسته.

> HTML و CSS آماده است (پوشه `starter`). پوشه `starter` را کنار همین پوشه کپی کنید و فقط `ex-n.js` را بنویسید. چون ساعت واقعی را نمی‌شود عوض کرد، هر تمرین یک بخش «آزمایش با ساعت دلخواه» دارد؛ پس منطق را در یک تابع بنویسید که **ساعت یا تاریخ را ورودی بگیرد**، نه این‌که خودش `new Date()` بسازد. پاسخ نمونه در پوشه `solution` است.

ساعت سرو «نارنج»: ناهار **۱۲ تا ۱۶** و شام **۱۹ تا ۲۳** (ساعت پایان یعنی بسته؛ ساعت ۱۶:۰۰ بسته است).

---

## تمرین ۱ — باز هستیم یا بسته؟ ⭐

**هدف:** نوشتن تابع `isOpenAt(hour)` و استفاده از `new Date().getHours()`.

**صورت مسئله:** سربرگ منو باید وضعیت لحظه باز شدن صفحه را نشان دهد، و برای آزمودن، کاربر بتواند هر ساعتی را امتحان کند.

**الزامات:**
- `isOpenAt(hour)` فقط `true` یا `false` برگرداند (بدون کار با DOM).
- سربرگ `#open-status`: باز ← «● الان باز هستیم» با کلاس `is-open`؛ بسته ← «● الان بسته‌ایم» با کلاس `is-closed`.
- دکمه «بررسی»: عدد `#test-hour` باید صحیح و بین ۰ تا ۲۳ باشد، وگرنه «ساعت باید عددی بین ۰ تا ۲۳ باشد.»
- نتیجه در `#hour-result`: «ساعت ۱۳: باز هستیم ✔» یا «ساعت ۱۷: بسته‌ایم ✖».

**تست‌ها:**
- `12` ← باز / `15` ← باز / `16` ← بسته
- `22` ← باز / `23` ← بسته / `9` ← بسته
- `25` یا خالی ← پیام خطا

---

## تمرین ۲ — ساعت کاری آخر هفته ⭐⭐

**هدف:** کار با `getDay()` و ساختن متن فارسی روز و ساعت از روی یک `Date`.

**صورت مسئله:** پنجشنبه و جمعه رستوران شلوغ‌تر است: ناهار تا **۱۷** و شام تا **۲۴** (نیمه‌شب) سرو می‌شود. بقیه روزها همان ساعت‌های عادی است.

**الزامات:**
- آرایه `DAY_NAMES` برای نام روزها (`getDay()` برای یکشنبه `0` و برای شنبه `6` برمی‌گرداند).
- تابع `getStatus(date)` یک شیء `{ open, period }` برگرداند؛ `period` برابر «ناهار»، «شام» یا `""`.
- مقدار `#test-time` با `new Date(input.value)` به تاریخ تبدیل شود؛ اگر خالی بود ← «تاریخ و ساعت را انتخاب کنید.»
- نتیجه در `#time-result`: «پنجشنبه ساعت ۱۶:۳۰ — باز هستیم (سرو ناهار)» یا «دوشنبه ساعت ۱۶:۳۰ — بسته‌ایم».
- سربرگ هم با `getStatus(new Date())` پر شود؛ ساعت فارسی با `toLocaleTimeString("fa-IR", { hour: "2-digit", minute: "2-digit" })`.

**تست‌ها:**
- دوشنبه ۲۶ اکتبر ۲۰۲۶، ۱۶:۳۰ ← «دوشنبه ساعت ۱۶:۳۰ — بسته‌ایم»
- پنجشنبه ۲۹ اکتبر ۲۰۲۶، ۱۶:۳۰ ← «… باز هستیم (سرو ناهار)»
- جمعه ۳۰ اکتبر ۲۰۲۶، ۲۳:۳۰ ← «… باز هستیم (سرو شام)»
- شنبه ۳۱ اکتبر ۲۰۲۶، ۲۳:۳۰ ← «شنبه ساعت ۲۳:۳۰ — بسته‌ایم»

## تمرین ۳ — چقدر مانده؟ ⭐⭐⭐

**هدف:** حساب با **دقیقه از اول روز** و به‌روزرسانی خودکار با `setInterval`.

**صورت مسئله:** به جای «باز/بسته»، مهمان دوست دارد بداند چقدر تا شروع یا پایان سرو مانده است (ساعت‌های عادی، بدون قاعده آخر هفته).

**الزامات:**
- بازه‌ها در یک آرایه: `[{ name: "ناهار", start: 720, end: 960 }, { name: "شام", start: 1140, end: 1380 }]` (دقیقه از نیمه‌شب؛ ۱۲×۶۰ = ۷۲۰).
- تابع `formatDuration(minutes)`: `45` ← «۴۵ دقیقه»، `120` ← «۲ ساعت»، `130` ← «۲ ساعت و ۱۰ دقیقه».
- تابع `getCountdownText(minutes)`: روی بازه‌ها حلقه بزند؛ قبل از شروع ← «… تا شروع سرو ناهار»، داخل بازه ← «… تا پایان سرو ناهار»، بعد از همه ← «امروز دیگر سرو نداریم؛ فردا از ساعت ۱۲ در خدمتیم.»
- `#countdown` و سربرگ با ساعت فعلی پر شوند و هر **۶۰ ثانیه** (`setInterval`) دوباره حساب شوند.
- بخش آزمایش: مقدار `#test-time` (مثل `"16:50"`) با `split(":")` به دقیقه تبدیل و نتیجه در `#test-result` نوشته شود.

**تست‌ها:**
- `15:15` ← «۴۵ دقیقه تا پایان سرو ناهار»
- `16:50` ← «۲ ساعت و ۱۰ دقیقه تا شروع سرو شام»
- `10:00` ← «۲ ساعت تا شروع سرو ناهار»
- `12:00` ← «۴ ساعت تا پایان سرو ناهار»
- `23:30` ← «امروز دیگر سرو نداریم؛ فردا از ساعت ۱۲ در خدمتیم.»

---

## اشتباه‌های رایج این مبحث

- `getMonth()` و `getDay()` از صفر شروع می‌شوند؛ `getDay()` یکشنبه را `0` می‌دهد، نه شنبه.
- شرط `hour <= 16` به جای `hour < 16`؛ ساعت پایان باید «بسته» باشد.
- ساختن `new Date()` داخل تابع منطق؛ آزمودن ساعت‌های دیگر غیرممکن می‌شود.
- مقایسه متن‌های ساعت مثل `"9:00" < "16:00"` (مقایسه حرف‌به‌حرف است و غلط درمی‌آید)؛ به عدد دقیقه تبدیل کنید.
- `setInterval` بدون صدا زدن یک‌باره تابع در ابتدا؛ تا یک دقیقه چیزی نمایش داده نمی‌شود.
