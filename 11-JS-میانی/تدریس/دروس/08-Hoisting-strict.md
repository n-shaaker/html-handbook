## ۱) شروع کلاس؛ مسئله قبل از تعریف

اول با **مسئله** شروع کن — نه با لیست property.

«گاهی نامی که پایین‌تر در فایل نوشته شده بالاتر قابل استفاده است و گاهی همان کار خطا می‌دهد. JavaScript پیش از اجرای هر محدوده، بعضی اسم‌ها را ثبت می‌کند. این رفتار را Hoisting می‌نامند، ولی مقدار همان لحظهٔ رسیدن اجرا به خط تعریف داده می‌شود. حالت سخت‌گیرانه هم بعضی اشتباه‌هایی را که بی‌صدا متغیر سراسری می‌ساختند به خطا تبدیل می‌کند تا زودتر دیده شوند.»

«JavaScript قبل از اجرای کد، همه تعریف‌های هر محدوده را پیدا می‌کند و اسم‌ها را از قبل «ثبت» می‌کند؛ انگار تعریف‌ها به بالای محدوده برده شده‌اند (Hoist). ولی مقدار فقط وقتی اجرا به همان خط برسد داده می‌شود. نتیجه برای هر نوع تعریف فرق دارد:»

«تعریف تابع با کلمهٔ function کل بدنه را هم در همان مرحلهٔ ثبت آماده می‌کند. به همین دلیل می‌توانید sayHi را در خطی بالاتر از خود تعریف صدا بزنید. این رفتار مخصوص همین شکل تعریف است و شامل تابعی که داخل const ذخیره شده نمی‌شود.»

«var اسم را از اول محدوده ثبت می‌کند ولی تا خط مقداردهی، مقدارش undefined است؛ پس چاپ قبل از مقداردهی خطا نیست و undefined نشان می‌دهد. let هم اسم را ثبت می‌کند، اما تا رسیدن اجرا به خط خودش در منطقهٔ مردهٔ موقت است و خواندنش ReferenceError می‌دهد. بعد از همان خط، b مثل متغیر عادی قابل استفاده است.»

**روی جزوه این عناوین را دنبال کنید:** *۸) بالا بردن و حالت سخت‌گیرانه (Hoisting & Strict Mode)* · *Hoisting چیست؟* · *تابع قبل از تعریف* · *var و let قبل از تعریف*

## ۳) Live Coding — مرحله‌به‌مرحله

«فایل live جدا می‌سازم تا index پروژه قاطی نشود — مثلاً `تدریس/live/` در همین ماژول.»

**مرحله 1 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
sayHi();           // ✔ کار می‌کند

function sayHi() {
  console.log("سلام از تابع!");
}
```

**مرحله 2 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
console.log(a);    // undefined
var a = 5;

console.log(b);    // ✖ ReferenceError: Cannot access 'b' before initialization
let b = 10;
```

**مرحله 3 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
console.log(calcTax(1000));   // ✖ ReferenceError: Cannot access 'calcTax' before initialization

const calcTax = (price) => price * 0.1;
```


**در حین تایپ بگو:** «الان فقط یک تغییر — save — refresh — چه فرقی دیدید؟»

**اشتباه عمدی (یک بار):** یک selector اشتباه یا property روی فرزند نادرست — خطا را با کلاس debug کنید.

## پیوست: نکات تکمیلی از جزوه (برای مدرس)

«اینجا تابع پیکانی داخل const است، نه یک تعریف تابع مستقل. اسم calcTax مثل هر const دیگری تا خط مقداردهی قابل خواندن نیست. اگر لازم دارید تابع را بالاتر صدا بزنید، یا تعریف را به بالای محل استفاده ببرید یا از شکل function calcTax() { ... } استفاده کنید.»

«قانون ساده: همیشه متغیرها را بالای محدوده‌شان تعریف کنید و قبل از تعریف از آن‌ها استفاده نکنید. خطای TDZ در واقع به نفع شماست: به جای اینکه بی‌صدا با undefined کار کنید (مثل var)، فوراً اشتباه را نشان می‌دهد.»

«با نوشتن "use strict"; در اول فایل یا تابع، JavaScript سخت‌گیرتر می‌شود و بعضی اشتباه‌های بی‌صدا را به خطا تبدیل می‌کند.»

«رشتهٔ "use strict" باید ابتدای فایل یا ابتدای همان تابع باشد تا اثر کند. داخل این تابع، نسبت دادن به نامی که تعریف نشده خطا می‌دهد. بدون حالت سخت‌گیرانه، همان خط در مرورگر اغلب یک ویژگی روی شیء سراسری می‌ساخت و اشتباه دیرتر دیده می‌شد. تابع‌های دیگر فایل، اگر خودشان این رشته را نداشته باشند، با همین یک تابع سخت‌گیر نمی‌شوند.»


**نکته مدرس:** بعد از هر save یک ثانیه مکث کنید تا کلاس خروجی را ببیند.

**نکته مدرس:** یک بار property را عمداً غلط بگذارید و با DevTools پیدا کنید.

**نکته مدرس:** از دانشجو بخواهید قبل از refresh پیش‌بینی بگوید.

**نکته مدرس:** DevTools → Elements → راست‌کلیک → Scroll into view برای آیتم‌های off-screen.

**نکته مدرس:** در RTL جهت main axis را با overlay Flex روی صفحه نشان دهید.
