## ۱) شروع کلاس؛ مسئله قبل از تعریف

اول با **مسئله** شروع کن — نه با لیست property.

«وقتی فهرست طولانی است، پیدا کردن یک عضو با چشم یا با حلقه‌ای که خودتان از صفر می‌نویسید هم کندتر خوانده می‌شود و هم راحت‌تر اشتباه می‌شود. متدهای جستجو یا شمارهٔ عضو را می‌دهند، یا خود عضو را، یا فقط می‌گویند آن مقدار هست یا نه. مرتب‌سازی ترتیب نمایش را عوض می‌کند، ولی قاعده‌اش برای متن، عدد و شیء یکی نیست. اگر تابع مقایسه را درست ننویسید، عددی مثل ۱۰۰ ممکن است قبل از ۲۵ قرار بگیرد.»

«const nums = [4, 9, 16, 25, 29]; console.log(nums.indexOf(16)); console.log(nums.indexOf(100)); console.log(nums.includes(25)); const firstBig = nums.find(function (n) { return n > 10; }); console.log(firstBig); console.log(nums.findIndex(function (n) { return n > 10; })); indexOf با برابری دقیق دنبال مقدار می‌گردد و شمارهٔ اولین مورد را برمی‌گرداند؛ اگر نباشد نتیجه -1 است، نه undefined . includes فقط هست یا نیست را با true و false می‌گوید. find تابعی می‌گیرد و آن را روی عضو‌ها اجرا می‌کند تا اولین عضوی که شرطش true شود را برگرداند. findIndex به‌جای خود عضو، شمارهٔ همان عضو را می‌دهد.»

«find یک تابع می‌گیرد و آن را برای تک‌تک عضوها اجرا می‌کند. اولین عضوی که تابع برایش true برگرداند، جواب است. اگر همه عضوهای منطبق را می‌خواهید، از filter (درس بعد) استفاده کنید.»

«sort() بدون ورودی، عضوها را به رشته تبدیل می‌کند و بر اساس کد یونیکد کاراکترها (مثل ترتیب واژه‌نامه، ولی حرف به حرف) مرتب می‌کند. برای همین حروف بزرگ انگلیسی قبل از حروف کوچک می‌آیند.»

**روی جزوه این عناوین را دنبال کنید:** *۳) جستجو و مرتب‌سازی آرایه (Search & Sort)* · *جستجو* · *مرتب‌سازی متن* · *مرتب‌سازی عدد — حتماً تابع مقایسه بدهید*

**چرخه این بخش:** نشان بده → دانشجو حدس بزند → یک خط کد → refresh.

## ۳) Live Coding — مرحله‌به‌مرحله

«فایل live جدا می‌سازم تا index پروژه قاطی نشود — مثلاً `تدریس/live/` در همین ماژول.»

**مرحله 1 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
const nums = [4, 9, 16, 25, 29];

console.log(nums.indexOf(16));
console.log(nums.indexOf(100));
console.log(nums.includes(25));

const firstBig = nums.find(function (n) {
  return n > 10;
});
console.log(firstBig);
console.log(nums.findIndex(function (n) { return n > 10; }));
```

**مرحله 2 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
const names = ["Sara", "Ali", "Maryam", "Reza"];
names.sort();
console.log(names);        // ["Ali","Maryam","Reza","Sara"]
names.reverse();           // فقط ترتیب فعلی را برعکس می‌کند
console.log(names);        // ["Sara","Reza","Maryam","Ali"]

const mixedCase = ["banana", "Cherry", "apple"];
console.log(mixedCase.sort());   // ["Cherry","apple","banana"] — حرف بزرگ اول!

const cities = ["مشهد", "گرگان", "تبریز", "پاوه", "اصفهان", "چالوس"];
console.log(cities.slice().sort());  // ✖ پ، چ و گ آخر رفتند (ترتیب یونیکد، نه الفبای فارسی)

// مرتب‌سازی درست متن (فارسی یا انگلیسی) با localeCompare
cities.sort(function (a, b) { return a.localeCompare(b, "fa"); });
console.log(cities);              // ✔ اصفهان، پاوه، تبریز، چالوس، گرگان، مشهد
```

**مرحله 3 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
const scores = [40, 100, 1, 5, 25, 10];

scores.sort();
console.log(scores);              // ✖ غلط! [1,10,100,25,40,5] — مثل متن مرتب شد

scores.sort(function (a, b) { return a - b; });
console.log(scores);              // ✔ صعودی: [1,5,10,25,40,100]

scores.sort(function (a, b) { return b - a; });
console.log(scores);              // ✔ نزولی: [100,40,25,10,5,1]
```


**در حین تایپ بگو:** «الان فقط یک تغییر — save — refresh — چه فرقی دیدید؟»

**اشتباه عمدی (یک بار):** یک selector اشتباه یا property روی فرزند نادرست — خطا را با کلاس debug کنید.
