## ۱) شروع کلاس؛ مسئله قبل از تعریف

اول با **مسئله** شروع کن — نه با لیست property.

«Scope یعنی یک متغیر از کدام بخش برنامه قابل خواندن و عوض کردن است. اگر نامی را بیرون از محدوده‌اش به کار ببرید، برنامه آن را نمی‌شناسد و معمولاً ReferenceError می‌دهد. سه محدودهٔ رایج در جدول زیر آمده‌اند. این تفکیک جلوی دو اشتباه را می‌گیرد: استفاده از متغیری که در آن بخش وجود ندارد، و فرض کردن اینکه دو متغیر هم‌نام در دو جای مختلف یکی هستند.»

«siteName بیرون از تابع ساخته شده، پس هم داخل showInfo دیده می‌شود و هم بعد از آن. author داخل تابع است و فقط تا پایان همان اجرا زنده است. خط آخر خطا می‌دهد چون در محدودهٔ سراسری چنین نامی ثبت نشده است. تابع می‌تواند متغیر بیرونی را بخواند، ولی بیرون نمی‌تواند متغیر درونی را بخواند.»

«خط آخر خطا می‌دهد و اجرای برنامه همان‌جا متوقف می‌شود (در جعبه Console پایین، خطا با ✖ نشان داده شده است). مدیریت خطا را در درس ۱۳ می‌بینیم.»

«آکولاد if یک بلوک است. let و const فقط داخل همان بلوک وجود دارند، حتی اگر شرط همیشه درست باشد. var به این آکولاد توجه نمی‌کند و بعد از بلوک هم قابل خواندن است. به همین دلیل در کد تازه، متغیر داخل شرط را با let یا const می‌سازیم.»

**روی جزوه این عناوین را دنبال کنید:** *۷) محدوده دسترسی (Scope)* · *Global و Function scope* · *Block scope* · *let در حلقه for*

**چرخه این بخش:** نشان بده → دانشجو حدس بزند → یک خط کد → refresh.

## ۳) Live Coding — مرحله‌به‌مرحله

«فایل live جدا می‌سازم تا index پروژه قاطی نشود — مثلاً `تدریس/live/` در همین ماژول.»

**مرحله 1 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
const siteName = "آموزش JS";      // سراسری

function showInfo() {
  const author = "سارا";          // تابعی
  console.log(siteName + " - " + author);
}

showInfo();
console.log(siteName);
console.log(author);              // ✖ ReferenceError: author is not defined
```

**مرحله 2 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
if (true) {
  let x = 10;
  const y = 20;
  var z = 30;         // var به بلوک اهمیت نمی‌دهد!
}
console.log(z);       // 30
console.log(x);       // ✖ ReferenceError: x is not defined
```

**مرحله 3 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
const prices = [120000, 85000, 40000];
let total = 0;

for (let i = 0; i < prices.length; i++) {
  const price = prices[i];     // هر دور یک price جدید
  total += price;
}

console.log(total);            // 245000 ← total بیرون حلقه تعریف شده، پس در دسترس است
console.log(typeof i);         // "undefined" ← i فقط داخل حلقه وجود دارد
```


**در حین تایپ بگو:** «الان فقط یک تغییر — save — refresh — چه فرقی دیدید؟»

**اشتباه عمدی (یک بار):** یک selector اشتباه یا property روی فرزند نادرست — خطا را با کلاس debug کنید.

## پیوست: نکات تکمیلی از جزوه (برای مدرس)

«یکی از دلایلی که var را کنار گذاشتیم همین است: var داخل if و for هم بیرون «نشت» می‌کند (var فقط به تابع محدود می‌شود، نه بلوک). let و const درست به بلوک محدود می‌شوند. در کد امروزی var ننویسید؛ اینجا فقط برای شناختن کدهای قدیمی آمده است.»

«total قبل از حلقه ساخته شده تا هر دور بتواند به همان جمع اضافه کند و بعد از حلقه هم خوانده شود. price و i با let یا const داخل حلقه هستند و بیرون از آن وجود ندارند. typeof برای نام اعلام‌نشده خطا نمی‌دهد و رشتهٔ "undefined" برمی‌گرداند.»

«قانون عملی: متغیر را در کوچک‌ترین محدوده‌ای تعریف کنید که لازم است. اگر نتیجه حلقه را بعد از حلقه لازم دارید (مثل total )، آن را قبل از حلقه تعریف کنید.»

«هر دو متغیر color نام دارند، ولی یکی نیستند. نسخهٔ داخل تابع متغیر بیرونی را پنهان می‌کند و هر تغییری روی همان نسخهٔ درونی می‌ماند. بعد از اتمام تابع، console.log بیرونی هنوز «قرمز» را می‌بیند. اگر داخل تابع let را نمی‌نوشتید، همان متغیر بیرونی خوانده و در صورت انتساب عوض می‌شد.»


**نکته مدرس:** بعد از هر save یک ثانیه مکث کنید تا کلاس خروجی را ببیند.

**نکته مدرس:** یک بار property را عمداً غلط بگذارید و با DevTools پیدا کنید.

**نکته مدرس:** از دانشجو بخواهید قبل از refresh پیش‌بینی بگوید.

**نکته مدرس:** DevTools → Elements → راست‌کلیک → Scroll into view برای آیتم‌های off-screen.

**نکته مدرس:** در RTL جهت main axis را با overlay Flex روی صفحه نشان دهید.
