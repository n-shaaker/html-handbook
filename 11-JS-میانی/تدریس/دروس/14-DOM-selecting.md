## ۱) شروع کلاس؛ مسئله قبل از تعریف

اول با **مسئله** شروع کن — نه با لیست property.

«وقتی مرورگر صفحه را می‌خواند، از HTML یک درخت از اشیا می‌سازد به اسم DOM (Document Object Model). JavaScript با این درخت کار می‌کند؛ هر تگ یک «گره» (node) است.»

«مرورگر سند را به شکل درخت نگه می‌دارد. document ریشهٔ دسترسی شماست. html دو شاخهٔ اصلی head و body دارد و هر تگ داخل بدنه یک گره است. انتخاب عنصر یعنی پیدا کردن یکی از این گره‌ها تا بعداً بتوانید متن یا ظاهرش را عوض کنید.»

«querySelector و querySelectorAll همان انتخابگرهای CSS را قبول می‌کنند که در دوره CSS یاد گرفتید؛ برای همین معمولاً فقط از همین دو استفاده می‌کنیم. NodeList خروجی querySelectorAll متد forEach دارد ولی map و filter ندارد؛ اگر لازم شد با Array.from(list) یا [...list] آن را به آرایه تبدیل کنید. HTMLCollection حتی forEach هم ندارد.»

«این نشانه‌گذاری همان درختی است که مثال بعدی انتخاب می‌کند. id باید در صفحه یکتا باشد. کلاس item روی هر سه آیتم تکرار شده و کلاس special فقط یکی را متمایز می‌کند. انتخابگرها از همین شناسه و کلاس‌ها استفاده می‌کنند.»

**روی جزوه این عناوین را دنبال کنید:** *۱۴) DOM: انتخاب عنصرها* · *روش‌های انتخاب* · *مثال* · *مثال زنده: آزمایشگاه انتخابگر*

**چرخه این بخش:** نشان بده → دانشجو حدس بزند → یک خط کد → refresh.

## ۳) Live Coding — مرحله‌به‌مرحله

«فایل live جدا می‌سازم تا index پروژه قاطی نشود — مثلاً `تدریس/live/` در همین ماژول.»

**مرحله 1 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
document
└── html
    ├── head
    │   └── title
    └── body
        ├── h1
        └── ul
            ├── li
            └── li
```

**مرحله 2 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
<ul id="menu">
  <li class="item">خانه</li>
  <li class="item special">محصولات</li>
  <li class="item">تماس</li>
</ul>
```

**مرحله 3 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
const menu = document.getElementById("menu");
const firstItem = document.querySelector("#menu .item");
const special = document.querySelector(".special");
const allItems = document.querySelectorAll("#menu li");

console.log(menu);                    // خود عنصر <ul>
console.log(firstItem.textContent);   // خانه
console.log(special.textContent);     // محصولات
console.log(allItems.length);         // 3

allItems.forEach(item => console.log("-", item.textContent));

console.log(document.querySelector("#no-such-id"));   // null ← پیدا نشد
```


**در حین تایپ بگو:** «الان فقط یک تغییر — save — refresh — چه فرقی دیدید؟»

**اشتباه عمدی (یک بار):** یک selector اشتباه یا property روی فرزند نادرست — خطا را با کلاس debug کنید.

## پیوست: نکات تکمیلی از جزوه (برای مدرس)

«getElementById فقط با شناسه کار می‌کند و یک عنصر یا null برمی‌گرداند. querySelector اولین عنصری را می‌دهد که با انتخابگر CSS جور باشد. querySelectorAll همهٔ موارد را در یک فهرست می‌ریزد که می‌شود روی آن forEach زد. اگر چیزی پیدا نشود، querySelector مقدار null می‌دهد و نباید مستقیم روی آن ویژگی بخوانید.»

«یک انتخابگر CSS بنویسید (مثلاً .fruit ، li:first-child ، #c3 ، .red ) تا عنصرهای منطبق با querySelectorAll پیدا و رنگی شوند:»

«جستجو روی lab.querySelectorAll(...) انجام شده، نه document ؛ یعنی فقط داخل همان فهرست می‌گردد. querySelector روی هر عنصری هم صدا زده می‌شود و فقط بین فرزندان آن جستجو می‌کند.»

«اشتباه رایج: فراموش کردن . یا # در querySelector: querySelector("menu") دنبال تگی به اسم menu می‌گردد، نه id.»


**نکته مدرس:** بعد از هر save یک ثانیه مکث کنید تا کلاس خروجی را ببیند.

**نکته مدرس:** یک بار property را عمداً غلط بگذارید و با DevTools پیدا کنید.

**نکته مدرس:** از دانشجو بخواهید قبل از refresh پیش‌بینی بگوید.

**نکته مدرس:** DevTools → Elements → راست‌کلیک → Scroll into view برای آیتم‌های off-screen.

**نکته مدرس:** در RTL جهت main axis را با overlay Flex روی صفحه نشان دهید.
