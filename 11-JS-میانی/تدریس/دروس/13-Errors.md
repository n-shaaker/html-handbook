## ۱) شروع کلاس؛ مسئله قبل از تعریف

اول با **مسئله** شروع کن — نه با لیست property.

«وقتی خطایی رخ می‌دهد، اجرای برنامه متوقف می‌شود. با try...catch می‌توانیم خطا را «بگیریم» و برنامه را ادامه دهیم.»

«try { // کدی که ممکن است خطا بدهد } catch (error) { // اگر خطا رخ داد اینجا اجرا می‌شود } finally { // همیشه اجرا می‌شود (اختیاری) } بلوک try کدی است که ممکن است هنگام اجرا خطا بدهد. اگر خطا رخ دهد، اجرا به catch می‌رود و شیء خطا در پارامتر error قرار می‌گیرد. finally در هر دو حالت اجرا می‌شود: چه خطا باشد و چه نباشد. این الگو برای کاری است که باید حتماً انجام شود، مثل بستن یک وضعیت موقت. خطای نحوی، یعنی کدی که از اول نادرست نوشته شده، به این بلوک نمی‌رسد چون برنامه اصلاً اجرا نمی‌شود.»

«try { console.log("قبل از خطا"); undefinedFunction(); // چنین تابعی وجود ندارد console.log("این خط اجرا نمی‌شود"); } catch (error) { console.log("خطا گرفته شد:", error.name); // ReferenceError console.log("پیام:", error.message); // undefinedFunction is not defined } finally { console.log("finally همیشه اجرا می‌شود"); } console.log("برنامه ادامه دارد ✔"); شیء خطا ( error ) دو ویژگی مهم دارد: name (نوع خطا) و message (توضیح خطا). finally چه خطا رخ بدهد چه ندهد اجرا می‌شود و برای کارهای «جمع‌وجور کردن» مثل پنهان کردن پیام «در حال بارگذاری...» مناسب است.»

«انواع رایج خطا نوع کی رخ می‌دهد مثال ReferenceError استفاده از متغیر تعریف‌نشده console.log(x) TypeError کار نادرست با یک نوع داده null.length SyntaxError اشتباه در نوشتن کد / JSON JSON.parse("{bad}") RangeError عدد خارج از محدوده مجاز (1.5).toFixed(200) throw — ساختن خطای دلخواه function divide(a, b) { if (b === 0) { throw new Error("تقسیم بر صفر ممکن نیست!"); } return a / b; } try { console.log(divide(10, 2)); // 5 console.log(divide(5, 0)); // اینجا خطا پرتاب می‌شود و به catch می‌رویم } catch (err) { console.log("✖", err.message); } throw اجرای عادی تابع را قطع می‌کند و یک شیء خطا به نزدیک‌ترین catch می‌فرستد. تقسیم موفق، نتیجه را برمی‌گرداند و به catch نمی‌رود. تقسیم بر صفر عمداً خطا می‌سازد تا به‌جای مقدار Infinity ، پیام قابل‌فهم به کاربر برسد. err.message همان متنی است که داخل Error گذاشته‌اید.»

**روی جزوه این عناوین را دنبال کنید:** *۱۳) مدیریت خطا (Try...Catch)* · *مثال: گرفتن خطا* · *انواع رایج خطا* · *throw — ساختن خطای دلخواه*

**چرخه این بخش:** نشان بده → دانشجو حدس بزند → یک خط کد → refresh.

## ۳) Live Coding — مرحله‌به‌مرحله

«فایل live جدا می‌سازم تا index پروژه قاطی نشود — مثلاً `تدریس/live/` در همین ماژول.»

**مرحله 1 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
try {
  // کدی که ممکن است خطا بدهد
} catch (error) {
  // اگر خطا رخ داد اینجا اجرا می‌شود
} finally {
  // همیشه اجرا می‌شود (اختیاری)
}
```

**مرحله 2 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
try {
  console.log("قبل از خطا");
  undefinedFunction();            // چنین تابعی وجود ندارد
  console.log("این خط اجرا نمی‌شود");
} catch (error) {
  console.log("خطا گرفته شد:", error.name);   // ReferenceError
  console.log("پیام:", error.message);        // undefinedFunction is not defined
} finally {
  console.log("finally همیشه اجرا می‌شود");
}
console.log("برنامه ادامه دارد ✔");
```

**مرحله 3 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
function divide(a, b) {
  if (b === 0) {
    throw new Error("تقسیم بر صفر ممکن نیست!");
  }
  return a / b;
}

try {
  console.log(divide(10, 2));   // 5
  console.log(divide(5, 0));    // اینجا خطا پرتاب می‌شود و به catch می‌رویم
} catch (err) {
  console.log("✖", err.message);
}
```


**در حین تایپ بگو:** «الان فقط یک تغییر — save — refresh — چه فرقی دیدید؟»

**اشتباه عمدی (یک بار):** یک selector اشتباه یا property روی فرزند نادرست — خطا را با کلاس debug کنید.
