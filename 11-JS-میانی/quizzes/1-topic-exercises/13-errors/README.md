# مبحث ۱۳: مدیریت خطا — تمرین‌های جداگانه

درس مرتبط: [۱۳) مدیریت خطا (Try...Catch)](../../../pages/13-errors.html)

ابزارهای این مبحث: `try`، `catch`، `finally`، `throw new Error(...)`، `error.name`، `error.message` و `instanceof SyntaxError`. خروجی در **Console** است.

## تمرین ۱ — JSON خراب ⭐

**هدف:** گرفتن خطا با `try...catch` و ادامه دادن برنامه.

**صورت مسئله:** از سرور دو متن رسیده؛ یکی سالم و یکی خراب. برنامه نباید با متن خراب از کار بیفتد.

**الزامات:**
- تابع `readUser(text)` داخل `try` متن را `JSON.parse` کند و اسم کاربر را چاپ کند.
- در `catch` اسم و پیام خطا (`error.name`) را چاپ کند.
- در `finally` بنویسد «بررسی تمام شد».
- تابع را با `'{"name":"سارا"}'` و `"{name: سارا}"` صدا بزنید و در آخر «برنامه ادامه دارد» چاپ شود.

**تست‌ها / خروجی مورد انتظار:**
```
کاربر: سارا
بررسی تمام شد
خطا: SyntaxError
بررسی تمام شد
برنامه ادامه دارد
```

## تمرین ۲ — برداشت از کیف پول ⭐⭐

**هدف:** ساختن خطای خودمان با `throw new Error` برای ورودی نامعتبر.

**صورت مسئله:** کیف پول یک اپ ۲۰۰٬۰۰۰ تومان موجودی دارد. برداشت فقط با مبلغ درست مجاز است.

**الزامات:**
- `withdraw(balance, amount)` در این حالت‌ها خطا پرتاب کند:
  - `amount` عدد نیست (`typeof` یا `Number.isNaN`) ← «مبلغ باید عدد باشد.»
  - `amount` صفر یا منفی ← «مبلغ باید بیشتر از صفر باشد.»
  - `amount` بیشتر از موجودی ← «موجودی کافی نیست.»
- در غیر این صورت موجودی جدید را برگرداند.
- چهار حالت را هر کدام در `try...catch` امتحان کنید.

**تست‌ها / خروجی مورد انتظار:**
```
withdraw(200000, 50000) → موجودی جدید: 150000
withdraw(200000, صد) → خطا: مبلغ باید عدد باشد.
withdraw(200000, -10) → خطا: مبلغ باید بیشتر از صفر باشد.
withdraw(200000, 900000) → خطا: موجودی کافی نیست.
```

## تمرین ۳ — خواندن تنظیمات با مقدار پیش‌فرض ⭐⭐⭐

**هدف:** تشخیص نوع خطا (`SyntaxError` یا خطای خودمان) و برگرداندن مقدار پیش‌فرض.

**صورت مسئله:** برنامه تنظیمات را از یک متن JSON می‌خواند. اگر متن خراب بود، تنظیمات پیش‌فرض استفاده شود؛ اگر `fontSize` عدد نبود، پیام مخصوص داده شود.

**الزامات:**
- `parseSettings(text)` متن را parse کند؛ اگر `fontSize` عدد نبود، `throw new Error("اندازه فونت باید عدد باشد.")`.
- در `catch`: اگر خطا `SyntaxError` بود پیام «تنظیمات خراب است» و اگر نه، پیام خود خطا را چاپ کند.
- در هر دو حالت خطا، شیء پیش‌فرض `{ theme: "light", fontSize: 14 }` برگردد.
- سه ورودی جدول را امتحان کنید.

**تست‌ها / خروجی مورد انتظار:**
```
{"theme":"dark","fontSize":18} → dark / 18
تنظیمات خراب است
{theme: dark} → light / 14
اندازه فونت باید عدد باشد.
{"theme":"dark","fontSize":"بزرگ"} → light / 14
```

## اشتباه‌های رایج این مبحث

- گذاشتن `try` دور کل برنامه؛ فقط دور کدی بگذارید که **ممکن است** خطا بدهد.
- `catch` خالی که خطا را بی‌صدا قورت می‌دهد؛ دست‌کم پیام را نشان دهید.
- `throw "متن"` به‌جای `throw new Error("متن")`؛ بدون `Error`، `name` و `message` ندارید.
- انتظار اینکه `try...catch` خطای **تایپی در نحو کد** (مثل پرانتز جاافتاده) را بگیرد؛ آن خطا قبل از اجرا رخ می‌دهد.
- فراموش کردن اینکه بعد از `throw` بقیه تابع اجرا **نمی‌شود**.
