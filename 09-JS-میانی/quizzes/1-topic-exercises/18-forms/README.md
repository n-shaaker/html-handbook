# مبحث ۱۸: فرم‌ها و اعتبارسنجی — تمرین‌های جداگانه

درس مرتبط: [۱۸) فرم‌ها و اعتبارسنجی (Forms & Validation)](../../../pages/18-forms.html)

ابزارهای این مبحث: رویداد `submit` روی فرم، `event.preventDefault()`، `form.elements.name.value`، `trim`، `checked`، `form.reset()` و رویداد `input` برای فرم. برای اعتبارسنجی با JS، فرم را `novalidate` کنید.

## تمرین ۱ — عضویت در خبرنامه ⭐

**هدف:** گرفتن رویداد `submit`، جلوگیری از ارسال و خواندن مقدار فیلد.

**صورت مسئله:** پایین سایت یک کتاب‌فروشی، فرم کوچک «عضویت در خبرنامه» با یک فیلد ایمیل هست.

**الزامات:**
- شنونده `submit` روی **فرم** (نه `click` روی دکمه) با `preventDefault`.
- مقدار ایمیل را با `trim` بخوانید.
- اگر خالی بود یا `@` نداشت، پیام «لطفاً ایمیل درست وارد کنید.» در `#message`.
- در غیر این صورت پیام «ایمیل … با موفقیت ثبت شد.» و فرم `reset` شود.

**تست‌ها / خروجی مورد انتظار:**
- خالی ← «لطفاً ایمیل درست وارد کنید.»
- `ali.example.com` ← همان پیام خطا.
- `  ali@example.com ` ← «ایمیل ali@example.com با موفقیت ثبت شد.» و کادر خالی می‌شود.
- زدن Enter داخل کادر هم همین رفتار را دارد.

## تمرین ۲ — ثبت‌نام با پیام خطای هر فیلد ⭐⭐

**هدف:** اعتبارسنجی چند فیلد و نشان دادن پیام خطا زیر همان فیلد.

**صورت مسئله:** فرم ثبت‌نام باشگاه سه فیلد دارد: نام، سن و رمز عبور. هر خطا باید زیر فیلد خودش نوشته شود.

**الزامات:**
- نام: دست‌کم ۳ حرف (بعد از `trim`) ← «نام باید حداقل ۳ حرف باشد.»
- سن: عدد صحیح بین ۱۲ تا ۹۰ ← «سن باید عددی بین ۱۲ تا ۹۰ باشد.»
- رمز: دست‌کم ۸ کاراکتر ← «رمز باید حداقل ۸ کاراکتر باشد.»
- هر بار ارسال، اول همه پیام‌های قبلی پاک شوند؛ اگر حتی یک خطا بود، پیام موفقیت نشان داده نشود.
- اگر همه درست بود: «… عزیز، ثبت‌نام شما انجام شد.» و `form.reset()`.

**تست‌ها / خروجی مورد انتظار:**
- «ع»، «۸» (یا 8)، «123» ← هر سه پیام خطا زیر فیلدها.
- «علی»، «25»، «12345678» ← «علی عزیز، ثبت‌نام شما انجام شد.»
- سن «12.5» ← خطای سن.

## تمرین ۳ — سفارش چای با قیمت زنده ⭐⭐⭐

**هدف:** خواندن `select`، `radio`، `checkbox` و `number` و محاسبه زنده قیمت با رویداد `input` روی فرم.

**صورت مسئله:** چایخانه سنتی سفارش آنلاین می‌گیرد: اندازه قوری (کوچک ۴۰٬۰۰۰ / بزرگ ۶۰٬۰۰۰)، نوع شیرینی (نبات / خرما / بدون شیرینی)، افزودنی‌ها (هل، دارچین؛ هر کدام ۱۰٬۰۰۰) و تعداد.

**الزامات:**
- تابع `calcTotal()` قیمت را از روی فیلدها حساب کند: (قیمت اندازه + افزودنی‌ها) × تعداد.
- با هر تغییر فرم (رویداد `input` روی خود فرم)، `#live-total` به‌روز شود.
- تعداد باید بین ۱ تا ۱۰ باشد؛ اگر نبود، به‌جای قیمت «تعداد باید بین ۱ تا ۱۰ باشد.» نشان داده شود.
- با `submit`، خلاصه سفارش به صورت فهرست (`ul` ساخته‌شده با `createElement`) در `#summary` نمایش داده شود.

**تست‌ها / خروجی مورد انتظار:**
- پیش‌فرض (کوچک، نبات، بدون افزودنی، ۱ عدد) ← «۴۰٬۰۰۰ تومان».
- بزرگ + هل + دارچین، ۲ عدد ← «۱۶۰٬۰۰۰ تومان».
- تعداد ۰ ← پیام خطای تعداد.
- ارسال ← فهرست: اندازه: بزرگ / شیرینی: خرما / افزودنی: هل، دارچین / تعداد: ۲ / جمع: ۱۶۰٬۰۰۰ تومان.

## اشتباه‌های رایج این مبحث

- گذاشتن `click` روی دکمه به‌جای `submit` روی فرم؛ Enter زدن را از دست می‌دهید.
- فراموش کردن `preventDefault()`؛ صفحه دوباره بارگذاری و همه چیز پاک می‌شود.
- `input.value` همیشه **رشته** است؛ برای محاسبه `Number(...)` لازم است.
- برای checkbox از `.value` استفاده کردن؛ تیک خوردن را با `.checked` بخوانید.
- پاک نکردن پیام‌های خطای دفعه قبل، که باعث می‌شود خطای رفع‌شده هنوز دیده شود.
