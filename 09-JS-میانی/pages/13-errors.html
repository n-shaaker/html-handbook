۱۳) مدیریت خطا (Try...Catch)

وقتی خطایی رخ می‌دهد، اجرای برنامه متوقف می‌شود. با try...catch می‌توانیم خطا را «بگیریم» و برنامه را ادامه دهیم.

try {
  // کدی که ممکن است خطا بدهد
} catch (error) {
  // اگر خطا رخ داد اینجا اجرا می‌شود
} finally {
  // همیشه اجرا می‌شود (اختیاری)
}

بلوک try کدی است که ممکن است هنگام اجرا خطا بدهد. اگر خطا رخ دهد، اجرا به catch می‌رود و شیء خطا در پارامتر error قرار می‌گیرد. finally در هر دو حالت اجرا می‌شود: چه خطا باشد و چه نباشد. این الگو برای کاری است که باید حتماً انجام شود، مثل بستن یک وضعیت موقت. خطای نحوی، یعنی کدی که از اول نادرست نوشته شده، به این بلوک نمی‌رسد چون برنامه اصلاً اجرا نمی‌شود.

مثال: گرفتن خطا

try {
  console.log("قبل از خطا");
  undefinedFunction();            // چنین تابعی وجود ندارد
  console.log("این خط اجرا نمی‌شود");
} catch (error) {
  console.log("خطا گرفته شد:", error.name);   // ReferenceError
  console.log("پیام:", error.message);        // undefinedFunction is not defined
} finally {
  console.log("finally همیشه اجرا می‌شود");
}
console.log("برنامه ادامه دارد ✔");

شیء خطا (error) دو ویژگی مهم دارد: name (نوع خطا) و message (توضیح خطا). finally چه خطا رخ بدهد چه ندهد اجرا می‌شود و برای کارهای «جمع‌وجور کردن» مثل پنهان کردن پیام «در حال بارگذاری...» مناسب است.

throw — ساختن خطای دلخواه



function divide(a, b) {
  if (b === 0) {
    throw new Error("تقسیم بر صفر ممکن نیست!");
  }
  return a / b;
}

try {
  console.log(divide(10, 2));   // 5
  console.log(divide(5, 0));    // اینجا خطا پرتاب می‌شود و به catch می‌رویم
} catch (err) {
  console.log("✖", err.message);
}



throw اجرای عادی تابع را قطع می‌کند و یک شیء خطا به نزدیک‌ترین catch می‌فرستد. تقسیم موفق، نتیجه را برمی‌گرداند و به catch نمی‌رود. تقسیم بر صفر عمداً خطا می‌سازد تا به‌جای مقدار Infinity، پیام قابل‌فهم به کاربر برسد. err.message همان متنی است که داخل Error گذاشته‌اید.










در JavaScript تقسیم بر صفر خودش خطا نمی‌دهد و Infinity برمی‌گرداند؛ ما با throw خودمان آن را به خطا تبدیل کردیم تا مقدار بی‌معنی وارد ادامه برنامه نشود. همیشه new Error("...") را throw کنید، نه یک رشته ساده؛ چون شیء Error ویژگی‌های name، message و محل خطا (stack) را دارد.



بررسی نوع خطا در catch



function countCartItems(text) {
  try {
    const cart = JSON.parse(text);
    return cart.items.length;
  } catch (err) {
    if (err instanceof SyntaxError) {
      console.log("داده سبد خراب است:", err.name);
    } else {
      console.log("خطای دیگر:", err.name, "-", err.message);
    }
    return 0;
  }
}

console.log(countCartItems('{"items": ["دفتر", "خودکار", "کیف"]}'));   // 3
console.log(countCartItems("{items: []}"));      // JSON نامعتبر → SyntaxError → 0
console.log(countCartItems('{"total": 5}'));     // items وجود ندارد → TypeError → 0



هر بار متن سبد با JSON.parse خوانده می‌شود. اگر متن JSON خراب باشد، خطا از نوع SyntaxError است. اگر JSON درست باشد ولی ویژگی items وجود نداشته باشد، خواندن length خطای نوع دیگری می‌دهد. در هر دو حالت تابع صفر برمی‌گرداند تا برنامه به‌جای توقف، یک نتیجهٔ قابل‌استفاده داشته باشد.










مثال زنده: اعتبارسنجی سن در فرم ثبت‌نام



function checkAge(value) {
  if (value.trim() === "") {
    throw new Error("سن را وارد کنید.");
  }
  const age = Number(value);
  if (Number.isNaN(age)) {
    throw new Error("سن باید عدد باشد.");
  }
  if (!Number.isInteger(age)) {
    throw new Error("سن باید عدد صحیح باشد.");
  }
  if (age < 12 || age > 120) {
    throw new Error("سن باید بین ۱۲ تا ۱۲۰ باشد.");
  }
  return age;
}

const ageInput = document.getElementById("age-input");
const ageBtn = document.getElementById("age-btn");
const msg = document.getElementById("age-msg");

ageBtn.addEventListener("click", () => {
  try {
    const age = checkAge(ageInput.value);
    msg.textContent = `✔ سن ${age} ثبت شد.`;
    msg.className = "msg-ok";
  } catch (err) {
    msg.textContent = "✖ " + err.message;
    msg.className = "msg-error";
  }
});













مقدارهای «12.5»، «abc»، «150» و کادر خالی را امتحان کنید. توجه کنید که Number("") و Number("   ") برابر 0 می‌شوند نه NaN؛ برای همین خالی بودن را جداگانه و قبل از تبدیل بررسی کردیم. نکته مهم برای کاربران فارسی‌زبان: Number("۲۵") (با رقم فارسی) هم NaN است؛ در برنامه واقعی قبل از تبدیل، رقم‌های فارسی را به انگلیسی تبدیل کنید یا در پیام خطا به کاربر بگویید.



try...catch فقط خطاهای زمان اجرا را می‌گیرد. اگر کد خطای نحوی (Syntax) داشته باشد، اصلاً اجرا نمی‌شود. همچنین خطایی که بعداً داخل یک callback رخ دهد (مثلاً داخل setTimeout یا تابع رویداد) با try...catch بیرونی گرفته نمی‌شود؛ try...catch را داخل همان callback بنویسید (مثل مثال بالا).



اشتباه رایج: خالی گذاشتن catch: catch (e) {}. خطا پنهان می‌شود و پیدا کردن مشکل خیلی سخت می‌شود. حداقل آن را با console.error چاپ کنید.



اشتباه رایج: گذاشتن همه برنامه داخل یک try بزرگ. try را فقط دور بخشی بگذارید که انتظار خطا در آن دارید (مثل JSON.parse یا ورودی کاربر) تا خطاهای برنامه‌نویسی خودتان پنهان نشوند.



تمرین: تابع getItem(arr, index) بنویسید که اگر index عدد صحیح نبود یا خارج از محدوده آرایه بود (کمتر از ۰ یا بزرگ‌تر مساوی arr.length)، با throw new Error("شماره نامعتبر") خطا بدهد و در غیر این صورت عضو را برگرداند. آن را با getItem(["دفتر", "خودکار"], 1) و getItem(["دفتر", "خودکار"], 5) داخل try...catch صدا بزنید و نتیجه یا پیام خطا را چاپ کنید.
