# ۱۱) JavaScript میانی — سوال و جواب

## آرایه و متدها

### ۱. آرایه را کی به‌جای چند متغیر؟
**جواب:** وقتی چند مقدار هم‌نوع/هم‌نقش دارید (لیست کارها، محصولات) و می‌خواهید حلقه/فیلتر بزنید.

### ۲. فرق `push` / `pop` / `shift` / `unshift`؟
**جواب:** push/pop انتها؛ unshift/shift ابتدا. shift/unshift معمولاً کندتر برای آرایه بزرگ.

### ۳. `map` با `forEach`؟
**جواب:** `map` آرایهٔ جدید برمی‌گرداند (تبدیل). `forEach` فقط برای هر آیتم کاری می‌کند و معمولاً برای side-effect. برای ساخت لیست جدید map.

### ۴. `filter` و `find`؟
**جواب:** `filter` همهٔ مطابق‌ها (آرایه). `find` اولین مطابق (یک عنصر یا undefined).

### ۵. `reduce` یک مثال جونیور؟
**جواب:** جمع قیمت‌ها: `prices.reduce((sum, p) => sum + p, 0)`. مقدار اولیه `0` را فراموش نکنید.

### ۶. آیا متدها آرایه اصلی را عوض می‌کنند؟
**جواب:** بعضی بله (`push`, `splice`, `sort`). `map`/`filter` معمولاً آرایه جدید می‌سازند. قبل از استفاده در سند چک کنید.

## scope، arrow، this، JSON، خطا

### ۷. Scope یعنی چه؟
**جواب:** محدودهٔ دیده شدن متغیر. بیرون تابع به `let` داخل بلوک دسترسی ندارید. این از تداخل اسم‌ها جلوگیری می‌کند.

### ۸. Hoisting را حفظ باشم؟
**جواب:** جزئیات را حفظ نکنید؛ بدانید `var` بالا می‌آید و گیج می‌کند، پس از `let`/`const` استفاده کنید.

### ۹. Arrow همیشه بهتر است؟ کی نه؟
**جواب:** برای callbacks کوتاه عالی است. وقتی به `this` دینامیک متد شیء نیاز دارید، تابع عادی گاهی درست‌تر است (بعداً عمیق‌تر می‌شود).

### ۱۰. قانون حداقلی `this` برای جونیور؟
**جواب:** داخل متد شیء با فراخوانی `obj.method()` معمولاً `this` همان `obj` است. در listener اگر گیج شدید، arrow و متغیر بیرونی را ترجیح دهید تا مسلط شوید.

### ۱۱. Destructuring و spread با مثال؟
**جواب:** `const { name, age } = user`؛ کپی آرایه/ادغام: `const all = [...a, ...b]`.

### ۱۲. JSON با شیء JS؟
**جواب:** JSON متن (رشته) با قواعد سخت‌گیرانه است. `JSON.stringify` شیء→متن؛ `JSON.parse` متن→شیء. برای storage و API ضروری است.

### ۱۳. `try/catch` دور چه کدی؟
**جواب:** جایی که ممکن است پرتاب خطا شود و نباید کل برنامه بمیرد (parse JSON، بخشی از کار با دادهٔ خارجی). دور همه چیز نپیچید.

## DOM عمیق و فرم

### ۱۴. `querySelector` یا `getElementById`؟
**جواب:** هر دو درست. id یکتا → getElementById سریع و واضح. برای کلاس/سلکتور پیچیده → querySelector.

### ۱۵. چرا `innerHTML` خطرناک است؟ جایگزین؟
**جواب:** اگر دادهٔ کاربر داخلش برود ممکن است XSS شود. برای متن: `textContent`. برای ساخت عنصر: `createElement` + `append`.

### ۱۶. چرا `createElement` طولانی ولی اصرار دارید؟
**جواب:** امن‌تر و کنترل‌شده‌تر است؛ عادت درست برای UI پویا. سرعت تایپ مهم‌تر از عادت بد نیست.

### ۱۷. `preventDefault` در فرم؟
**جواب:** جلوی رفتار پیش‌فرض (ارسال و رفرش صفحه) را می‌گیرد تا خودتان با JS پردازش کنید.

### ۱۸. اعتبارسنجی دستی با HTML5؟
**جواب:** HTML5 سریع و رایگان است. دستی کنترل پیام و منطق سفارشی می‌دهد. در جزوه مسیر دستی تمرین می‌شود؛ ترکیب هم در کار واقعی رایج است.

### ۱۹. چرا Debugging قبل از Todo؟
**جواب:** Todo باگ‌خیز است. بدون Console/breakpoint ساعت‌ها در تاریکی می‌مانید.

## پروژه Todo

### ۲۰. State چیست؟ چرا اول آرایه بعد render؟
**جواب:** State دادهٔ حقیقت برنامه (`todos`). UI باید از روی آن ساخته شود. اگر مستقیم DOM را دستکاری کنید، داده و صفحه از هم جدا می‌شوند.

### ۲۱. با رفرش پاک می‌شود؛ عمدی است؟
**جواب:** بله در این درس؛ تمرکز روی DOM/آرایه است. ماندگاری در `localStorage` درس پیشرفته است.

### ۲۲. همین‌جا storage اضافه کنم؟
**جواب:** بعد از تمام شدن Todo منطق، بله به‌عنوان چالش؛ اول درس [web-storage](../12-JS-پیشرفته/pages/13-web-storage.html) را بخوانید.

### ۲۳. فیلتر را چطور به render وصل کنم؟
**جواب:** متغیر `filter` را عوض کنید، بعد `render()` که از روی `todos` + `filter` لیست را می‌سازد.

### ۲۴. باگ دارم؛ breakpoint کجا؟
**جواب:** اولی روی `render`، دومی روی handler افزودن/حذف. ببینید state قبل/بعد چه شده.
