## ۱) شروع کلاس؛ مسئله قبل از تعریف

اول با **مسئله** شروع کن — نه با لیست property.

«Callback تابعی است که آن را به تابع دیگری می‌دهید تا در زمان مناسب صدایش بزند. گاهی این صدا زدن همان لحظه است، مثل وقتی که map برای هر عضو یک تابع را اجرا می‌کند. گاهی صدا زدن بعداً است، وقتی کاری مثل تایمر یا پاسخ شبکه تمام شده باشد. تفاوت این دو را اول ببینید، چون شکل نوشتن callback در هر دو شبیه است ولی زمان اجرا فرق دارد.»

«function processUser(name, callback) { const formatted = name.trim().toUpperCase(); callback(formatted); } processUser(" sara ", (result) => { console.log("نتیجه:", result); }); processUser نام را تمیز و بزرگ می‌کند، ولی خودش نتیجه را چاپ نمی‌کند. تابعی که شما به‌عنوان callback می‌دهید بعد از آماده‌شدن متن صدا زده می‌شود و نتیجه را تحویل می‌گیرد. این جدایی باعث می‌شود همان پردازش را با کارهایی غیر از چاپ هم استفاده کنید.»

«Callback ناهمگام: شبیه‌سازی گرفتن داده از سرور function getUser(id, callback) { log(`در حال دریافت کاربر ${id}...`); setTimeout(() => { const user = { id: id, name: "سارا" }; callback(user); // وقتی داده آماده شد }, 1000); } getUser(7, (user) => { log("کاربر رسید:", user); }); log("این خط زودتر چاپ می‌شود!"); // ترتیب خروجی: // در حال دریافت کاربر 7... // این خط زودتر چاپ می‌شود! // کاربر رسید: {"id":7,"name":"سارا"} ← یک ثانیه بعد setTimeout شبیه‌سازی کاری است که طول می‌کشد، مثل پاسخ سرور. خط بعد از getUser منتظر تایمر نمی‌ماند و زودتر اجرا می‌شود. وقتی زمان بگذرد، شیء کاربر ساخته می‌شود و به callback داده می‌شود. به همین دلیل پیام «کاربر رسید» بعد از پیام همگام دیده می‌شود.»

«مشکل: جهنم Callback (Callback Hell) وقتی چند کار ناهمگام باید پشت سر هم انجام شوند (هر مرحله به نتیجه مرحله قبل نیاز دارد)، callbackها تو در تو می‌شوند و خواندن و مدیریت خطا سخت می‌شود. کد زیر فقط برای نشان دادن شکل مشکل است (توابع آن فرضی‌اند):»

**روی جزوه این عناوین را دنبال کنید:** *۸) توابع Callback و کد ناهمگام* · *همگام (Synchronous) در مقابل ناهمگام (Asynchronous)* · *Callback همگام* · *Callback ناهمگام: شبیه‌سازی گرفتن داده از سرور*

**چرخه این بخش:** نشان بده → دانشجو حدس بزند → یک خط کد → refresh.

## ۳) Live Coding — مرحله‌به‌مرحله

«فایل live جدا می‌سازم تا index پروژه قاطی نشود — مثلاً `تدریس/live/` در همین ماژول.»

**مرحله 1 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
function processUser(name, callback) {
  const formatted = name.trim().toUpperCase();
  callback(formatted);
}

processUser("  sara ", (result) => {
  console.log("نتیجه:", result);
});
```

**مرحله 2 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
function getUser(id, callback) {
  log(`در حال دریافت کاربر ${id}...`);
  setTimeout(() => {
    const user = { id: id, name: "سارا" };
    callback(user);                  // وقتی داده آماده شد
  }, 1000);
}

getUser(7, (user) => {
  log("کاربر رسید:", user);
});
log("این خط زودتر چاپ می‌شود!");

// ترتیب خروجی:
// در حال دریافت کاربر 7...
// این خط زودتر چاپ می‌شود!
// کاربر رسید: {"id":7,"name":"سارا"}   ← یک ثانیه بعد
```

**مرحله 3 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
getUser(1, (user) => {
  getOrders(user.id, (orders) => {
    getOrderDetails(orders[0], (details) => {
      getShipping(details.shipId, (shipping) => {
        console.log(shipping);       // هرم وحشت 😱
      });
    });
  });
});
```


**در حین تایپ بگو:** «الان فقط یک تغییر — save — refresh — چه فرقی دیدید؟»

**اشتباه عمدی (یک بار):** یک selector اشتباه یا property روی فرزند نادرست — خطا را با کلاس debug کنید.
