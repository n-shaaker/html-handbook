۵) وراثت، static و فیلدهای خصوصی

وراثت یعنی کلاس فرزند رفتار کلاس پدر را به ارث ببرد و فقط تفاوت‌های خودش را اضافه یا جایگزین کند. extends این رابطه را می‌سازد و super سازنده یا متد پدر را صدا می‌زند. در کنار آن، عضو ایستا به خود کلاس تعلق دارد و فیلد خصوصی با # از بیرون کلاس مخفی می‌ماند.

وراثت با extends و super

کلاس فرزند همه ویژگی‌ها و متدهای کلاس پدر را به ارث می‌برد و می‌تواند چیزهای جدید اضافه یا متدها را بازنویسی (override) کند.

class Animal {
  constructor(name) {
    this.name = name;
  }
  speak() {
    return `${this.name} صدایی درمی‌آورد.`;
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name);              // اجرای constructor پدر (اجباری، قبل از this)
    this.breed = breed;
  }
  speak() {                   // بازنویسی متد پدر
    return `${this.name} (${this.breed}) واق واق می‌کند!`;
  }
}

class Cat extends Animal {
  speak() {
    return super.speak() + " میو!";   // استفاده از نسخه پدر
  }
}

const animals = [new Animal("حیوان"), new Dog("رکس", "ژرمن"), new Cat("پیشی")];
animals.forEach(a => console.log(a.speak()));
console.log(animals[1] instanceof Animal);   // true ← سگ، حیوان هم هست

extends متدهای کلاس پدر را در دسترس فرزند می‌گذارد. در سازندهٔ سگ، super(name) باید پیش از استفاده از this سازندهٔ پدر را اجرا کند تا name ساخته شود و بعد نژاد روی همان شیء ذخیره شود. سگ speak را کاملاً عوض می‌کند. گربه سازندهٔ جدا ندارد و speak پدر را با super.speak() صدا می‌زند و فقط «میو» را به آن اضافه می‌کند. هر سه نمونه در یک آرایه هستند و instanceof Animal برای سگ هم true است، چون در زنجیرهٔ وراثت حیوان مانده است.








شکل استفاده از superکجاکار


super(...)فقط داخل constructor فرزندconstructor پدر را اجرا می‌کند؛ باید قبل از اولین استفاده از this باشد


super.method()داخل هر متد فرزندنسخه پدرِ یک متد را صدا می‌زند (مثل Cat بالا)





کلاس Cat constructor ندارد؛ در این حالت JavaScript خودش یک constructor پیش‌فرض می‌سازد که همه آرگومان‌ها را به super(...args) می‌دهد. پس فقط وقتی constructor بنویسید که ویژگی جدیدی (مثل breed) لازم دارید.



متد و ویژگی static



عضوهای static مال خود کلاس هستند نه نمونه‌ها؛ با اسم کلاس صدا زده می‌شوند (مثل Math.random()).



class MathHelper {
  static PI = 3.14159;

  static circleArea(r) {
    return MathHelper.PI * r * r;
  }
}

console.log(MathHelper.circleArea(2));   // 12.56636
const m = new MathHelper();
console.log(m.circleArea);    // undefined ← روی نمونه نیست



متد و ویژگی static به خود کلاس تعلق دارند، نه به نمونه‌هایی که با new ساخته می‌شوند. آن‌ها را با نام کلاس صدا می‌زنید. روی نمونه، circleArea وجود ندارد و undefined است. از این شکل برای ابزارهایی استفاده می‌کنید که به دادهٔ یک شیء خاص وابسته نیستند.










نمونه‌های آشنای static در خود JavaScript: Math.round()، Array.isArray()، Number.isInteger()، Object.keys() و Date.now(). همه با اسم کلاس صدا زده می‌شوند، نه روی یک نمونه.



فیلد و متد خصوصی با #



عضوی که اسمش با # شروع شود واقعاً خصوصی است: فقط کدهای داخل همان کلاس به آن دسترسی دارند. مثال کاربردی: حساب بانکی که موجودی آن فقط از راه واریز و برداشت تغییر می‌کند.



class BankAccount {
  #balance = 0;                 // فیلد خصوصی: فقط داخل کلاس قابل دسترسی

  constructor(owner, initial) {
    this.owner = owner;
    this.#balance = initial;
  }

  deposit(amount) {
    if (amount <= 0) throw new Error("مبلغ نامعتبر است");
    this.#balance += amount;
    return this.#balance;
  }

  withdraw(amount) {
    if (amount > this.#balance) throw new Error("موجودی کافی نیست");
    this.#balance -= amount;
    return this.#balance;
  }

  getBalance() {                // تنها راه خواندن موجودی از بیرون
    return this.#balance;
  }
}

const acc = new BankAccount("سارا", 500);
console.log(acc.deposit(200));          // 700

try {
  acc.withdraw(5000);
} catch (err) {
  console.log("خطا:", err.message);    // خطا: موجودی کافی نیست
}

acc.balance = 1000000;                  // یک ویژگی معمولی تازه می‌سازد؛ ربطی به #balance ندارد
console.log(acc.getBalance());          // 700
console.log(Object.keys(acc));          // ["owner","balance"] ← فیلد خصوصی #balance دیده نمی‌شود
// console.log(acc.#balance);           // ✖ SyntaxError



فیلدهایی که با # شروع می‌شوند فقط داخل بدنهٔ همان کلاس قابل خواندن‌اند. حتی کد بیرونی که به نمونه دسترسی دارد نمی‌تواند acc.#balance را بنویسد و این کار خطای نحوی است. واریز و برداشت از متدها انجام می‌شود تا مبلغ نامعتبر قبل از تغییر موجودی رد شود.










اگر خط آخر (acc.#balance) را از حالت توضیح دربیاورید، کل فایل با خطای نحوی SyntaxError: Private field '#balance' must be declared in an enclosing class اصلاً اجرا نمی‌شود. (Console مرورگر Chrome برای راحتی اشکال‌زدایی اجازه خواندن فیلد خصوصی را می‌دهد؛ این استثنا فقط مخصوص DevTools است و در فایل JS کار نمی‌کند.)



balance و #balance دو چیز کاملاً جدا هستند. برای همین خط acc.balance = 1000000 موجودی واقعی حساب را تغییر نمی‌دهد.



قبل از وجود #، برنامه‌نویس‌ها اسم ویژگی‌های «خصوصی» را با خط زیر شروع می‌کردند (this._balance). این فقط یک قرارداد است و از بیرون قابل تغییر است؛ # واقعاً جلوی دسترسی را می‌گیرد.



اشتباه رایج: استفاده از this در constructor فرزند قبل از super(). خطای ReferenceError: Must call super constructor in derived class before accessing 'this' or returning from derived constructor می‌گیرید.



اشتباه رایج: استفاده از فیلد خصوصی بدون تعریف آن در بدنه کلاس. this.#x = 1 فقط وقتی مجاز است که بالای کلاس #x; (یا #x = مقدار;) نوشته شده باشد.



تمرین: کلاس Shape با متد area() (که در کلاس پدر 0 برمی‌گرداند) بسازید. دو کلاس Rectangle (با عرض و طول) و Circle (با شعاع) از آن به ارث ببرند و area() را بازنویسی کنند. یک متد static به اسم Shape.compare(a, b) بنویسید که از بین دو شکل، شکلی را که مساحت بزرگ‌تری دارد برگرداند. در آخر به Circle یک فیلد خصوصی #radius با getter و setter بدهید که شعاع منفی را نپذیرد (خطا throw کند).
