۴) ترتیب لایه‌ها (Z-index)

وقتی چند عنصر روی هم رسم می‌شوند، z-index ترتیب عمقی آن‌ها را تعیین می‌کند. عدد بزرگ‌تر روی عدد کوچک‌تر قرار می‌گیرد؛ مثل برگه‌هایی که روی میز روی هم چیده شده‌اند. این ویژگی فقط وقتی اثر دارد که عنصر از حالت position: static خارج شده باشد، یا فرزند مستقیم یک ظرف flex یا grid باشد. اگر z-index ننویسید، عنصری که در HTML دیرتر آمده، در شرایط برابر، روی عنصر قبلی رسم می‌شود.

مثال ۱: سه کارت روی هم

.stage { position: relative; height: 190px; }   /* مرجع سه کارت */

.red   { position: absolute; top: 0;    right: 0;     z-index: 1; }
.green { position: absolute; top: 30px; right: 60px;  z-index: 2; }
.blue  { position: absolute; top: 60px; right: 120px; z-index: 3; }  /* از همه بالاتر */
قرمز z=1
سبز z=2
آبی z=3

مثال ۲: همان کارت‌ها، ترتیب برعکس

.red  { z-index: 3; }  /* حالا قرمز رو است */
.blue { z-index: 1; }
قرمز z=3
سبز z=2
آبی z=1

مثال ۳: متن روی تصویر (بنر محصول)

عنصری که position دارد به‌طور پیش‌فرض روی عنصرهای بدون position (مثل همین img) می‌نشیند؛ z-index: 2 را برای اطمینان می‌گذاریم تا اگر بعداً عنصر positioned دیگری اضافه شد، متن باز هم رو بماند. 

.photo   { position: relative; }
.caption {
  position: absolute;
  bottom: 0;
  right: 0;
  left: 0;                              /* تمام‌عرض روی پایین تصویر */
  z-index: 2;
  background-color: rgba(0, 0, 0, 0.6); /* نوار نیمه‌شفاف تا متن خوانا باشد */
}

حراج پاییزه — تا ۴۰٪ تخفیف

اگر z-index مشخص نکنید، عنصری که در HTML دیرتر آمده، روی قبلی‌ها می‌نشیند. عدد منفی هم مجاز است؛ z-index: -1 عنصر را پشت محتوای عادی پدرش می‌فرستد (مثلاً برای یک شکل تزئینی پشت متن).

اشتباه رایج: z-index روی عنصرهایی کار می‌کند که position آن‌ها static نیست (یعنی relative، absolute، fixed یا sticky). تنها استثنا فرزندان مستقیم flex و grid هستند؛ در بقیه موارد، بدون position هر عددی بنویسید بی‌اثر است.

نکته مهم: z-index فقط بین «هم‌گروه‌ها» مقایسه می‌شود

مقایسه z-index سراسری نیست. مرورگر عنصرها را در گروه‌هایی به نام stacking context می‌چیند و عددها را فقط داخل همان گروه با هم می‌سنجد. یک گروه تازه وقتی ساخته می‌شود که عنصری position غیر از static و z-index غیر از auto داشته باشد، یا opacity کمتر از ۱ داشته باشد، یا transform غیر از none داشته باشد. فرزندان فقط داخل گروه پدرشان بالا و پایین می‌روند. برای همین منویی با z-index خیلی بزرگ هم ممکن است زیر بخش دیگری بماند، اگر پدر آن منو در گروه پایین‌تری باشد. در این حالت باید z-index را به پدر بدهید.

اشتباه رایج: استفاده از عددهای بی‌حساب مثل 99999. بهتر است چند سطح ثابت داشته باشید؛ مثلاً محتوای عادی ۱، منوی کشویی ۱۰، هدر چسبان ۱۰۰ و پنجره مودال ۱۰۰۰.

تمرین: دو دایره رنگی بسازید که نیمی از آن‌ها روی هم بیفتد. با تغییر z-index جای «رو» و «زیر» را عوض کنید.
