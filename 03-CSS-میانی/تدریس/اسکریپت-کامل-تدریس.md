## صفر) افتتاحیهٔ دوره — نقشهٔ ذهنی

«بچه‌ها، دورهٔ مقدماتی تمام شده. رنگ، حاشیه، padding، مدل جعبه، فونت و لینک را بلدیم. از امروز می‌خواهیم صفحه‌ای بسازیم که شبیه سایت واقعی رفتار کند: منو بالای صفحه، کارت دوره با برچسب «جدید»، متن مقاله خوانا، تصویر بریده داخل قاب، فرم ثبت‌نام تمیز، و در موبایل بدون اسکرول افقی.

اسم پروژه‌مان را می‌گذاریم **آکادمی وب**. هر مبحثی که یاد می‌گیریم، تکه‌ای از همین صفحه را کامل‌تر می‌کند. لزوماً هر ویژگی تکمیل‌کنندهٔ قبلی نیست؛ بعضی‌ها ابزار جدا هستند. ولی هرجا طبیعی باشد، همان فایل را جلو می‌بریم تا وسط ترم ده تا دموی بی‌ربط نداشته باشیم.

**قبل از شروع کدنویسی، نمونهٔ نهایی را باز کنید و به دانشجو نشان دهید:** [`نمونه-نهایی/index.html`](./نمونه-نهایی/index.html) — بگویید: «تا پایان این مسیر، چنین صفحه‌ای می‌سازیم.»

فایل زندهٔ پیشنهادی را از اول با این اسکلت باز کنید:»

```html
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>آکادمی وب — Live</title>
  <style>
    * { box-sizing: border-box; }
    body {
      margin: 0;
      font-family: Tahoma, Vazirmatn, sans-serif;
      background: #f1f5f9;
      color: #0f172a;
      line-height: 1.7;
    }
  </style>
</head>
<body>
  <!-- اینجا در طول دوره پر می‌شود -->
</body>
</html>
```

«تا پایان مسیر اصلی این‌ها را می‌شناسیم: نوع جعبه، سقف عرض، موقعیت، لایه‌ها، سرریز، شناوری متن دور تصویر، کنار هم نشاندن جعبه‌ها، تراز، انتخابگرهای دقیق‌تر، حالت‌های hover و focus، تزئین با شبه‌عنصر، شفافیت، نوار منو و کشویی، فرم، اسکلت چیدمان صفحه، و media query. بین فرم و چیدمان صفحه، Flexbox و Grid را در ماژول خودشان عمیق می‌کنیم.»

## ۱) نمایش (Display) — جعبه چطور در جریان صفحه می‌نشیند؟

**جزوه:** [`01-display.html`](../pages/01-display.html)

### آنچه روی سایت می‌خواهیم

«قبل از رنگ و سایه، مرورگر باید بداند هر تکه **چه نوع جعبه‌ای** است. در آکادمی وب سه خواسته داریم:

1. در فرم ثبت‌نام موبایل، دکمهٔ «ارسال» و «انصراف» هر کدام یک ردیف کامل باشند تا انگشت راحت بزند.  
2. بالای لیست دوره‌ها چند برچسب فیلتر — رایگان، جدید، تخفیف — در **همان خط** کنار هم بنشینند.  
3. بنر «جشنواره تمام شد» را گاهی کاملاً برداریم طوری که جایش هم نماند؛ گاهی فقط مخفی کنیم ولی جای خالی بماند تا بقیه نپرند.

HTML معنی تگ را عوض نمی‌کند؛ CSS فقط مدل جعبه را عوض می‌کند. لینک با `display: block` هنوز لینک است.»

### یادآوری block و inline

«`div`، `p`، عنوان‌ها معمولاً **block**اند: از خط جدید، عرض در دسترس والد. `span`، `a`، `strong` معمولاً **inline**اند: در همان خط، به اندازهٔ محتوا. روی pure inline معمولاً `width` و `height` اثر مورد انتظار ندارد — برای همین روی برچسب فیلتر اگر فقط `width: 120px` بگذارید ممکن است هیچ‌چیز عوض نشود.»

Live اول داخل `body`:

```html
<section class="filters">
  <span class="tag">رایگان</span>
  <span class="tag">جدید</span>
  <span class="tag">تخفیف</span>
</section>

<form class="signup-actions">
  <button type="submit">ارسال</button>
  <button type="button">انصراف</button>
</form>
```

```css
.tag {
  width: 120px;           /* روی span معمولی معمولاً بی‌اثر */
  padding: 0.35rem 0.75rem;
  background: #ffe8cc;
  margin-inline-end: 0.35rem;
}

.signup-actions button {
  display: block;
  width: 100%;
  margin-bottom: 0.5rem;
  padding: 0.75rem 1rem;
}
```

**در مرورگر:** دکمه‌ها زیر هم تمام‌عرض می‌شوند — خواستهٔ موبایل. برچسب‌ها هنوز مثل متن کنار هم‌اند ولی عرض قفل نشده.

«اگر بخواهیم هر برچسب مثل یک ردیف اطلاعات زیر هم باشد، span را block می‌کنیم:»

```css
.info span {
  display: block;
  padding: 0.25rem 0.5rem;
  border-right: 3px solid #1a5fb4;
  margin-bottom: 0.25rem;
  background: #e7f5ff;
}
```

### پنهان کردن: `none` در برابر `visibility`

```html
<div class="banner-row">
  <div class="mini">۱</div>
  <div class="mini is-gone">۲</div>
  <div class="mini">۳</div>
</div>
```

```css
.is-gone { display: none; }          /* جا هم نیست */
.is-invisible { visibility: hidden; } /* جا هست، دیده نمی‌شود */
```

«برای بنر تمام‌شده معمولاً `display: none`. برای نگه داشتن جای خالی موقت، `visibility: hidden`. `opacity: 0` جای دیگری است — عنصر هنوز کلیک‌پذیر می‌ماند؛ بعداً می‌رسیم.»

### منوی خیلی خام (فعلاً فقط مفهوم)

«آیتم‌های `li` زیر هم‌اند. برای منوی افقی موقت می‌توانیم بگوییم:»

```css
.menu-inline {
  list-style: none;
  margin: 0;
  padding: 0;
}
.menu-inline li {
  display: inline;
  margin-inline-start: 1rem;
}
```

«این را در جیب‌تان داشته باشید. بعداً وقتی به نوار منوی واقعی برسیم، همین خواسته را تمیزتر با ساختار `nav` و بعد با Flex کامل می‌کنیم. امروز فقط فهمیدیم **نوع جعبه** جریان صفحه را عوض می‌کند.»

**پل:** «جعبه را شناختیم. حالا محتوای آکادمی روی مانیتور عریض نباید تا لب صفحه خط شود و روی موبایل نباید اسکرول افقی بسازد.»

## ۲) حداکثر عرض — ستون خوانا و قاب امن

**جزوه:** [`02-max-width.html`](../pages/02-max-width.html)

### آنچه می‌خواهیم

«متن معرفی دوره روی مانیتور ۲۷ اینچی اگر لبه تا لبه باشد، چشم خسته می‌شود. روی گوشی اگر `width: 960px` قفل باشد، صفحه افقی اسکرول می‌گیرد. می‌خواهیم: سقف عرض + جمع شدن در فضای کم + وسط‌چین + تصویر داخل قاب بیرون نزند.»

اسکلت پروژه را با container گسترش بده:

```html
<header class="site-header">
  <div class="container">
    <strong>آکادمی وب</strong>
  </div>
</header>

<main>
  <div class="container">
    <article class="intro">
      <h1>دوره CSS سطح میانی</h1>
      <p>از رفتار جعبه‌ها تا منو و فرم؛ آماده‌سازی برای Flex و Grid.</p>
    </article>
  </div>
</main>
```

```css
.container {
  width: 100%;
  max-width: 72rem;
  margin-inline: auto;
  padding-inline: 1rem;
}

.intro {
  max-width: 40rem;       /* ستون خوانا برای متن */
  margin-inline: auto;
}
```

«`width: 100%` یعنی تا جای والد برو؛ `max-width` سقف است. `margin-inline: auto` فضای افقی باقی‌مانده را دو طرف می‌گذارد و جعبه وسط می‌ایستد.»

مقایسهٔ زنده:

```css
.bad  { width: 600px; }
.good { max-width: 600px; width: 100%; }
```

**در مرورگر:** عرض را تا ۳۲۰px کم کن. `bad` بیرون می‌زند؛ `good` جمع می‌شود.

تصویر جلد دوره داخل کارت:

```css
.card img {
  max-width: 100%;
  height: auto;
  display: block;
}
```

«این سه خط تقریباً در هر سایتی هست. تا پایان دوره هر تصویری داخل کارت آکادمی همین را می‌گیرد.»

**پل:** «محتوا داخل قاب امن است. حالا روی کارت دوره می‌خواهیم برچسب «جدید» بچسبد به گوشه — نه اینکه یک خط جدا زیر عنوان بسازد.»

## ۳) موقعیت (Position) — مرجع جابه‌جایی

**جزوه:** [`03-position.html`](../pages/03-position.html)

### آنچه می‌خواهیم روی همان کارت

«چهار خواستهٔ رایج:

1. برچسب روی گوشهٔ کارت (`absolute` داخل والد `relative`)  
2. کمی جابه‌جایی بدون از بین رفتن جای خالی (`relative`)  
3. عنوان بخش هنگام اسکرول بچسبد (`sticky`)  
4. دکمهٔ «برو بالا» گوشهٔ پنجره بماند (`fixed`)

`top` / `left` alone کافی نیست. اول باید `position` بگوید نسبت به چه مرجعی.»

کارت دوره را به پروژه اضافه کن:

```html
<div class="container">
  <article class="course-card">
    <span class="badge">جدید</span>
    <img src="course.jpg" alt="جلد دوره">
    <h2>CSS میانی</h2>
    <p>چیدمان، موقعیت، منو و فرم.</p>
    <p class="price">۱٬۲۰۰٬۰۰۰ تومان</p>
  </article>
</div>
```

```css
.course-card {
  position: relative;          /* مرجع برچسب */
  width: 100%;
  max-width: 22rem;
  margin-inline: auto;
  padding: 1rem;
  padding-top: 1.5rem;
  background: #fff;
  border-radius: 0.5rem;
}

.course-card .badge {
  position: absolute;
  top: -0.5rem;
  inset-inline-start: -0.5rem;
  padding: 0.25rem 0.6rem;
  background: #c92a2a;
  color: #fff;
  font-size: 0.85rem;
  border-radius: 0.25rem;
}

.course-card img {
  max-width: 100%;
  height: auto;
  display: block;
  border-radius: 0.35rem;
}
```

**در مرورگر:** برچسب روی گوشه می‌نشیند و ارتفاع کارت را مثل یک پاراگراف اضافه بلند نمی‌کند.

جدول کوتاه برای کلاس:

| مقدار | معنی برای پروژه |
|--------|------------------|
| `static` | پیش‌فرض؛ top بی‌اثر |
| `relative` | جابه‌جایی نسبت به جای خودش؛ جای خالی می‌ماند؛ مرجع خوبی برای فرزند absolute |
| `absolute` | از جریان خارج؛ نسبت به نزدیک‌ترین ancestor غیر static |
| `fixed` | نسبت به viewport؛ با اسکرول صفحه نمی‌رود |
| `sticky` | تا قبل از آستانه عادی؛ بعد می‌چسبد — معمولاً با `top` |

دکمهٔ برو بالا (آخر `body`):

```css
.to-top {
  position: fixed;
  inset-inline-end: 1rem;
  bottom: 1rem;
  z-index: 50; /* فعلاً یک عدد؛ درس بعد دقیق‌تر */
}
```

«`left`/`right` فیزیکی‌اند؛ در RTL معنی‌شان جابه‌جا نمی‌شود. برای منطقی بودن اغلب `inset-inline-*` تمیزتر است.»

**پل:** «برچسب روی کارت است. اگر روی بنر هیرو متن تخفیف هم بگذاریم، یا مودال ورود باز شود، باید بدانیم کدام لایه رو است.»

## ۴) ترتیب لایه‌ها (z-index)

**جزوه:** [`04-z-index.html`](../pages/04-z-index.html)

### آنچه می‌خواهیم

«متن تخفیف روی تصویر هیرو باشد. بعداً منوی کشویی روی محتوا. مودال روی همه‌چیز. عدد بزرگ‌تر معمولاً بالاتر است — ولی فقط وقتی عنصر positioned باشد (یا آیتم flex/grid)، و فقط داخل همان **stacking context**.»

هیرو را به پروژه اضافه کن:

```html
<section class="hero">
  <div class="container hero-inner">
    <img class="hero-photo" src="banner.jpg" alt="">
    <p class="hero-caption">ثبت‌نام بهاره — ۲۰٪ تخفیف تا پایان هفته</p>
  </div>
</section>
```

```css
.hero-inner {
  position: relative;
  max-width: 48rem;
  margin-inline: auto;
}

.hero-photo {
  display: block;
  width: 100%;
  height: auto;
  border-radius: 0.5rem;
}

.hero-caption {
  position: absolute;
  right: 0;
  left: 0;
  bottom: 0;
  z-index: 2;
  margin: 0;
  padding: 0.75rem 1rem;
  color: #fff;
  background: rgb(0 0 0 / 0.55);
}
```

«سطوح ثابت پیشنهاد دوره — صفرهای الکی ننویسید:»

```css
:root {
  --z-dropdown: 10;
  --z-sticky-header: 100;
  --z-modal: 1000;
}
```

«اگر فرزند `z-index: 9999` داخل پدری با context پایین باشد، از sibling بیرون پدر با z بالاتر جلو نمی‌زند. اول سلسله‌مراتب را درست کنید، بعد عدد.»

**پل:** «تصویر هیرو گاهی از قاب بزرگ‌تر است؛ عنوان کارت گاهی خیلی بلند است؛ ردیف برچسب‌ها در موبایل جا نمی‌شود. سرریز را تصمیم می‌گیریم.»

## ۵) سرریز (Overflow)

**جزوه:** [`05-overflow.html`](../pages/05-overflow.html)

### آنچه می‌خواهیم روی همان اجزا

«۱) قاب تصویر کارت گوشهٔ گرد و crop. ۲) عنوان بلند با سه‌نقطه. ۳) ردیف فیلترها اسکرول افقی داخلی — نه اسکرول کل صفحه.»

```css
.course-card .media {
  height: 10rem;
  overflow: hidden;
  border-radius: 0.5rem;
}
.course-card .media img {
  width: 100%;
  height: 100%;
  object-fit: cover;
  display: block;
}

.course-card h2 {
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
}

.filters {
  overflow-x: auto;
  white-space: nowrap;
  padding-bottom: 0.35rem;
}
.filters .tag {
  display: inline-block; /* پیش‌نمایش بخش بعد */
  width: auto;
  padding: 0.35rem 0.75rem;
}
```

«`visible` پیش‌فرض است. `hidden` می‌برد. `scroll` اغلب همیشه نوار نشان می‌دهد. `auto` فقط وقتی لازم — برای باکس قوانین معمولاً `auto`.

هشدار برای آیندهٔ منوی کشویی: `overflow: hidden` روی هدر یا کارت والد می‌تواند dropdown را ببرد. sticky هم گاهی با overflow غیر visible روی ancestor می‌شکند. crop را روی همان قاب کوچک بگذارید، نه روی کل صفحه.»

**پل:** «در صفحهٔ بلاگ آکادمی می‌خواهیم عکس خبر کنار متن باشد و متن دورش بپیچد — الگوی روزنامه.»

## ۶) شناوری (Float) — فقط برای پیچیدن متن؛ نه برای کل چیدمان

**جزوه:** [`06-float.html`](../pages/06-float.html)

```html
<article class="post container">
  <img class="post-figure" src="news.jpg" alt="">
  <h1>چرا قبل از Flex باید جعبه را بفهمیم؟</h1>
  <p>متن خبر دور تصویر می‌پیچد…</p>
  <p>ادامه…</p>
  <aside class="post-note">منبع: وبلاگ آکادمی</aside>
</article>
```

```css
.post-figure {
  float: inline-start;
  width: 8rem;
  margin-inline-end: 1rem;
  margin-bottom: 0.5rem;
}
.post-note {
  clear: both;
  background: #fff3bf;
  padding: 0.75rem;
}
.post::after {
  content: "";
  display: table;
  clear: both; /* clearfix تا ارتفاع مقاله نریزد */
}
```

«float را برای مقاله بشناسید و کد قدیمی را بخوانید. نوار منو و گرید کارت‌ها را با float نسازید — آن کار مال Flex و Grid است. اگر ارتفاع والد عجیب شد، معمولاً فرزندان float هستند و clearfix لازم است.»

**پل:** «فیلترهای بالای دوره‌ها باید کنار هم جعبهٔ واقعی باشند — عرض و padding عمودی — نه فقط متن لاغر inline.»

## ۷) Inline-block — و فاصلهٔ مرموز بین تگ‌ها

**جزوه:** [`07-inline-block.html`](../pages/07-inline-block.html)

«`inline` کنار هم است ولی width سخت می‌گیرد. `block` عرض می‌گیرد ولی خط می‌شکند. `inline-block` هر دو را می‌خواهد.»

```css
.filters .tag {
  display: inline-block;
  min-width: 5.5rem;
  padding: 0.5rem 0.75rem;
  text-align: center;
  background: #e2e8f0;
  border-radius: 0.35rem;
  margin-inline-end: 0.35rem;
}
```

«اگر بین تگ‌ها در HTML خط جدید باشد، یک فاصلهٔ ریز مثل فاصلهٔ کلمات می‌آید. راه‌حل‌های قدیمی شکننده بودند. راه‌حل امروز برای نوار تب‌ها:»

```css
.filters {
  display: flex;
  flex-wrap: wrap;
  gap: 0.5rem;
  overflow-x: auto;
  white-space: normal;
}
```

«جزئیات Flex را در ماژول ۰۷ عمیق می‌کنیم؛ اینجا فقط درد whitespace را دوا کردیم و پروژه تمیزتر شد.»

**پل:** «عنوان هیرو و دکمه باید حس وسط بدهند؛ ستون معرفی هم وسط صفحه.»

## ۸) تراز — دو معنی متفاوت برای «وسط»

**جزوه:** [`08-align.html`](../pages/08-align.html)

«قبل از نوشتن center بپرسید: **متن داخل جعبه** را می‌خواهم وسط، یا **خود جعبه** را؟»

```css
.hero-copy {
  text-align: center; /* محتوای inline / دکمهٔ inline-block */
  padding: 2rem 1rem;
}

.intro {
  max-width: 40rem;
  margin-inline: auto; /* خود ستون وسط صفحه */
}
```

«`text-align: center` روی والد، یک فرزند block تمام‌عرض را وسط نمی‌کند. آن فرزند باید عرض محدود و `margin-inline: auto` بگیرد.

`vertical-align` برای inline / inline-block است، نه برای وسط کردن section در کل صفحه. وسط کامل صفحه را بعداً با Flex/Grid (`place-items: center`) می‌سازیم.»

**پل:** «صفحه شلوغ می‌شود. می‌خواهیم بگوییم فقط پاراگراف‌های مستقیم داخل مقاله، یا فقط لینک داخل منو — نه همهٔ لینک‌های دنیا.»

## ۹) ترکیب‌کننده‌ها — آدرس دقیق‌تر در درخت HTML

**جزوه:** [`09-combinators.html`](../pages/09-combinators.html)

روی همان HTML پروژه:

```css
/* نسل: هر p داخل .post */
.post p { color: #334155; }

/* فرزند مستقیم */
.post > h1 { font-size: 1.75rem; }

/* خواهر/برادر مجاور: p بلافاصله بعد از h1 */
.post h1 + p { font-size: 1.1rem; color: #0f172a; }

/* خواهر/برادر عام: هر note بعد از figure در همان سطح */
.post-figure ~ .post-note { margin-top: 1rem; }
```

«فاصله ( ) نسل است. `>` فقط فرزند مستقیم. `+` عنصر بلافاصله بعدی هم‌سطح. `~` بعدی‌های هم‌سطح.

این‌ها ظاهر تازه نمی‌سازند؛ به شما اجازه می‌دهند بدون کلاس اضافه روی هر تگ، بخش درست پروژه را نشانه بگیرید. زیاده‌روی نکنید — گاهی یک کلاس روی عنصر خواناتر است.»

**پل:** «وقتی موس روی دکمه می‌رود، وقتی تب روی لینک است، وقتی اولین کارت لیست است — حالت می‌خواهیم نه کلاس دستی برای همه.»

## ۱۸) Media Queries — اول موبایل، بعد گسترش

**جزوه:** [`21-media-queries.html`](../pages/21-media-queries.html)

```css
/* پایه = موبایل */
.header-bar {
  flex-direction: column;
  align-items: flex-start;
}
.hero-copy h1 { font-size: 1.5rem; }

@media (min-width: 48rem) {
  .header-bar {
    flex-direction: row;
    align-items: center;
  }
  .hero-copy h1 { font-size: 2.25rem; }
  .signup button { width: auto; min-width: 12rem; }
}
```

«viewport meta را از اول داشتیم. mobile-first یعنی استایل پایه برای صفحهٔ باریک، بعد با `min-width` قابلیت اضافه کنید — نه اینکه دسکتاپ بنویسید و با `max-width` مدام حذف کنید.

محک قبول: عرض ۳۲۰px بدون اسکرول افقی. Device Toolbar را زنده نشان دهید. تصاویر از قبل `max-width: 100%` داشتند؛ اگر چیزی بیرون زد، `width` ثابت یا مین‌ویدث بزرگ را پیدا کنید.»

«تغییر رنگ دکمه و برچسب را نرم کنید: `transition: background-color 0.2s ease, color 0.2s ease`. همهٔ ویژگی‌ها را transition ندهید. در UI واقعی hover، focus و باز شدن پنل را نرم کنید — نه حرکت‌های آزاردهنده.»

### Animation
**جزوه:** [`24-animations.html`](../pages/24-animations.html)  
«`@keyframes` برای توجه به بنر یا اسپینر بارگذاری. کم استفاده کنید؛ `prefers-reduced-motion` را محترم بشمارید.»

```css
@media (prefers-reduced-motion: reduce) {
  * {
    animation: none !important;
    transition: none !important;
  }
}
```

## پیام پایانی استاد

«هدف این ماژول حفظ کردن فهرست propertyها نبود. هدف این بود که وقتی به یک صفحهٔ واقعی نگاه می‌کنید، اول بگویید روی سایت چه رفتاری می‌خواهید، بعد ابزار درست CSS را انتخاب کنید، و همان پروژه را تکه تکه جلو ببرید.

جعبه را بفهمید، قاب امن بسازید، موقعیت و لایه را آگاهانه بچینید، سرریز را تصمیم بگیرید، انتخابگر و حالت را دقیق بزنید، منو و فرم را معنادار بسازید، بعد با Flex و Grid و media query صفحه را پاسخ‌گو کنید.

درس بعد در مسیر handbook می‌تواند [`آبشاری بودن CSS`](../../04-CSS-آبشاری/index.html) یا [`تصاویر`](../../05-CSS-تصاویر/index.html) باشد — وقتی اولویت قوانین و گالری را جداگانه محکم می‌کنید.»
