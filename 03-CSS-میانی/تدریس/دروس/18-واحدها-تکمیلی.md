## ۱) شروع کلاس؛ چرا دوباره سراغ واحد می‌آییم

«این جلسه **اختیاری** است، ولی اگر روی سایت واقعی کار کنید هر روز با آن طرفید.

تا اینجا نوشته‌ایم `width: 300px` و `font-size: 1.25rem`. سؤال امروز این نیست که واحد چیست. سؤال این است: **این عدد نسبت به چه چیزی حساب می‌شود؟**

یک رزومه آنلاین را در نظر بگیرید. نوار «تسلط بر CSS: ۷۰٪» باید ۷۰ درصد **عرض همان نوار** باشد، نه ۷۰ پیکسل و نه ۷۰ درصد کل پنجره. تیتر هیرو باید با پهن شدن پنجره کمی بزرگ شود، ولی متن پاراگراف باید با تنظیم درشت‌نمایی قلم کاربر بزرگ شود. این دو نیاز، دو مرجع متفاوت دارند.»

اسکلت را بدون واحدهای نسبی بنویس تا مشکل دیده شود:

```html
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Live — واحدها</title>
  <style>
    body {
      font-family: Tahoma, sans-serif;
      margin: 0;
      padding: 1.5rem;
      background: #f8fafc;
      line-height: 1.7;
    }
  </style>
</head>
<body>
  <h1>رزومه امیر حسینی</h1>
  <p>طراح رابط کاربری</p>
  <p>CSS</p>
  <div class="bar"><div class="fill">۷۰٪</div></div>
</body>
</html>
```

```css
.fill {
  width: 70px;
  background: #0f766e;
  color: white;
}
```

**در مرورگر:** نوار ۷۰ پیکسل است. عرض پنجره را زیاد کن. نوار همان‌قدر کوتاه می‌ماند، در حالی که برچسب می‌گوید ۷۰٪. این فاصله بین «معنی روی سایت» و «واحد اشتباه» است.

«هر جا در CSS طول می‌نویسیم، بعد از عدد باید واحد بیاید. `width: 20` نامعتبر است و مرورگر **کل آن خط** را نادیده می‌گیرد. دو استثنا مهم: عدد `0`، چون صفر در هر واحدی همان صفر است؛ و ویژگی‌هایی که از اول عدد بی‌واحد می‌خواهند، مثل `opacity`، `z-index`، و `line-height` وقتی به‌صورت ضریب نوشته شود (`line-height: 1.7`).»

```css
/* معتبر */
width: 20px;
margin: 0;
opacity: 0.8;
line-height: 1.7;

/* نامعتبر */
width: 20;
margin: 20 px; /* فاصله بین عدد و واحد ممنوع */
```

### سؤال کلاسی

- «`padding: 0` چرا واحد نمی‌خواهد؟»  
  **پاسخ:** صفر، صفر است. `0px` هم درست است، ولی لازم نیست.

## ۲) مطلق و نسبی — یک جمله برای هر واحد

«واحد مطلق به عنصرهای اطراف وابسته نیست. واحد نسبی نسبت به یک مرجع حساب می‌شود. مرجع را اگر بلد نباشی، عدد هیچ معنایی ندارد.»

| واحد | نوع | مرجع |
|------|------|------|
| `px` | مطلق | پیکسل CSS؛ پرکاربردترین واحد صفحه |
| `cm` ، `mm` ، `in` ، `pt` | مطلق | بیشتر برای چاپ؛ روی صفحه نمایش کم |
| `%` | نسبی | برای `width` معمولاً عرض پدر؛ برای `font-size` فونت پدر |
| `em` | نسبی | در `font-size`: فونت **پدر**؛ در padding و margin: فونت **خود عنصر** |
| `rem` | نسبی | فونت ریشه، یعنی `html` (اغلب ۱۶px تا وقتی کاربر عوضش نکرده) |
| `vw` / `vh` | نسبی | ۱٪ عرض / ارتفاع پنجره |
| `dvh` | نسبی | ۱٪ ارتفاع واقعی پنجره در موبایل، با نوار آدرسی که باز و بسته می‌شود |

«یک `px` در CSS همیشه یک پیکسل فیزیکی نمایشگر نیست. در گوشی‌های پرتراکم، مرورگر یک پیکسل CSS را با چند پیکسل دستگاه رسم می‌کند تا اندازه دیده‌شده منطقی بماند. در این کلاس لازم نیست وارد نسبت دستگاه شوی. همین قدر که `px` را «اندازه ثابت از دید چیدمان» بدانی کافی است.

`cm` و `pt` را فقط نام ببر: برای صفحه‌ای که قرار است چاپ شود گاهی به کار می‌آیند. برای چیدمان سایت از آن‌ها استفاده نمی‌کنیم.»

### اشتباهات رایج

- `20 px` با فاصله → قانون نامعتبر.  
- جا انداختن واحد روی `width` و `margin` و `font-size`.  
- فرض کردن اینکه `%` همیشه نسبت به پنجره است. برای `width` نسبت به **پدر** است، مگر در حالت‌هایی که بعداً با `absolute` مرجع عوض می‌شود؛ امروز پدر را ملاک بگیر.

## ۳) درصد — نوار مهارت رزومه

نیاز:

«نوار مهارت باید با عرض کارت رزومه مقیاس شود. اگر کارت در موبایل باریک شد، ۷۰٪ هنوز ۷۰٪ همان کارت باشد.»

```html
<p>HTML</p>
<div class="bar"><div class="fill w90">۹۰٪</div></div>
<p>CSS</p>
<div class="bar"><div class="fill w70">۷۰٪</div></div>
<p>JavaScript</p>
<div class="bar"><div class="fill w40">۴۰٪</div></div>
```

```css
.bar {
  width: 100%;
  max-width: 28rem;
  background: #e2e8f0;
  border-radius: 999px;
  overflow: hidden;
}

.fill {
  background: #0f766e;
  color: white;
  padding: 0.2rem 0.6rem;
  font-size: 0.85rem;
}

.w90 { width: 90%; }
.w70 { width: 70%; }
.w40 { width: 40%; }
```

«`.bar` می‌گوید من تا جایی که پدر اجازه می‌دهد عرض بگیر، ولی از `28rem` بیشتر نشو. `.fill` می‌گوید از **عرض همین نوار** این درصد را رنگ کن.

`overflow: hidden` اینجاست تا گوشه گرد پدر، گوشه فرزند را هم ببرد. اگر هنوز overflow را درس نداده‌ای، یک جمله بس است: بدون آن، مستطیل داخلی از کپسول بیرون می‌زند.»

**در مرورگر:** DevTools را باریک کن. نسبت ۹۰ / ۷۰ / ۴۰ ثابت می‌ماند. بعد موقتاً `.w70 { width: 70px; }` بگذار و تفاوت را نشان بده، بعد برگردان.

### سؤال کلاسی

- «اگر `.bar` عرض ۲۰۰ پیکسل داشته باشد، `width: 50%` روی `.fill` چند پیکسل است؟»  
  **پاسخ:** ۱۰۰ پیکسل. درصد عرض، نسبت به عرض پدر است.

- «اگر به‌جای درصد، `70vw` بگذاریم چه فرقی دارد؟»  
  **پاسخ:** دیگر به عرض نوار نگاه نمی‌کند؛ به عرض پنجره نگاه می‌کند و ممکن است از خود نوار بیرون بزند.

### اشتباهات رایج

- درصد روی فرزند، در حالی که پدر عرض مشخصی ندارد و خودش هم با محتوا جمع می‌شود → درصد گاهی طوری حساب می‌شود که انتظار نداری. برای نوار، پدر را `width: 100%` با یک `max-width` ببند.  
- جمع کردن چند فرزند درصدی بدون توجه به padding پدر. اگر `box-sizing` را مرور کرده‌ای، یادآوری کن padding پدر از فضای داخلی کم می‌کند.

## ۴) یادآوری em و rem — فقط تا جایی که واحد جدید را قاطی نکند

«`rem` و `em` را در مقدماتی ساخته‌اید. اینجا فقط دو صحنه را دوباره زنده می‌بینیم، چون بقیه واحدهای امروز با همین‌ها اشتباه می‌شوند.»

صحنه اول، فونت:

```css
html {
  font-size: 16px;
}

.parent {
  font-size: 20px;
}

.em {
  font-size: 1.5em; /* 1.5 × 20 = 30px */
}

.rem {
  font-size: 1.5rem; /* 1.5 × 16 = 24px */
}
```

```html
<div class="parent">
  متن پدر (20px)
  <p class="em">با 1.5em</p>
  <p class="rem">با 1.5rem</p>
</div>
```

«`em` برای `font-size` به فونت پدر نگاه می‌کند. `rem` همیشه به `html`. اگر فردا فونت ریشه را برای یک پوسته درشت‌تر ۱۸ پیکسل کنیم، فقط `rem`ها با هم تکان می‌خورند.»

حالا `html { font-size: 20px; }` را عوض کن. پاراگراف `rem` درشت می‌شود؛ `em` همچنان ۳۰px می‌ماند چون پدرش ۲۰px است.

صحنه دوم، تله تودرتو. کوتاه:

```css
li { font-size: 1.2em; }
```

«هر `li` داخل `li` دیگر، ۱٫۲ برابر پدرش می‌شود. سطح‌ها روی هم ضرب می‌شوند. برای فونت سراسری سایت، `rem` قابل پیش‌بینی‌تر است.»

صحنه سوم، جایی که `em` را **می‌خواهیم**. دکمه:

```html
<button class="btn small" type="button">کوچک</button>
<button class="btn medium" type="button">متوسط</button>
<button class="btn large" type="button">بزرگ</button>
```

```css
.btn {
  padding: 0.5em 1em;
  border: none;
  border-radius: 0.35em;
  background: #1a3a5c;
  color: white;
  cursor: pointer;
}

.small  { font-size: 0.75rem; }
.medium { font-size: 1rem; }
.large  { font-size: 1.5rem; }
```

«اینجا `em` در padding به فونت **خود دکمه** نگاه می‌کند، نه به پدر. فونت را با `rem` از ریشه گرفتیم تا اندازه سه دکمه قابل پیش‌بینی باشد؛ padding را با `em` بستیم تا فاصله داخلی با همان فونت مقیاس شود. یک قانون جدا برای padding هر سایز لازم نیست.»

**قاعده شروع کار که در جزوه هم هست:**

- فونت‌ها با `rem`، تا اگر کاربر کم‌بینا اندازه قلم پیش‌فرض مرورگر را بزرگ کند، متن همراهش بزرگ شود. متن `px` ثابت می‌ماند.  
- فاصله‌های خیلی کوچک و خط‌های ۱ پیکسلی با `px`.  
- عرض‌هایی که باید با ظرف جمع شوند با `%` یا با الگوی `width: 100%` و `max-width`.

این را روی برد بنویس و رد شو. بحث دسترس‌پذیری را طولانی نکن؛ یک جمله درباره تنظیم فونت مرورگر کافی است.

### سؤال کلاسی

- «با ریشه ۱۶px و پدر ۲۰px، `2em` برای font-size فرزند و `2rem` هر کدام چند پیکسل‌اند؟»  
  **پاسخ:** `2em` = ۴۰px؛ `2rem` = ۳۲px.

## ۵) vw و vh — نسبت به پنجره، نه پدر

نیاز روی سایت:

«صفحه اول یک دوره، یک نوار خوش‌آمد می‌خواهد که حدود یک‌سوم ارتفاع **پنجره‌ای که الان باز است** را بگیرد، نه یک‌سوم ارتفاع پدر. پدر maybe فقط به اندازه محتوا باشد و آن وقت درصد ارتفاع اغلب آن چیزی که طراح گفته نیست.

`vh` یک‌صدم ارتفاع viewport است. `vw` یک‌صدم عرض همان پنجره. `height: 30vh` یعنی حدود ۳۰ درصد ارتفاع پنجره.»

```html
<section class="hero">
  <p class="vw-title">پنجره را تغییر اندازه دهید</p>
</section>
<section>
  <p>بخش بعدی صفحه، زیر هیرو.</p>
</section>
```

```css
.hero {
  height: 30vh;
  min-height: 8rem;
  background: #1a3a5c;
  color: white;
  display: flex;
  justify-content: center;
  align-items: center;
}

.vw-title {
  font-size: 5vw;
  margin: 0;
}
```

«`display: flex` با دو خط وسط‌چین را از درس تراز (ماژول همین دوره، درس ۸) قرض گرفتیم. امروز وارد محورهای Flex نمی‌شویم؛ فقط می‌خواهیم متن وسط نوار دیده شود. اگر آن درس یادشان نیست، موقتاً `text-align: center` و `padding-top` بده تا مفهوم `vh` گم نشود.»

**در مرورگر:** ارتفاع پنجره را کم و زیاد کن. نوار هیرو حدود ۳۰٪ ارتفاع viewport می‌ماند. عرض را زیاد کن: تیتر `5vw` درشت می‌شود. عرض را تا حدود ۳۲۰px کم کن: تیتر ریز و ناخوانا می‌شود.

«این همان تله است. فونتِ فقط با `vw` دو مشکل دارد:

۱. با تنظیم درشت‌نمایی قلم مرورگر آن‌طور که `rem` بزرگ می‌شود، بزرگ نمی‌شود؛ به عرض پنجره وصل است.  
۲. در موبایل خیلی ریز و در مانیتور خیلی پهن خیلی درشت می‌شود.

در جزوه نوشته راه‌حل، محدود کردن با `clamp()` است. آن تابع درس **بعد** است. امروز فقط تله را ببینید و روی تیتر اصلی سایت `5vw` خالی نگذارید.»

`min-height: 8rem` را نشان بده: اگر پنجره خیلی کوتاه شود، `30vh` ممکن است از متن کوچک‌تر شود. برای هیرو واقعی اغلب `min-height` امن‌تر از `height` ثابت است، چون محتوا اگر دو خط شد بیرون نمی‌زند. یک‌بار `height: 30vh` را با متن طولانی امتحان کن تا سرریز دیده شود، بعد بگو در پروژه از `min-height` استفاده می‌کنیم.

### سؤال کلاسی

- «`width: 50%` با پدر ۴۰۰px، و `width: 50vw` با پنجره ۴۰۰px، اگر پدر تمام‌عرض باشد یکی‌اند. اگر پدر یک کارت ۳۰۰px داخل پنجره ۱۰۰۰px باشد چه؟»  
  **پاسخ:** ۵۰٪ می‌شود ۱۵۰px (نصف کارت). ۵۰vw می‌شود ۵۰۰px (نصف پنجره) و از کارت بیرون می‌زند.

## ۶) dvh و چرا 100vh در موبایل گاهی می‌پرد

«روی دسکتاپ `100vh` تقریباً همان ارتفاع پنجره است. روی خیلی از مرورگرهای موبایل، نوار آدرس هنگام اسکرول جمع می‌شود. `vh` قدیمی گاهی ارتفاع را با نوار **باز** حساب می‌کند، گاهی با نوار بسته، و هیرو یک‌لحظه می‌پرد یا زیر نوار می‌رود.

`dvh` یعنی dynamic viewport height: ۱٪ ارتفاع **فعلی** پنجره، با در نظر گرفتن نوار آدرس. برای هیرو تمام‌صفحه در موبایل، الگوی رایج این است:

```css
.hero {
  min-height: 100vh;   /* مرورگرهای قدیمی */
  min-height: 100dvh;  /* اگر dvh را بفهمد، همین برنده است */
}
```

خط دوم را مرورگری که `dvh` نمی‌شناسد نادیده می‌گیرد و خط اول می‌ماند. این را به‌عنوان نکته تکمیلی بگو، نه تمرین اجباری. اگر کلاس موبایل واقعی ندارد، با توضیح کلامی رد شو و در DevTools اصرار نکن `dvh` را «ببینی»؛ تفاوت نوار آدرس در شبیه‌ساز همیشه واضح نیست.»

واحدهای `svh` (کوچک، با نوار باز) و `lvh` (بزرگ، با نوار جمع) را فقط اگر کسی پرسید نام ببر. در جزوه همین `dvh` آمده است.

## ۷) پروژه ترکیبی — کارت معرفی با سه مرجع متفاوت

همه‌چیز را در یک صفحه کوچک جمع کن. سه تصمیم را بلند بگو:

- عرض کارت: `%` + `max-width`  
- فونت متن: `rem`  
- padding دکمه: `em`  
- ارتفاع هیرو: `vh`  
- تیتر هیرو را عمداً با `vw` نگذار؛ با `rem` بگذار و بگو درس بعد آن را سیال می‌کنیم

```html
<header class="hero">
  <h1>امیر حسینی</h1>
  <p>طراح رابط کاربری</p>
</header>
<main class="card">
  <h2>مهارت‌ها</h2>
  <p>CSS</p>
  <div class="bar"><div class="fill w70">۷۰٪</div></div>
  <p>HTML</p>
  <div class="bar"><div class="fill w90">۹۰٪</div></div>
  <button class="btn" type="button">دانلود رزومه</button>
</main>
```

```css
body {
  margin: 0;
  font-family: Tahoma, sans-serif;
  background: #f1f5f9;
  color: #0f172a;
}

.hero {
  min-height: 30vh;
  background: #1a3a5c;
  color: white;
  padding: 2rem 1rem;
  text-align: center;
}

.hero h1 {
  font-size: 2rem;
  margin: 0 0 0.5rem;
}

.card {
  width: 100%;
  max-width: 32rem;
  margin: 1.5rem auto;
  padding: 1.25rem;
  background: white;
  box-sizing: border-box;
}

.btn {
  margin-top: 1rem;
  font-size: 1rem;
  padding: 0.5em 1em;
  background: #0f766e;
  color: white;
  border: none;
  border-radius: 0.4em;
}
```

«ببینید هر عدد به چه مرجعی وصل است. اگر `html` را ۱۸px کنیم، تیتر و دکمه با `rem` بزرگ می‌شوند و padding دکمه چون `em` است همراه فونت دکمه بزرگ می‌شود. نوار درصد همچنان نسبت به عرض کارت است. ارتفاع هیرو همچنان نسبت به پنجره است.»

**نمایش:** یکی‌یکی `html { font-size: 20px; }` و عرض پنجره را عوض کن و هر بار فقط یک چیز را نام ببر که تکان خورد.

## ۸) جمع‌بندی مدرس و سؤالات پایانی

1. برای نوار «۷۰٪ مهارت» کدام واحد درست است و مرجعش چیست؟  
   **پاسخ:** `%` نسبت به عرض پدر (خود نوار)، نه `px` و نه `vw`.

2. چرا فونت بدنه را معمولاً با `rem` می‌نویسیم؟  
   **پاسخ:** به فونت ریشه وصل است؛ اگر کاربر یا خودمان فونت `html` را عوض کنیم، متن‌های `rem` با هم مقیاس می‌شوند. `px` ثابت می‌ماند.

3. `padding: 0.5em 1em` روی دکمه نسبت به چیست؟  
   **پاسخ:** نسبت به `font-size` خود همان دکمه.

4. اشکال `font-size: 5vw` به‌تنهایی چیست؟  
   **پاسخ:** در عرض کم ریز و در عرض زیاد درشت می‌شود و مثل `rem` با تنظیم قلم مرورگر مقیاس نمی‌شود. محدود کردنش با `clamp()` درس بعد است.

**پیام پایانی:**

«واحد را از روی شکل عدد انتخاب نکن. اول بپرس این اندازه باید دنبال پدر برود، دنبال ریشه برود، یا دنبال پنجره. درصد برای نسبت به پدر، `rem` برای مقیاس سراسری متن، `em` برای قطعاتی که باید با فونت خودشان نفس بکشند، `px` برای خط مویین و جزئیات ثابت، `vh` برای نسبت به ارتفاع پنجره.»

## تمرین‌ها (ساده → چالشی)

جزوه: یک نوار «مهارت‌های من» با سه مهارت و درصد عرض متفاوت.  
پوشه [`quizzes/1-topic-exercises/18-units`](../../quizzes/1-topic-exercises/18-units/README.md):

### ساده
1. رزومه با چهار مهارت: HTML ۹۰٪، CSS ۸۰٪، JavaScript ۶۰٪، فتوشاپ ۴۰٪. نوار بیرونی `width: 100%`، بخش رنگی با درصد همان مهارت. با تغییر عرض صفحه نسبت‌ها بماند.  
2. سه نمونه متن ۱۲ / ۲۰ / ۳۲ پیکسل کنار هم، فقط برای اینکه اختلاف `px` ثابت دیده شود.

### متوسط
3. سه دکمه کوچک، معمولی، بزرگ. کلاس مشترک `padding: 0.5em 1.2em`. اندازه فونت فقط با `rem` (مثلاً `0.8rem`، `1rem`، `1.4rem`). در یک کامنت بنویس چرا padding با `em` است.

### چالشی
4. صفحه «آرام»: بخش خوش‌آمد با `min-height: 100vh`، تیتر با `vw` (مثلاً `6vw`)، پاراگراف زیرش با `rem`، و یک بخش دوم زیر آن تا معلوم شود بخش اول تقریباً یک پنجره است. بعد در یک جمله بنویس چرا تیترِ فقط-`vw` را در محصول نهایی کافی نمی‌دانی.  
5. بدون جزوه، برای هر کدام از این‌ها واحد پیشنهاد بده و مرجع را بگو: ضخامت حاشیه ۱ پیکسلی، عرض ستون اصلی داخل کارت، فاصله داخلی دکمه‌ای که سه سایز دارد، ارتفاع نوار بالای صفحه.
