## ۱) شروع کلاس؛ نیاز روی سایت

«این جلسه **اختیاری** است. مسئله‌اش را تقریباً هر صفحه فروشگاهی دارد.

نوار جستجو: یک دکمه «جستجو» به عرض ثابت ۱۰۰ پیکسل، و یک کادر که **بقیه جا** را پر کند. اگر فقط `width: 80%` بدهی، در یک عرض درست به نظر می‌رسد و در عرض دیگر یا روی دکمه می‌افتد یا ته ردیف خالی می‌ماند. درصدِ پدر منهای یک پیکسل ثابت، با یک واحد تنها نوشته نمی‌شود.

تابع‌های ریاضی CSS همان‌جا که مقدار را می‌نویسیم حساب می‌کنند و اجازه می‌دهند واحدهای مختلف در یک مقدار قاطی شوند.»

اسکلت:

```html
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Live — توابع ریاضی</title>
  <style>
    body {
      font-family: Tahoma, sans-serif;
      padding: 1.5rem;
      background: #f8fafc;
    }
    * { box-sizing: border-box; }
  </style>
</head>
<body>
  <form class="search" action="#">
    <input type="search" name="q" placeholder="نام کتاب">
    <button type="submit">جستجو</button>
  </form>
</body>
</html>
```

«هنوز عرض‌ها را نداده‌ایم. اول جدول چهار تابع را روی برد بنویس، بعد یکی‌یکی با همین صفحه و چند جعبه دیگر پرشان کن.»

| تابع | به زبان ساده |
|------|----------------|
| `calc()` | یک محاسبه: جمع، تفریق، ضرب، تقسیم |
| `min()` | از بین چند مقدار، **کوچک‌ترین** |
| `max()` | از بین چند مقدار، **بزرگ‌ترین** |
| `clamp(کمینه, دلخواه, بیشینه)` | دلخواه را بین کف و سقف نگه دار |

## ۲) calc() — عرض منهای مقدار ثابت

اول نسخه خراب را عمداً بنویس:

```css
.search input {
  width: calc(100%-110px);
}
```

**در مرورگر:** کادر عرض مورد انتظار را نمی‌گیرد. در DevTools آن خط خط‌خورده است.

«دور `+` و `-` حتماً فاصله بگذار. بدون فاصله، `100%-110px` برای مرورگر یک تفریق خوانا نیست؛ `-110px` را مثل یک عدد منفی به `%` چسبیده می‌بیند و کل `calc` نامعتبر می‌شود. قانون نامعتبر یعنی آن خط اصلاً اعمال نمی‌شود.

برای `*` و `/` فاصله الزامی نیست، ولی برای خواندن بهتر است باشد.»

نسخه درست، مطابق تمرین کتاب‌فروشی:

```css
.search input,
.search button {
  display: inline-block;
  vertical-align: middle;
}

.search button {
  width: 100px;
}

.search input {
  width: calc(100% - 110px); /* ۱۰۰px دکمه + ۱۰px فاصله */
}
```

«۱۰۰٪ یعنی عرض پدر. منهای ۱۱۰ پیکسل. پیکسل و درصد در یک `calc` مجازند، چون مرورگر موقع چیدمان درصد را به پیکسل همان لحظه تبدیل می‌کند و بعد تفریق می‌کند.

عرض پنجره را بکش. دکمه ۱۰۰px می‌ماند و کادر بقیه را می‌گیرد.»

مثال دوم جزوه را هم نشان بده، با این مقدمه که Flex را عمیق نمی‌کنیم:

```css
.layout {
  display: flex; /* فقط برای کنار هم دیدن؛ جزئیات در ماژول Flexbox */
}

.sidebar {
  width: 120px;
  background: #1a3a5c;
  color: white;
  padding: 0.75rem;
}

.main {
  width: calc(100% - 120px);
  background: #e0f2fe;
  padding: 0.75rem;
}
```

«اینجا `display: flex` را مثل یک برچسب «کنار هم بنشین» استفاده کردیم. اینکه `flex-grow` چیست و چرا در عمل اغلب به‌جای این حساب `flex: 1` می‌نویسند، درس Flexbox است. `calc` را وقتی لازم داری که عدد دقیق بخواهی: مثلاً ستون کناری دقیقاً ۱۲۰ پیکسل بماند و بقیه مال محتوا باشد، حتی قبل از اینکه Flex را تمام کرده باشی.»

### قانون ضرب و تقسیم

«در `calc`، ضرب و تقسیم با **عدد بدون واحد** است.

```css
width: calc(100% / 3);     /* درست */
width: calc(100% / 3px);   /* نامعتبر */
width: calc(2px * 10);     /* درست: px ضربدر عدد */
```

نمی‌شود دو طول را در هم ضرب کرد. `100% * 10px` معنی هندسی روشنی برای مرورگر ندارد.»

### سؤال کلاسی

- «چرا `calc(100% - 110px)` در فایل درست است و `calc(100%-110px)` نه؟»  
  **پاسخ:** دو طرف `-` باید فاصله داشته باشد.

- «`calc(100% - 2rem)` مجاز است؟»  
  **پاسخ:** بله. واحدها لازم نیست یکی باشند؛ باید هر دو طول باشند.

### اشتباهات رایج

- فراموش کردن `box-sizing: border-box` وقتی input خودش padding و border دارد → جمع ظاهری از ۱۰۰٪ بیشتر می‌شود و دکمه به خط بعد می‌افتد. در ابتدای فایل زنده `border-box` را گذاشته‌ایم؛ یک‌بار برش دار کن تا شکستگی دیده شود.  
- گذاشتن `calc` داخل گیومه. `width: "calc(100% - 110px)"` رشته است نه طول.

## ۳) سه ستون با calc — و مرز با Flex

جزوه این را دارد تا حساب را ببینی، نه تا روش اصلی چیدمان شود:

```css
.cols {
  display: flex;
  gap: 20px;
}

.col {
  width: calc((100% - 40px) / 3);
  background: #eef2f7;
  padding: 0.75rem;
  text-align: center;
}
```

«بین سه ستون، **دو** فاصله است. اگر `gap` برابر ۲۰px باشد، ۴۰ پیکسل از عرض کم می‌شود و بقیه بر ۳ تقسیم می‌شود. پرانتز ترتیب را روشن می‌کند.

در عمل، بعد از ماژول Flexbox خیلی وقت‌ها به‌جای این حساب می‌نویسی `flex: 1` و `gap` را به پدر می‌سپاری. `calc` وقتی هنوز به درد می‌خورد که عرض باید **دقیقاً** یک‌سوم باشد، حتی اگر در ردیف آخر فقط یک کارت مانده باشد و نخواهی آن یکی تمام ردیف را پهن کند. آن بحث را امروز باز نکن؛ یک جمله بس است.»

**در مرورگر:** سه جعبه. عرض را کم کن تا جایی که محتوا داخل ستون باریک فشرده شود. بگو: «اینجا دیگر calc به‌تنهایی واکنش‌گرا نیست؛ درس media query ستون‌ها را زیر هم می‌برد.»

### سؤال کلاسی

- «اگر gap برابر ۱۶px باشد، داخل پرانتز به‌جای ۴۰px چه می‌نویسیم؟»  
  **پاسخ:** ۳۲px، چون دو فاصله بین سه ستون است. `calc((100% - 32px) / 3)`.

## ۴) min() — کوچک‌ترین مقدار، که در عمل سقف می‌سازد

نیاز:

«کارت مقاله در صفحه پهن نباید از ۴۰۰ پیکسل پهن‌تر شود، و در صفحه باریک باید حدود ۹۰٪ عرض را بگیرد و از لبه‌ها کمی فاصله بماند. قبلاً این را با دو ویژگی می‌نوشتیم: `width: 90%` و `max-width: 400px`. `min()` هر دو را در یک مقدار جمع می‌کند.»

```css
.card-min {
  width: min(90%, 400px);
  margin: 0 auto;
  background: white;
  padding: 1rem;
  border: 1px solid #cbd5e1;
}
```

«`min` از بین مقدارها **کوچک‌ترین** را برمی‌دارد. در صفحه پهن، ۴۰۰px از ۹۰٪ کوچک‌تر است، پس عرض ۴۰۰ می‌ماند. در صفحه باریک، ۹۰٪ از ۴۰۰px کوچک‌تر می‌شود و همان اعمال می‌شود.

اسم تابع از دید ریاضی است، نه از دید «حداکثر عرض طراحی». `min()` کوچک‌ترین عدد را برمی‌دارد، پس در این مثال **سقف** می‌سازد. این جمله را آرام و با تغییر عرض پنجره بگو، وگرنه اسم تابع دانشجو را برعکس یاد می‌دهد.»

**در مرورگر:** از عرض زیاد به حدود ۳۲۰px برو. یک‌بار در DevTools مقدار محاسبه‌شده `width` را نشان بده.

### سؤال کلاسی

- «`min(90%, 400px)` در پنجره ۲۰۰۰px کدام را انتخاب می‌کند؟ در پنجره ۳۰۰px؟»  
  **پاسخ:** در ۲۰۰۰px، ۹۰٪ خیلی بزرگ‌تر از ۴۰۰ است، پس ۴۰۰px. در ۳۰۰px، ۹۰٪ برابر ۲۷۰px است و از ۴۰۰ کوچک‌تر است، پس ۲۷۰px. (اگر پدر همان viewport باشد.)

### اشتباهات رایج

- عوضی گرفتن `min` و `max`. اگر کسی `max(90%, 400px)` بنویسد، در صفحه باریک ۴۰۰px برنده می‌شود و کارت از صفحه بیرون می‌زند. همین را عمداً یک‌بار خراب کن.

## ۵) max() — بزرگ‌ترین مقدار، که در عمل کف می‌سازد

«`max()` بزرگ‌ترین عدد را برمی‌دارد، پس اندازه از کف تعیین‌شده پایین‌تر نمی‌رود.»

```css
.note-max {
  font-size: max(14px, 1.2vw);
}
```

«اگر ۱٫۲ درصد عرض پنجره از ۱۴ پیکسل کوچک‌تر شد، همان ۱۴ پیکسل استفاده می‌شود تا متن ناخوانا ریز نشود. در صفحه پهن، `1.2vw` بزرگ‌تر می‌شود و همان را برمی‌دارد.

باز هم اسم را با کار طراحی قاطی نکن: `max` یعنی «نرو پایین‌تر از بزرگ‌ترین این‌ها». کف خوانایی است، نه سقف.»

تمرین ۲ جزوه را اگر وقت هست روی تخته حساب کن، لازم نیست هر دو را تا آخر کد بزنی:

- ظرف مقاله: `width: min(90%, 800px)` — سقف ۸۰۰ پیکسل.  
- جعبه نویسنده: `width: max(220px, 30%)` — کف ۲۲۰ پیکسل.

«در مانیتور پهن، ۳۰٪ از ۲۲۰ بزرگ‌تر است و جعبه ۳۰٪ می‌شود. در گوشی، ۳۰٪ کوچک‌تر از ۲۲۰ می‌شود و کف ۲۲۰ برنده است. اگر آن کف از عرض صفحه بزرگ‌تر شود، باز هم سرریز داری؛ `max` معجزه نمی‌کند. برای آن حالت media query یا خود `min` روی ظرف لازم است.»

### سؤال کلاسی

- «برای اینکه فونت هیچ‌وقت از ۱۶px کوچک‌تر نشود ولی در صفحه پهن با `2vw` رشد کند، `min` می‌نویسیم یا `max`؟»  
  **پاسخ:** `max(16px, 2vw)`.

## ۶) clamp() — تیتری که هم کف دارد هم سقف

نیاز، همان تله درس واحدها:

«تیتر صفحه کارگاه عکاسی اگر فقط `5vw` باشد، در گوشی ریز است و در مانیتور بزرگ داد می‌زند. `clamp` سه آرگومان دارد، به همین ترتیب: کمینه، مقدار دلخواه، بیشینه.»

```css
.clamp-title {
  font-size: clamp(18px, 5vw, 40px);
}
```

«اگر `5vw` از ۱۸px کوچک‌تر شود، ۱۸px می‌ماند. اگر از ۴۰px بزرگ‌تر شود، ۴۰px می‌ماند. بین این دو، همان `5vw` است.

ترتیب را عوض نکن. اگر کمینه را بزرگ‌تر از بیشینه بنویسی، همیشه کمینه برنده می‌شود و با تغییر پنجره هیچ تغییری نمی‌بینی. این را یک‌بار با `clamp(40px, 5vw, 18px)` خراب کن تا قفل شدن را ببینند، بعد درستش کن.»

نسخه بهتر برای زوم قلم، مطابق نکته جزوه:

```css
.clamp-title {
  font-size: clamp(1.125rem, 1rem + 2vw, 2.5rem);
}
```

«داخل `clamp` و `min` و `max` لازم نیست دور جمع، `calc` بنویسی. `1rem + 2vw` خودش جمع است. بخش `rem` با تنظیم فونت کاربر بزرگ می‌شود و بخش `vw` با عرض پنجره. این همان چیزی است که `5vw` خالی کم داشت.

`clamp` فقط برای فونت نیست. padding سیال:

```css
.intro {
  padding: clamp(16px, 5vw, 48px);
}
```

در موبایل فاصله ۱۶px می‌ماند، در دسکتاپ از ۴۸px بیشتر نمی‌شود.»

**در مرورگر:** پنجره را از ۳۲۰ تا عرض کامل بکش و اندازه فونت را در DevTools بخوان. سه نقطه را نشان بده: چسبیده به کف، در حال لغزش، چسبیده به سقف.

### سؤال کلاسی

- «`clamp(20px, 4vw, 48px)` — کدام آرگومان کف است؟»  
  **پاسخ:** اولی، ۲۰px. سومی سقف است. وسطی مقدار ترجیحی است.

## ۷) پروژه ترکیبی — جستجو + معرفی کارگاه

دو تکه را در یک فایل تمام کن. دیگر تابع جدید معرفی نکن.

```html
<header class="intro">
  <h1 class="clamp-title">کارگاه عکاسی نور</h1>
  <p>ثبت‌نام تا وقتی ظرفیت پر شود باز است.</p>
</header>

<form class="search" action="#">
  <input type="search" name="q" placeholder="جستجوی دوره">
  <button type="submit">جستجو</button>
</form>
```

```css
* { box-sizing: border-box; }

body {
  margin: 0;
  font-family: Tahoma, sans-serif;
  background: #f8fafc;
}

.intro {
  width: min(90%, 720px);
  margin: 0 auto;
  padding: clamp(16px, 5vw, 48px);
}

.clamp-title {
  font-size: clamp(1.25rem, 1rem + 2vw, 2.5rem);
  margin: 0 0 0.5rem;
}

.search {
  width: min(90%, 720px);
  margin: 1rem auto 2rem;
}

.search button {
  width: 100px;
}

.search input {
  width: calc(100% - 110px);
  font: inherit;
}
```

«ظرف با `min` از ۷۲۰px پهن‌تر نمی‌شود. padding و تیتر با `clamp` کف و سقف دارند. کادر جستجو بقیه ردیف را با `calc` می‌گیرد. هیچ media queryای ننوشتیم؛ این توابع جای همه media queryها را نمی‌گیرند، ولی برای **یک** اندازه سیال اغلب کافی‌اند. ستون‌هایی که باید زیر هم بروند هنوز درس ۲۱ هستند.»

**نمایش:** عرض ۳۲۰، حدود ۷۰۰، و تمام‌صفحه. هر بار بگو کدام تابع در حال محدود کردن است.

## ۸) جمع‌بندی مدرس و سؤالات پایانی

1. چرا `calc(100%-110px)` اعمال نمی‌شود؟  
   **پاسخ:** دو طرف `-` فاصله ندارد و مقدار نامعتبر است؛ مرورگر آن خط را دور می‌ریزد.

2. `min(90%, 400px)` در صفحه خیلی پهن چه عرضی می‌دهد؟  
   **پاسخ:** ۴۰۰px، چون کوچک‌تر است.

3. برای کف ۱۴px روی فونتی که با viewport رشد می‌کند، کدام تابع است؟  
   **پاسخ:** `max(14px, …vw)`.

4. ترتیب آرگومان‌های `clamp` چیست؟  
   **پاسخ:** کمینه، دلخواه، بیشینه.

**پیام پایانی:**

«این تابع‌ها ماشین‌حساب داخل مقدار CSS هستند. `calc` وقتی دو واحد را با هم داری، `min` وقتی سقف می‌خواهی، `max` وقتی کف می‌خواهی، و `clamp` وقتی هر دو را با یک مقدار ترجیحی در وسط می‌خواهی. اسم‌ها را با «حداکثر عرض» قاطی نکن؛ همیشه بپرس کدام عدد کوچک‌تر یا بزرگ‌تر است.»

---

## تمرین‌ها (ساده → چالشی)

جزوه: تیتر با `clamp(20px, 4vw, 48px)` و جعبه با `width: calc(100% - 40px)`.  
پوشه [`quizzes/1-topic-exercises/19-math-functions`](../../quizzes/1-topic-exercises/19-math-functions/README.md):

### ساده
1. نوار جستجوی کتاب‌فروشی: دکمه `width: 100px`، کادر `width: calc(100% - 110px)`، هر دو `inline-block` و `border-box`. با تغییر عرض، دکمه کنار کادر بماند.  
2. یک جعبه با `width: calc(100% - 40px)` و حاشیه ۱۶px تا لبه، تا تفریق با فاصله درست دیده شود.

### متوسط
3. ظرف مقاله `width: min(90%, 800px)` و `margin: 0 auto`، بدون ویژگی جداگانه `max-width`. جعبه «درباره نویسنده» با `width: max(220px, 30%)`. در کامنت بنویس هر تابع کدام مقدار را در صفحه پهن و صفحه باریک انتخاب می‌کند.

### چالشی
4. صفحه کارگاه عکاسی **بدون** media query: تیتر `clamp(1.5rem, 5vw, 3rem)`، padding بخش `clamp(16px, 5vw, 48px)`، پاراگراف `clamp(0.95rem, 2vw, 1.15rem)`. در کامنت سه آرگومان تیتر را نام ببر.  
5. توضیح بده چرا `calc(100% / 3px)` نامعتبر است و به‌جای آن چه می‌نویسی اگر عرض باید یک‌سوم پدر باشد.
