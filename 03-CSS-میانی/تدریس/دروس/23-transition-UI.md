## ۱) شروع کلاس؛ نیاز روی سایت

«درس قبل یک دکمه را نرم کردیم. روی سایت، کاربر بیشتر از دکمه تنها، با **منو** و **فوکوس** طرف است.

دو مشکل واقعی:

۱. لینک منو زیر ماوس یک‌باره رنگ عوض می‌کند و کسی که با Tab می‌آید اصلاً نمی‌فهمد کجای منو است، اگر حلقه فوکوس را با `outline: none` حذف کرده باشید.  
۲. منوی کشویی درس ۱۴ یا هست یا نیست. باز شدنش پرش است. اگر برای باز کردن از `display: none` به `display: block` بپری، transition کمکی نمی‌کند؛ جلسه قبل این شکست را دیدید.

امروز هر دو را روی همان الگوهای درس ۱۳ و ۱۴ نرم می‌کنیم، بدون اینکه Flex منو یا موقعیت‌دهی را از نو درس بدهیم.»

اسکلت:

```html
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Live — transition در UI</title>
  <style>
    body {
      font-family: Tahoma, sans-serif;
      padding: 2rem;
      background: #f8fafc;
    }
  </style>
</head>
<body>
  <nav class="bar" aria-label="اصلی">
    <a class="nav-link" href="#home">خانه</a>
    <a class="nav-link" href="#menu">منو</a>
    <a class="nav-link" href="#contact">تماس</a>
  </nav>
</body>
</html>
```

لینک‌ها را اول بدون transition و بدون حالت فوکوس نشان بده. با Tab رد شو. حلقه پیش‌فرض مرورگر را ببینند تا بعداً اگر عوضش کردیم، جایگزین داشته باشیم.

## ۲) لینک منو — hover و کیبورد یک شکل

مطابق جزوه:

```css
.nav-link {
  color: #1a3a5c;
  text-decoration: none;
  padding: 6px 10px;
  border-bottom: 2px solid transparent;
  transition: color 0.2s ease, border-color 0.2s ease;
}

.nav-link:hover,
.nav-link:focus-visible {
  color: #0b6e4f;
  border-color: #0b6e4f;
}
```

«خط پایین از اول هست، ولی شفاف است. اگر خط را فقط در hover با `border-bottom: 2px solid` **اضافه** کنی، ارتفاع لینک یک‌باره زیاد می‌شود و منو می‌پرد. پس ضخامت را همیشه بگذار و فقط **رنگ** خط را عوض کن.

`transition` دوباره روی حالت پایه است، تا برگشتن ماوس هم نرم باشد.

`:focus-visible` یعنی وقتی فوکوس از کیبورد آمده، نه لزوماً با هر کلیک ماوس. تغییر رنگ را برای hover و برای این فوکوس یکی نوشتیم تا دو ظاهر متفاوت نسازی.

حلقه پیش‌فرض را پاک نکن مگر جایگزین دیدی گذاشته باشی. در این مثال خط رنگی جایگزین است. اگر `outline: none` را بدون این خط اضافه کنی، کاربر کیبورد لینک را گم می‌کند. یک‌بار عمداً `outline: none` را تنها بگذار و Tab بزن تا گم شدن را ببینند، بعد حذفش کن و به نسخه جزوه برگرد.»

**در مرورگر:** ماوس را روی «تماس» ببر. بعد از اول صفحه Tab بزن تا هر سه لینک به نوبت خط سبز بگیرند.

### سؤال کلاسی

- «چرا `border-bottom` را از اول `transparent` می‌گذاریم؟»  
  **پاسخ:** تا ظاهر شدن خط، جعبه را بزرگ نکند. فقط رنگ عوض می‌شود و همان رنگ است که transition دارد.

### اشتباهات رایج

- transition روی `border-width` از ۰ به ۲px → هم نرم است هم منو را در طول راه هل می‌دهد. رنگِ ضخامت ثابت بهتر است.  
- استایل فقط روی `:hover` → Tab هیچ بازخوردی ندارد.  
- `:focus` به‌جای `:focus-visible` بدون فکر → با کلیک ماوس هم کادر می‌ماند. برای این منو جزوه `focus-visible` خواسته.

اگر کلاس `:focus-visible` را در درس شبه‌کلاس‌ها کم دیده، یک جمله: «مرورگر تشخیص می‌دهد فوکوس از صفحه‌کلید است.» جزئیات بیشتر نده.

## ۳) دراپ‌داون — اول شکست display، بعد الگوی جزوه

HTML همان درس منوی کشویی، ساده شده:

```html
<div class="drop">
  <button class="drop-btn" type="button">بخش‌ها</button>
  <div class="drop-menu">
    <a href="#1">پیش‌غذا</a>
    <a href="#2">غذای اصلی</a>
    <a href="#3">دسر</a>
  </div>
</div>
```

نسخه پرشی را اول بنویس:

```css
.drop { position: relative; display: inline-block; }

.drop-btn {
  padding: 8px 14px;
  background: #1a3a5c;
  color: white;
  border: none;
  border-radius: 6px;
  cursor: pointer;
}

.drop-menu {
  display: none;
  position: absolute;
  top: 110%;
  right: 0;
  min-width: 160px;
  background: white;
  border: 1px solid #cfd8e3;
  border-radius: 6px;
  padding: 8px 0;
}

.drop:hover .drop-menu { display: block; }
```

«باز شدن آنی است. حالا اگر بنویسی `transition: display 0.2s` هیچ میان‌حالی نمی‌آید. `display: none` عنصر را از چیدمان برمی‌دارد؛ نمی‌شود «نیمه‌بلوک» بود.

الگوی جزوه سه ویژگی را با هم عوض می‌کند:

- `opacity` از ۰ به ۱ — محو و ظاهر شدن، و این یکی میان‌فریم دارد.  
- `visibility` — وقتی پنهان است کلیک و Tab به لینک‌های داخلش نرسد. opacity صفر به‌تنهایی عنصر را هنوز قابل فوکوس می‌گذارد.  
- `transform: translateY(-6px)` تا `translateY(0)` — چند پیکسل سر خوردن. نه `display`.»

```css
.drop-menu {
  position: absolute;
  top: 110%;
  right: 0;
  min-width: 160px;
  background: white;
  border: 1px solid #cfd8e3;
  border-radius: 6px;
  padding: 8px 0;
  opacity: 0;
  visibility: hidden;
  transform: translateY(-6px);
  transition: opacity 0.2s ease, transform 0.2s ease, visibility 0.2s;
}

.drop:hover .drop-menu,
.drop:focus-within .drop-menu {
  opacity: 1;
  visibility: visible;
  transform: translateY(0);
}

.drop-menu a {
  display: block;
  padding: 8px 14px;
  color: #222;
  text-decoration: none;
}

.drop-menu a:hover {
  background: #eef2f7;
}
```

«`position: absolute` و `right: 0` را از درس موقعیت و درس منوی کشویی قرض کردیم. امروز containing block را باز نکن. اگر منو جای عجیبی رفت، یادآوری کن پدر `.drop` باید `position: relative` باشد؛ همان درس ۱۴.

`visibility` را در لیست transition گذاشته‌ایم تا با تمام شدن opacity هماهنگ باشد. انتظار شفافیت از خود visibility نداشته باش؛ محو شدن کار opacity است. اگر visibility را آنی عوض کنی و opacity را نرم، ممکن است منو یک فریم زودتر کلیک‌پذیر شود یا برعکس ناپدید شود. نگه داشتن هر دو در حدود ۰٫۲s برای این دمو کافی است.

در صفحه راست‌چین `right: 0` منو را به لبه راست دکمه می‌چسباند. اگر کسی `left: 0` بگذارد منو از دکمه آن طرف می‌افتد. یک‌بار نشان بده و برگردان.»

**در مرورگر:** ماوس را روی «بخش‌ها» ببر. منو کمی پایین می‌آید و ظاهر می‌شود، نه اینکه یک‌باره وجود پیدا کند.

### سؤال کلاسی

- «چرا opacity صفر کافی نیست و visibility هم می‌خواهیم؟»  
  **پاسخ:** عنصر شفاف هنوز آنجاست. Tab می‌تواند روی لینک‌های نامرئی برود و کلیک هم به آن‌ها می‌رسد.

## ۴) کیبورد — focus-within

«`:hover` برای کسی که ماوس ندارد هیچ‌وقت روشن نمی‌شود. `:focus-within` یعنی فوکوس داخل این `.drop` است؛ یا روی خود دکمه، یا روی یکی از لینک‌های منو.

Tab را بزن تا به دکمه «بخش‌ها» برسی. منو باید باز شود. Tab بعدی باید وارد «پیش‌غذا» شود، نه اینکه منو بسته شود و فوکوس بپرد ته صفحه.

اگر فقط `:hover` داشته باشی، با Tab منو بسته می‌ماند و لینک‌هایش چون `visibility: hidden` هستند از ترتیب Tab حذف شده‌اند. این را با حذف موقت `focus-within` نشان بده، بعد برگردان.»

### محدودیت را صادقانه بگو

«این الگو برای درس ما کافی است و با ماوس و Tab باز می‌شود. منوی تولیدِ واقعی اغلب این‌ها را هم می‌خواهد: بسته شدن با Escape، باز شدن با کلیک روی صفحه لمسی نه فقط hover، و اعلام وضعیت برای صفحه‌خوان. جزوه گفته برای دسترسی کامل بعداً جاوااسکریپت لازم است. امروز قول نده این CSS همه‌جای کار را تمام کرده. قول بده پرش نمایش و گم شدن فوکوس را حل کرده.»

روی صفحه لمسی، `:hover` ممکن است با اولین ضربه بچسبد و منو باز بماند. اگر کسی پرسید: «برای لمس، دکمه را با JS باز و بسته می‌کنند. CSS این جلسه جایگزین آن نیست.»

### اشتباهات رایج

- `transition` روی `display`.  
- منوی `opacity: 0` بدون `visibility: hidden` → لینک نامرئی در مسیر Tab.  
- فراموش کردن `:focus-within` کنار `:hover`.  
- `outline: none` روی دکمه دراپ‌داون بدون جایگزین. برای `.drop-btn` اگر حلقه را برمی‌داری، حداقل همان تغییر پس‌زمینه یا خط را در `:focus-visible` بگذار.

```css
.drop-btn:focus-visible {
  outline: 2px solid #0b6e4f;
  outline-offset: 2px;
}
```

## ۵) کارت محصول — حرکت کوتاه

نیاز فروشگاه: کارت با hover کمی بلند شود تا قابل کلیک بودن حس شود، نه اینکه بچرخد و سایه‌اش نصف صفحه را بگیرد.

```html
<a class="product" href="#p">
  <h2>ماگ سرامیک</h2>
  <p>۱۸۰٬۰۰۰ تومان</p>
</a>
```

```css
.product {
  display: block;
  width: min(100%, 240px);
  padding: 1rem;
  background: white;
  border: 1px solid #e2e8f0;
  border-radius: 10px;
  color: inherit;
  text-decoration: none;
  transition: transform 0.2s ease, box-shadow 0.2s ease;
}

.product:hover,
.product:focus-visible {
  transform: translateY(-4px);
  box-shadow: 0 8px 20px rgb(15 23 42 / 12%);
}
```

«`translateY(-4px)` یعنی چهار پیکسل به بالا. بیشتر از این برای یک فروشگاه معمولی شلوغ است. مدت ۰٫۲ ثانیه.

سایه را هم در همان لیست گذاشتیم. اگر سایه را جا بیندازی، کارت نرم بالا می‌رود و سایه می‌پرد.

چون خود کارت لینک است، `:focus-visible` همان حرکت را برای کیبورد تکرار می‌کند. `color: inherit` و حذف زیرخط برای این است که لینک شبیه کارت بماند؛ معنا هنوز لینک است، `div` کلیک‌خور نیست.

`width: min(100%, 240px)` اگر درس ۱۹ را نخوانده‌اند: «از ۲۴۰px پهن‌تر نشو و از پدر هم بیرون نزن». اگر نخوانده‌اند همان `max-width: 240px; width: 100%` را بنویس. وارد تابع‌ها نشو.»

**در مرورگر:** hover و بعد Tab. حرکت باید کوتاه باشد. اگر دانشجو `scale(1.2)` پیشنهاد کرد، بگذار یک‌بار ببیند متن اطراف می‌لرزد یا کارت روی کارت بعدی می‌افتد، بعد برگرد به ۴ پیکسل.

## ۶) حرکت را کم نگه دار

«هر قطعه این صفحه یک transition دارد: لینک، منو، کارت. اگر پس‌زمینه بخش‌ها هم ۰٫۵ ثانیه رنگ عوض کند، همه‌چیز در حال لغزش است و هیچ‌چیز مهم دیده نمی‌شود.

قاعده این جلسه:

- مدت hover رابط: حدود ۰٫۱۵ تا ۰٫۳ ثانیه.  
- جابه‌جایی: چند پیکسل، نه چند ده.  
- ویژگی‌ها را اسم ببر؛ `all` ننویس، چون باز شدن media query در درس ۲۱ اگر عرض کارت را عوض کند نباید انیمیشن شود.  
- چیزی که اطلاعات را می‌رساند (باز بودن منو، محل فوکوس) مهم‌تر از تزئین است.

`prefers-reduced-motion` را یک خط نشان بده و بگو درس انیمیشن جدی‌تر با آن رفتار می‌کند. اگر کسی در سیستمش کاهش حرکت را روشن کرده، لازم نیست کارت بپرد:»

```css
@media (prefers-reduced-motion: reduce) {
  .nav-link,
  .drop-menu,
  .product {
    transition: none;
  }
}
```

«رنگ hover می‌تواند بماند؛ فقط راه میان‌فریم حذف می‌شود. این media query را اگر وقت کم است به‌صورت نکته آخر بگو و در تمرین پایه اجباری نکن. در درس ۲۴ اجباری است.»

## ۷) جمع‌بندی مدرس و سؤالات پایانی

1. چرا خط زیر لینک منو را با رنگ شفاف رزرو می‌کنیم؟  
   **پاسخ:** تا با hover، ارتفاع و چیدمان منو نپرد؛ فقط رنگ خط عوض شود.

2. سه ویژگی الگوی باز شدن نرم منو چیست و کدام‌یک را به‌خاطر میان‌فریم می‌خواهیم؟  
   **پاسخ:** `opacity` (محو شدن)، `visibility` (خارج کردن از کلیک و Tab وقتی بسته است)، `transform` (لغزش کوتاه). میان‌فریم اصلی مال opacity و transform است.

3. `:hover` تنها برای دراپ‌داون چه کسی را جا می‌گذارد؟  
   **پاسخ:** کسی که با کیبورد می‌آید. کنارش `:focus-within` لازم است.

4. حرکت کارت را چرا کوتاه گرفتیم؟  
   **پاسخ:** هدف، قابل تشخیص بودن حالت hover و فوکوس است، نه نمایش انیمیشن.

**پیام پایانی:**

«Transition در UI یعنی همان نرمی درس قبل، روی قطعاتی که کاربر واقعاً با ماوس و کیبورد طی می‌کند. اگر حالت فقط با hover دیده شود، هنوز نیمه‌کاره است.»

## تمرین‌ها (ساده → چالشی)

جزوه: کارت محصول با hover و `translateY` ملایم.

### ساده
1. سه لینک ناوبری با خط پایین شفاف، transition روی `color` و `border-color` در ۰٫۲s، و همان ظاهر برای `:focus-visible`. با Tab تست شود.  
2. کارت «ماگ» با `translateY(-4px)` و سایه، مدت حداکثر ۰٫۳s، لیست ویژگی صریح.

### متوسط
3. دراپ‌داون «بخش‌ها» با opacity و visibility و translateY. باز شدن با hover **و** focus-within. لینک داخل منو وقتی بسته است در مسیر Tab نباشد.  
4. عمداً یک نسخه با `display: none` / `block` بساز و در دو خط بنویس چرا transition آنجا اثری ندارد؛ بعد نسخه درست را تحویل بده.

### چالشی
5. هر سه قطعه (لینک، دراپ‌داون، کارت) در یک صفحه، بدون `transition: all`. دکمه دراپ‌داون `:focus-visible` واضح داشته باشد، حتی اگر حلقه پیش‌فرض را عوض کرده‌ای.  
6. توضیح بده چرا `opacity: 0` بدون `visibility: hidden` برای منوی بسته کافی نیست.
