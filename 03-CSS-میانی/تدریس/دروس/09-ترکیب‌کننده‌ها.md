## ۱) شروع کلاس — مسئله اول (دیالوگ)

«بچه‌ها، منوی سایت را استایل کردید:

```css
nav a {
  color: white;
  text-decoration: none;
}
```

روی لینک‌های سطح اول عالی است. بعد **زیرمنو** اضافه می‌کنید — لینک «دوره CSS» داخل `<ul>` تودرتو. باز هم سفید و بدون underline — در حالی که طراحی می‌گوید زیرمنو باید متن تیره روی پس‌زمینه روشن باشد.

مشکل: انتخابگر **`nav a`** یعنی **هر** `a` که **هر جایی** داخل `nav` باشد — نوه هم شامل می‌شود.

سؤال: چطور فقط لینک **مستقیم** زیر `li` سطح اول را بگیریم؟  
جواب: **combinator** — رابطه بین دو انتخابگر.»

Live اولیه — ساختار ساده (فایل: `تدریس/live/09-combinators.html`):

```html
<nav class="demo-nav">
  <ul>
    <li><a href="#">خانه</a></li>
    <li>
      <a href="#">آموزش</a>
      <ul>
        <li><a href="#" class="sub">CSS مقدماتی</a></li>
      </ul>
    </li>
  </ul>
</nav>
```

```css
.demo-nav a {
  color: #4338ca;
  font-weight: 600;
}
```

**در مرورگر:** لینک زیرمنو هم بنفش شد — همان باگ.

## ۲) جدول چهار combinator (بعد از دیدن درد)

| علامت | نام | معنی |
|--------|-----|------|
| `A B` (فاصله) | descendant | هر `B` داخل `A` — فرزند، نوه، … |
| `A > B` | child | فقط `B` که **مستقیم** فرزند `A` |
| `A + B` | adjacent sibling | اولین `B` که **بلافاصله بعد** از `A` و هم‌سطح |
| `A ~ B` | general sibling | همه `B` بعد از `A` با پدر مشترک |

«**فاصله** بین دو انتخابگر یعنی descendant — **بدون فاصله** یعنی element+class روی یک گره: `div.card` ≠ `div .card`.»

---

## ۳) Live Coding مرحله ۱ — descendant: `.post p`

«مقاله — همه پارagraphهای داخل `.post` زرد:

```css
.post p {
  background-color: yellow;
}
```

HTML مطابق جزوه:

```html
<div class="post">
  <p>پاراگراف فرزند ✔</p>
  <section>
    <p>پاراگراف نوه ✔</p>
  </section>
</div>
<p>بیرون از post ✘</p>
```

**در مرورگر:** demo [`09-combinators.html`](../../pages/09-combinators.html) — هر دو p داخل post رنگی؛ بیرون نه.

### سؤال کلاسی

«`.post p` نوه داخل `<section>` را می‌گیرد؟»  
**پاسخ:** بله — descendant هر عمقی.

---

## ۴) Live Coding مرحله ۲ — child: `.card > p`

«فقط پارagraph **مستقیم** زیر `.card`:

```css
.card > p {
  background-color: lightgreen;
}
```

```html
<div class="card">
  <p>فرزند مستقیم ✔</p>
  <section>
    <p>نوه ✘</p>
  </section>
  <p>فرزند مستقیم دیگر ✔</p>
</div>
```

**نمایش:** فقط دو p سبز — نوه دست‌نخورده.

### سؤال کلاسی

«`.card p` vs `.card > p` — کدام برای footer تو در تو داخل card امن‌تر است؟»  
**پاسخ:** `>` وقتی فقط لایه اول محتوا را می‌خواهید؛ ` ` (descendant) همه سطوح را می‌زند.

---

## ۵) Live Coding مرحله ۳ — `h4 + p` (مقدمه بعد تیتر)

«در مقاله، اولین پارagraph بعد تیتر = lead:

```css
h4 + p {
  font-weight: bold;
  color: #0b6e4f;
}
```

```html
<h4>تیتر مقاله</h4>
<p>خلاصه ✔</p>
<p>بدنه ✘</p>
```

**در مرورگر:** فقط اولین p بعد h4 — نه پارagraph دوم.

«`+` فقط **یک** همسایه بلافاصله بعد — اگر `<span>` بین h4 و p باشد، `h4 + p` دیگر match نمی‌کند.»

---

## ۶) Live Coding مرحله ۴ — `h4 ~ p`

«همه پارagraphهای **بعد از** تیتر (هم‌سطح):

```css
h4 ~ p {
  border-inline-end: 4px solid orange;
}
```

```html
<p>قبل از تیتر ✘</p>
<h4>تیتر</h4>
<p>بعد ✔</p>
<span>وسط</span>
<p>بعد ✔</p>
```

**نمایش:** span وسط مانع `+` نمی‌شود برای `~` — هر p بعد از h4 خط نارنجی.

### سؤال کلاسی

«`+` و `~` عنصر **قبل** از h4 را می‌گیرند؟»  
**پاسخ:** خیر — فقط هم‌سطح‌های **بعد**.

---

## ۷) Live Coding مرحله ۵ — منو: `nav > ul > li > a`

«رفع باگ جلسه:

```css
nav > ul > li > a {
  color: white;
}
nav ul ul a {
  color: #334155;
  font-weight: 400;
}
```

یا فقط سطح اول:

```css
nav > ul > li > a {
  color: white;
}
```

**در مرورگر:** demo `ex5` در [`combinators.css`](../../css/demos/combinators.css) — لینک‌های سطح اول سفید روی nav.

«انتخابگر `body div ul li a span` شکننده است — با یک wrapper HTML می‌شکند. **کلاس + حداکثر یک combinator** معمولاً کافی است.»

---

## ۸) specificity (سطح میانی — اشاره عملی)

«هر element در selector به specificity اضافه می‌شود — combinator خودش امتیاز ندارد، **فاصله** فقط رابطه است.

`.post p` دو element/type — قوی‌تر از فقط `p`.

در DevTools → Styles → روی selector hover — «matches N elements» را ببینید.»

### اشتباهات رایج

- `div.box` به‌جای `div .box` — اولی div با class box؛ دومی descendant.  
- انتظار `+` روی عنصر غیرمجاور.  
- `.nav a` برای منوی چندسطحی بدون استثناء زیرمنو.

## ۹) پروژه mini جلسه

**Nav** با `nav > ul > li > a` برای سطح اول.  
**مقاله** با `h3 + p` برای lead بعد هر بخش.

```html
<article class="lesson-article">
  <h3>بخش اول</h3>
  <p class="lead">این lead درشت است.</p>
  <p>بدنه معمولی.</p>
  <h3>بخش دوم</h3>
  <p class="lead">lead دوم.</p>
</article>
```

```css
.lesson-article h3 + p {
  font-size: 1.05rem;
  color: #0b6e4f;
  margin-block-start: 0.25rem;
}
```

**نمایش:** فقط اولین p بعد هر h3 سبز — بدون class روی هر lead (یا با class اگر HTML عوض شد).

---

## ۱۰) جمع‌بندی و سؤالات پایانی

1. `.card p` vs `.card > p`؟  
   **پاسخ:** اولی همه عمق‌ها؛ دومی فقط فرزند مستقیم.

2. `h2 + p` چند پارagraph را style می‌کند؟  
   **پاسخ:** حداکثر یک — بلافاصله بعد از h2.

3. چرا `nav a` برای زیرمنو مشکل‌ساز است؟  
   **پاسخ:** descendant — همه لینک‌های تو در تو.

**پیام پایانی:** «Combinator یعنی *رابطه در درخت HTML* — نه فقط نام class. فردا **pseudo-class** — استایل بر اساس *state* (hover، focus)، نه فقط ساختار.»
