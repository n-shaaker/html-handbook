## ۱) شروع کلاس؛ مسئله واقعی سایت

«بچه‌ها، نوار سایت را استایل کردید. لینک‌ها سفیدند و زیرخط ندارند:

```css
nav a {
  color: white;
  text-decoration: none;
}
```

روی «خانه» و «آموزش» و «تماس» درست است. بعد زیرِ «آموزش» یک فهرست دیگر می‌گذارید: «CSS مقدماتی». همان قانون سفید روی آن هم می‌نشیند. طرح می‌گوید زیرمنو پس‌زمینه روشن دارد و متنش باید تیره باشد.

این باگ رنگ نیست. باگ **رابطه** است. `nav a` یعنی هر `a` که هر جایی داخل `nav` باشد: فرزند، نوه، و عمیق‌تر.»

فایل زنده (پیشنهاد: `تدریس/live/09-combinators.html`):

```html
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Live — ترکیب‌کننده‌ها</title>
  <style>
    body {
      font-family: Tahoma, sans-serif;
      padding: 1.5rem;
      background: #f8fafc;
      line-height: 1.7;
    }
    .demo-nav {
      background: #1e293b;
      padding: 0.5rem 1rem;
    }
    .demo-nav ul {
      list-style: none;
      margin: 0;
      padding: 0;
    }
    .demo-nav a {
      color: white;
      text-decoration: none;
      font-weight: 600;
    }
  </style>
</head>
<body>
  <nav class="demo-nav">
    <ul>
      <li><a href="#">خانه</a></li>
      <li>
        <a href="#">آموزش</a>
        <ul>
          <li><a href="#">CSS مقدماتی</a></li>
        </ul>
      </li>
      <li><a href="#">تماس</a></li>
    </ul>
  </nav>
</body>
</html>
```

**در مرورگر:** «CSS مقدماتی» هم سفید و پررنگ است، روی همان زمینه تیره، یا اگر زمینه زیرمنو را روشن کنی، سفیدِ ناخوانا. درخت را روی تخته بکش:

```text
nav
  ul
    li
      a  خانه
    li
      a  آموزش
      ul
        li
          a  CSS مقدماتی
    li
      a  تماس
```

«سؤال جلسه: چطور فقط لینک‌هایی را بگیریم که در سطح اول این درخت‌اند، نه هر لینکی که جایی داخل nav است؟

جواب، یک کلاس تازه برای هر لینک نیست، اگر ساختار خودش رابطه را دارد. جواب **ترکیب‌کننده** است: علامتی بین دو انتخابگر که می‌گوید عنصر دوم نسبت به عنصر اول کجای درخت باشد.»

چهار علامت را همین‌جا فقط نام ببر. مثال هر کدام بخش خودش را دارد. عجله نکن که هر چهار تا را روی منو خالی کنی.

| علامت | نام | معنی ساده |
|--------|-----|-----------|
| `A B` (فاصله) | نسل (descendant) | هر B داخل A، در هر عمقی |
| `A > B` | فرزند مستقیم (child) | فقط B که مستقیم داخل A است |
| `A + B` | همسایه بعدی (adjacent sibling) | فقط اولین B که بلافاصله بعد از A آمده |
| `A ~ B` | هم‌سطح‌های بعدی (general sibling) | هر B بعد از A که پدر مشترک دارند |

«فاصله بین دو انتخابگر یعنی نسل. **بدون فاصله** یعنی همان یک عنصر: `div.card` با `div .card` یکی نیست. این را آخرِ همین بخش با یک خط ثابت کن، چون پرتکرارترین اشتباه فایل است.»

```html
<div class="card">جعبه خودش</div>
<div>
  <p class="card">پاراگراف داخل div</p>
</div>
```

```css
div.card { outline: 3px solid #16a34a; }
div .card { background: #fde68a; }
```

**در مرورگر:** div اول فقط دور سبز دارد (خودش کلاس card است). پاراگراف دوم پس‌زمینه زرد دارد (عنصری با کلاس card *داخل* div). اگر این دو را یکی بدانی، بقیه درس غلط ذخیره می‌شود.

### سؤال کلاسی

- «`nav a` کدام لینک‌های فایل زنده را می‌گیرد؟»  
  **پاسخ:** هر سه: خانه، آموزش، و CSS مقدماتی.

### انتقال

«منو را باز نگه دار. چهار علامت را روی مثال‌های کوچک جزوه جدا ببینیم، بعد برگردیم و همان باگ سفید را با `>` ببندیم.»

## ۲) فاصله — `.post p` هر پاراگرافی داخل مقاله

«فاصله را اول روی چیزی ساده‌تر از منو ببینید تا «هر عمق» ملموس شود.»

```html
<div class="post">
  <p>پاراگراف فرزند</p>
  <section>
    <p>پاراگراف نوه (داخل section)</p>
  </section>
</div>
<p>پاراگراف بیرون از post</p>
```

```css
.post p {
  background-color: yellow;
}
```

**در مرورگر:** هر دو پاراگراف داخل `.post` زردند، حتی آن که نوه است و داخل `section` نشسته. پاراگراف بیرون زرد نیست. این مثال ۱ صفحه [`09-combinators.html`](../../pages/09-combinators.html) است.

«فاصله یعنی: از `.post` برو پایین درخت، هر `p` دیدی بردار. مهم نیست چند لایه `section` و `div` وسط باشد.»

در DevTools روی یکی از `p`های زرد، برگه Styles را باز کن و نشان بده انتخابگر `.post p` همان عنصر را گرفته. اگر ابزار تعداد match را نشان می‌دهد، بگو هر دو پاراگراف داخل post، و سومی نه.

### سؤال کلاسی

- «اگر داخل section یک `div` دیگر و داخل آن باز `p` باشد، `.post p` آن را هم می‌گیرد؟»  
  **پاسخ:** بله. نسل به عمق محدود نیست.

### اشتباهات رایج

- نوشتن `.post, p` به‌جای `.post p`. ویرگول یعنی گروه: خود post و **همه** `p`های صفحه، از جمله پاراگراف بیرون. فاصله یعنی رابطه.

## ۳) `>` — فقط فرزند مستقیم `.card > p`

«حالا همان درخت را محدود کن. فقط پاراگرافی که مستقیم داخل کارت است، نه پاراگراف داخل بخش تو در تو.»

```html
<div class="card">
  <p>پاراگراف فرزند مستقیم</p>
  <section>
    <p>پاراگراف نوه</p>
  </section>
  <p>پاراگراف فرزند مستقیم دیگر</p>
</div>
```

```css
.card > p {
  background-color: lightgreen;
}
```

**در مرورگر:** دو پاراگراف مستقیم سبز می‌شوند. پاراگراف داخل `section` سبز نمی‌شود، هرچند هنوز داخل `.card` است. این فرق فاصله و `>` است.

کنار هم، بدون پاک کردن قبلی، این را هم اضافه کن تا هر دو قانون همزمان دیده شوند:

```css
.card p {
  outline: 1px dashed #64748b;
}
```

**در مرورگر:** هر سه پاراگراف دور خط‌چین دارند (نسل). فقط دو تای مستقیم پس‌زمینه سبز دارند (فرزند).

«وقتی می‌گویی «متن خود کارت، نه متن فوترِ داخل کارت»، `>` ابزار توست. وقتی می‌گویی «هر پاراگراف این مقاله، حتی داخل نقل‌قول»، فاصله ابزار توست.»

### سؤال کلاسی

- «`.card > section > p` نوه را می‌گیرد؟»  
  **پاسخ:** بله، اگر ساختار دقیقاً کارت، بعد section، بعد p باشد. این دیگر «هر نوه» نیست؛ یک مسیر مشخص است. اگر کسی یک `div` وسط section و p بگذارد، این انتخابگر می‌شکند.

- «علامت `>` خودش به specificity امتیاز جدا می‌دهد؟»  
  **پاسخ:** نه. ترکیب‌کننده فقط رابطه است. امتیاز از خود انتخابگرها می‌آید (عنصر، کلاس، شناسه). `.card > p` از نظر نوع انتخابگر مثل `.card p` دو بخش دارد؛ تفاوتشان معنی است، نه یک جایزه عددی برای علامت `>`.

### اشتباهات رایج

- `>` را «قوی‌تر از فاصله» دانستن. قوی‌تر نیست؛ تنگ‌تر است. عناصر کمتری را انتخاب می‌کند.

## ۴) `+` — اولین پاراگراف بلافاصله بعد از تیتر

«مقاله چند بخش دارد. طراح می‌خواهد جمله بلافاصله بعد از هر تیتر، خلاصه همان بخش باشد: پررنگ و سبز. پاراگراف‌های بعدی بدنه معمولی بمانند.

این دو عنصر خواهر و برادرند، نه پدر و فرزند. تیتر داخل پاراگراف نیست. پس فاصله و `>` این رابطه را نمی‌گویند.»

```html
<div class="ex3">
  <h4>تیتر مقاله</h4>
  <p>اولین پاراگراف بعد از تیتر (خلاصه)</p>
  <p>پاراگراف دوم</p>
  <p>پاراگراف سوم</p>
</div>
```

```css
h4 + p {
  font-weight: bold;
  color: #0b6e4f;
}
```

**در مرورگر:** فقط خلاصه سبز و پررنگ است. پاراگراف دوم و سوم همان رنگ متن صفحه‌اند. `+` یعنی: عنصر سمت راست، **اولین** همسایه باشد که بلافاصله بعد از عنصر سمت چپ آمده، و هر دو یک پدر داشته باشند.

آزمایش را حتماً انجام بده. بین `h4` و `p` یک `span` بگذار:

```html
<h4>تیتر مقاله</h4>
<span>برچسب</span>
<p>این دیگر بلافاصله بعد از تیتر نیست</p>
```

**در مرورگر:** `h4 + p` دیگر آن پاراگراف را نمی‌گیرد، چون همسایه بلافاصله، `span` است نه `p`. دانشجو باید این را ببیند، وگرنه در پروژه فکر می‌کند `+` خراب است.

«`+` به عقب نگاه نمی‌کند. پاراگرافی که *قبل* از `h4` باشد هرگز با `h4 + p` انتخاب نمی‌شود.»

### سؤال کلاسی

- «دو `h4` پشت سر هم، هر کدام یک `p` مستقیم بعدشان. چند پاراگراف سبز می‌شود؟»  
  **پاسخ:** هر دو خلاصه. قانون برای هر `h4` جدا تکرار می‌شود؛ `+` فقط «اولین همسایه بعد از همین h4» را می‌گیرد، نه فقط اولین h4 صفحه.

### اشتباهات رایج

- انتظار اینکه `h4 + p` همه پاراگراف‌های بعد از تیتر را سبز کند. آن کارِ `~` است، نه `+`.  
- گذاشتن `div` دور پاراگراف خلاصه («برای زیبایی») و بعد تعجب از اینکه `h4 + p` ساکت شده. همسایه بلافاصله دیگر `p` نیست.

## ۵) `~` — هر پاراگراف بعد از تیتر، حتی با فاصله

«گاهی نمی‌خواهی فقط خلاصه را عوض کنی. می‌خواهی هر پاراگراف *بعد از* تیتر، تا وقتی هنوز هم‌سطح است، یک خط کناری داشته باشد. پاراگراف قبل از تیتر نه.»

```html
<div class="ex4">
  <p>قبل از تیتر</p>
  <h4>تیتر</h4>
  <p>بعد از تیتر</p>
  <span>یک span وسط</span>
  <p>این هم بعد از تیتر است</p>
</div>
```

```css
h4 ~ p {
  border-right: 4px solid orange;
  padding-right: 0.5rem;
}
```

**در مرورگر:** پاراگراف قبل از تیتر خط ندارد. هر دو پاراگراف بعد از تیتر خط نارنجی دارند. `span` وسط مانع نشده، چون `~` لازم ندارد عنصر بعدی *بلافاصله* باشد؛ فقط باید بعد از `h4` بیاید، `p` باشد، و پدرش با `h4` یکی باشد.

«جزوه برای این خط از `border-right` استفاده کرده، چون صفحه نمونه راست‌چین است و خط کنار شروع خواندن، سمت راست جعبه، دیده می‌شود. اگر خواستی خط همیشه سمت شروع خط باشد، `border-inline-start` هم همان نقش را دارد. در کلاس همان `border-right` جزوه را بنویس تا با صفحه یکی باشد.»

`+` را هم‌زمان روشن کن تا فرق یک همسایه و همه بعدی‌ها روی همان HTML دیده شود:

```css
h4 + p {
  font-weight: bold;
}
```

**در مرورگر:** اولین `p` بعد از تیتر هم پررنگ است هم خط دارد. `p` بعد از span فقط خط دارد. `p` قبل از تیتر هیچ‌کدام را ندارد.

### سؤال کلاسی

- «`h4 ~ p` عنصرهای داخل یک `p` بعدی را جدا انتخاب می‌کند؟»  
  **پاسخ:** نه. `~` خودِ هم‌سطح‌های `p` را می‌گیرد، نه نوه‌های داخل آن‌ها. برای داخل پاراگراف، دوباره به رابطه پدر-فرزندی نیاز داری.

- «یک `p` داخل `span` بعد از تیتر چطور؟»  
  **پاسخ:** آن `p` هم‌سطح `h4` نیست. `h4 ~ p` آن را نمی‌گیرد.

### اشتباهات رایج

- فکر کردن که `~` یعنی «هر پاراگراف این صفحه». فقط هم‌سطح‌های **بعد** از A.  
- عوض کردن ترتیب: `p ~ h4` تیترهای بعد از یک پاراگراف را می‌گیرد، نه پاراگراف‌های بعد از تیتر. سمت چپ و راست علامت، نقش عوض می‌کنند.

## ۶) برگشت به منو — `nav > ul > li > a`

«باگ اول کلاس را ببند. لینک سطح اول مسیر ثابتی دارد: `nav`، فرزند مستقیم `ul`، فرزند مستقیم `li`، فرزند مستقیم `a`. لینک «CSS مقدماتی» یک `ul` اضافه در مسیر دارد، پس این زنجیره را طی نمی‌کند.»

```css
.demo-nav > ul > li > a {
  color: white;
  text-decoration: none;
  font-weight: 600;
}

.demo-nav ul ul a {
  color: #334155;
  font-weight: 400;
  background: #e2e8f0;
  display: inline-block;
  padding: 0.15rem 0.4rem;
}
```

قانون قبلی `.demo-nav a { color: white }` را حذف کن وگرنه هر دو لینک هنوز سفید می‌مانند و دانشجو فکر می‌کند `>` کار نکرده. اگر هر دو را نگه می‌داری، باید توضیح specificity بدهی: هر دو چند عنصر دارند و هر کدام که دیرتر آمده، در شرایط مساوی برنده است. برای این کلاس پاک کردن قانون کلی روشن‌تر است.

**در مرورگر:** خانه، آموزش، تماس سفید روی نوار تیره. «CSS مقدماتی» خاکستری تیره روی زمینه روشن. مثال ۵ جزوه زنجیره سطح اول را دارد؛ زیرمنو را ما به همان فایل زنده اضافه کردیم تا باگ اول جلسه واقعاً بسته شود.

«انتخابگر را بلندتر نکن تا «دقیق‌تر» شود. این نمونه بد است:

```css
body div nav ul li a span { }
```

یک `div` اضافه در HTML و کل قانون می‌خوابد. جزوه می‌گوید معمولاً یک کلاس به‌علاوه حداکثر یک یا دو ترکیب‌کننده کافی است. `.demo-nav > ul > li > a` قابل دفاع است چون هر `>` یک لایه واقعی منو است. از آن طولانی‌تر، نشانه این است که باید روی خود زیرمنو کلاس بگذاری، مثلاً `.submenu a`.»

### سؤال کلاسی

- «اگر لینک سطح اول را داخل یک `span` بگذاریم، `nav > ul > li > a` هنوز کار می‌کند؟»  
  **پاسخ:** نه. `a` دیگر فرزند مستقیم `li` نیست. یا `span` را بردار، یا انتخابگر را با ساختار جدید میزان کن.

### اشتباهات رایج

- `nav > a` وقتی `a` مستقیم داخل `nav` نیست و داخل `li` است. این انتخابگر هیچ لینکی را نمی‌گیرد و دانشجو نتیجه می‌گیرد «ترکیب‌کننده خراب است».  
- رنگ زیرمنو را با `!important` درست کردن، به‌جای تنگ کردن انتخابگر سطح اول.

## ۷) پروژه جلسه — مقاله با خلاصه بعد از هر `h3`، و همان منو

یک صفحه کوچک که هر دو رابطه درس را دارد: هم‌سطح (`+`) و فرزند (`>`).

```html
<nav class="demo-nav">
  <ul>
    <li><a href="#">خانه</a></li>
    <li>
      <a href="#">آموزش</a>
      <ul>
        <li><a href="#">CSS مقدماتی</a></li>
        <li><a href="#">CSS میانی</a></li>
      </ul>
    </li>
    <li><a href="#">تماس</a></li>
  </ul>
</nav>

<article class="lesson-article">
  <h3>بخش اول</h3>
  <p>این خلاصه بخش اول است و باید درشت‌تر و سبز باشد.</p>
  <p>بدنه معمولی بخش اول، بدون آن رنگ.</p>
  <h3>بخش دوم</h3>
  <p>خلاصه بخش دوم.</p>
  <p>ادامه بدنه.</p>
</article>
```

```css
.demo-nav > ul > li > a {
  color: white;
}

.demo-nav ul ul a {
  color: #334155;
  font-weight: 400;
}

.lesson-article h3 + p {
  font-size: 1.05rem;
  font-weight: 700;
  color: #0b6e4f;
  margin-top: 0.25rem;
}
```

**در مرورگر:** دو خلاصه سبزند، بدنه‌ها نه. دو لینک زیرمنو تیره می‌مانند حتی اگر قانون سفید سطح اول را گسترده‌تر کنی. از دانشجو بخواه قبل از ذخیره پیش‌بینی کند: اگر بین `h3` بخش دوم و خلاصه‌اش یک `div` خالی بگذاریم، کدام پاراگراف رنگ را از دست می‌دهد؟ بگذارید آزمایش کنند.

«اگر فردا ویرایشگر متن دور هر پاراگراف `div` بپیچد، `h3 + p` می‌شکند. آن وقت کلاس `.lead` روی خود خلاصه صادق‌تر از یک زنجیره شکننده است. ترکیب‌کننده را جایی به کار ببر که ساختار HTML پایدار است و خودت مالکشی.»

### سؤال حین پروژه

- «`.lesson-article > h3 + p` با `.lesson-article h3 + p` در این HTML فرقی دارد؟»  
  **پاسخ:** در این فایل هر دو خلاصه را می‌گیرند، چون `h3` فرزند مستقیم article است. اگر یک `section` دور بخش‌ها بگذاری، نسخه با `>` دیگر `h3` را نمی‌بیند و `+` هم اجرا نمی‌شود. نسخه با فاصله هنوز `h3`های نسل را پیدا می‌کند.

## ۸) جمع‌بندی مدرس و سؤالات پایانی

۱. `.card p` و `.card > p` هر کدام کدام پاراگراف‌ها را می‌گیرند؟  
   **پاسخ راهنما:** اولی هر عمقی داخل کارت. دومی فقط `p` که مستقیم فرزند `.card` است.

۲. `h3 + p` چند پاراگراف بعد از هر تیتر را عوض می‌کند، و اگر یک `span` بین تیتر و پاراگراف باشد چه می‌شود؟  
   **پاسخ راهنما:** فقط همان یکی که بلافاصله بعد است. با `span` وسط، دیگر match نمی‌شود.

۳. چرا `nav a` لینک زیرمنو را هم سفید کرد، و کدام زنجیره فقط سطح اول را می‌گیرد؟  
   **پاسخ راهنما:** فاصله، همه نسل‌ها را شامل می‌شود. `nav > ul > li > a` فقط مسیر مستقیم سطح اول.

**پیام پایانی:**

«ترکیب‌کننده اسم تازه‌ای برای عنصر نیست. می‌گوید این عنصر نسبت به آن یکی کجای درخت است: داخلش در هر عمق (فاصله)، بچه مستقیمش (`>`)، همسایه چسبیده بعد (`+`)، یا هر هم‌سطح بعد (`~`). هیچ‌کدام به خواهر و برادر قبلی، یا به داخل یک هم‌سطح، سرک نمی‌کشند.»

## تمرین‌ها (ساده → چالشی)

### ساده

۱. HTML مثال ۱ و ۲ جزوه را بنویس. قبل از ذخیره پیش‌بینی کن `.post p` و `.card > p` کدام جمله‌ها را رنگی می‌کنند. بعد نتیجه را با پیش‌بینی مقایسه کن.  
۲. `div.box` و `div .box` را روی دو تکه HTML جدا رنگ کن و در یک جمله فرق‌شان را بگو.

### متوسط

۳. مقاله با دو `h3`. با `h3 + p` فقط پاراگراف اول بعد از هر تیتر را بزرگ‌تر کن. این تمرین خود جزوه است.  
۴. همان مقاله را به `h3 ~ p` عوض کن و بگو پاراگراف قبل از اولین تیتر چرا خط نمی‌گیرد. یک `span` بین دو پاراگراف بعد از تیتر بگذار و نشان بده `~` هنوز پاراگراف دوم را می‌گیرد و `+` نه.

### چالشی

۵. منوی دو سطحی پروژه را بساز. قانون `nav a` را عمداً برگردان تا زیرمنو سفید شود، بعد با `>` سطح اول را جدا کن و برای `ul ul a` رنگ تیره بگذار.  
۶. انتخابگر `body main article section div p` را روی یک مقاله واقعی امتحان کن، یک `div` را از HTML حذف کن تا قانون بشکند، بعد همان کار را با `.lesson-article p` یا `.lesson-article > p` انجام بده و بنویس کدام را در پروژه نگه می‌داری و چرا.
