## ۱) شروع کلاس؛ نیاز روی سایت

«این جلسه **اختیاری** است. سایت بدون آن کار می‌کند. فرق در احساس قطعه است.

یک دکمه «ثبت‌نام» دو حالت دارد: آبی، و وقتی ماوس روی آن است سبز و دو پیکسل بالاتر. اگر فقط `:hover` بنویسیم، مرورگر در **یک فریم** از آبی به سبز می‌پرد. چشم پرش را می‌بیند و گاهی فکر می‌کند صفحه خطا داده.

`transition` یعنی: این ویژگی‌ها را، در این مدت، با این ریتم، از مقدار قبلی به مقدار جدید ببر. خودِ مقدار جدید همچنان کار `:hover` یا هر حالت دیگر است. transition حالت جدید اختراع نمی‌کند؛ فقط راه رسیدن را نرم می‌کند.»

HTML:

```html
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Live — transition</title>
  <style>
    body {
      font-family: Tahoma, sans-serif;
      padding: 2rem;
      background: #f8fafc;
    }
  </style>
</head>
<body>
  <button class="btn" type="button">ثبت‌نام در دوره</button>
</body>
</html>
```

اول **بدون** transition:

```css
.btn {
  padding: 10px 18px;
  background: #1a5fb4;
  color: white;
  border: none;
  border-radius: 6px;
  cursor: pointer;
}

.btn:hover {
  background: #0b6e4f;
  transform: translateY(-2px);
}
```

**در مرورگر:** چند بار ماوس را وارد و خارج کن. «پرش را ببینید. حالا همان را نرم می‌کنیم. مقدارهای hover را دست نمی‌زنیم.»

### سؤال کلاسی

- «اگر transition را روی خود دکمه نگذاریم و فقط رنگ hover را عوض کنیم، کاربر چه می‌بیند؟»  
  **پاسخ:** تغییر ناگهانی. حالت hover وجود دارد؛ فقط میان‌فریم‌ها ساخته نمی‌شوند.

## ۲) چهار قسمت، و چرا دستور را روی حالت عادی می‌نویسیم

کوتاه‌شده را به چهار سؤال بشکن:

| قسمت | مثال | سؤال |
|------|------|------|
| کدام ویژگی | `background-color` | چه چیزی باید راه برود، نه بپرد |
| مدت | `0.25s` یا `250ms` | راه چقدر طول بکشد |
| timing | `ease` | سرعت در طول راه یکنواخت است یا ته و ابتدا کند است |
| تأخیر | `0s` (اغلب حذف می‌شود) | قبل از شروع کمی صبر کند یا نه |

```css
.btn {
  background: #1a5fb4;
  transition: background-color 0.25s ease, transform 0.25s ease;
}
```

«این خط را روی **خود دکمه** می‌نویسیم، نه داخل `:hover`. دلیلش را آزمایش کن: اگر transition فقط داخل `:hover` باشد، رفتن به سبز نرم است و برگشت به آبی، وقتی ماوس می‌رود، دوباره می‌پرد — چون در حالت عادی دیگر قانونی برای میان‌فریم نیست.

با گذاشتن transition روی حالت پایه، هم رفتن و هم برگشتن نرم است.

دو ویژگی را با ویرگول جدا کرده‌ایم. اگر فقط `background-color` را بنویسیم، رنگ نرم می‌شود و `translateY` همچنان می‌پرد. هر ویژگی که در hover عوض می‌شود و قابلیت میان‌فریم دارد باید در لیست باشد، یا عمداً بپذیری که همان یکی بپرد.»

ویژگی‌های بلند را یک‌بار نشان بده تا کوتاه‌شده جادو نباشد:

```css
.btn {
  transition-property: background-color, transform;
  transition-duration: 0.25s;
  transition-timing-function: ease;
  transition-delay: 0s;
}
```

«در کار روزمره همان یک خط `transition` کافی است. اگر مدت‌ها متفاوت باشند، کوتاه‌شده هنوز جواب می‌دهد:

```css
transition: background-color 0.25s ease, transform 0.45s ease 0.1s;
```

اینجا transform کمی دیرتر و کمی طولانی‌تر حرکت می‌کند. در دکمه ثبت‌نام این اختلاف لازم نیست؛ هر دو را ۰٫۲۵s نگه دار تا دکمه یک حرکت دیده شود نه دو حرکت.»

**در مرورگر:** خط transition را اضافه کن. وارد و خارج شو. بعد عمداً `transform` را از لیست حذف کن تا پرش عمودی کنار رنگِ نرم دیده شود. برگردان.

### سؤال کلاسی

- «`0.25s` و `250ms` فرق عملی دارند؟»  
  **پاسخ:** نه. ۲۵۰ میلی‌ثانیه همان ۰٫۲۵ ثانیه است. در یک فایل یکی را انتخاب کن.

## ۳) timing را با سه دکمه نشان بده، حفظ نکن

سه دکمه با مدت یکسان `0.8s` (عمداً کند تا ریتم دیده شود) و timing متفاوت. در پروژه واقعی ۰٫۸ ثانیه برای hover دکمه طولانی است؛ فقط برای دیدن منحنی است. بعداً برگرد به ۰٫۲ تا ۰٫۳.

```html
<button class="swatch linear" type="button">linear</button>
<button class="swatch ease" type="button">ease</button>
<button class="swatch in-out" type="button">ease-in-out</button>
```

```css
.swatch {
  display: block;
  width: 140px;
  margin: 8px 0;
  padding: 8px;
  border: none;
  background: #1a5fb4;
  color: white;
  text-align: right;
}

.swatch:hover {
  width: 280px;
}

.linear { transition: width 0.8s linear; }
.ease   { transition: width 0.8s ease; }
.in-out { transition: width 0.8s ease-in-out; }
```

«`linear` سرعت ثابت؛ اغلب مکانیکی به نظر می‌رسد. `ease` پیش‌فرض است: شروع و پایان کمی نرم‌تر از وسط. `ease-in-out` هر دو سر را کند می‌کند. `ease-out` برای چیزی که وارد صفحه می‌شود معمولاً طبیعی‌تر است، چون با سرعت می‌آید و آرام می‌ایستد.

لازم نیست منحنی بزیه را بکشی. برای UI این جلسه: hover را `ease` یا `ease-out` بگذار و مدت را زیر حدود ۰٫۳ ثانیه نگه دار. اگر کاربر حس کند سایت «سنگین» است، اغلب مدت زیاد است نه رنگ اشتباه.»

**در مرورگر:** سه دکمه را پشت سر هم hover کن. بعد مدت پروژه را برگردان به `0.25s`.

### نکته مدرس

`transition` روی `width` را برای آموزش timing استفاده کردیم چون تغییرش با چشم دیده می‌شود. در بخش عملکرد بگو برای منو و کارت، `transform` معمولاً روان‌تر از انیمیت کردن `width` و `height` و `top` است. این توصیه جزوه است: برای عملکرد بهتر `transform` و `opacity` را ترجیح بده. وارد لایه compositor نشو؛ یک جمله «مرورگر این دو را اغلب بدون چیدمان مجدد کل صفحه جابه‌جا می‌کند» کافی است.

## ۴) جعبه جزوه — رنگ و عرض

مثال ۲ صفحه جزوه:

```css
.panel {
  width: 120px;
  height: 80px;
  background: #c92a2a;
  border-radius: 8px;
  transition: width 0.4s ease, background-color 0.4s ease;
}

.panel:hover {
  width: 220px;
  background: #1a5fb4;
}
```

«ماوس را روی جعبه ببر. هم عرض و هم رنگ در ۰٫۴ ثانیه می‌روند. این دمو است. در یک کارت محصول واقعی، باز و بسته کردن `width` متن داخل را در هر فریم دوباره می‌چیند. اگر فقط می‌خواهی کارت کمی بالا بیاید، `transform: translateY(-2px)` همان حس را با هزینه کمتر می‌دهد. دکمه اول جلسه را به‌عنوان الگوی درست نگه دار و این جعبه را به‌عنوان «می‌شود width را هم نرم کرد، ولی همیشه بهترین انتخاب نیست».»

### ویژگی‌هایی که میان‌فریم دارند و آن‌هایی که ندارند

روی برد دو ستون:

نرم می‌شوند، اگر مقدارشان عددی یا رنگی باشد: `color`، `background-color`، `opacity`، `transform`، `border-color`، خیلی از طول‌ها مثل `padding` و `width`.

نرم **نمی‌شوند:** `display` (نمی‌شود بین `none` و `block` نیمه راه داشت)، `visibility` به آن معنی که نیمه پنهان شود — در عمل `visibility` تأخیر می‌پذیرد ولی شفافیت تدریجی نمی‌سازد؛ برای محو شدن از `opacity` استفاده کن. `font-family` هم بین دو فونت میانگین ندارد.

آزمایش `display` را همین حالا بکن، چون درس ۲۳ به آن تکیه می‌کند:

```css
.panel {
  display: none;
}
.wrap:hover .panel {
  display: block;
  transition: display 0.4s;
}
```

«هیچ نرمی نمی‌بینی. یا هست یا نیست. transition روی `display` در این سطح به کار نمی‌آید. برای نشان دادن و پنهان کردن نرم، درس بعد از `opacity` و `visibility` و `transform` استفاده می‌کنیم.»

کد آزمایش را بعد از دیدن شکست پاک کن تا فایل زنده با جعبه سالم تمام شود.

### سؤال کلاسی

- «برای محو شدن یک برچسب، `display` را transition می‌کنی یا `opacity`؟»  
  **پاسخ:** `opacity`. `display` میان‌حالت ندارد.

## ۵) `all` — کوتاه، و اغلب شلخته

```css
.btn {
  transition: all 0.3s ease;
}
```

«`all` یعنی هر ویژگی‌ای که عوض شد نرم حرکت کند. امروز که فقط رنگ و transform را عوض می‌کنی درست به نظر می‌رسد. فردا که در یک media query `padding` یا `width` همان دکمه عوض شود، آن هم ۰٫۳ ثانیه راه می‌رود و صفحه انگار کش می‌آید.

جزوه گفته با احتیاط از `all` استفاده کن. در این کلاس لیست صریح را ترجیح بده. `all` را فقط وقتی نشان بده که بخواهی خطرش را ببینی: موقتاً روی `.btn` بگذار و در DevTools یک `padding` را عوض کن تا بقیه ویژگی‌ها هم بلغزند.»

### اشتباهات رایج

- transition فقط داخل `:hover` → برگشت می‌پرد.  
- مدت‌های بالای حدود نیم‌ثانیه روی hover معمولی → رابط کند حس می‌شود.  
- انیمیت کردن `margin` یا `width` برای جابه‌جایی کوچک، در حالی که `transform` همان جابه‌جایی را می‌دهد.  
- انتظار نرمی از تغییری که خودت در hover ننوشته‌ای. transition ویژگی جدید اختراع نمی‌کند.

## ۶) تأخیر کوتاه، فقط وقتی دو حرکت را از هم جدا می‌کنی

روی همان دکمه، تأخیر را آزمایش کن و بعد بردار:

```css
.btn {
  transition: background-color 0.25s ease, transform 0.25s ease 0.15s;
}
```

«عدد آخرِ قسمت دوم، `transition-delay` است. رنگ بلافاصله راه می‌افتد و دو پیکسل بالا آمدن ۰٫۱۵ ثانیه دیرتر شروع می‌شود. برای یک دکمه ثبت‌نام این جدایی لازم نیست و حس «لنگیدن» می‌دهد. برگردان به تأخیر صفر.

تأخیر وقتی به درد می‌خورد که چیزی باید بعد از تمام شدن چیز دیگری دیده شود، مثلاً منویی که اول محو می‌شود و بعد از دید خارج می‌شود. آن الگو درس ۲۳ است. اینجا فقط نشان بده که جای تأخیر در کوتاه‌شده، بعد از timing است:

`transition: transform 0.25s ease 0.15s;`

یعنی ویژگی، مدت، ریتم، تأخیر. اگر تأخیر را قبل از مدت بنویسی، مرورگر معنی را عوض می‌کند یا مقدار را نامعتبر می‌بیند. در این کلاس تأخیر را حذف کن مگر بخواهی ترتیب دو حرکت را عمداً نشان بدهی.»

### سؤال کلاسی

- «مدت ۰٫۲۵ ثانیه است و تأخیر ۰٫۱۵. از لحظه hover تا **شروع** بالا آمدن چقدر طول می‌کشد، و تا **پایان** آن؟»  
  **پاسخ:** شروع بعد از ۰٫۱۵ ثانیه؛ پایان حدود ۰٫۱۵ + ۰٫۲۵ = ۰٫۴۰ ثانیه بعد از hover. رنگ، اگر تأخیر نداشته باشد، در ۰٫۲۵ تمام شده است.

## ۷) پروژه ترکیبی — دکمه و لینک

دو قطعه، هر دو با لیست صریح و مدت کوتاه. منو و dropdown را نساز؛ مال درس ۲۳ است.

```html
<p><a class="more" href="#details">ادامه مطلب</a></p>
<button class="btn" type="button">ثبت‌نام در دوره</button>
```

```css
.more {
  color: #1a3a5c;
  text-decoration: none;
  border-bottom: 2px solid transparent;
  transition: color 0.2s ease, border-color 0.2s ease;
}

.more:hover {
  color: #0b6e4f;
  border-bottom-color: #0b6e4f;
}

.btn {
  padding: 10px 18px;
  background: #1a5fb4;
  color: white;
  border: none;
  border-radius: 6px;
  cursor: pointer;
  transition: background-color 0.25s ease, transform 0.25s ease;
}

.btn:hover {
  background: #0b6e4f;
  transform: translateY(-2px);
}
```

«لینک، رنگ و خط زیر را در ۰٫۲ ثانیه می‌برد. دکمه، پس‌زمینه و دو پیکسل بالا آمدن را در ۰٫۲۵ ثانیه. هیچ‌کدام `all` نیستند. هر دو transition روی حالت پایه است.

`:focus-visible` را این جلسه اگر وقت کم است فقط اعلام کن: کسی که با کیبورد می‌آید hover ندارد، پس در درس ۲۳ همان تغییر را برای فوکوس هم می‌نویسیم. اگر الان یک خط اضافه کنی بد نیست، ولی پروژه را معطل آن نکن.»

**نمایش:** چند بار وارد و خارج شو. در DevTools مدت را روی `2s` بگذار تا میانه‌ی راه را ببینند، بعد برگردان. عادت کنند مدت طولانی ابزارِ دیدن است نه محصول.

## ۸) جمع‌بندی مدرس و سؤالات پایانی

1. transition را روی حالت عادی می‌نویسی یا فقط روی `:hover`؟ چرا؟  
   **پاسخ:** روی حالت عادی، تا هم رفتن و هم برگشتن میان‌فریم داشته باشد.

2. سه بخشی که تقریباً همیشه در کوتاه‌شده هست چیست؟  
   **پاسخ:** نام ویژگی، مدت، timing. تأخیر اختیاری است.

3. چرا برای بالا آمدن دکمه `translateY` را به `margin` ترجیح دادیم؟  
   **پاسخ:** جزوه `transform` و `opacity` را برای این‌جور حرکت‌های کوچک ترجیح می‌دهد؛ margin چیدمان اطراف را در طول حرکت تکان می‌دهد.

4. چرا `transition: display 0.3s` منو را نرم باز نمی‌کند؟  
   **پاسخ:** `display` مقدار میانی ندارد.

**پیام پایانی:**

«Transition معجزه طراحی نیست. یک راه کوتاه بین دو مقداری است که خودت در CSS نوشته‌ای. ویژگی را اسم ببر، مدت را کوتاه نگه دار، و چیزی را که میان‌فریم ندارد داخل لیست نگذار.»

### ساده

2. دکمه ثبت‌نام با `background-color` و `transform` در `0.25s ease`.

### متوسط
3. سه نسخه از یک جعبه با `linear` و `ease` و `ease-in-out` و مدت یکسان، فقط برای مقایسه ریتم. در کنارش بنویس کدام را برای hover واقعی سایت انتخاب می‌کنی و چرا مدت ۰٫۸ ثانیه را در محصول نمی‌گذاری.  
4. جعبه عرض‌متغیر جزوه را بساز، بعد همان حس «کمی بزرگ شدن» را با `transform: scale(1.03)` جایگزین کن و تفاوت تکان خوردن متن اطراف را بگو.

### چالشی
5. یک کارت کوچک با hover: سایه و `translateY(-4px)`. لیست transition صریح باشد، نه `all`. مدت هر دو ۰٫۲ تا ۰٫۳ ثانیه.  
6. توضیح بده اگر transition را فقط داخل `:hover` بگذاری، کدام مسیر می‌پرد.

**ارجاع:** [`22-transitions.html`](../../pages/22-transitions.html). هنوز dropdown و `focus-visible` را الزام این تمرین نکن.
