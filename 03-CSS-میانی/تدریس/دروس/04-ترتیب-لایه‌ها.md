# سناریوی تدریس درس ۴: ترتیب لایه‌ها (Z-index)

**صفحه جزوه:** [`pages/04-z-index.html`](../../pages/04-z-index.html)

**مدت پیشنهادی:** حدود ۷۵ دقیقه  
**هدف جلسه:** دانشجو اول بگوید کدام لایه باید روی کدام بنشیند (کارت‌ها، نوشته روی بنر، پنجرهٔ گفتگو روی صفحه)، بعد `z-index` را فقط روی عنصر positioned اعمال کند، و بفهمد عددها سراسری مقایسه نمی‌شوند؛ هر گروه (stacking context) جدا است.

## ۱) شروع کلاس؛ اول بگو چه چیزی روی سایت می‌خواهیم

اول کلاس این‌طور شروع کن:

«بچه‌ها، درس قبل عنصرها را از جریان درآوردیم. برچسب روی کارت افتاد و دکمهٔ ثابت روی متن افتاد. تا وقتی فقط یک چیز روی بقیه است، مرورگر معمولاً همان را رو می‌کشد. روی سایت واقعی چند لایه با هم می‌آیند و باید خودمان ترتیب را بگوییم.

سه خواسته را قبل از اسم ویژگی بنویسیم.

خواسته اول: سه کارت معرفی روی هم افتاده‌اند، مثل برگه‌های روی میز. می‌خواهیم آبی از همه رو باشد، سبز وسط، قرمز زیر.

خواسته دوم: روی عکس بنر یک نوار نوشته می‌خواهیم: «حراج پاییزه». نوشته باید روی عکس باشد، نه پشت آن، و تمام لبهٔ پایین تصویر را بگیرد تا خوانا بماند.

خواسته سوم: پنجرهٔ گفتگو. اول یک لایهٔ تیره تمام پنجره را می‌پوشاند تا صفحهٔ پشت کم‌رنگ شود. بعد خود جعبهٔ سفید پیام باید **روی** آن لایهٔ تیره باشد، و هر دو باید روی هدر چسبان و روی محتوای عادی بمانند. اگر جعبهٔ سفید پشت لایهٔ تیره برود، کاربر پیام را نمی‌بیند.

ویژگی‌ای که این ترتیب عمقی را می‌گوید `z-index` است. عدد بزرگ‌تر روی عدد کوچک‌تر قرار می‌گیرد. مثل دستهٔ برگه: هر چه بالاتر در دسته باشد، دیرتر دیده می‌شود.

اما یک شرط از درس قبل همراهش است: روی عنصر `static` این عدد اثر ندارد. عنصر باید `relative` یا `absolute` یا `fixed` یا `sticky` باشد. استثنا را هم می‌گوییم: فرزند مستقیم یک ظرف `flex` یا `grid` می‌تواند `z-index` بگیرد حتی اگر static باشد. امروز ظرف ما flex نیست؛ پس position را فراموش نکنید.»

فایل زنده (پیشنهاد: `تدریس/live/04-z-index.html`) با `dir="rtl"` باز شود.

## ۲) اگر عدد ننویسیم، چه کسی رو است؟

بگو:

«قبل از عدد، یک قاعدهٔ پیش‌فرض هست. اگر `z-index` ننویسید و شرایط برابر باشد، عنصری که در HTML **دیرتر** آمده روی قبلی رسم می‌شود.

پس ترتیب تگ‌ها خودش یک جور لایه است. عدد را وقتی می‌نویسیم که این ترتیب پیش‌فرض خواستهٔ ما را برآورده نمی‌کند، یا وقتی می‌خواهیم نیت را برای نفر بعدی صریح کنیم.»

دو مربع هم‌پوشان بدون z-index بساز:

```html
<div class="stage plain">
  <div class="sheet a">اول در HTML</div>
  <div class="sheet b">دوم در HTML</div>
</div>
```

```css
.stage {
  position: relative;
  height: 160px;
  background: #f8fafc;
  border: 1px dashed #94a3b8;
  margin-bottom: 16px;
}

.sheet {
  position: absolute;
  width: 140px;
  height: 90px;
  padding: 8px;
}

.a {
  top: 16px;
  right: 16px;
  background: #ffd8a8;
}

.b {
  top: 48px;
  right: 70px;
  background: #b2f2bb;
}
```

**در مرورگر:** سبز که دیرتر در HTML است روی نارنجی قرار دارد. حالا در HTML جایشان را عوض کن. سبز می‌رود زیر. عدد هنوز نداریم.

«این آزمایش را نگه دارید. بسیاری از «باگ‌های لایه» فقط همین است: تگ دیرتر آمده رو شده، بی‌آنکه کسی `z-index` نوشته باشد.»

### سؤال کلاسی

- «بدون `z-index`، کدام مربع رو بود؟»  
  **پاسخ:** آن که در HTML دیرتر نوشته شده بود.

## ۳) سه کارت؛ عدد بزرگ‌تر رو است

«حالا خواستهٔ اول را با عدد صریح کنیم. صحنه باید `position: relative` باشد تا هر سه کارت absolute نسبت به همین صحنه سنجیده شوند، نه نسبت به کل صفحه. این همان مرجع درس قبل است.»

```html
<div class="stage">
  <div class="layer red">قرمز z=1</div>
  <div class="layer green">سبز z=2</div>
  <div class="layer blue">آبی z=3</div>
</div>
```

```css
.stage {
  position: relative;
  height: 190px;
}

.layer {
  position: absolute;
  width: 160px;
  height: 100px;
  color: #fff;
  padding: 8px;
}

.red {
  top: 0;
  right: 0;
  z-index: 1;
  background: #e03131;
}

.green {
  top: 30px;
  right: 60px;
  z-index: 2;
  background: #2f9e44;
}

.blue {
  top: 60px;
  right: 120px;
  z-index: 3;
  background: #1c7ed6;
}
```

«قرمز را اول نوشتیم با عدد ۱، سبز با ۲، آبی با ۳. آبی از همه رو است، حتی اگر کسی ترتیب HTML را به هم بریزد. دیگر به «دیرتر آمدن» تکیه نمی‌کنیم.

`right` را به خاطر صفحهٔ راست‌چین انتخاب نکردیم. همان‌طور که درس قبل گفتیم، `right` لبهٔ راست فیزیکی صحنه است. کارت‌ها از راست صحنه شروع می‌شوند و به سمت چپ روی هم می‌روند تا در کلاس دیده شوند.»

**در مرورگر:** آبی روی سبز، سبز روی قرمز. با DevTools عدد را روی آبی موقتاً `0` بگذار. آبی می‌رود زیر بقیه، چون ۱ و ۲ از صفر بزرگ‌ترند. بعد برگردان به ۳.

«عدد منفی هم مجاز است. `z-index: -1` عنصر را پشت محتوای عادی همان پدر می‌فرستد. برای یک لکهٔ تزئینی پشت متن به کار می‌آید. اگر پدر خودش گروه تازه نساخته باشد، منفی گاهی پشت خود پدر هم می‌رود و ناپدید به نظر می‌رسد. این را در بخش گروه‌ها دوباره می‌بینیم. امروز فقط بدانید منفی یعنی «عقب‌تر»، نه اینکه مرورگر خطا بدهد.»

### سؤال کلاسی

- «اگر آبی `z-index: 3` باشد و در HTML اول آمده باشد، باز هم رو است؟»  
  **پاسخ:** بله. وقتی عددها نوشته شده‌اند، مقایسه با عدد است. بزرگ‌تر رو می‌ماند.

- «`z-index: 5` روی یک `div` که position ندارد چه می‌کند؟»  
  **پاسخ:** بی‌اثر است، چون هنوز static است. اول position را از static خارج کنید. استثنای flex و grid را همین‌جا یک جمله تکرار کن.

### اشتباهات رایج

- نوشتن `z-index` و فراموش کردن `position`. در تب Computed اثر نمی‌بینید و عدد را هی بزرگ می‌کنید.  
- منفی دادن به تزئین، و بعد متعجب شدن که کلاً ناپدید شده چون پشت پدر رفته.

## ۴) همان کارت‌ها، ترتیب برعکس

«خواسته عوض شد: حالا قرمز باید رو باشد و آبی زیر. لازم نیست HTML را زیر و رو کنیم. عددها را عوض می‌کنیم.»

روی یک صحنهٔ دوم، یا با یک کلاس اضافه:

```css
.stage.reverse .red {
  z-index: 3;
}

.stage.reverse .blue {
  z-index: 1;
}
```

متن داخل کارت را هم عوض کن تا عدد روی صفحه دروغ نگوید: «قرمز z=3»، «سبز z=2»، «آبی z=1».

**در مرورگر:** قرمز روی سبز است و آبی زیر همه در ناحیهٔ هم‌پوشانی. کنار صحنهٔ اول نگه دار تا هر دو خواسته همزمان دیده شوند.

«ببینید مکان `top` و `right` هیچ عوض نشد. فقط عمق عوض شد. اگر دانشجویی جای کارت را با `top` جابه‌جا کند تا «رو» شود، دارد مسئلهٔ دیگری را حل می‌کند.»

### سؤال کلاسی

- «برای رو آوردن قرمز، HTML را عوض کردیم یا CSS را؟»  
  **پاسخ:** CSS. مقدار `z-index` قرمز و آبی را عوض کردیم.

## ۵) نوشته روی تصویر بنر

«خواستهٔ دوم. عکس به‌خودی‌خود position ندارد. یک لایهٔ positioned به‌طور پیش‌فرض روی محتوای بدون position همان محدوده رسم می‌شود. با این حال `z-index: 2` را می‌نویسیم تا اگر بعداً عنصر positioned دیگری به بنر اضافه شد، نوشته همچنان رو بماند. این عدد برای «اطمینان از نیت» است، نه برای مسابقه با یک دشمن نامرئی.»

```html
<div class="photo">
  <img src="../images/bg.jpg" alt="تصویر نمونه بنر">
  <p class="caption">حراج پاییزه — تا ۴۰٪ تخفیف</p>
</div>
```

```css
.photo {
  position: relative;
  width: min(100%, 420px);
  margin: 16px 0;
}

.photo img {
  display: block;
  width: 100%;
  height: auto;
}

.caption {
  position: absolute;
  bottom: 0;
  right: 0;
  left: 0;
  z-index: 2;
  margin: 0;
  padding: 8px 12px;
  color: #fff;
  background-color: rgba(0, 0, 0, 0.6);
}
```

«پدر `relative` است تا نوار نسبت به عکس بماند، نه نسبت به صفحه.

`bottom: 0` نوار را به لبهٔ پایین عکس می‌چسباند.

`right: 0` و `left: 0` با هم یعنی هر دو لبهٔ فیزیکی چپ و راست به لبهٔ پدر بچسبند، پس نوار تمام‌عرض می‌شود. اینجا جهت فارسی مهم نیست؛ هر دو لبه را صفر کرده‌ایم.

`rgba(0, 0, 0, 0.6)` زمینهٔ سیاه با شفافیت است تا متن سفید روی عکس خوانا باشد. خود ویژگی `opacity` روی کل عنصر، درس جداگانه‌ای است. اینجا فقط رنگ زمینه شفاف است و متن کاملاً خواناست.»

اگر `width: min(...)` را هنوز درس نداده‌ای، به‌جایش `max-width: 420px; width: 100%;` بنویس تا به درس ۲ وصل شود. هر دو درست است. در کلاس اگر `min()` ناآشناست، همان الگوی max-width را بگذار.

**در مرورگر:** نوار پایین عکس است و با عکس جابه‌جا می‌شود. `z-index` را بردار؛ نوار هنوز روی عکس است، چون عکس position ندارد. بعد یک مربع absolute دیگر با `z-index: 5` گوشهٔ بنر بگذار تا ببینند بدون عدد ۲، ممکن بود آن مربع بیاید روی نوشته. عدد ۲ را برگردان و مربع آزمایشی را ۵ بگذار تا نوشته برود زیر آن، بعد مربع را پاک کن.

«پس `z-index` وقتی معنی پیدا می‌کند که حداقل دو لایهٔ positioned با هم رقابت کنند.»

### سؤال کلاسی

- «چرا `.photo` باید `position: relative` باشد؟»  
  **پاسخ:** تا مرجع نوار absolute خود بنر باشد و نوار به پایین همان عکس بچسبد.

- «`left: 0` و `right: 0` با هم چه عرضی می‌سازند؟»  
  **پاسخ:** عرض بین دو لبهٔ پدر؛ یعنی نوار تمام عرض عکس.

### اشتباهات رایج

- absolute کردن نوشته بدون relative کردن `.photo`. نوار می‌رود پایین صفحه.  
- دادن `opacity` به کل `.caption` و کم‌رنگ شدن خود متن. شفافیت را به رنگ زمینه بدهید.

## ۶) عددها فقط داخل یک گروه مقایسه می‌شوند

«خواستهٔ سوم جایی است که دانشجوها عدد را بی‌حساب بزرگ می‌کنند. منوی بازشونده `z-index: 9999` دارد و باز هم زیر یک نوار دیگر می‌رود. مقایسه سراسری نیست.

مرورگر عنصرها را در گروه‌هایی می‌چیند. اسم این گروه stacking context است. در کلاس بگویید **گروه لایه**. عددها فقط داخل همان گروه با هم سنجیده می‌شوند. فرزندان هر قدر عدد بزرگ داشته باشند، از گروه پدرشان بیرون نمی‌روند تا با بچه‌های یک پدر دیگر مسابقه بدهند.

یک گروه تازه در این سطح وقتی ساخته می‌شود که یکی از این‌ها باشد:

عنصر position غیر از static داشته باشد و `z-index` آن هم غیر از `auto` باشد.

یا `opacity` کمتر از ۱ باشد.

یا `transform` چیزی غیر از `none` باشد.

جزئیات کامل فهرست مرورگر لازم نیست. همین سه تا باگ‌های واقعی کلاس را توضیح می‌دهند.»

این آزمایش را آرام بساز. دو ستون، هر کدام یک پدر:

```html
<div class="fathers">
  <div class="father low">
    <div class="child big">فرزند ۹۹۹۹</div>
  </div>
  <div class="father high">
    <div class="child small">فرزند ۱</div>
  </div>
</div>
```

```css
.fathers {
  position: relative;
  height: 180px;
}

.father {
  position: absolute;
  width: 200px;
  height: 140px;
  top: 10px;
}

.father.low {
  right: 20px;
  z-index: 1;
  background: #ffe3e3;
}

.father.high {
  right: 120px;
  z-index: 2;
  background: #d3f9d8;
}

.child {
  position: absolute;
  left: 16px;
  bottom: 16px;
  padding: 8px;
  background: #1a3a5c;
  color: #fff;
}

.child.big {
  z-index: 9999;
}

.child.small {
  z-index: 1;
}
```

«پدر قرمز عدد ۱ دارد و گروه خودش را ساخته، چون هم position دارد هم z-index غیر auto. پدر سبز عدد ۲ دارد و گروه بالاتری است.

فرزند داخل قرمز ۹۹۹۹ است. این ۹۹۹۹ فقط داخل گروه پدر قرمز معنی دارد. پدر سبز با عدد ۲ کل گروهش از کل گروه قرمز روتر است. پس جعبهٔ «فرزند ۱» که مال پدر سبز است، روی «فرزند ۹۹۹۹» دیده می‌شود.»

**در مرورگر:** جعبهٔ سفیدِ آبیِ داخل پدر سبز روی پدر قرمز و روی فرزند ۹۹۹۹ قرار گرفته. DevTools را باز کن و عدد ۹۹۹۹ را نشان بده. بگو: «عدد بزرگ است و باخته، چون در گروه پایین است.»

«راه‌حل این نیست که ۹۹۹۹ را بکنیم ۹۹۹۹۹. راه‌حل این است که عدد را به پدری بدهیم که باید نسبت به پدرهای دیگر رو باشد. اگر منو زیر هدر می‌رود، `z-index` را روی خود والد منو تنظیم کنید، نه فقط روی لینک داخل منو.»

یک سطح ثابت پیشنهاد کن و روی برد بنویس. این قرارداد کلاس است، نه قانون مرورگر:

| لایه | عدد پیشنهادی |
|------|----------------|
| محتوای عادی positioned | ۱ |
| منوی بازشونده | ۱۰ |
| هدر چسبان | ۱۰۰ |
| پنجرهٔ گفتگو | ۱۰۰۰ |

«بین این سطح‌ها جا برای استثنا می‌ماند. `99999` این فاصله را نابود می‌کند و نفر بعدی هیچ چاره‌ای جز عدد بزرگ‌تر ندارد.»

### سؤال کلاسی

- «فرزند با `z-index: 9999` داخل پدری با `z-index: 1`، با برادرهای بیرون از آن پدر مقایسه می‌شود؟»  
  **پاسخ:** نه. فقط داخل گروه پدرش بالا و پایین می‌رود. برای رقابت با بیرون، باید خود پدر عدد مناسب بگیرد.

- «چرا `opacity: 0.99` روی یک پدر گاهی ترتیب را عجیب می‌کند؟»  
  **پاسخ:** چون opacity کمتر از ۱ یک گروه لایهٔ تازه می‌سازد و فرزندان داخل همان گروه حبس می‌شوند.

### اشتباهات رایج

- مسابقهٔ عددهای بی‌حساب مثل `99999`.  
- بزرگ کردن z-index فرزند وقتی پدر در گروه پایین است.  
- `transform: scale(1)` یا شفافیت جزئی روی پدر، بدون اینکه بدانیم گروه تازه ساخته‌ایم. اگر در پروژه کسی transform گذاشته و لایه خراب شده، همین را نشان بده و transform را بردار تا گروه اضافی برود.

## ۷) پروژه کوچک جلسه — لایهٔ تیره و جعبهٔ پیام

خواستهٔ سوم را با همان قرارداد اعداد بساز. لازم نیست JavaScript دکمهٔ بستن باشد؛ صفحهٔ استاتیک کافی است.

### Live Coding مرحله‌به‌مرحله

۱) HTML، ترجیحاً انتهای `body`:

```html
<div class="backdrop"></div>
<div class="modal">
  <div class="panel">
    <h2>پیام ثبت شد</h2>
    <p>سفارش شما ذخیره شد. این جعبه باید روی لایه تیره باشد.</p>
  </div>
</div>
```

۲) CSS:

```css
.backdrop {
  position: fixed;
  inset: 0;
  background: rgb(0 0 0 / 0.5);
  z-index: 1000;
}

.modal {
  position: fixed;
  inset: 0;
  z-index: 1001;
  display: grid;
  place-items: center;
}

.panel {
  width: min(100% - 2rem, 24rem);
  background: #fff;
  color: #0f172a;
  padding: 1.5rem;
  border-radius: 0.5rem;
}
```

«`inset: 0` خلاصهٔ همان چهار لبه است: بالا، راست، پایین و چپ، همه صفر. لایهٔ تیره و لایهٔ پنجره هر دو به پنجرهٔ مرورگر چسبیده‌اند، چون `fixed` هستند. این همان خواسته‌ای است که درس قبل گفتیم: پوشش باید کل دید را بگیرد، نه داخل یک کارت.

عدد ۱۰۰۰ و ۱۰۰۱ هر دو در سطح «پنجرهٔ گفتگو» هستند. لایهٔ تیره ۱۰۰۰ است و جعبه یکی بالاتر، ۱۰۰۱. اگر هدر چسبان شما ۱۰۰ باشد، هر دو روی هدر می‌مانند.

`display: grid` و `place-items: center` فقط جعبهٔ سفید را وسط همین لایه می‌آورند. اگر grid را هنوز درس نداده‌اید، بگویید این دو خط برای وسط‌چین کردن است و وارد جزئیات grid نشوید. جایگزین ساده: به `.panel` حاشیهٔ بالا بدهید تا تقریبی وسط دیده شود، و همان را قبول کنید.

خود `.panel` لازم نیست z-index جدا داشته باشد، چون داخل پدر ۱۰۰۱ است و پدر از لایهٔ تیره بالاتر است.»

**در مرورگر:** صفحهٔ پشت کمی تیره است و جعبهٔ سفید خواناست. موقتاً عدد `.modal` را `999` بگذار. جعبه می‌رود پشت تاریکی و متن عملاً گم می‌شود. برگردان به ۱۰۰۱. این خراب کردن عمدی، همان خواستهٔ سوم است.

اگر `inset` در مرورگر کلاس پشتیبانی نشد، چهار ویژگی `top/right/bottom/left: 0` را بنویس. نتیجه همان است.

### سؤال کلاسی

- «چرا لایهٔ تیره `fixed` است نه `absolute` داخل مقاله؟»  
  **پاسخ:** چون باید کل پنجرهٔ دید را بپوشاند و با اسکرول نرود.

- «اگر هر دو را ۱۰۰۰ بگذاریم چه می‌شود؟»  
  **پاسخ:** در عدد مساوی، آنکه در HTML دیرتر آمده رو می‌ماند. باز هم بهتر است عدد جعبه را یکی بالاتر بنویسیم تا به ترتیب تگ‌ها تکیه نکنیم.

## ۸) جمع‌بندی مدرس

۱. `z-index` روی عنصر static چه می‌کند؟  
   **پاسخ:** بی‌اثر است، مگر آن عنصر فرزند مستقیم flex یا grid باشد.

۲. عدد بزرگ‌تر یعنی چه؟  
   **پاسخ:** داخل همان گروه لایه، روی عدد کوچک‌تر رسم می‌شود.

۳. چرا فرزند ۹۹۹۹ ممکن است زیر یک عنصر با عدد ۱ برود؟  
   **پاسخ:** چون آن ۹۹۹۹ داخل گروه پدری است که خودش از پدر دیگر پایین‌تر است. باید عدد پدر را نسبت به پدرهای هم‌گروه درست کرد.

۴. برای بنر، مرجع نوار نوشته کدام بود؟  
   **پاسخ:** `.photo` با `position: relative`.

**پیام پایانی:**

«هدف این جلسه حفظ کردن یک عدد جادویی نبود. هدف این بود که بگویید کدام لایه باید رو باشد، عدد را فقط بین رقبا بنویسید، و وقتی عددی خیلی بزرگ هم باخت، به‌جای بزرگ‌تر کردنش بروید سراغ پدر و گروه لایه.»
