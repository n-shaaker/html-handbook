## ۱) شروع کلاس؛ اول بگو چه چیزی روی سایت می‌خواهیم

اول کلاس این‌طور شروع کن:

«بچه‌ها، تا اینجا هر عنصر در جریان عادی صفحه نشسته: یکی تمام می‌شود، بعدی از جایی که قبلی تمام کرده شروع می‌کند. برای ستون مقاله همین را می‌خواهیم.

چهار جای سایت این جریان کافی نیست.

خواسته اول: روی کارت دوره یک برچسب **«جدید»** یا **«۳۰٪»** بچسبد به گوشه. این برچسب نباید یک خط جدا زیر عنوان بسازد و کارت را بلند کند. باید روی خود کارت بنشیند، کمی هم بیرون گوشه بیاید.

خواسته دوم: گاهی یک جعبه را فقط کمی از جای عادی‌اش تکان می‌دهیم، مثلاً برای تأکید، ولی جای خالی‌اش باید بماند تا جعبهٔ بعدی نپرد بالا.

خواسته سوم: داخل یک فهرست بلند میوه و سبزی، عنوان گروه هنگام اسکرول به بالای همان فهرست بچسبد تا یادمان نرود الان داخل کدام گروه‌ایم. هدر خود سایت هم گاهی همین رفتار را می‌خواهد.

خواسته چهارم: دکمهٔ **برو بالای صفحه** گوشهٔ پنجره بماند. هر قدر صفحه را پایین ببریم، دکمه همان‌جا باشد.

حالا اگر فقط بنویسیم:

```css
.badge {
  top: -10px;
  left: -10px;
}
```

برچسب تکان نمی‌خورد. `top` و `left` فاصله از یک مرجع‌اند. تا وقتی نگفته‌ایم مرجع چیست، مرورگر این فاصله را اعمال نمی‌کند. ویژگی‌ای که مرجع را انتخاب می‌کند `position` است.»

فایل زنده (پیشنهاد: `تدریس/live/03-position.html`) را با `lang="fa"` و `dir="rtl"` باز کن. پس‌زمینهٔ ساده بده تا جعبه‌ها دیده شوند.

«امروز پنج مقدار را با همین چهار خواسته یکی‌یکی می‌بینیم: `static`، `relative`، `absolute`، `sticky`، `fixed`. عدد `z-index` را درس بعد تنظیم می‌کنیم. اگر چیزی رفت زیر چیز دیگر، فقط یادتان بماند لایه‌اش مانده برای جلسهٔ بعد.»

## ۲) static؛ حالتی که top در آن بی‌اثر است

بگو:

«مقدار پیش‌فرض `position` برابر `static` است. یعنی عنصر در جریان عادی می‌ماند. در این حالت `top`، `right`، `bottom`، `left` و حتی `z-index` اثری ندارند. عنصر قرار نیست از جایش جدا شود، پس فاصله از لبه معنا ندارد.»

یک جعبهٔ معمولی بگذار و موقتاً فقط `top: 40px` بده، بدون `position`:

```html
<div class="box ghost">من هنوز static هستم</div>
```

```css
.box {
  background: #e7f5ff;
  border: 1px solid #1a5fb4;
  padding: 8px;
  margin-bottom: 6px;
  width: 260px;
}

.ghost {
  top: 40px;
}
```

**در مرورگر:** جعبه سر جایش است. در DevTools قانون `top` را نشان بده؛ ممکن است نوشته شده باشد ولی روی static اعمال نشود. این لحظه را نگه دار: «کد هست، اثر نیست، چون مرجع را انتخاب نکرده‌ایم.»

### سؤال کلاسی

- «چرا `top: 40px` به‌تنهایی جعبه را پایین نبرد؟»  
  **پاسخ:** عنصر هنوز `static` است و ویژگی‌های جابه‌جایی روی static اثر ندارند.

## ۳) relative؛ تکان نسبت به جای خودمان

«خواستهٔ دوم: جعبه را نسبت به همان جایی که در جریان داشته کمی جابه‌جا کنیم، و جای اولیه‌اش خالی بماند تا بعدی‌ها تکان نخورند.»

```html
<div class="box">جعبه معمولی</div>
<div class="box moved">جعبه relative (جابه‌جا شده)</div>
<div class="box">جعبه معمولی بعدی</div>
```

```css
.moved {
  position: relative;
  top: 15px;
  right: 40px;
  background: #ffe3e3;
  border-color: #c92a2a;
}
```

«`position: relative` یعنی مرجع، همان جای عادی خود این عنصر است.

`top: 15px` یعنی نسبت به آن جای عادی، ۱۵ پیکسل به سمت پایین برو. `top` فاصله از لبهٔ بالا را زیاد می‌کند، پس عنصر پایین می‌آید.

`right: 40px` یعنی از لبهٔ راستِ جای اصلی ۴۰ پیکسل فاصله بگیر. پس جعبه به سمت چپ می‌رود.

صفحهٔ ما `dir="rtl"` است. این جهت، معنی فیزیکی `left` و `right` را عوض نمی‌کند. راست همچنان راست صفحه است. اگر کسی انتظار دارد در فارسی `right` یعنی «به سمت ابتدای خط»، این انتظار با این ویژگی جور نیست. `left` و `right` سمت فیزیکی‌اند.»

**در مرورگر:** جعبهٔ قرمز پایین‌تر و به سمت چپ جای اولیه‌اش است. بین جعبهٔ اول و سوم یک فضای خالی می‌ماند، تقریباً هم‌قد جایی که جعبهٔ قرمز *قبلاً* اشغال کرده بود. جعبهٔ سوم بالا نمی‌پرد. خود قرمز روی آن فضای خالی و کمی هم روی همسایه می‌افتد.

«جای اولیه را مثل یک صندلی رزروشده حساب کنید. صاحب صندلی کمی آن‌طرف‌تر ایستاده، ولی صندلی را برنداشته‌ایم. عنصر بعدی هنوز بعد از آن صندلی می‌نشیند.»

`top` را لحظه‌ای صفر کن و دوباره ۱۵ بگذار تا جهت برایشان قطعی شود.

### سؤال کلاسی

- «`top: 15px` روی relative جعبه را به کدام سمت می‌برد؟»  
  **پاسخ:** ۱۵ پیکسل پایین‌تر از جای عادی.

- «اگر `position: relative` را پاک کنیم و `top` و `right` بمانند، چه می‌شود؟»  
  **پاسخ:** عنصر برمی‌گردد به static و آن دو فاصله بی‌اثر می‌شوند. جای خالی اضافه هم جمع می‌شود.

- «در صفحهٔ راست‌چین، `right: 40px` جعبه را به راست می‌برد یا به چپ؟»  
  **پاسخ:** به چپ. از لبهٔ راستِ جای اصلی فاصله می‌گیرد. `dir="rtl"` این معنی را عوض نمی‌کند.

### اشتباهات رایج

- تصور اینکه `right` در فارسی «سمت شروع خط» است.  
- انتظار اینکه با relative، عنصرهای بعدی بیایند جای خالی را پر کنند. جای اولیه می‌ماند.

## ۴) absolute؛ برچسب روی گوشهٔ کارت

«خواستهٔ اول فروشگاه این است. برچسب نباید در جریان کارت یک ردیف بسازد. باید از جریان خارج شود و نسبت به خود کارت سنجیده شود.»

الگو را قبل از کد به زبان ساده بگو:

«پدر را `relative` می‌کنیم تا بشود مرجع. فرزند را `absolute` می‌کنیم تا از جریان بیرون برود. بعد `top` و `left` را نسبت به همان پدر می‌دهیم.»

```html
<div class="card">
  <span class="badge">جدید</span>
  <strong>دوره CSS مقدماتی</strong>
  <p>برچسب «جدید» با absolute روی گوشه کارت نشسته است.</p>
</div>
```

```css
.card {
  position: relative;
  width: 220px;
  background: #fff;
  border: 1px solid #cfd8e3;
  border-radius: 8px;
  padding: 14px;
  margin: 28px 16px 16px;
}

.badge {
  position: absolute;
  top: -10px;
  left: -10px;
  background: #2b8a3e;
  color: #fff;
  font-size: 12px;
  padding: 2px 10px;
  border-radius: 12px;
}
```

«`top: -10px` یعنی لبهٔ بالای برچسب ۱۰ پیکسل بالاتر از لبهٔ بالای کارت باشد. عدد منفی برچسب را از کارت بیرون می‌زند، روی گوشه. `left: -10px` همین کار را نسبت به لبهٔ چپ فیزیکی می‌کند.

چون برچسب absolute است، از جریان خارج شده. عنوان و پاراگراف انگار برچسب آنجا نیست؛ جایش را خالی نمی‌گذارند. ارتفاع کارت را متن تعیین می‌کند، نه برچسب.»

**در مرورگر:** برچسب سبز کمی بیرون گوشهٔ چپ بالای کارت است. عنوان از زیر آن شروع نمی‌شود به شکل یک خط اضافه؛ متن کارت سر جای عادی خودش است.

حالا پدر را عمداً خراب کن: `position: relative` را از `.card` بردار.

**در مرورگر:** برچسب می‌پرد به گوشه‌ای دور، اغلب نسبت به صفحه، چون دیگر جدِّ نزدیکِ غیر static ندارد. جزوه می‌گوید مرجع absolute نزدیک‌ترین جدی است که `position` آن `static` نباشد. اگر چنین جدی نباشد، مرجع صفحه است.

`relative` را برگردان تا برچسب برگردد سر کارت. این خراب‌و‌درست کردن از خود کد مهم‌تر است.

«`relative` روی پدر اینجا برای جابه‌جا کردن خود کارت نیست. `top` به پدر نداده‌ایم. فقط او را «مرجع» کرده‌ایم. این رایج‌ترین استفادهٔ relative در کارت محصول است.»

کارت دوم را با کلاس اضافه بگذار تا ببینند همان مکان، رنگ دیگر:

```html
<div class="card">
  <span class="badge sale">۳۰٪</span>
  <strong>کتاب HTML</strong>
  <p>همان مکان؛ فقط رنگ فروش.</p>
</div>
```

```css
.badge.sale {
  background: #e8590c;
}
```

**در مرورگر:** دو کارت، دو برچسب، هر کدام نسبت به پدر خودش. اگر کارت‌ها را جابه‌جا کنید، برچسب با کارت می‌رود، چون مرجعش کارت است نه پنجره.

### سؤال کلاسی

- «اگر `.card` را relative نکنیم، برچسب نسبت به چه چیزی سنجیده می‌شود؟»  
  **پاسخ:** نزدیک‌ترین جد غیر static، و اگر هیچ‌کدام نباشد، صفحه.

- «آیا برچسب absolute ارتفاع کارت را زیاد می‌کند؟»  
  **پاسخ:** نه. از جریان خارج است و جایش برای بقیه خالی نمی‌ماند.

- «چرا روی پدر `position: relative` گذاشتیم ولی `top` ندادیم؟»  
  **پاسخ:** تا مرجع فرزند شود، بدون اینکه خود کارت از جای عادی‌اش تکان بخورد.

### اشتباهات رایج

- `absolute` روی فرزند بدون `relative` روی همان پدری که باید مرجع باشد. برچسب به جد دور یا صفحه می‌چسبد.  
- انتظار اینکه `left` در صفحهٔ راست‌چین خودش به راست برود. برای گوشهٔ راست فیزیکی باید `right` را تنظیم کنید.

## ۵) sticky؛ عنوانی که داخل محدودهٔ والد می‌چسبد

«خواستهٔ سوم: هنگام اسکرول، عنوان گروه به لبه بچسبد، ولی فقط تا وقتی داخل همان ناحیه هستیم. این رفتار ترکیبی است. تا قبل از رسیدن به آستانه مثل relative در جریان می‌ماند. بعد از آن، داخل محدودهٔ والد به لبه‌ای که گفتیم می‌چسبد.»

```html
<div class="scroll-area">
  <h4 class="sticky-title">میوه‌ها</h4>
  <p>سیب</p>
  <p>پرتقال</p>
  <p>موز</p>
  <p>انار</p>
  <h4 class="sticky-title">سبزیجات</h4>
  <p>هویج</p>
  <p>کاهو</p>
  <p>خیار</p>
  <p>گوجه</p>
</div>
```

```css
.scroll-area {
  height: 170px;
  overflow: auto;
  border: 1px solid #adb5bd;
  background: #fff;
  padding: 0 10px;
}

.sticky-title {
  position: sticky;
  top: 0;
  margin: 0;
  background: #1a3a5c;
  color: #fff;
  padding: 4px 8px;
}
```

«`overflow: auto` و ارتفاع محدود را گذاشتیم تا همین جعبه اسکرول بخورد و مجبور نشویم کل صفحه را بلند کنیم. `position: sticky` و `top: 0` یعنی وقتی عنوان به لبهٔ بالای این ناحیهٔ اسکرول رسید، همان‌جا بچسبد.

بدون `top` یا `bottom` چسبیدن شروع نمی‌شود. خود کلمهٔ sticky آستانه ندارد؛ آستانه را آن فاصله تعیین می‌کند.»

**در مرورگر:** داخل جعبه اسکرول کن. «میوه‌ها» می‌چسبد. با رسیدن به سبزیجات، عنوان بعدی جایش را می‌گیرد. پس از تمام شدن محتوا، عنوان با انتهای والد می‌رود و به پنجرهٔ مرورگر نچسبیده می‌ماند.

حالا `top: 0` را موقتاً حذف کن.

**در مرورگر:** عنوان با بقیه اسکرول می‌شود و نمی‌چسبد. برگردان.

«سه دلیل رایج که دانشجو می‌گوید sticky خراب است:

اول، `top` یا `bottom` را ننوشته.

دوم، یکی از جدها `overflow` غیر از `visible` دارد و چسبیدن داخل همان جعبه اتفاق می‌افتد، نه لزوماً نسبت به کل صفحه. در مثال ما این عمدی است: ظرف اسکرول همان `.scroll-area` است.

سوم، پدر هم‌قد خود عنوان است. اگر پدر فقط به اندازهٔ همان یک خط باشد، محدوده‌ای نمی‌ماند که عنوان داخلش بلغزد و بچسبد. پدر باید از فرزند بلندتر باشد؛ این فهرست بلند همان پدر است.»

برای هدر سایت فقط اشاره کن، جداگانه نساز اگر وقت کم است:

«الگوی `header { position: sticky; top: 0; }` همین است، به شرطی که اسکرول مال خود صفحه باشد و یک جد با overflow پنهان، هدر را داخل جعبهٔ کوتاه حبس نکرده باشد.»

### سؤال کلاسی

- «sticky بدون `top` می‌چسبد؟»  
  **پاسخ:** نه. باید `top` یا `bottom` (یا آستانهٔ مشابه) معلوم باشد.

- «چرا در این مثال عنوان به پنجرهٔ کل مرورگر نچسبید و داخل جعبه ماند؟»  
  **پاسخ:** محدودهٔ چسبیدن، ناحیهٔ اسکرول والد است. والد ارتفاع محدود و `overflow: auto` دارد.

### اشتباهات رایج

- sticky بدون آستانه.  
- پدر کوتاه، هم‌قد خود عنوان. جایی برای چسبیدن نمی‌ماند.  
- `overflow: hidden` روی یک جد، و انتظار چسبیدن نسبت به کل صفحه. جزئیات overflow درس پنجم است؛ اینجا فقط اسم دلیل را بگو.

## ۶) fixed؛ دکمه نسبت به پنجره

«خواستهٔ چهارم: دکمه هنگام اسکرول صفحه همان گوشه بماند. مرجع این یکی پنجرهٔ مرورگر است، نه کارت و نه جای عادی.»

صفحه را با چند پاراگراف بلند کن تا اسکرول واقعی داشته باشی. بعد:

```html
<a class="to-top" href="#top">↑</a>
```

روی `body` یا یک عنوان بالا `id="top"` بگذار تا لینک مقصد داشته باشد.

```css
.to-top {
  position: fixed;
  bottom: 20px;
  left: 20px;
  width: 44px;
  height: 44px;
  line-height: 44px;
  text-align: center;
  background: #0b6e4f;
  color: #fff;
  text-decoration: none;
  border-radius: 50%;
}
```

«`bottom: 20px` و `left: 20px` فاصله از لبهٔ پایین و چپ **پنجره** است، نه لبهٔ مقاله. برای همین با اسکرول تکان نمی‌خورد.

مثل absolute از جریان خارج است. جایی در بین پاراگراف‌ها برایش رزرو نمی‌شود. روی محتوای زیر خودش قرار می‌گیرد. اگر دکمه رفت زیر یک لایهٔ دیگر، درس بعد با `z-index` ترتیب را درست می‌کنیم.»

**در مرورگر:** صفحه را بالا و پایین کن. دایرهٔ سبز گوشهٔ چپ پایین ثابت است. در RTL هم `left: 20px` همچنان چپ فیزیکی است، همان گوشه‌ای که جزوه نشان می‌دهد.

«فرق sticky و fixed را با یک جمله تمام کن:

fixed به پنجره چسبیده و از جریان بیرون است.

sticky تا آستانه در جریان می‌ماند، بعد داخل محدودهٔ والد می‌چسبد، و جای اولیه‌اش در جریان حفظ می‌شود.»

یک هشدار عملی، بدون ساختن هدر کامل اگر وقت کم است. اگر ساختی، این را نشان بده:

«اگر هدر را `fixed` کنید، از جریان خارج می‌شود و اول صفحه می‌رود زیر هدر. باید به `body` به اندازهٔ ارتفاع هدر `padding-top` بدهید تا خط اول دیده شود. sticky این مشکل را ندارد، چون جای خودش را در جریان نگه می‌دارد.»

اگر هدر fixed را زنده می‌سازی، ارتفاع را حدود ۵۶ پیکسل بگیر و `padding-top: 56px` را روی body بگذار و بردار تا قایم شدن عنوان دیده شود.

### سؤال کلاسی

- «دکمهٔ برو بالا با اسکرول صفحه حرکت می‌کند؟»  
  **پاسخ:** نه. `position: fixed` مرجعش پنجره است.

- «بین fixed و sticky کدام یک جای خودش را در جریان صفحه نگه می‌دارد؟»  
  **پاسخ:** sticky. fixed از جریان خارج می‌شود و روی محتوا می‌افتد.

### اشتباهات رایج

- fixed کردن هدر و فراموش کردن `padding-top` برای محتوای زیر آن.  
- استفاده از fixed برای برچسب کارت. برچسب باید با کارت برود، پس مرجعش کارت است و absolute، نه پنجره.

## ۷) پروژه کوچک جلسه — دو کارت و یک دکمه

### Live Coding مرحله‌به‌مرحله

۱) دو کارت درس را کنار توضیح نگه دار: یکی «جدید»، یکی «۳۰٪».

۲) مطمئن شو هر `.card` خودش `position: relative` دارد و برچسب‌ها `absolute` هستند.

۳) لینک `.to-top` با `fixed` گوشه بماند.

۴) یک جملهٔ آزمایش: کارت‌ها را داخل همان `.post` درس قبل با `max-width` بگذار تا دانشجو ببیند position جریان عرض را لغو نمی‌کند. کارت هنوز در ستون است؛ فقط برچسب نسبت به کارت سنجیده می‌شود.

**در مرورگر:** اسکرول کن، دکمه ثابت بماند. برچسب‌ها با کارت‌هایشان بمانند و به دکمهٔ fixed نچسبند. اگر برچسب زیر دکمه رفت، بگو ترتیب لایه‌ها درس بعد است و امروز با جابه‌جا کردن مکان دکمه از روی کارت، تداخل را موقتاً کنار بگذار.

### سؤال کلاسی

- «مرجع برچسب کارت کدام عنصر است و مرجع دکمهٔ برو بالا کدام؟»  
  **پاسخ:** مرجع برچسب، کارت relative است. مرجع دکمه، پنجره است.

## ۸) جمع‌بندی مدرس

جدول را یک بار از روی خواسته بپرس، نه از روی حفظ اسم:

| خواسته | مقدار |
|--------|--------|
| بماند در جریان؛ top اثر نکند | `static` |
| کمی نسبت به جای خودش برود و صندلی‌اش خالی بماند | `relative` |
| برچسب گوشه، بیرون از جریان، نسبت به پدر | `absolute` با پدر `relative` |
| عنوان بچسبد داخل اسکرول والد | `sticky` با `top` |
| دکمه بچسبد به پنجره | `fixed` |

۱. مرجع absolute چیست؟  
   **پاسخ:** نزدیک‌ترین جد که position آن static نباشد. اگر نباشد، صفحه.

۲. relative با جریان صفحه چه می‌کند؟  
   **پاسخ:** عنصر دیده جابه‌جا می‌شود، ولی جای اولیه در جریان می‌ماند و بعدی‌ها نمی‌پرند بالا.

۳. فرق fixed و sticky؟  
   **پاسخ:** fixed به پنجره چسبیده و از جریان خارج است. sticky داخل محدودهٔ والد و بعد از رسیدن به `top` یا `bottom` می‌چسبد و جای جریان را نگه می‌دارد.

**پیام پایانی:**

«هدف این جلسه پنج تعریف پشت سر هم نبود. هدف این بود که برای برچسب گوشه، پدر را مرجع کنید، برای دکمهٔ شناور مرجع را پنجره بگیرید، و بدانید بدون انتخاب `position`، نوشتن `top` هیچ خواسته‌ای را برآورده نمی‌کند.»

## تمرین‌ها (ساده → چالشی)

### ساده

۱. جعبهٔ `.moved` را یک بار با `top: 0` و `right: 0` ببین، بعد `top: 15px` و `right: 40px`. جای خالی بین همسایه‌ها را توصیف کن.  
۲. برچسب کارت را از `left: -10px` به `right: -10px` عوض کن و بگو حالا روی کدام گوشهٔ فیزیکی نشسته.

### متوسط

۳. عنوان sticky را بدون `top` ذخیره کن و اسکرول کن. بعد `top: 0` را برگردان و فرق را بنویس.  
۴. برای برچسب «جدید» روی کاغذ بنویس مرجع (containing block) کدام عنصر است، و اگر relative پدر پاک شود مرجع بعدی چیست.

### چالشی

۵. کارت و برچسب absolute را بدون `overflow: hidden` نگه دار و ببین برچسبِ بیرون‌زده از گوشه هنوز دیده می‌شود. یک جمله بنویس: اگر بعداً روی کارت `overflow: hidden` بگذاریم، این گوشه چه خطری دارد. خود overflow درس پنجم است؛ امروز فقط پیش‌بینی کن.  
۶. توضیح بده چرا لایهٔ تیرهٔ پشت یک پنجرهٔ گفتگو را معمولاً `position: fixed` می‌کنند تا کل پنجرهٔ دید را بپوشاند، نه `absolute` داخل یک کارت کوچک.
