## ۱) شروع کلاس؛ اول بگو چه چیزی روی سایت می‌خواهیم

اول کلاس این‌طور شروع کن:

«بچه‌ها، دوره مقدماتی را تمام کرده‌ایم. می‌دانیم جعبه چیست، margin و padding چیست، و عرض را چطور می‌نویسیم.

امروز هنوز سراغ ویژگی تازه‌ای به اسم Flex نمی‌رویم. اول یک سؤال ساده‌تر: وقتی در یک صفحه واقعی چند تکه کنار هم یا زیر هم می‌نشینند، مرورگر از کجا تصمیم می‌گیرد؟

سه چیزی را که روی سایت‌های واقعی می‌خواهیم با هم ببینیم.»

روی برد سه خواسته را بنویس. هنوز CSS ننویس.

«خواسته اول: صفحه **ثبت‌نام**. دو دکمه داریم: «ارسال» و «انصراف». روی موبایل می‌خواهیم هر دکمه **یک ردیف کامل** باشد تا انگشت راحت به آن برسد.

خواسته دوم: بالای لیست محصولات چند **برچسب فیلتر** داریم: رایگان، جدید، تخفیف. می‌خواهیم در **همان خط** کنار هم بنشینند، مثل کلمات یک جمله.

خواسته سوم: یک بنر «جشنواره تمام شد» را می‌خواهیم **کاملاً از صفحه برداریم** تا جای خالی‌اش هم نماند. گاهی هم فقط می‌خواهیم چیزی دیده نشود ولی **جایش خالی بماند** تا بقیه تکان نخورند.

تا وقتی این سه خواسته را نگفته‌ایم، `display` فقط یک کلمه در جزوه است. حالا برویم سراغ اینکه مرورگر همین خواسته‌ها را با چه نوع جعبه‌ای می‌سازد.»

فایل زنده را باز کن (پیشنهاد: `تدریس/live/01-display.html`):

```html
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Live — نمایش</title>
  <style>
    body {
      font-family: Tahoma, sans-serif;
      padding: 1.5rem;
      background: #f1f5f9;
    }
  </style>
</head>
<body>
  <button type="button">ارسال</button>
  <button type="button">انصراف</button>
</body>
</html>
```

بعد بگو:

«همون‌طور که می‌بینید، هنوز هیچ `display`ای ننوشته‌ایم. دو دکمه کنار هم‌اند. این رفتار پیش‌فرض خود دکمه‌هاست. امروز یاد می‌گیریم کی این رفتار را عوض کنیم و کی دست به آن نزنیم.»

**در مرورگر:** دو دکمه در یک خط. عرض را کم کن؛ اگر جا کم شود ممکن است بشکنند و بروند خط بعد، ولی هر کدام تمام عرض والد را نمی‌گیرند.

## ۲) مفهوم؛ display یعنی چه نوع جعبه‌ای

بگو:

«ویژگی `display` به مرورگر می‌گوید برای این عنصر **چه مدل جعبه‌ای** بساز و آن جعبه در جریان عادی صفحه کنار بقیه چطور بنشیند.

HTML از قبل یک مقدار پیش‌فرض دارد. `div` و `p` و تیترها معمولاً block هستند. `span` و `a` و `strong` معمولاً inline هستند.

وقتی در CSS می‌نویسیم `display: block`، **معنی تگ در HTML عوض نمی‌شود**. یک لینک که block شده هنوز لینک است؛ صفحه‌خوان هنوز آن را لینک می‌داند؛ فقط جعبهٔ نمایشی‌اش مثل یک ردیف کامل جا می‌گیرد.»

این جمله را روی برد نگه دار:

«`display` ظاهر و جای جعبه را عوض می‌کند، نه نقش تگ را.»

### سؤال کلاسی

- «اگر به یک `a` بگوییم `display: block`، آیا هنوز می‌شود روی آن کلیک کرد و به آدرس رفت؟»  
  **پاسخ:** بله. فقط شکل جعبه عوض شده. لینک، لینک می‌ماند.

## ۳) Live — block و inline را کنار هم ببینیم

«قبل از اینکه دکمه‌های فرم را تمام‌عرض کنیم، دو جعبهٔ آشنا را زنده ببینیم تا زبان مشترک داشته باشیم.»

HTML را داخل همان صفحه اضافه کن:

```html
<div class="box-block">من یک div هستم (block)</div>
<div class="box-block">من هم div هستم؛ زیر قبلی آمدم</div>
<span class="box-inline">من span هستم</span>
<span class="box-inline">من هم span هستم؛ کنار قبلی نشستم</span>
```

CSS را آرام تایپ کن و هر قانون را بلند بخوان:

```css
.box-block {
  background-color: #ffe8cc;
  border: 1px solid #f08c00;
  padding: 6px 10px;
  margin: 4px 0;
}

.box-inline {
  background-color: #d3f9d8;
  border: 1px solid #2b8a3e;
  padding: 2px 8px;
}
```

«به div هیچ `display`ای ندادیم، چون پیش‌فرضش block است. از خط تازه شروع می‌شود و عرض در دسترس والد را می‌گیرد. به span هم `display` ندادیم؛ پیش‌فرضش inline است و فقط به اندازه متنش جا می‌گیرد.»

**در مرورگر:** دو نوار نارنجی زیر هم، تمام عرض ناحیه. دو تراشه سبز در یک خط.

جدول جزوه را با همین تصویر پر کن. حفظ کردنش لازم نیست؛ باید بتواند از روی صفحه بگوید:

| | block | inline |
|---|--------|--------|
| شروع | خط تازه | همان خط |
| عرض | عرض در دسترس والد | به اندازه محتوا |
| `width` و `height` | اثر دارند | روی inline خالص اثر ندارند |
| margin بالا و پایین | عنصر بعدی را هل می‌دهد | جای خط را عوض نمی‌کند |

بلافاصله روی span این را امتحان کن و نتیجه را قبل از refresh حدس بگیرند:

```css
.box-inline {
  width: 200px;
  height: 80px;
}
```

«عرض و ارتفاع را نوشتیم، اما جعبه سبز به اندازه متن مانده. مرورگر قانون را «پاک نکرده»؛ نوع جعبه inline اجازه نمی‌دهد `width` و `height` همان اثری را بگذارند که روی div می‌گذارند.

پس اگر روی سایت برچسب فیلتر ساختید و `width` جواب نداد، اول بپرسید: این عنصر inline است؟»

### سؤال کلاسی

- «`p` بدون هیچ CSS چه `display`ای دارد؟»  
  **پاسخ:** `block`.

- «اگر فقط `width: 200px` روی span بگذاریم و تعجب کنیم که عرض عوض نشد، اشکال از واحد است یا از نوع جعبه؟»  
  **پاسخ:** از نوع جعبه. واحد درست است؛ inline خالص عرض را آن‌طور که انتظار داریم اعمال نمی‌کند.

### اشتباهات رایج

- دادن `width` به `span` یا `a` معمولی و انتظار یک جعبهٔ ۲۰۰ پیکسلی.  
- فکر کردن که اگر `display` را عوض کنیم، تگ از نظر HTML چیز دیگری می‌شود.

## ۴) دکمه و تصویر؛ inline هستند ولی مثل span نیستند

برگرد به دو دکمهٔ اول صفحه.

«بچه‌ها، `button` و `img` و `input` هم در جریان صفحه درون‌خطی‌اند؛ یعنی می‌توانند کنار متن بنشینند. اما از نوع **جایگزین‌شونده** هستند. برخلاف `span`، می‌شود به آن‌ها عرض و ارتفاع داد، حتی وقتی هنوز `display: inline` محاسبه‌شده دارند. رفتارشان به `inline-block` نزدیک است.»

روی دکمه این را نشان بده:

```css
button {
  width: 160px;
  height: 44px;
}
```

**در مرورگر:** عرض دکمه واقعاً ۱۶۰ پیکسل می‌شود، در حالی که همان `width` روی span سبز اثر مورد انتظار را نداشت.

«حالا خواستهٔ فرم موبایل را پیاده کنیم: هر دکمه یک ردیف کامل.»

```css
button {
  display: block;
  width: 100%;
  margin-bottom: 8px;
}
```

**در مرورگر:** «ارسال» تمام عرض را می‌گیرد و «انصراف» می‌رود خط بعد. این باگ نیست؛ خودمان نوع جعبه را block کردیم.

«روی دسکتاپ شاید بخواهیم دکمه‌ها کنار هم بمانند. پس `display: block` و `width: 100%` را همه‌جا کورکورانه نگذارید. این الگو برای فرم موبایل و برای وقتی است که واقعاً یک ردیف کامل می‌خواهید.»

### سؤال کلاسی

- «چرا `width` روی `button` اثر داشت ولی روی `span` نه؟»  
  **پاسخ:** دکمه عنصر جایگزین‌شونده است و عرض می‌پذیرد. `span` خالص inline است.

## ۵) خواستهٔ دوم؛ منوی افقی

«حالا فهرست را ببینیم. در فروشگاه و در هدر ساده، لینک‌ها را در یک ردیف می‌خواهیم: خانه، محصولات، درباره ما، تماس.

اگر فقط `ul` و `li` بنویسیم، هر آیتم زیر قبلی می‌آید. چون `li` پیش‌فرضش `list-item` است و از نظر چیدمان مثل block رفتار می‌کند: خط تازه.»

```html
<ul class="menu-inline">
  <li><a href="#">خانه</a></li>
  <li><a href="#">محصولات</a></li>
  <li><a href="#">درباره ما</a></li>
  <li><a href="#">تماس</a></li>
</ul>
```

اول بدون CSS نشان بده: چهار آیتم زیر هم، با نقطهٔ فهرست.

بعد:

```css
.menu-inline {
  margin: 0;
  padding: 0;
}

.menu-inline li {
  display: inline;
  margin-left: 16px;
}
```

«`margin: 0` و `padding: 0` فاصلهٔ پیش‌فرض خود فهرست را برمی‌دارد تا منو به لبه نچسبد به شکل پیش‌فرض مرورگر.

`display: inline` روی `li` یعنی: دیگر یک ردیف کامل نباش؛ در همان خط بنشین.

`margin-left: 16px` در صفحهٔ راست‌چین فاصله را سمت چپ هر آیتم می‌گذارد، یعنی بین این آیتم و آیتم بعدی.»

**در مرورگر:** چهار لینک در یک ردیف. نقطهٔ فهرست هم با inline شدن معمولاً می‌رود، چون نشانگر list-item به این حالت وصل است. اگر جایی ماند، بگو بعداً با `list-style` جمعش می‌کنیم؛ امروز موضوع ما نوع جعبه است.

«این منو برای فهم inline کافی است. روش امروزی ردیف‌کردن لینک‌ها Flex است و در ماژول Flexbox می‌آید. اگر امروز همه‌چیز را با inline حل کنید، فاصلهٔ عمودی و وسط‌چین کردنشان دردسر دارد. این محدودیت را عمداً ببینید، پاکش نکنید.»

### سؤال کلاسی

- «اگر `display: inline` را روی `ul` بگذاریم و روی `li` نگذاریم، آیا آیتم‌ها کنار هم می‌آیند؟»  
  **پاسخ:** نه. خود `li`ها هنوز list-item هستند و زیر هم می‌مانند. باید همان عنصری را عوض کنیم که ردیف شده است.

### اشتباهات رایج

- inline کردن `ul` به‌جای `li`.  
- فراموش کردن صفر کردن `padding` فهرست و فکر کردن که «منو چسبیده چون inline خراب است».

## ۶) برعکس؛ یک span را مثل ردیف کامل کن

«گاهی خواسته برعکس است. اطلاعات دانشجو را داریم، ولی می‌خواهیم هر قلم در خط خودش باشد: نام، شهر، رشته. معنایشان تکهٔ متن است، پس `span` درست است؛ فقط جعبه را block می‌کنیم.»

```html
<p class="span-block">
  <span>نام: سارا</span>
  <span>شهر: شیراز</span>
  <span>رشته: طراحی وب</span>
</p>
```

```css
.span-block span {
  display: block;
  background-color: #e7f5ff;
  border-right: 4px solid #1a5fb4;
  padding: 4px 10px;
  margin-bottom: 4px;
}
```

**در مرورگر:** سه ردیف آبی زیر هم. هنوز در HTML سه `span` داخل یک پاراگراف‌اند.

حالا که block شده‌اند، عرض را دوباره امتحان کن:

```css
.span-block span {
  width: 50%;
}
```

**در مرورگر:** هر ردیف نصف عرض والد می‌شود. همان ویژگی‌ای که ده دقیقه پیش روی span سبز بی‌اثر بود.

### سؤال کلاسی

- «آیا با `display: block` این spanها تبدیل به `div` شده‌اند؟»  
  **پاسخ:** نه. تگ همان `span` است. فقط مدل جعبه block شده است.

## ۷) خواستهٔ سوم؛ برداشتن از صفحه یا فقط نامرئی کردن

«دو راه برای «نشان نده» داریم و نتیجه‌شان یکی نیست. روی سایت این فرق پول و جای خالی است.»

سه جعبه در یک ردیف. برای اینکه کنار هم بمانند، والد را فقط برای همین نمایش flex می‌کنیم و می‌گوییم عمق flex مال این درس نیست:

```html
<p>با display: none</p>
<div class="row-boxes">
  <div class="mini">۱</div>
  <div class="mini hide-none">۲</div>
  <div class="mini">۳</div>
</div>

<p>با visibility: hidden</p>
<div class="row-boxes">
  <div class="mini">۱</div>
  <div class="mini hide-hidden">۲</div>
  <div class="mini">۳</div>
</div>
```

```css
.row-boxes {
  display: flex;
  gap: 8px;
}

.mini {
  width: 48px;
  height: 48px;
  background: #dbe4ff;
  border: 1px solid #4c6ef5;
  text-align: center;
  line-height: 48px;
}

.hide-none {
  display: none;
}

.hide-hidden {
  visibility: hidden;
}
```

«ردیف اول: جعبهٔ ۲ با `display: none` از چیدمان حذف شده. نه دیده می‌شود، نه جا می‌گیرد. جعبهٔ ۳ می‌آید کنار ۱. معمولاً صفحه‌خوان هم آن را نمی‌خواند.

ردیف دوم: جعبهٔ ۲ با `visibility: hidden` نامرئی است، ولی جعبهٔ خالی‌اش سر جایش مانده. ۳ جابه‌جا نشده.»

**در مرورگر:** هر دو ردیف را کنار هم نگه دار. با DevTools روی جعبهٔ none کلیک کن و نشان بده در درخت هست، ولی Computed مقدار `display: none` است. بعد کلاس را لحظه‌ای بردار تا ۲ برگردد.

«کی کدام را می‌خواهیم؟

اگر بنر جشنواره تمام شده و باید از صفحه برود تا کارت‌ها بیایند بالا، `display: none`.

اگر جای یک ستون جدول باید خالی بماند تا ستون‌های دیگر نپرند، `visibility: hidden`.

`opacity: 0` هیچ‌کدام از این دو نیست. عنصر دیده نمی‌شود، جایش می‌ماند، و هنوز کلیک‌پذیر است. برای حذف واقعی از آن استفاده نکنید.»

یک دکمهٔ نامرئی با opacity بساز و روی ناحیه‌اش کلیک کن تا ببینند رویداد هنوز می‌رسد. لازم نیست انیمیشن بسازی.

### سؤال کلاسی

- «پنجرهٔ راهنما بسته است و نباید جا بگیرد. کدام را می‌نویسیم؟»  
  **پاسخ:** `display: none`.

- «می‌خواهیم فاصلهٔ جعبه بماند ولی محتوا دیده نشود. کدام؟»  
  **پاسخ:** `visibility: hidden`.

- «عنصری با `opacity: 0` آیا کلیک را می‌گیرد؟»  
  **پاسخ:** بله. جای عنصر هست و هنوز می‌توان روی آن کلیک کرد.

### اشتباهات رایج

- `visibility: hidden` برای «این بنر را از لایه‌بندی حذف کن». جای خالی می‌ماند.  
- `opacity: 0` برای بستن منو. منو دیده نمی‌شود ولی جلوی کلیک بقیه را می‌گیرد.  
- فراموش کردن که `display: none` معمولاً از دسترس‌پذیری هم پنهان می‌کند؛ اگر چیزی باید برای صفحه‌خوان بماند، این راه‌حل را با عجله انتخاب نکن. در این سطح فقط هشدار بده، وارد تکنیک‌های ARIA نشو.

## ۸) مقدارهایی که امروز فقط اسمشان را می‌شنویم

جدول جزوه را بخوان، بدون ساختن پروژهٔ Flex:

«`inline-block` یعنی در همان خط بنشین، ولی `width` و `height` را قبول کن. درس ۷ همین ماژول مال همین است. اگر امروز برچسب فیلتر را inline کردید و عرض نداد، آنجا کامل می‌شود.

`flex` یعنی فرزندان را در یک ردیف یا ستون با کنترل فاصله بچین. منوی حرفه‌ای و ردیف کارت‌ها آنجا هستند.

`grid` چیدمان دو بعدی است؛ اسکلت صفحه و گالری.

`none` را همین امروز برای حذف واقعی دیدیم: منوی بسته، پیام موقتی، آیتمی که نباید در چیدمان باشد.

اگر کسی پرسید چرا از همین حالا همه‌چیز را flex نمی‌کنیم: چون تا فرق block و inline را با چشم نبینید، flex مثل جادو به نظر می‌رسد و وقتی خراب شود نمی‌دانید جریان عادی چه بوده.»

## ۹) پروژه کوچک جلسه — نوار فیلتر محصول

دیگر مثال تازه نزن. همان سه خواستهٔ اول را در یک تکه جمع کن.

### Live Coding مرحله‌به‌مرحله

۱) HTML:

```html
<section class="filters">
  <h2>فیلتر محصولات</h2>
  <span class="tag">رایگان</span>
  <span class="tag">جدید</span>
  <span class="tag off">تمام‌شده</span>
  <button type="button" class="apply">اعمال فیلتر</button>
</section>
```

۲) CSS را خط‌به‌خط بگو چرا این‌طور است:

```css
.filters {
  background: #fff;
  padding: 1rem;
  border: 1px solid #e2e8f0;
}

.tag {
  display: inline-block; /* پیش‌نمایش درس ۷؛ اگر نخواهی، inline کافی است */
  margin-left: 8px;
  padding: 4px 10px;
  background: #d3f9d8;
  border-radius: 999px;
}

.tag.off {
  display: none; /* فیلتر غیرفعال؛ جایش هم نمی‌ماند */
}

.apply {
  display: block;
  width: 100%;
  margin-top: 12px;
  padding: 10px;
}
```

«برچسب‌ها در یک خط‌اند، چون inline هستند. برچسب «تمام‌شده» با `none` از نوار حذف شده. دکمهٔ اعمال، block و تمام‌عرض است؛ همان خواستهٔ فرم.

اگر بخواهید جای «تمام‌شده» خالی بماند، به‌جای `display: none` می‌نویسید `visibility: hidden`. هر دو را جلوی کلاس عوض کنید و تفاوت را ببینید.»

**در مرورگر:** DevTools را باز کن، عنصر `.tag.off` را انتخاب کن، در Computed مقدار `display` را نشان بده. بعد تیک `display: none` را بردار تا برچسب برگردد.

### سؤال کلاسی

- «چرا برای برچسب از `span` استفاده کردیم نه `div`؟»  
  **پاسخ:** برچسب تکهٔ کوتاه داخل یک خط است. اگر از اول `div` می‌گذاشتیم، هر کدام یک ردیف کامل می‌شد و باید دوباره display را عوض می‌کردیم.

## ۱۰) جمع‌بندی مدرس

قبل از تمرین این سه سؤال را بپرس. جواب را خودشان از صفحهٔ زنده بگویند.

۱. چرا `width` روی یک `span` معمولی اثر مورد انتظار را ندارد؟  
   **پاسخ:** چون inline خالص است. اول `display` را `block` یا `inline-block` کن، بعد عرض بده.

۲. فرق `display: none` و `visibility: hidden` چیست؟  
   **پاسخ:** `none` عنصر را از چیدمان برمی‌دارد و جایش نمی‌ماند. `hidden` فقط نامرئی می‌کند و جعبهٔ خالی سر جایش می‌ماند.

۳. برای منوی سادهٔ افقی، `display: inline` را روی کدام عنصر گذاشتیم؟  
   **پاسخ:** روی `li`. خود لینک از قبل inline است؛ این `li` است که پیش‌فرضش ردیف جدا دارد.

**پیام پایانی:**

«هدف این جلسه حفظ کردن جدول display نبود. هدف این بود که وقتی دکمه تمام عرض شد، یا برچسب عرض نگرفت، یا چیزی را پنهان کردید و جای خالی ماند، بدانید دارید نوع جعبه را عوض می‌کنید. Flex را اسم بردیم و عمداً واردش نشدیم.»

## تمرین‌ها (ساده → چالشی)

### ساده

۱. دو `div` با پس‌زمینهٔ متفاوت بساز و بدون هیچ `display` ببین زیر هم می‌آیند. بعد هر دو را `display: inline` کن.  
۲. یک `ul` با چهار غذای مورد علاقه بساز و با الگوی `.menu-inline` افقی‌اش کن. یکی از `li`ها را با `display: none` بردار و ببین بقیه جمع می‌شوند.

### متوسط

۳. به یک `a` بگو `display: block`، عرض ۵۰ درصد بده، و در مرورگر کلیک کن. برای خودت بنویس: لینک مانده یا نه، و جعبه چه فرقی کرده.  
۴. همان سه جعبهٔ ۱ و ۲ و ۳ را یک بار با `none` و یک بار با `hidden` بچین و روی کاغذ جای خالی را بکش.

### چالشی

۵. منوی افقی را فقط با `inline` نگه دار و یک محدودیت واقعی‌اش را بنویس؛ مثلاً اینکه وسط‌چین کردن عمودی یا فاصلهٔ یکسان به‌سختی inline درنمی‌آید. راه‌حل را نساز؛ فقط محدودیت را نام ببر تا در Flex برگردیم.  
۶. توضیح بده چرا در فرم موبایل الگوی `button { display: block; width: 100%; }` رایج است، و در چه صفحه‌ای این الگو را نمی‌خواهی.
