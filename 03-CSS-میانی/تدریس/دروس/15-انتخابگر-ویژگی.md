## ۱) شروع کلاس؛ نیاز واقعی سایت

«بچه‌ها، در صفحه منابع درس دو جور لینک داریم. یکی می‌ماند در همین سایت. یکی `target="_blank"` دارد و در تب تازه باز می‌شود. طراح می‌خواهد قبل از کلیک، کاربر بفهمد این لینک او را از صفحه فعلی بیرون می‌برد. علامت `↗` کافی است.

راه شتاب‌زده این است که به هر لینک بیرونی کلاس `external` بدهیم. راه امروز این است که بپرسیم: این اطلاع از قبل در HTML هست یا نه؟ هست. خود `target="_blank"` همان اطلاع است. اگر CSS بتواند از روی همین ویژگی انتخاب کند، نویسنده محتوا کلاس تزئینی اضافه نمی‌کند و اگر کسی لینک را بدون کلاس کپی کند، علامت از بین نمی‌رود.

دومین نیاز همین صفحه است. سه فیلد داریم: نام کاربری، رمز، ایمیل. هر سه تگشان `input` است. رنگ حاشیه باید فرق کند. باز هم می‌شود کلاس گذاشت. ولی تفاوتشان از قبل در `type` نوشته شده.

سؤال جلسه: انتخابگر را به چه چیزی غیر از نام تگ و نام کلاس می‌توان وصل کرد؟»

فایل پیشنهادی: `تدریس/live/15-attr-selectors.html`

```html
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Live — انتخابگر ویژگی</title>
  <style>
    body { font-family: Tahoma, sans-serif; padding: 1.5rem; line-height: 1.7; }
    input { display: block; margin: 0.4rem 0; padding: 0.4rem 0.6rem; }
  </style>
</head>
<body>
  <p><a href="about.html">درباره همین سایت</a></p>
  <p><a href="https://developer.mozilla.org/en-US/" target="_blank" rel="noopener">مستندات MDN</a></p>

  <input type="text" placeholder="نام کاربری" aria-label="نام کاربری">
  <input type="password" placeholder="رمز عبور" aria-label="رمز عبور">
  <input type="email" placeholder="ایمیل" aria-label="ایمیل" dir="ltr">
</body>
</html>
```

«`rel="noopener"` را کنار `target="_blank"` عادت بدهید. بحث امنیتی باز شدن پنجره را همین یک جمله بگویید و رد شوید: صفحه مقصد نباید به پنجره شما دسترسی راحت داشته باشد. موضوع درس امروز خود انتخابگر است.

`aria-label` اینجا هست چون این فیلدها هنوز `label` دیداری ندارند. در درس فرم برچسب واقعی را می‌گذاریم. امروز فقط نوع فیلد را انتخاب می‌کنیم.»

**در مرورگر:** دو لینک شبیه هم‌اند. سه فیلد هم حاشیه پیش‌فرض یکسان دارند. تفاوت در کد هست، در ظاهر نیست.

## ۲) کروشه یعنی «به ویژگی نگاه کن»

«انتخابگر ویژگی داخل کروشه نوشته می‌شود. دو شکل اول را از هم جدا کنید.

`[target]` یعنی این ویژگی وجود دارد، هر مقداری که داشته باشد.  
`[target="_blank"]` یعنی وجود دارد و مقدارش دقیقاً همین رشته است.

نقل‌قول دور مقدار را از همین ساعت عادت کنید. برای مقدار ساده گاهی مرورگر بدون نقل‌قول هم می‌فهمد، ولی به محض اینکه نقطه یا فاصله یا علامت داشته باشیم، بدون نقل‌قول کل قانون نامعتبر است و بی‌صدا نادیده گرفته می‌شود.»

```css
a[target] {
  color: #1a5fb4;
}

a[target="_blank"]::after {
  content: " ↗";
}
```

«قانون اول هر لینکی را که اصلاً `target` دارد آبی می‌کند. قانون دوم فقط مقدار `_blank` را علامت‌دار می‌کند. اگر لینکی `target="_self"` باشد، آبی می‌شود ولی پیکان نمی‌گیرد. این تفاوت را با یک لینک سوم آزمایش کن.»

علامت را با `::after` ساختیم چون تزئین است. خود کلمه «مستندات MDN» در HTML هست. درس ۱۱ را یک جمله یادآوری کن: اگر خطر باز شدن تب فقط با همین پیکان فهمیده می‌شود، در متن لینک هم بنویسید «در تب جدید»، چون بعضی صفحه‌خوان‌ها محتوای `content` را نمی‌خوانند. در جزوه متن لینک خودش می‌گوید «تب جدید». پیکان کمک دیداری است.

**در مرورگر:** فقط لینک MDN پیکان دارد. لینک داخلی نه. در DevTools انتخابگر را روی هر دو `a` مقایسه کن.

### سؤال کلاسی

- «`[target]` و `[target="_blank"]` کدام لینک‌ها را می‌گیرند؟»  
  **پاسخ:** اولی هر عنصری که ویژگی `target` داشته باشد. دومی فقط مقدار دقیق `_blank`.

- «چرا دور `_blank` نقل‌قول گذاشتیم؟»  
  **پاسخ:** مقدار ویژگی است و شکل امن و خوانا همین است. برای مقدارهای دارای نقطه، نقل‌قول اجباری است.

### اشتباهات رایج

- نوشتن `a[target=_blank]` و عادت کردن به شکل بی‌نقل‌قول، بعد شکست در `[href$=.pdf]`.  
- فراموش کردن `content` روی `::after` و گمان اینکه انتخابگر خراب است.

## ۳) مقدار دقیق روی `type` فیلدها

«نام تگ هر سه تا `input` است. انتخابگر `input` به همه می‌خورد. تفاوت در ویژگی `type` است.»

```css
input[type="text"] {
  border: 2px solid #1a5fb4;
}

input[type="password"] {
  border: 2px solid #c92a2a;
}

input[type="email"] {
  border: 2px solid #2b8a3e;
}
```

«این تطبیق دقیق است، مثل `[type="text"]`. فیلد `search` یا `tel` این رنگ‌ها را نمی‌گیرد، مگر اینکه برایشان قانون جدا بنویسیم.

حساسیت به بزرگی و کوچکی حروف در HTML برای مقدار `type` معمولاً مسئله نیست، چون `type` را کوچک می‌نویسیم. در بخش فایل‌ها یک پرچم `i` را برای وقتی نشان می‌دهم که `.PDF` و `.pdf` هر دو در سایت باشند.»

**در مرورگر:** سه حاشیه آبی و قرمز و سبز. یک `input` بدون `type` اضافه کن. پیش‌فرض مرورگر `text` است، ولی اگر ویژگی در HTML نوشته نشده باشد انتخابگر `[type="text"]` آن را نمی‌گیرد. این آزمایش ظریف را انجام بده: ویژگی غایب با مقدار پیش‌فرض یکی نیست.

### سؤال کلاسی

- «چرا به این سه فیلد کلاس `blue` و `red` و `green` ندادیم؟»  
  **پاسخ:** چون `type` از قبل نوع داده را گفته. کلاس وقتی لازم است که ظاهر به اطلاعاتی وصل باشد که در هیچ ویژگی‌ای نیست.

### اشتباهات رایج

- گمان اینکه `input[type="text"]` شامل password هم می‌شود. تطبیق دقیق، شامل انواع دیگر نیست.

## ۴) شروع، پایان، و «جایی در وسط»

جدول را بعد از دیدن درد پر کن، نه قبلش. اول لینک فایل را نشان بده.

```html
<ul>
  <li><a href="downloads/css-notes.pdf">جزوه CSS</a></li>
  <li><a href="downloads/exercises.zip">فایل تمرین‌ها</a></li>
  <li><a href="mailto:info@example.com">info@example.com</a></li>
  <li><a href="https://example.com/guide">راهنمای آنلاین</a></li>
</ul>
```

«می‌خواهیم کنار PDF یک علامت سند باشد، کنار ZIP علامت بسته، کنار ایمیل پاکت. نمی‌خواهیم نویسنده هر بار کلاس `pdf` یادش بماند.»

```css
a[href$=".pdf"]::before { content: "📄 "; }
a[href$=".zip"]::before { content: "🗜️ "; }
a[href^="mailto:"]::before { content: "✉️ "; }
a[href^="https"] { color: #0b6e4f; }
```

«`^=` یعنی مقدار با این رشته **شروع** می‌شود. `mailto:` و `https` از همین خانواده‌اند.  
`$=` یعنی مقدار با این رشته **تمام** می‌شود. پسوند فایل ته `href` است.  
`*=` را هنوز ننوشته‌ام. یعنی آن رشته هر جای مقدار آمده باشد، اول یا وسط یا آخر.»

یک دام را همین‌جا نشان بده:

```css
a[href$=".pdf" i]::before { content: "📄 "; }
```

«حرف `i` قبل از بستن کروشه یعنی بزرگی و کوچکی حروف مهم نباشد. `.pdf` و `.PDF` هر دو سند حساب می‌شوند. بدون `i`، لینک `Notes.PDF` بی‌علامت می‌ماند. در نام فایل‌های واقعی هر دو شکل را می‌بینید.»

کنار نام لینک، نوع فایل را در خود متن هم بنویس: «جزوه CSS (PDF)». آیکون CSS برای صفحه‌خوان تضمین نشده. این همان حرف درس ۱۱ است.

**در مرورگر:** چهار لینک، سه علامت متفاوت، راهنمای https سبز. یک href را به `file.PDF` عوض کن و فرق با پرچم `i` را نشان بده.

### سؤال کلاسی

- «برای لینکی که آدرسش با `https://` شروع می‌شود کدام علامت را می‌گذاریم؟»  
  **پاسخ:** `^=` مثل `[href^="https"]`.

- «برای فایلی که نامش به `.zip` ختم می‌شود؟»  
  **پاسخ:** `$=` مثل `[href$=".zip"]`.

- «اگر بخواهیم هر آدرسی که کلمه `download` را جایی در خودش دارد انتخاب شود؟»  
  **پاسخ:** `[href*="download"]`. این یکی وسیع است و ممکن است ناخواسته هم بگیرد.

### اشتباهات رایج

- جا انداختن نقل‌قول: `[href$=.pdf]` نامعتبر است، چون نقطه در مقدار بدون نقل‌قول قانون را می‌شکند.  
- استفاده از `*=` برای پسوند. `guide.pdf.backup` را هم می‌گیرد اگر بنویسی `[href*=".pdf"]`. برای پسوند، `$=` دقیق‌تر است.

## ۵) `*=` روی کلاس، و کلمه‌ای که باید جدا باشد

«گاهی در پروژه کلاس‌ها این‌شکل‌اند: `btn-red`، `btn-green`، `btn-blue`. یک نفر می‌نویسد:»

```css
[class*="btn"] {
  padding: 6px 14px;
  border-radius: 4px;
}
```

«این قانون هر عنصری را می‌گیرد که حروف `btn` جایی در مقدار `class` باشد. `btn-red` درست است. `submit-btn-wrapper` و `dd-btn` هم گرفته می‌شوند. شاید اصلاً دکمه نباشند.

اگر منظورتان کلاس‌هایی است که با `btn-` شروع می‌شوند، بنویسید `[class^="btn-"]`. و اگر فقط یک خانواده مشخص می‌خواهید، یک کلاس مشترک `.btn` در HTML هنوز ساده‌تر و خواناتر است. انتخابگر ویژگی جای کلاس را در همه جا نمی‌گیرد. وقتی مجبورید به نشانه‌ای که از قبل در HTML است تکیه کنید، سراغش می‌رویم.»

حالا `~=` را با عکس نشان بده. این یکی کلمه کامل می‌خواهد، جدا شده با فاصله:

```html
<img src="a.jpg" alt="عکس جدید" title="new photo">
<img src="b.jpg" alt="عکس قدیمی" title="old photo">
<img src="c.jpg" alt="نوسازی" title="renewal">
```

```css
[title~="new"] {
  outline: 2px dashed #e8590c;
}
```

«فقط عکس اول کادر نارنجی می‌گیرد. در `new photo` کلمه `new` جدا است. در `old photo` آن کلمه نیست. در `renewal` حروف `new` وسط کلمه‌اند، ولی `~=` کلمه کامل می‌خواهد نه تکه‌ای از کلمه. اگر اینجا `*=` می‌نوشتیم، `renewal` هم انتخاب می‌شد.»

**در مرورگر:** سه تصویر. فقط اولی outline دارد. در DevTools مقدار `title` را از `new photo` به `newphoto` عوض کن تا کادر برداشته شود.

### سؤال کلاسی

- «فرق `[class*="btn"]` و `[class^="btn-"]` چیست؟»  
  **پاسخ:** اولی `btn` را در هر جای رشته کلاس پیدا می‌کند. دومی فقط رشته کلاسی را که با `btn-` شروع شود.

- «فرق `*=` و `~=` روی کلمه `new` چیست؟»  
  **پاسخ:** `*=` هر جا آن حروف را ببیند کافی است. `~=` یک کلمه جدا در فهرستِ جدا شده با فاصله می‌خواهد.

### اشتباهات رایج

- تکیه بر `[class*="btn"]` در پروژه‌ای که اسم کلاس‌ها طولانی و ترکیبی است.  
- انتظار اینکه `~=` تکه‌ای از یک کلمه را بگیرد.

## ۶) زبان: دقیقاً `fa` یا `fa-` با ادامه

«`|=` را کمتر می‌نویسید، ولی در سایت دوزبانه دقیقاً به درد می‌خورد.»

```html
<p lang="fa">این پاراگراف فارسی است.</p>
<p lang="fa-IR">این هم فارسی ایران است.</p>
<p lang="en">This one is English.</p>
```

```css
[lang|="fa"] {
  font-family: Tahoma, sans-serif;
}
```

«این انتخابگر یا مقدار دقیق `fa` را می‌گیرد، یا مقداری که با `fa-` شروع شود، مثل `fa-IR`. پاراگراف انگلیسی را نمی‌گیرد.

اگر بنویسیم `[lang^="fa"]`، رشته‌ای مثل `fake` را هم می‌گیریم اگر چنین کدی وجود داشته باشد. `|=` برای همین الگوی «کد، یا کد با خط تیره و زیرکد» ساخته شده. اسمش را حفظ کنید به همراه همین مثال زبان.»

**در مرورگر:** دو پاراگراف فارسی فونت می‌گیرند، انگلیسی نه.

### سؤال کلاسی

- «`[lang|="fa"]` شامل `fa-IR` می‌شود؟»  
  **پاسخ:** بله. شامل `en` نمی‌شود.

## ۷) ترکیب با تگ و کلاس

«انتخابگر ویژگی تنها نمی‌ماند. می‌شود نوشت `a.btn[target="_blank"]`. یعنی هم لینک، هم کلاس دکمه، هم باز شدن در تب تازه.

هر چه انتخابگر را خاص‌تر کنید، دیرتر با قانون‌های کلی بجنگید. اگر همه `a[target="_blank"]`های سایت باید پیکان داشته باشند، همان شکل کلی درست است. اگر فقط دکمه‌های کارت محصول، شکل ترکیبی را بنویسید.»

اشاره کوتاه به specificity، بدون جدول طولانی: وجود یک ویژگی در کروشه از نظر وزن انتخابگر شبیه یک کلاس حساب می‌شود. اگر `.nav a` و `a[target="_blank"]` هر دو رنگ بدهند و وزنشان با هم بجنگد، DevTools را باز کن و ببین کدام خط خورده. وارد محاسبه عددی طولانی نشو مگر کسی بپرسد.

## ۸) جدول را بعد از دیدن، با صدای بلند پر کن

حالا که هر علامت را در مرورگر دیده‌اید، جدول جزوه را از حفظ نخوان. از کلاس بخواه هر ردیف را با یک جمله فارسی بگوید و تو فقط علامت را روی تخته بنویسی.

| انتخابگر | جمله‌ای که دانشجو باید بگوید |
|----------|------------------------------|
| `[target]` | ویژگی هست؛ مقدارش هر چه باشد |
| `[type="text"]` | مقدار دقیقاً text است |
| `[href^="https"]` | مقدار با https شروع می‌شود |
| `[href$=".pdf"]` | مقدار با .pdf تمام می‌شود |
| `[class*="btn"]` | رشته btn جایی داخل مقدار هست |
| `[title~="new"]` | کلمه جداگانه new، با فاصله از بقیه |
| `[lang\|="fa"]` | دقیقاً fa، یا fa با خط تیره و ادامه |

«یک ردیف اضافه که در جدول جزوه داخل نکته آمده: پرچم `i`. `[href$=".pdf" i]` یعنی پایان مقدار `.pdf` باشد و بزرگی حروف مهم نباشد.

اگر کسی `~=` را با `*=` قاطی کرد، برگرد به سه تصویر. اگر کسی `|=` را با `^=` قاطی کرد، برگرد به `fa` و `fa-IR` و کلمه خیالی `fake`. جدول وقتی مفید است که پشت هر ردیفش یک صفحه زنده باشد.»

### سؤال کلاسی

- «کدام علامت را برای پسوند فایل انتخاب می‌کنی و کدام را برای پروتکل اول آدرس؟»  
  **پاسخ:** پسوند با `$=`، شروع آدرس با `^=`.

## ۹) سه قانون خراب را در DevTools زنده کن

این بخش را حذف نکن. دانشجو باید ببیند قانون نامعتبر هیچ اثری نمی‌گذارد و مرورگر معمولاً پیام بلندی هم نشان نمی‌دهد.

اول، نقل‌قول جاافتاده:

```css
a[href$=.pdf]::before { content: "📄 "; }
```

«ذخیره کن. آیکون PDF نیست. در DevTools این قانون خط خورده یا اصلاً در فهرست قوانین معتبر نیست. نقطه بدون نقل‌قول مقدار را از شکل یک رشته خارج کرده. درستش: `[href$=".pdf"]`.»

دوم، انتخابگر بیش از حد گشاد روی کلاس دکمه منوی کشویی دیروز. در همان صفحه هم `btn-primary` داریم هم کلاس `dd-btn` روی دکمه دسته‌بندی:

```html
<a class="btn-primary" href="buy.html">خرید</a>
<button class="dd-btn" type="button">دسته‌بندی‌ها</button>
```

```css
[class*="btn"] { background: #0b6e4f; color: white; }
```

«هر دو سبز شدند. دکمه منو نباید استایل خرید را بگیرد. انتخابگر را عوض کن:»

```css
[class^="btn-"] { background: #0b6e4f; color: white; }
```

«حالا فقط کلاسی که مقدارش با `btn-` شروع شود سبز است. `dd-btn` با `dd` شروع شده و کنار می‌ماند. اگر فردا کلاس دومِ یک عنصر باشد، مثلاً `class="nav btn-primary"`، شروع کل رشته دیگر `btn-` نیست. این محدودیت `^=` روی ویژگی `class` است. برای همین باز هم یک کلاس واقعی `.btn` وقتی خودتان HTML را می‌نویسید مطمئن‌تر است. انتخابگر ویژگی را برای داده‌ای بگذارید که کلاس نیست: `href`، `type`، `target`، `required`، `lang`.»

سوم، اطلاعات مهم فقط در آیکون:

«لینک را موقتاً بگذارید `<a href="notes.pdf">جزوه</a>` بدون کلمه PDF. آیکون هست. از یکی بپرسید اگر CSS لود نشود یا صفحه‌خوان آیکون را نخواند، کاربر از کجا بفهمد فایل چیست. بعد متن را به «جزوه (PDF)» برگردانید. آیکون بماند، ولی معنی در HTML باشد.»

**در مرورگر:** هر سه خرابی را یکی‌یکی بساز و درست کن. بین هر کدام صفحه را ذخیره کن تا تفاوت دیده شود، نه اینکه فقط درباره‌اش حرف بزنید.

### اشتباهات رایج

- اعتماد به اینکه «قانون را نوشتم پس حتماً اعمال شده»، بدون نگاه به DevTools وقتی نقل‌قول جا مانده.  
- `[class*="btn"]` در صفحه‌ای که اسم کلاس‌ها همدیگر را شامل می‌شوند.  
- پسوند فایل فقط داخل `content`.

## ۱۰) پروژه جلسه — فهرست منابع درس

همه علامت‌ها را در یک فهرست جمع کن.

```html
<section>
  <h2>منابع این جلسه</h2>
  <ul class="files">
    <li><a href="downloads/css-notes.pdf">جزوه CSS (PDF)</a></li>
    <li><a href="downloads/exercises.ZIP">تمرین‌ها (ZIP)</a></li>
    <li><a href="mailto:info@example.com">ایمیل مدرس</a></li>
    <li>
      <a href="https://developer.mozilla.org/" target="_blank" rel="noopener">
        MDN (تب جدید)
      </a>
    </li>
  </ul>
  <form>
    <input type="text" required placeholder="نام" aria-label="نام">
    <input type="email" required placeholder="ایمیل" aria-label="ایمیل" dir="ltr">
  </form>
</section>
```

```css
a[href$=".pdf" i]::before { content: "📄 "; }
a[href$=".zip" i]::before { content: "🗜️ "; }
a[href^="mailto:"]::before { content: "✉️ "; }

a[target="_blank"]::after { content: " ↗"; }

input[required] {
  border: 2px solid #e8590c;
}

input[type="email"] {
  border-color: #2b8a3e;
}
```

«فایل ZIP با حروف بزرگ هم علامت می‌گیرد، چون `i` گذاشتیم. لینک MDN هم پیکان ته متن دارد هم اگر خواستید رنگ لینک https. فیلدهای `required` حاشیه نارنجی دارند، بدون کلاس `required` در HTML. ویژگی از قبل هست.

اگر هم `input[required]` حاشیه نارنجی بدهد و هم `input[type="email"]` رنگ دیگری، هر دو ویژگی روی فیلد ایمیل صادق‌اند. در DevTools ببینید کدام قانون آخر آمده یا کدام انتخابگر در آن ویژگی خاص‌تر است. برای این پروژه، نارنجی بودن «الزامی» را مهم‌تر بگیرید و ترتیب را طوری بچینید که دانشجو نتیجه را عمداً پیش‌بینی کند.»

**در مرورگر:** چهار منبع با علامت درست. دو فیلد با حاشیه نارنجی. یک فیلد را بدون `required` بگذار تا نارنجی از بین برود.

### سؤال کلاسی

- «اگر نویسنده فراموش کند کلاس بگذارد ولی `href` را درست بنویسد، آیکون PDF می‌ماند؟»  
  **پاسخ:** بله. انتخابگر به `href` وصل است، نه به کلاس.

## ۱۱) جمع‌بندی مدرس و سؤالات پایانی

1. `[type="text"]` یعنی چه؟  
   **پاسخ راهنما:** عنصری که ویژگی `type` دارد و مقدارش دقیقاً `text` است.

2. فرق `^=` و `$=` و `*=` را با یک `href` بگو.  
   **پاسخ:** شروع مقدار، پایان مقدار، و آمدن آن رشته در هر جای مقدار.

3. چرا `[href$=.pdf]` بدون نقل‌قول خطرناک است؟  
   **پاسخ:** مقدار دارای نقطه است و قانون ممکن است کاملاً نادیده گرفته شود. مقدار را داخل نقل‌قول بنویس.

4. چه وقت کلاس از انتخابگر ویژگی بهتر است؟  
   **پاسخ:** وقتی ظاهر به یک گروه طراحی وصل است که در ویژگی HTML معنایی ندارد، یا وقتی `*=` روی `class` ناخواسته اسم‌های دیگر را هم می‌گیرد. آن وقت یک کلاس مشترک `.btn` روشن‌تر است.

**پیام پایانی:**

«انتخابگر ویژگی یعنی CSS به داده‌ای نگاه کند که HTML از قبل گفته: نوع فیلد، مقصد لینک، زبان، الزامی بودن. کلاس را برای وقتی نگه دارید که آن داده در نشانه‌گذاری نیست. نقل‌قول دور مقدار را هم دیگر فراموش نکنید.»

## تمرین‌ها (ساده → چالشی)

### ساده

1. به هر لینک `target="_blank"` با `::after` علامت `↗` بده. یک لینک داخلی بدون target کنارش بگذار.  
2. سه `input` از نوع text و password و email با رنگ حاشیه متفاوت بساز.

### متوسط

3. برای `href`هایی که به `.pdf` و `.zip` ختم می‌شوند و برای `mailto:` آیکون `::before` بگذار. یک فایل با پسوند `.PDF` را هم با پرچم `i` پوشش بده.  
4. دو تصویر با `title="new photo"` و `title="renewal"` بساز و فقط کلمه جدا را با `~=` انتخاب کن. بعد همان کار را با `*=` مقایسه کن.

### چالشی

5. فهرست منابع پروژه همین جلسه را کامل کن. فیلدهای `required` را با `input[required]` حاشیه نارنجی بده.  
6. توضیح بده چرا `[class*="btn"]` در یک صفحه که `dd-btn` و `btn-primary` هر دو را دارد دردسر می‌سازد، و به‌جایش چه می‌نویسی.
