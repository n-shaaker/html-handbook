**هدف جلسه:** دانشجو بفهمد *چرا* فرم پیش‌فرض مرورگر برای یک ثبت‌نام واقعی کافی نیست، فیلد تمام‌عرض را بدون بیرون زدن از کارت بسازد، فونت فیلد را با فونت سایت یکی کند، حالت فوکوس را واضح نگه دارد، و فرم را با `label` واقعی تحویل بدهد.

## ۱) شروع کلاس؛ نیاز واقعی سایت

«بچه‌ها، صفحه ثبت‌نام کتاب‌سرا را باز کنید، قبل از هر CSS تازه. نام، ایمیل، رمز، یک چک‌باکس قوانین، دکمه ثبت‌نام.

مرورگر این‌ها را نشان می‌دهد: کادر کوچک، فونت سیستم که با بقیه سایت یکی نیست، حاشیه خاکستری نازک، و وقتی Tab می‌زنید یک حلقه پیش‌فرض. فرم کار می‌کند. داده را هم می‌تواند بفرستد. ولی کنار کارت محصولی که دیروز با دقت استایل شد، این فرم انگار از یک صفحه دیگر آمده.

کاربر باید سه چیز را بدون توضیح ما بفهمد: این کادر مال کدام اطلاعات است، الان دارد در کدام کادر تایپ می‌کند، و اگر ایمیل را بد نوشته چرا دکمه او را رد کرده.

سؤال: کدام را با CSS درست می‌کنیم و کدام را اگر از HTML حذف کنیم CSS جبران نمی‌کند؟»

فایل پیشنهادی: `تدریس/live/16-forms.html`

نسخه بدون CSS را اول نشان بده:

```html
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Live — فرم</title>
  <style>
    body { font-family: Tahoma, sans-serif; background: #f8fafc; padding: 1.5rem; }
    .card { max-width: 420px; background: white; padding: 1rem; }
  </style>
</head>
<body>
  <form class="card" action="#thanks">
    <h1>ساخت حساب</h1>
    <input type="text" name="name">
    <input type="email" name="email">
    <button type="submit">ثبت‌نام</button>
  </form>
</body>
</html>
```

«عمداً هنوز `label` نگذاشته‌ام تا ته جلسه، وقتی برچسب را اضافه می‌کنیم، فرق کلیک روی برچسب را ببینید. این نسخه را تحویل مشتری نمی‌دهیم. نقطه شروع است.»

**در مرورگر:** دو کادر باریک با فونتی غیر از Tahoma، دکمه کوچک. عرض کارت ۴۲۰ پیکسل است و فیلدها به آن نچسبیده‌اند.

## ۲) چرا فیلد فونت صفحه را به ارث نمی‌برد

«خیلی از کنترل‌های فرم، `font-family` پدر را به ارث نمی‌برند. مرورگر برایشان فونت سیستم می‌گذارد. برای همین متن داخل کادر با متن عنوان یکی نیست.»

```css
input,
textarea,
select,
button {
  font-family: inherit;
  font-size: 1rem;
}
```

«`inherit` یعنی همان مقداری که عنصر پدر دارد. پدر این‌جا `body` است و Tahoma است. این یک خط را در همه فرم‌های پروژه بگذارید، وگرنه هر بار تعجب می‌کنید چرا فقط فیلدها فونت دیگری دارند.»

**در مرورگر:** قبل و بعد از `font-family: inherit` را نشان بده. عنوان و داخل کادر باید یک خانواده فونت شوند.

### سؤال کلاسی

- «اگر این خط را ننویسیم، با عوض کردن فونت `body` فیلد هم عوض می‌شود؟»  
  **پاسخ:** معمولاً نه. کنترل فرم از این جهت استثناست و باید `inherit` بگیرد.

## ۳) عرض صددرصد که از کارت بیرون می‌زند

«طراح گفته کادر به اندازه کارت باشد. اولین حدس:»

```css
input[type="text"],
input[type="email"],
input[type="password"] {
  width: 100%;
  padding: 12px 16px;
  margin: 8px 0;
}
```

«در ظاهر درست است. در عمل، با `box-sizing` پیش‌فرض که `content-box` است، `width: 100%` فقط ناحیه محتواست. padding چپ و راست و border به آن اضافه می‌شوند. جمع از عرض پدر بیشتر می‌شود و کادر از کارت بیرون می‌زند. اسکرول افقی کوچک همان علامت این اشتباه است.»

کارت را `max-width: 420px` نگه دار و بیرون‌زدگی را نشان بده. بعد:

```css
input[type="text"],
input[type="email"],
input[type="password"],
textarea,
select {
  width: 100%;
  box-sizing: border-box;
}
```

«`border-box` یعنی آن ۱۰۰درصد شامل padding و border هم باشد. کادر دیگر از کارت بیرون نمی‌زند. این خط را همراه `font-family: inherit` جزو پایه فرم حساب کنید.

انتخابگر را از درس دیروز گرفتیم. اگر فقط بنویسیم `input`، چک‌باکس و دکمه رادیویی هم عرض ۱۰۰درصد می‌گیرند و شکلشان خراب می‌شود. نوع را محدود کن، یا چک‌باکس را بعداً با یک قانون جدا برگردان.»

**در مرورگر:** بدون `border-box` اسکرول یا بیرون‌زدگی. با آن، لبه کادر روی لبه داخلی کارت می‌نشیند. در DevTools اندازه کل جعبه را بخوان.

### سؤال کلاسی

- «`width: 100%` با padding زیاد، در `content-box` چه می‌شود؟»  
  **پاسخ:** عرض نهایی از پدر بیشتر می‌شود.

- «چرا انتخابگر را `input[type="text"]` نوشتیم نه همه `input`ها؟»  
  **پاسخ:** تا چک‌باکس و رادیو عرض تمام‌خط نگیرند.

### اشتباهات رایج

- `width: 100%` و `padding` بدون `border-box`.  
- Reset عرض روی همه `input`ها.

## ۴) سه جور حاشیه، یک جور فوکوس

«ظاهر کادر سلیقه‌ای است، به شرطی که مرزش دیده شود. سه نمونه جزوه را سریع کنار هم بساز، بعد روی فوکوس توقف کن.»

```css
.f-border {
  border: 2px solid #1a5fb4;
  border-radius: 4px;
}

.f-bottom {
  border: none;
  border-bottom: 2px solid #e8590c;
  background: transparent;
}

.f-filled {
  border: none;
  background: #3f51b5;
  color: white;
}
```

«کادر فقط-خط-پایین شیک است و اگر contrast خط با پس‌زمینه کم باشد نامرئی می‌شود. کادر پررنگ باید رنگ متنش روشن بماند. هر کدام را انتخاب کردید، حالت فوکوس را جدا طراحی کنید.»

حالا نیاز اصلی: کاربر همیشه بفهمد فوکوس کجاست.

```css
input:focus {
  outline: none;
  border-color: #0b6e4f;
  box-shadow: 0 0 0 3px rgba(11, 110, 79, 0.35);
}
```

«`outline: none` را تنها وقتی بنویسید که جایگزینش واقعاً واضح باشد. اینجا حلقه سبز با `box-shadow` جایگزین است. اگر این سایه را برندارید و outline را حذف کنید، کاربر کیبورد گم می‌شود. دیروز در منو هم همین قرارداد را داشتیم.

چرا `box-shadow` به‌جای ضخیم کردن `border`؟ چون سایه معمولاً اندازه چیدمان را عوض نمی‌کند و کادر نمی‌پرد. اگر به‌جایش `border-width` را از ۱ به ۳ تغییر دهید، فیلدهای زیرین تکان می‌خورند.»

**در مرورگر:** با Tab بین فیلدها برو. حلقه سبز باید روی هر کدام دیده شود. یک بار outline را حذف کن و سایه را هم بردار تا کلاس ببیند فوکوس ناپدید می‌شود. بعد سایه را برگردان.

### سؤال کلاسی

- «چرا outline پیش‌فرض را بی‌دلیل حذف نمی‌کنیم؟»  
  **پاسخ:** چون تنها نشانه فوکوس کیبورد در خیلی از مرورگرها همان است. حذفش فقط با یک نشانه دیگر مجاز است.

### اشتباهات رایج

- `outline: none` روی `input, button, a` در یک reset سراسری، بدون جایگزین.  
- فوکوس فقط با تغییر خیلی کم رنگ حاشیه، که در نور زیاد دیده نمی‌شود.

## ۵) جستجو در صفحه راست‌چین

«کادر جستجوی بالای فروشگاه یک ذره‌بین می‌خواهد. در صفحه راست‌چین متن از راست شروع می‌شود، پس آیکون هم سمت راست است و padding همان سمت باید جا باز کند.»

```css
.search {
  width: 100%;
  box-sizing: border-box;
  font-family: inherit;
  border: 1px solid #ced4da;
  border-radius: 20px;
  background-image: url("search-icon.svg");
  background-repeat: no-repeat;
  background-position: right 14px center;
  padding: 12px 42px 12px 16px;
}
```

«`padding` چهار مقداری را با صدای بلند بخوان: بالا ۱۲، راست ۴۲، پایین ۱۲، چپ ۱۶. آن ۴۲ پیکسل جا برای آیکون است تا کلمه «جستجو» روی تصویر ننشیند.

اگر آیکون را سمت چپ کپی کرده باشید از یک آموزش `ltr`، در سایت فارسی ته جمله می‌افتد. `background-position` را با صفحه خودتان تنظیم کنید، نه با عادت چپ‌چین.

آیکون تزئین است. خود فیلد باید `type="search"` و برچسب داشته باشد. تصویر پس‌زمینه نام فیلد نیست.»

**در مرورگر:** متن فارسی را تایپ کن و ببین از راست، بعد از آیکون، شروع می‌شود. اگر زیر آیکون رفت، padding راست را زیاد کن.

### سؤال کلاسی

- «چرا padding راست از padding چپ بزرگ‌تر است؟»  
  **پاسخ:** چون آیکون در این صفحه سمت راست نشسته و متن نباید زیرش برود.

## ۶) فهرست استان و جعبه پیام

«همه داده‌ها یک‌خطی نیستند. استان یک انتخاب از فهرست است. پیام چند خط است.»

```html
<label for="province">استان</label>
<select id="province" name="province">
  <option value="">استان را انتخاب کنید</option>
  <option>تهران</option>
  <option>فارس</option>
  <option>اصفهان</option>
</select>

<label for="message">پیام</label>
<textarea id="message" name="message" placeholder="مثلاً سؤال درباره سفارش ۱۲۳"></textarea>
```

```css
select,
textarea {
  width: 100%;
  box-sizing: border-box;
  font-family: inherit;
  padding: 10px;
  border-radius: 4px;
  border: 1px solid #ced4da;
}

textarea {
  height: 120px;
  resize: vertical;
}
```

«`resize: vertical` یعنی کاربر بتواند ارتفاع را بکشد، نه عرض را. اگر عرض آزاد باشد، کارت را به‌هم می‌ریزد. `resize: none` را فقط وقتی بگذارید که واقعاً نمی‌خواهید تغییری در کار باشد. برای پیام، کشیدن عمودی مفید است.

`select` را هم‌قد و هم‌حاشیه با `input` کنید تا فرم یک‌شکل شود. گزینه اول با `value` خالی، انتخاب واقعی نیست و در اعتبارسنجی می‌تواند با `required` جلوی ارسال را بگیرد.»

**در مرورگر:** گوشه textarea را فقط بالا و پایین بکش. `resize: both` را یک لحظه نشان بده تا عرض کارت خراب شود، بعد به `vertical` برگرد.

### سؤال کلاسی

- «چرا عرض textarea آزاد رها نشده؟»  
  **پاسخ:** چون کشیدن افقی چیدمان فرم باریک را می‌شکند. ارتفاع کافی است.

## ۷) دکمه ارسال

```css
.submit {
  background: #0b6e4f;
  color: white;
  border: none;
  border-radius: 4px;
  padding: 12px 24px;
  font-family: inherit;
  font-size: 1rem;
  cursor: pointer;
}

.submit:hover,
.submit:focus-visible {
  background: #08533b;
}

.reset {
  background: white;
  color: #333;
  border: 1px solid #ced4da;
  border-radius: 4px;
  padding: 12px 24px;
  font-family: inherit;
  cursor: pointer;
}
```

«`cursor: pointer` نشان می‌دهد این عنصر کلیک‌پذیر است. خود دکمه را `type="submit"` بگذارید اگر باید فرم را بفرستد، و `type="button"` یا `type="reset"` را با معنی واقعی‌شان. `reset` را سبک‌تر از ارسال نشان بدهید تا عمل اصلی معلوم باشد.

دکمه هم مثل فیلد، فونت را به ارث نمی‌برد مگر `font-family: inherit`.»

**در مرورگر:** hover و Tab روی ارسال. رنگ تیره‌تر شود و فوکوس گم نشود.

## ۸) برچسب واقعی، نه placeholder

حالا فرم ثبت‌نام جزوه را کامل بنویس. این بخش را عجله نکن.

```html
<form class="signup" action="#forms">
  <h2>ساخت حساب کاربری</h2>

  <label for="su-name">نام و نام خانوادگی</label>
  <input id="su-name" name="name" type="text" autocomplete="name" required>

  <label for="su-email">ایمیل</label>
  <input id="su-email" name="email" type="email" autocomplete="email"
         placeholder="example@mail.com" dir="ltr" required>

  <label for="su-pass">رمز عبور (حداقل ۸ کاراکتر)</label>
  <input id="su-pass" name="password" type="password" autocomplete="new-password"
         minlength="8" dir="ltr" required>

  <label class="remember">
    <input type="checkbox" name="terms" required>
    قوانین سایت را می‌پذیرم
  </label>

  <button type="submit" class="submit">ثبت‌نام</button>
</form>
```

```css
.signup {
  max-width: 420px;
  background: white;
  padding: 1.25rem;
}

.signup label {
  display: block;
  margin-top: 0.8rem;
  font-size: 14px;
}

.signup .remember {
  display: flex;
  gap: 0.4rem;
  align-items: center;
}

.signup input[type="text"],
.signup input[type="email"],
.signup input[type="password"] {
  width: 100%;
  box-sizing: border-box;
  font-family: inherit;
  padding: 12px 16px;
  margin-top: 0.35rem;
  border: 1px solid #ced4da;
  border-radius: 4px;
}

.signup input:focus {
  outline: none;
  border-color: #0b6e4f;
  box-shadow: 0 0 0 3px rgba(11, 110, 79, 0.35);
}

.signup input:user-invalid {
  border-color: #c92a2a;
}

.signup input[type="checkbox"] {
  width: auto;
  accent-color: #0b6e4f;
}
```

«هر کادر یک `label` دارد. `for` همان `id` فیلد است. با کلیک روی کلمه «ایمیل»، فوکوس می‌رود داخل کادر. ناحیه کلیک بزرگ‌تر می‌شود و صفحه‌خوان هم می‌گوید این کادر ایمیل است.

`placeholder` نمونه ورودی است: `example@mail.com`. با شروع تایپ ناپدید می‌شود. رنگش معمولاً کم‌رنگ است. بعضی صفحه‌خوان‌ها آن را به‌عنوان نام فیلد نمی‌خوانند. پس placeholder جای برچسب نیست. اگر فقط placeholder داشته باشیم، کاربر وسط تایپ دیگر نمی‌داند این کادر چه بود.

`autocomplete` به مرورگر کمک می‌کند نام و ایمیل ذخیره‌شده را پیشنهاد بدهد. این HTML است، نه CSS، و در فرم واقعی حذفش نکنید.

ایمیل و رمز `dir="ltr"` دارند چون خود مقدار چپ‌به‌راست است، حتی در صفحه فارسی.

`:user-invalid` را بعد از اینکه کاربر چیزی وارد کرده و مقدار با قیدها نمی‌خواند اعمال کنید، نه همان لحظه بار شدن صفحه. اگر از `:invalid` خالی استفاده کنید، فرم تازه که باز شده همه‌اش قرمز است، چون فیلدهای خالیِ required هنوز نامعتبرند. این فرق را زنده نشان بده: صفحه را تازه باز کن، قرمز نباشد. یک ایمیل بدون `@` بنویس و بیرون از فیلد کلیک کن، حاشیه قرمز شود.

`minlength="8"` و `type="email"` و `required` را CSS قرمز نمی‌کند اگر در HTML نباشند. رنگ فقط وضعیت را نشان می‌دهد.

چک‌باکس را داخل `label` گذاشتیم تا کلیک روی جمله هم مربع را عوض کند. `accent-color` رنگ خود مربع را با سبز سایت یکی می‌کند. عرض `auto` را برگردان تا قانون صددرصدِ فیلدهای متنی، مربع را کش ندهد.»

**در مرورگر:** روی برچسب کلیک کن، نه فقط داخل کادر. فرم خالی را ارسال کن و پیام مرورگر را ببین. ایمیل غلط را بعد از تایپ قرمز کن. رمز کوتاه را هم امتحان کن. چک‌باکس را با کلیک روی متن روشن کن.

### سؤال کلاسی

- «چرا فرم خالی از همان اول با `:user-invalid` قرمز نیست؟»  
  **پاسخ:** این شبه‌کلاس بعد از دخالت کاربر و نامعتبر شدن مقدار اعمال می‌شود. `:invalid` از اول روی فیلد خالی required هم صادق است.

- «اگر placeholder را «ایمیل» بگذاریم و label را حذف کنیم چه می‌شود؟»  
  **پاسخ:** با اولین حرف، نام فیلد غیب می‌شود و اتکا به آن برای دسترس‌پذیری سست است.

### اشتباهات رایج

- placeholder به‌جای label.  
- `:invalid` روی همه فیلدها طوری که صفحه تازه یک دیوار قرمز است.  
- فراموش کردن `width: auto` برای چک‌باکس بعد از قانون `input { width: 100% }`.

## ۹) پروژه جلسه — تماس با ما

دانشجو این فرم را با تو از صفر تایپ می‌کند. از ثبت‌نام کپی کور نکن؛ فیلدها فرق دارند.

```html
<form class="contact" action="#sent">
  <h2>تماس با ما</h2>

  <label for="c-name">نام</label>
  <input id="c-name" name="name" type="text" autocomplete="name" required>

  <label for="c-email">ایمیل</label>
  <input id="c-email" name="email" type="email" autocomplete="email" dir="ltr" required>

  <label for="c-topic">موضوع</label>
  <select id="c-topic" name="topic" required>
    <option value="">موضوع را انتخاب کنید</option>
    <option>سفارش</option>
    <option>پیشنهاد</option>
  </select>

  <label for="c-msg">پیام</label>
  <textarea id="c-msg" name="message" required></textarea>

  <button class="submit" type="submit">ارسال</button>
</form>
```

همان پایه CSS را به کلاس `.contact` بده: `border-box`، `inherit`، فوکوس با سایه، `:user-invalid`، `resize: vertical`، دکمه تمام‌عرض اگر در موبایل می‌خواهی با یک کلاس `full` و `width: 100%`.

«پنج کنترل، پنج برچسب. موضوع `select` است نه فیلد متنی. پیام ارتفاع اولیه دارد و فقط عمودی کش می‌آید. ارسال `type="submit"` است. در عرض ۳۲۰ پیکسل کارت از صفحه بیرون نمی‌زند.»

**در مرورگر:** Tab را از نام تا دکمه برو و هر فوکوس را ببین. موضوع را خالی بفرست. یک ایمیل غلط بعد از تایپ قرمز شود. عرض را باریک کن.

### سؤال کلاسی

- «کدام بخش این فرم اگر فقط CSS باشد و HTML را خالی از label و required کنیم، هنوز تحویل‌دادنی است؟»  
  **پاسخ:** هیچ‌کدام به‌تنهایی. CSS ظاهر و فوکوس را می‌سازد. نام فیلد و قید اعتبار در HTML می‌مانند.

## ۱۰) جمع‌بندی مدرس و سؤالات پایانی

1. چرا فیلد با `width: 100%` و padding از کارت بیرون می‌زند؟  
   **پاسخ راهنما:** در `content-box` عرض شامل padding و border نیست. `box-sizing: border-box` جمع را داخل همان ۱۰۰درصد نگه می‌دارد.

2. چرا `font-family: inherit` را روی کنترل فرم می‌نویسیم؟  
   **پاسخ:** چون این عنصرها فونت پدر را خودبه‌خود به ارث نمی‌برند.

3. حذف `outline` در `:focus` با چه شرطی قابل قبول است؟  
   **پاسخ:** وقتی یک نشانه واضح دیگر، مثل `box-shadow` یا تغییر قوی حاشیه، جایش باشد.

4. placeholder چه کاری می‌کند و چه کاری نمی‌کند؟  
   **پاسخ:** نمونه مقدار را نشان می‌دهد. نام فیلد نیست. نام فیلد کار `label` متصل به `id` است.

**پیام پایانی:**

«فرم خوب قبل از رنگ دکمه، یک فرم فهمیدنی است. برچسب سر جایش، فوکوس پیدا، کادر داخل پدر، و قرمز شدن فقط وقتی کاربر واقعاً مقدار را خراب کرده. CSS این‌ها را قابل دیدن می‌کند. قیدها را هنوز HTML باید بگوید.»

## تمرین‌ها (ساده → چالشی)

### ساده

1. یک فیلد متنی با `width: 100%` و padding داخل کارتی با عرض ثابت بساز. بیرون‌زدگی را ببین و با `border-box` درست کن.  
2. به `input` و `button` مقدار `font-family: inherit` بده و با فونت صفحه مقایسه کن.

### متوسط

3. حالت `:focus` را با `box-shadow` بساز و outline پیش‌فرض را فقط در حضور همین سایه بردار. با Tab امتحان کن.  
4. یک `textarea` با `resize: vertical` و یک `select` هم‌سبک با فیلد متنی بساز.

### چالشی

5. فرم «تماس با ما» پروژه جلسه را کامل کن: نام، ایمیل، موضوع، پیام، دکمه ارسال. هر کنترل `label` داشته باشد. ایمیل نامعتبر بعد از تایپ کاربر حاشیه قرمز بگیرد، نه در بار اول صفحه. در عرض ۳۲۰ پیکسل اسکرول افقی نسازی.  
6. توضیح بده چرا `input { width: 100% }` چک‌باکس را خراب می‌کند و قانون را چطور محدود می‌کنی.
