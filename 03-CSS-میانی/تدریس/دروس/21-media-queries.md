**جایگاه در مسیر:** درس **اصلی** و آخرِ ابزار چیدمان این ماژول.  
**هدف جلسه:** دانشجو بفهمد چرا بدون viewport گوشی سایت را «کوچک‌شده دسکتاپ» نشان می‌دهد، قانون پایه را برای باریک‌ترین صفحه بنویسد، و با `min-width` فقط جاهایی که جا هست ستون اضافه کند. در پایان، ردیف کارت و اسکلت درس ۲۰ در عرض حدود ۳۲۰px اسکرول افقی نداشته باشند.

## ۱) شروع کلاس؛ نیاز روی سایت

فایل رستوران یا سه کارت درس ۲۰ را باز کن، بدون هیچ `@media`. دستگاه را روی عرض ۳۲۰px بگذار.

«سایت روی لپ‌تاپ درست بود. روی این عرض، یا کارت‌ها آن‌قدر باریک‌اند که کلمه می‌شکند، یا صفحه به چپ و راست اسکرول می‌خورد. کاربر موبایل این را تمام‌نشده حساب می‌کند، حتی اگر دسکتاپ قشنگ باشد.

Media query یعنی: اگر شرطی درباره دستگاه یا صفحه برقرار بود، این تکه‌ی CSS را هم اعمال کن. شرط این جلسه بیشتر **عرض viewport** است. viewport یعنی همان ناحیه‌ای که صفحه در آن دیده می‌شود، نه عرض مانیتور فیزیکی وقتی پنجره نصف است؛ ملاک، عرض پنجره است.»

جمله را روی برد بنویس:

«بدون media query، یک ظاهر برای همه عرض‌ها داری. با media query، همان HTML دو (یا سه) چیدمان می‌گیرد.»

هنوز کد ننویس. بگذار اسکرول افقی یا کارت له‌شده ده ثانیه روی پرده بماند.

### سؤال کلاسی

- «آیا برای موبایل باید یک فایل HTML جدا بسازیم؟»  
  **پاسخ:** نه. همان HTML، با CSS شرطی. دو HTML یعنی دو برابر نگهداری و اغلب محتوای ناهماهنگ.

---

## ۲) متای viewport — اگر نباشد بقیه درس کار نمی‌کند

در `<head>` نشان بده. اگر فایل زنده این خط را ندارد، عمداً حذف کن و با نوار دستگاه رفرش کن:

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```

«مرورگر موبایل، اگر این خط نباشد، اغلب وانمود می‌کند صفحه حدود ۹۸۰ پیکسل عرض دارد و بعد آن را کوچک می‌کند تا در گوشی جا شود. نتیجه‌اش متن ریز است و media queryهایی که با عرض ۷۰۰px نوشته‌ای **اصلاً فعال نمی‌شوند**، چون از دید CSS عرض هنوز حدود ۹۸۰ است.

`width=device-width` یعنی عرض چیدمان برابر عرض دستگاه باشد. `initial-scale=1` یعنی هنگام باز شدن، بزرگ‌نمایی اولیه ۱ باشد و صفحه از پیش کوچک نشده باشد.

این خط HTML است، نه CSS. جزوه آن را اشتباه رایج نامیده: CSS واکنش‌گرا بدون متای viewport.»

**آزمایش:** خط را بردار، در نمای ۳۷۵px رفرش کن، متن ریز و query خاموش. خط را برگردان، رفرش کن، queryها زنده می‌شوند. این آزمایش از خودِ `@media` مهم‌تر است؛ عجله نکن.

### اشتباهات رایج

- نوشتن viewport فقط در یکی از صفحات سایت. هر HTML مستقل این متا را می‌خواهد.  
- `user-scalable=no` برای قفل کردن زوم. این کار را نکن؛ کاربر کم‌بینا باید بتواند زوم کند. در این کلاس آن ویژگی را معرفی نکن مگر کسی از کد قدیمی پرسیده باشد، و همان‌جا بگو اضافه نکنید.

## ۳) شکل دستور، و دو جهت شرط

```css
@media (min-width: 700px) {
  /* این قانون‌ها فقط وقتی عرض viewport حداقل ۷۰۰px است */
}
```

«`@media` بیرون انتخابگر است. داخل آکولادش انتخابگرهای معمولی می‌نویسی. اگر شرط غلط باشد، انگار آن بلوک در فایل نیست.

| شرط | کی درست است | رویکرد |
|------|----------------|--------|
| `(max-width: 700px)` | عرض **حداکثر** ۷۰۰px، یعنی باریک | دسکتاپ‌اول: اول سبک پهن را می‌نویسی، بعد برای باریک خرابش را جمع می‌کنی |
| `(min-width: 700px)` | عرض **حداقل** ۷۰۰px، یعنی پهن | موبایل‌اول: اول سبک باریک، بعد برای پهن امکانات اضافه |

هر دو معتبرند. پیشنهاد جزوه: **یکی** را انتخاب کن و در پروژه ثابت بمان. انتخاب این کلاس: `min-width`.

چرا موبایل‌اول:

۱. سبک پایه همان چیزی است که در باریک‌ترین حالت لازم است: یک ستون، فاصله کم، عرض‌هایی که از صفحه بیرون نمی‌زنند.  
۲. هر query فقط **اضافه** می‌کند: دو ستون، سه ستون، منوی افقی. کمتر مجبوری عرض ۱۰۰٪ را دوباره «پس بگیرم».  
۳. اگر یک query لود نشود یا مرورگر خیلی قدیمی بلوک را نفهمد، صفحه همچنان یک ستون خوانا می‌ماند، نه یک دسکتاپ له شده.

`max-width` غلط نیست. در جزوه همین درس و در درس ۲۰ نمونه‌ها با آن نوشته شده‌اند. اگر در پروژه‌ای دیدی، بخوان: «پایه را پهن فرض کرده‌اند و برای باریک override کرده‌اند.» در فایل خودت اگر پایه را موبایل نوشتی، overrideها باید `min-width` باشند. قاطی کردن یعنی یک قانون عرض را کم می‌کند و دیگری زیاد، و دیگر نمی‌دانی برنده کیست.»

### سؤال کلاسی

- «عرض ۶۹۹px: `(max-width: 700px)` روشن است یا `(min-width: 700px)`؟»  
  **پاسخ:** max روشن است (۶۹۹ ≤ ۷۰۰). min خاموش است.

- «عرض دقیقاً ۷۰۰px برای هر دو `(max-width: 700px)` و `(min-width: 700px)` چه وضعی دارد؟»  
  **پاسخ:** هر دو شرط ≤ و ≥ هستند، پس هر دو در ۷۰۰ روشن‌اند. اگر در یک فایل هر دو را روی یک ویژگی بگذاری، تعارض داری. برای مرزها معمولاً یکی را ۷۰۰ و بعدی را با همان عدد در جهت دیگر طوری می‌چینند که هم‌پوشانی عمدی نباشد؛ در mobile-first ما فقط min را پله‌پله بالا می‌بریم و همپوشانی را با ترتیب آبشار کنترل می‌کنیم.

## ۴) نمونه جزوه را بخوان، بعد بازنویسی کن

اول عین جزوه را بگذار تا صفحه [`21-media-queries.html`](../../pages/21-media-queries.html) برایشان آشنا باشد. این نسخه **دسکتاپ‌اول** است:

```css
.cards {
  display: grid;
  grid-template-columns: 1fr 1fr 1fr;
  gap: 10px;
}

@media (max-width: 700px) {
  .cards {
    grid-template-columns: 1fr;
  }
}
```

«پایه: همیشه سه ستون. زیر ۷۰۰px: یک ستون. پنجره را از پهن به باریک ببر تا پرش را ببینند. جعبه رنگی جزوه هم همین الگوست: پس‌زمینه آبی و متن «عرض بزرگ»، و زیر ۷۰۰px سبز و متن «عرض کوچک». لازم نیست آن جعبه را در پروژه کپی کنی؛ فقط بفهم شرط max یعنی چه.»

حالا بگو: «فایل زنده کلاس را پاک می‌کنیم و همان کارت‌ها را mobile-first می‌نویسیم.»

HTML:

```html
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Live — media queries</title>
  <style>
    body {
      margin: 0;
      font-family: Tahoma, sans-serif;
      background: #f8fafc;
    }
  </style>
</head>
<body>
  <main class="wrap">
    <h1>دوره‌ها</h1>
    <div class="cards">
      <article class="card">کارت ۱</article>
      <article class="card">کارت ۲</article>
      <article class="card">کارت ۳</article>
    </div>
  </main>
</body>
</html>
```

CSS پایه، **بدون** media query. این باید در ۳۲۰px سالم باشد:

```css
* { box-sizing: border-box; }

.wrap {
  width: 100%;
  max-width: 60rem;
  margin: 0 auto;
  padding: 1rem;
}

.cards {
  display: grid;
  grid-template-columns: 1fr; /* یک ستون؛ پیش‌فرض موبایل */
  gap: 10px;
}

.card {
  background: #eef2f7;
  border: 1px solid #cfd8e3;
  border-radius: 6px;
  padding: 12px;
}
```

**در مرورگر روی ۳۲۰px:** یک ستون، بدون اسکرول افقی. این را معیار قبول بگیر. اگر اسکرول هست، قبل از query یک عرض ثابت پیکسلی یا margin منفی جایی مانده.

بعد پله‌ها:

```css
@media (min-width: 600px) {
  .cards {
    grid-template-columns: 1fr 1fr;
  }
}

@media (min-width: 900px) {
  .cards {
    grid-template-columns: 1fr 1fr 1fr;
  }
}
```

«زیر ۶۰۰ همیشه یک ستون، چون هیچ شرطی روشن نیست. از ۶۰۰ تا قبل از ۹۰۰ هر دو قانون… نه: قانون ۹۰۰ هنوز خاموش است و قانون ۶۰۰ روشن است، پس دو ستون. از ۹۰۰ به بالا **هر دو** بلوک روشن‌اند. هر دو به `grid-template-columns` مقدار می‌دهند. آنکه در فایل **پایین‌تر** است برنده می‌شود، به شرطspecificity یکسان. پس بلوک ۹۰۰ را بعد از بلوک ۶۰۰ بنویس.

`1fr` را دوباره درس نده. بگو: یک سهم از عرض، جزئیاتش ماژول Grid.»

**نمایش اجباری:** ۳۲۰ (یک)، ۶۰۰ (دو)، ۸۹۹ (دو)، ۹۰۰ (سه)، ۱۲۰۰ (سه، و `.wrap` از `max-width` پهن‌تر نمی‌شود).

کارت سوم در حالت دو ستونه تنها در ردیف بعد می‌ماند. بگو این رفتار Grid است و اگر خواستند آن یکی هم تمام ردیف را بکشد، مال ماژول Grid است نه این جلسه.

### سؤال کلاسی

- «اگر بلوک `min-width: 900px` را در فایل **بالای** بلوک ۶۰۰px بگذاریم، در عرض ۱۲۰۰px چند ستون می‌بینیم؟»  
  **پاسخ:** دو ستون. هر دو query روشن‌اند و قانون بعدی (۶۰۰px) مقدار را عوض می‌کند. ترتیب فایل در mobile-first بخشی از معنی است.

### اشتباهات رایج

- فراموش کردن viewport.  
- `width: 320px` روی body برای «ساختن موبایل». عرض را ثابت نکن؛ بگذار پنجره تعیین کند.  
- نقطه شکست‌های ۴۸۰ و ۷۶۸ و ۹۹۲ را از حفظ نوشتن چون یک مقاله گفته «سایز آیفون». پایین‌تر روش درست را می‌گوییم.

## ۵) نقطه شکست را از روی به‌هم ریختن محتوا انتخاب کن

«۶۰۰ و ۹۰۰ این تمرین عدد مقدس نیستند. روش کار:

۱. از باریک شروع کن و چیدمان یک‌ستونه را راحت کن.  
۲. پنجره را آرام پهن کن.  
۳. جایی که یک ستون بیش از حد خالی و کشیده شد، همان عرض را در DevTools بخوان و همان حوالی یک `min-width` بگذار.  
۴. دوباره پهن کن تا دو ستون هم بد شود؛ پله بعد.

اگر در ۵۴۰px متن کارت هنوز راحت است، لازم نیست در ۴۸۰ یک query خالی بنویسی. تعداد پله‌ها را کم نگه دار: برای این صفحه دو پله کافی است.

شرط‌های دیگر وجود دارند: `orientation`، `prefers-color-scheme`، `prefers-reduced-motion`. امروز فقط نام `prefers-reduced-motion` را بگو و جزئیاتش را بده به درس اختیاری انیمیشن. شرط اصلی چیدمان همین عرض است.

می‌شود دو شرط را با `and` نوشت:

```css
@media (min-width: 600px) and (max-width: 899px) {
  /* فقط این بازه */
}
```

در mobile-first معمولاً لازم نیست، چون پله بعدی خودش مقدار را عوض می‌کند. نشان بده که ممکن است، بعد در پروژه از آن استفاده نکن تا فایل ساده بماند.»

### سؤال کلاسی

- «سه کارت داریم. در ۷۰۰px دو ستون هنوز خوب است و در ۱۰۰۰px وسط صفحه خالی زیاد دارد. پله دوم را کجا می‌گذاری؟»  
  **پاسخ:** حوالی همان جایی که خالی آزاردهنده شد، نه لزوماً روی نام یک گوشی. عدد را از DevTools بخوان.

## ۶) چه چیزهایی را در query عوض می‌کنیم و چه چیزهایی را نه

روی همان فایل، چند تغییر رایج سایت را اضافه کن تا query فقط «تعداد ستون» نباشد. باز هم عمق Flex نده.

```css
.site-nav {
  display: flex;
  flex-direction: column;
  background: #1a3a5c;
}

.site-nav a {
  color: white;
  padding: 10px 16px;
  text-decoration: none;
}

.hero {
  padding: 1.25rem 1rem;
  background: #0f766e;
  color: white;
}

@media (min-width: 600px) {
  .site-nav {
    flex-direction: row;
  }

  .hero {
    padding: 2.5rem 1.5rem;
  }
}
```

«در موبایل لینک‌های منو زیر هم، هدف لمس بزرگ‌تر. از ۶۰۰px در یک ردیف. `flex-direction` را یک جمله توضیح بده و اگر پرسیدند چرا `row` در راست‌چین از راست شروع می‌شود، بگو در ماژول Flexbox است.

اندازه فونت تیتر را اگر با `clamp` بلدند می‌توانند بدون query سیال کنند (درس اختیاری ۱۹). media query را برای **تغییر ساختار** نگه دار: تعداد ستون، ستونی شدن منو، نشان دادن ستون کناری. برای یک درجه بزرگ‌تر شدن فونت، query اجباری نیست.

چیزی را که در موبایل لازم است `display: none` نکن فقط چون جا کم است، مگر واقعاً تکرار باشد. پنهان کردن منو بدون دکمه جایگزین، محتوا را حذف می‌کند. همبرگریِ واقعی اسکریپت می‌خواهد؛ در این جلسه منو را زیر هم نشان بده، مخفی نکن.»

### اشتباهات رایج

- تفاوت فقط در رنگ، برای اینکه query «کار کرده». کاربر چیدمان را می‌بیند نه آزمایش رنگ را. رنگ جزوه برای دمو شرط است؛ در پروژه ساختار را عوض کن.  
- نوشتن دوباره کل CSS داخل هر query. فقط ویژگی‌هایی که عوض می‌شوند را بنویس.  
- `!important` برای بردن یک عرض. اگر نوبت و ترتیب فایل درست باشد لازم نیست. اولویت را به ماژول آبشاری بسپار.

## ۷) پروژه ترکیبی — رستوران درس ۲۰، mobile-first

فایل درس ۲۰ را کپی کن. سبک‌های پهن (ردیف ۷۰/۳۰، شبکه سه ستونه) را از بخش پایه **بردار** و بگذار داخل `min-width`.

پایه:

```css
.row {
  display: flex;
  flex-direction: column;
  gap: 16px;
}

.row main,
.row aside {
  width: 100%;
}

.grid-3 {
  display: grid;
  grid-template-columns: 1fr;
  gap: 12px;
}
```

ارتقای دسکتاپ:

```css
@media (min-width: 800px) {
  .row {
    flex-direction: row;
    align-items: flex-start;
  }

  .row main { width: 70%; }
  .row aside { width: 30%; }

  .grid-3 {
    grid-template-columns: repeat(3, 1fr);
  }
}
```

«`align-items` را اگر در ۰۷ نخوانده‌اند حذف کن تا ستون‌ها کش بیایند؛ اگر خوانده‌اند، `flex-start` یعنی ارتفاع اضافه را تقسیم نکن و هر ستون به اندازه محتوا بماند. یک جمله، نه تمرین تازه.

عدد ۸۰۰ را این‌طور توجیه کن: دو ستون ۷۰ و ۳۰ با متن فارسی، زیر این حوالی ستون کناری خیلی باریک می‌شود. اگر در آزمایش شما در ۷۶۰px هنوز خوانا بود، همان را بگذار. عدد را از محتوا بگیر.

یک پله میانی اختیاری برای کارت‌ها، اگر وقت هست:

```css
@media (min-width: 560px) {
  .grid-3 { grid-template-columns: 1fr 1fr; }
}
```

یادت باشد بلوک ۸۰۰ که `repeat(3, 1fr)` دارد باید **بعد** از این بیاید.»

**چک لیست پایان پروژه، با صدای بلند روی سه عرض:**

| عرض | انتظار |
|------|--------|
| ۳۲۰px | یک ستون، منو اگر ستونی است زیر هم، بدون اسکرول افقی |
| ۶۰۰px | هنوز ردیف اصلی ستونی، یا اگر پله کارت را گذاشته‌ای کارت‌ها دوتایی؛ صفحه هنوز به پهلو نمی‌لغزد |
| ۱۰۰۰px | محتوا کنار ساعت کاری، سه کارت ویژه در یک ردیف، ظرف از `max-width` بیشتر نرود |

اسکرول افقی را در DevTools با نشانگر overflow پیدا کن. مقصر رایج: `width` پیکسلی ثابت، تصویر بدون `max-width: 100%`، یا جمع درصد و padding. تصویر را اگر در صفحه هست همین حالا محدود کن:

```css
img {
  max-width: 100%;
  height: auto;
}
```

این خط را حتی اگر درس تصویر ماژول ۰۵ است بگو؛ بدون آن media query ستون را درست می‌کند و عکس صفحه را پهن می‌کند.

## ۸) جمع‌بندی مدرس و سؤالات پایانی

1. متای viewport چه را برای CSS درست می‌کند؟  
   **پاسخ:** عرض viewport را به عرض دستگاه وصل می‌کند تا شرط‌های عرضی واقعاً در گوشی فعال شوند و صفحه از پیش مثل یک دسکتاپ کوچک‌شده دیده نشود.

2. در mobile-first قانون یک‌ستونه کجا نوشته می‌شود؟  
   **پاسخ:** بیرون از `@media`، به‌عنوان سبک پایه. `min-width` فقط چیدمان پهن‌تر را اضافه می‌کند.

3. نمونه جزوه با `max-width: 700px` یعنی چه؟  
   **پاسخ:** دسکتاپ‌اول؛ سه ستون پایه است و زیر ۷۰۰px یک ستون می‌شود. معتبر است و با روش این کلاس فرق دارد. در یک فایل قاطی‌شان نمی‌کنیم.

4. نقطه ۷۰۰px را از کجا آورده‌ای؟  
   **پاسخ:** از جایی که چیدمان قبلی واقعاً بد می‌شود، نه از لیست مدل گوشی.

**پیام پایانی:**

«واکنش‌گرا یعنی همان HTML، با چیدمانی که از باریک شروع می‌شود و هر وقت جا هست گسترده‌تر می‌شود. معیار تمام شدن کار، قشنگی لپ‌تاپ نیست؛ نبودن اسکرول افقی در حدود ۳۲۰px و خوانا ماندن متن است.»

## تمرین‌ها (ساده → چالشی)

جزوه: ردیف سه‌ستونه که زیر ۶۰۰px تک‌ستون شود و در DevTools موبایل چک شود. در کلاس این تمرین را **معادل mobile-first** تحویل بگیرند: پایه یک ستون، از ۶۰۰px به بالا سه ستون (یا دو پله). اگر کسی عین `max-width` جزوه را نوشت، قبول است فقط به شرطی که viewport داشته باشد و در همان فایل `min-width` را قاطی نکرده باشد؛ بعد نسخه `min-width` را کنارش ببیند.

### ساده
1. سه کارت دوره با پایه `grid-template-columns: 1fr` و یک `@media (min-width: 600px)` که سه ستون شود. متای viewport فراموش نشود. در ۳۲۰ و در ۹۰۰ چک شود.  
2. جعبه معرفی که متن یا پس‌زمینه‌اش در پهن شدن عوض شود، فقط برای اینکه شرط را در DevTools روشن و خاموش ببینند؛ این جعبه را به‌جای چیدمان واقعی تحویل ندهند.

### متوسط
3. منوی لینک: پایه ستونی، از ۶۰۰px افقی (`flex-direction`). لینک‌ها `padding` کافی برای لمس داشته باشند.  
4. رستوران درس ۲۰ با چک‌لیست سه عرض همین سناریو.

### چالشی
5. صفحه «باغبان» تمرین چیدمان: خدمات در پایه یک ستون، از حدود ۵۶۰px دو ستون، از حدود ۹۰۰px سه ستون. ترتیب بلوک‌ها در فایل طوری باشد که در ۱۲۰۰px سه ستون بماند. یک پاراگراف بنویسند چرا عددها را انتخاب کرده‌اند.  
6. توضیح دهند چرا بدون `<meta name="viewport">` همان query در گوشی واقعی اعمال نمی‌شود.
