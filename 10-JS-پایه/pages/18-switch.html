۱۸) دستور Switch

وقتی یک مقدار را با چند حالت ثابت و مشخص مقایسه می‌کنید، مثل روز هفته یا گزینهٔ یک فهرست، زنجیرهٔ طولانی else if شلوغ می‌شود. switch همان مقدار را یک بار می‌گیرد و هر حالت را در یک case جدا می‌نویسد. این دستور برای بازه‌ها مناسب نیست؛ «بزرگ‌تر از ۱۷» همچنان کار if است، چون case فقط برابری دقیق را بررسی می‌کند.

let day = new Date().getDay();   // 0 = یکشنبه ... 6 = شنبه
let dayName;

switch (day) {
  case 6:
    dayName = "شنبه";
    break;
  case 0:
    dayName = "یکشنبه";
    break;
  case 1:
    dayName = "دوشنبه";
    break;
  case 2:
    dayName = "سه‌شنبه";
    break;
  case 3:
    dayName = "چهارشنبه";
    break;
  case 4:
    dayName = "پنج‌شنبه";
    break;
  case 5:
    dayName = "جمعه";
    break;
  default:
    dayName = "نامعلوم";   // هیچ‌وقت نباید پیش بیاید، ولی نوشتن default عادت خوبی است
}

console.log("امروز " + dayName + " است.");

خروجی این مثال به روزی بستگی دارد که صفحه را باز کرده‌اید.






new Date().getDay() شمارهٔ روز هفته را برمی‌گرداند: ۰ یکشنبه است و ۶ شنبه. switch این عدد را با هر case مقایسه می‌کند. اولین مورد برابر، دستورهای خودش را اجرا می‌کند و break از کل switch بیرون می‌آید تا بقیهٔ روزها نوشته نشوند. اگر هیچ شماره‌ای مطابق نباشد، شاخهٔ default اجرا می‌شود. در عمل برای ۰ تا ۶ این شاخه پیش نمی‌آید، ولی اگر بعداً مقدار دیگری به متغیر برسد، به‌جای متن خالی یک پیام مشخص می‌ماند.





بخشکار


caseیک حالت ممکن


breakاز switch خارج شو (بدون آن، caseهای بعدی هم اجرا می‌شوند)


defaultاگر هیچ case مطابق نبود (مثل else). اختیاری است، ولی بهتر است همیشه بنویسید. معمولاً آخر می‌آید و آنجا break لازم ندارد





چرا break لازم است؟ (Fall-through)



let level = 2;

switch (level) {
  case 1:
    console.log("دسترسی: مشاهده");
  case 2:
    console.log("دسترسی: ویرایش");     // از اینجا شروع می‌شود...
  case 3:
    console.log("دسترسی: حذف");        // ...و چون break نیست، این هم اجرا می‌شود!
}










مقدار level برابر ۲ است، پس اجرا از case 2 شروع می‌شود. چون بعد از چاپ «ویرایش» دستور break نیست، برنامه به case 3 هم ادامه می‌دهد و «حذف» را هم چاپ می‌کند. case 1 چاپ نمی‌شود، چون نقطهٔ شروع قبل از آن نیست. این ادامه پیدا کردن را fall-through می‌نامند.



switch فقط نقطه شروع را با case پیدا می‌کند و از آنجا تا اولین break (یا پایان switch) پیش می‌رود. معمولاً این رفتار باگ است، مگر اینکه عمداً چند case را کنار هم بگذاریم، مثل مثال بعد.



چند case با یک نتیجه



const fruitSelect = document.getElementById("fruit-select");
const fruitInfo = document.getElementById("fruit-info");

fruitSelect.addEventListener("change", function () {
  const fruit = fruitSelect.value;
  let info;

  switch (fruit) {
    case "سیب":
    case "گلابی":
      info = "میوه پاییزی";
      break;
    case "هندوانه":
    case "گیلاس":
      info = "میوه تابستانی";
      break;
    default:
      info = "فصل این میوه در فهرست ما نیست!";
  }

  fruitInfo.textContent = fruit + ": " + info;
});







یک میوه انتخاب کن





رویداد change وقتی انتخاب فهرست عوض شود اجرا می‌شود. چند case پشت سر هم، بدون دستور و بدون break، عمداً یک نتیجه دارند: سیب و گلابی هر دو به همان جملهٔ پاییزی می‌رسند و آنجا break جلوی ادامه را می‌گیرد. اگر مقدار انتخاب‌شده با هیچ میوه‌ای نخوانَد، default پیام جایگزین را می‌سازد. در پایان، نام میوه و توضیح با textContent در صفحه نوشته می‌شوند.



switch برای مقایسه === استفاده می‌کند؛ پس case "1" با عدد 1 برابر نیست. مقدار select و input همیشه متن است؛ اگر caseها عدد هستند، اول مقدار را با Number() تبدیل کنید.



کی switch و کی if؟ switch برای مقایسه یک مقدار با چند حالت ثابت و مشخص است (روز هفته، نوع کاربر، گزینه منو). برای بازه‌ها مثل «نمره بیشتر از ۱۷» از if...else استفاده کنید.



اشتباه رایج: فراموش کردن break. در این حالت اجرای کد به caseهای پایینی «سُر می‌خورد» (fall-through).



تمرین: (۱) تابع getSeason(month) بنویسید که شماره ماه شمسی (۱ تا ۱۲) را بگیرد و با switch فصل را برگرداند: ۱ تا ۳ «بهار»، ۴ تا ۶ «تابستان»، ۷ تا ۹ «پاییز»، ۱۰ تا ۱۲ «زمستان» و برای هر عدد دیگر «ماه نامعتبر» (راهنما: چند case پشت سر هم). (۲) یک select با گزینه‌های «عادی»، «نقره‌ای» و «طلایی» بسازید و با switch درصد تخفیف مشتری (۰، ۵ و ۱۰ درصد) را داخل صفحه نشان دهید.
