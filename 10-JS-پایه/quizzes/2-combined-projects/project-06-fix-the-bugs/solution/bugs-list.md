# پاسخ پروژه ترکیبی ۶: فهرست باگ‌ها

شماره خط‌ها مربوط به فایل `starter/app.js` است. ترتیب جدول همان ترتیبی است که معمولاً هنرجو با باز کردن
Console به باگ‌ها برمی‌خورد (هر باگ تا درست نشود، باگ بعدی را پنهان می‌کند).

| # | خط | باگ | اصلاح | چرا؟ |
| :---: | :---: | --- | --- | --- |
| ۱ | ۸۶ | `addEventListener("click", check())` | `addEventListener("click", check)` | با پرانتز، تابع **همان لحظه** (هنگام بارگذاری صفحه) اجرا می‌شود و حاصلش (`undefined`) به‌عنوان listener ثبت می‌شود؛ پس کلیک هیچ کاری نمی‌کند. باید **خود تابع** را بدهیم، نه نتیجه اجرایش را. |
| ۲ | ۳ | `getElementById("user-name")` | `getElementById("username")` | در HTML شناسه `username` است. با id اشتباه، `usernameInput` برابر `null` می‌شود و `null.value` خطای `TypeError` می‌دهد. |
| ۳ | ۸۳ | `passwordInput.value.length()` | `passwordInput.value.length` | `length` یک **ویژگی** (property) است نه متد؛ صدا زدنش خطای `... .length is not a function` می‌دهد و شمارنده طول رمز کار نمی‌کند. |
| ۴ | ۴۶ | `if (username = "" \|\| password === "")` | `if (username === "" \|\| password === "")` | `=` یعنی **مقداردهی**، نه مقایسه. چون `=` کمترین اولویت را دارد، این خط `username` را برابر `("" \|\| password === "")` یعنی `true` یا `false` می‌کند! نام کاربری از بین می‌رود و بقیه بررسی‌ها روی یک boolean انجام می‌شوند. (اگر `username` را `const` تعریف کرده بودیم، مرورگر خودش خطا می‌داد؛ یکی از دلایلی که `const` را ترجیح می‌دهیم.) |
| ۵ | ۴۱ | `var username = usernameInput.value;` | `const username = usernameInput.value.trim();` | دو اشکال: (الف) بدون `trim()` نام «&nbsp;&nbsp;sara&nbsp;&nbsp;» با فاصله‌ها ذخیره و شمرده می‌شود و «&nbsp;&nbsp;&nbsp;&nbsp;» (فقط فاصله) خالی حساب نمی‌شود. (ب) `var` در این دوره ممنوع است؛ `const` جلوی اشتباهی مثل باگ ۴ را هم می‌گیرد. |
| ۶ | ۱۶ | `return name === "admin";` | `return name.toLowerCase() === "admin";` | مقایسه رشته‌ها به بزرگی و کوچکی حروف حساس است؛ «Admin» یا «ADMIN» از این قانون رد می‌شدند. |
| ۷ | ۲۰ | `password.length >= 8;` (بدون `return`) | `return password.length >= 8;` | تابعی که `return` ندارد همیشه `undefined` برمی‌گرداند. `!undefined` برابر `true` است، پس **هر** رمزی (حتی ۲۰ حرفی) «کوتاه» اعلام می‌شد. |
| ۸ | ۴۳ | `captchaA.textContent + captchaB.textContent` | `Number(captchaA.textContent) + Number(captchaB.textContent)` | `textContent` همیشه **رشته** است و `+` روی دو رشته آن‌ها را **به هم می‌چسباند**: `"7" + "5"` می‌شود `"75"`، نه `12`. تازه `12 !== "75"` و حتی `75 !== "75"` هم هست (نوع متفاوت)، پس هیچ جوابی قبول نمی‌شد. |
| ۹ | ۷۱ تا ۷۶ | `let strength` داخل بلوک‌های `if` و `else` تعریف شده و بیرون از آن‌ها استفاده شده | یک بار **قبل از** `if` تعریف شود: `let strength = "متوسط";` و داخل `if` فقط مقدارش عوض شود | `let` و `const` **محدوده بلوکی** دارند؛ متغیری که داخل `{ }` ساخته شود بیرون از آن وجود ندارد و خط ۷۶ خطای `ReferenceError: strength is not defined` می‌دهد. |

## بررسی نهایی (بعد از اصلاح)

| ورودی | خروجی مورد انتظار |

| نام «&nbsp;&nbsp;sara&nbsp;&nbsp;»، رمز `books2024`، جواب `12` | سبز: «خوش آمدید، sara! قدرت رمز شما: متوسط» |
| نام `reader`، رمز `my-long-password`، جواب `12` | سبز: «... قدرت رمز شما: قوی» |
| نام `Admin`، رمز `books2024`، جواب `12` | «این نام کاربری رزرو شده است؛ ...» |
| نام `sara`، رمز `1234`، جواب `12` | «رمز عبور باید حداقل ۸ حرف باشد.» |
| نام `sara`، رمز `books2024`، جواب `75` | «جواب سؤال امنیتی درست نیست.» |
| نام «&nbsp;&nbsp;&nbsp;»، رمز `books2024` | «نام کاربری و رمز عبور را وارد کنید.» |
| تایپ در کادر رمز | متن «طول رمز: n حرف» هم‌زمان به‌روز می‌شود |

## نمره‌دهی پیشنهادی

هر باگ پیدا و درست‌شده ۱٫۵ نمره (جمعاً ۱۳٫۵) + توضیح درست «چرا» برای هر باگ ۰٫۵ نمره (جمعاً ۴٫۵) + ۲ نمره تمیزی و عدم ایجاد باگ جدید.
