## صورت مسئله

کارآموز قبلی کتابخانه «دانش» یک فرم ورود ساده نوشته و رفته است. فرم ظاهراً درست است ولی **هیچ‌چیزش کار نمی‌کند**:
دکمه ورود واکنشی ندارد، شمارنده طول رمز خطا می‌دهد و حتی جواب درست سؤال امنیتی هم قبول نمی‌شود.
پوشه `starter` کد او را دارد. فایل `index.html` و `style.css` **سالم** هستند؛ همه باگ‌ها در `app.js` است.

**قانون‌های درست فرم** (همان چیزی که کارآموز می‌خواست بسازد):

- فاصله‌های اول و آخر نام کاربری حذف شود؛ نام کاربری و رمز هر دو اجباری‌اند.
- نام کاربری حداقل ۴ حرف و نباید «admin» باشد (با هر ترکیبی از حروف بزرگ و کوچک، مثل `Admin`).
- رمز عبور حداقل ۸ حرف و نباید با نام کاربری یکی باشد.
- جواب سؤال امنیتی باید برابر **مجموع** دو عدد داخل `captcha-a` و `captcha-b` باشد (اینجا ۱۲).
- اگر همه‌چیز درست بود: پیام سبز «خوش آمدید، نام! قدرت رمز شما: ...» (رمز ۱۲ حرف یا بیشتر «قوی»، وگرنه «متوسط»).
- با تایپ در کادر رمز، متن «طول رمز: n حرف» زیر آن به‌روز شود.

## الزامات

1. محتوای پوشه `starter` را در پوشه خودتان کپی کنید و صفحه را با Console باز (<kbd>F12</kbd>) اجرا کنید.
2. در `app.js` **حداقل ۸ باگ** وجود دارد. همه را پیدا و درست کنید؛ ساختار کلی کد (نام تابع‌ها و ترتیب بررسی‌ها) را عوض نکنید.
3. یک فایل `bugs-list.md` بسازید و برای هر باگ یک ردیف جدول بنویسید: **شماره خط** (در فایل اصلی starter)، **کد اشتباه**،
   **کد درست** و **چرا** اشتباه بود (یک یا دو جمله به زبان خودتان).
4. بعد از اصلاح، این موارد آزمون باید درست کار کنند:

| ورودی | خروجی مورد انتظار |
| --- | --- |
| نام «&nbsp;&nbsp;sara&nbsp;&nbsp;» (با فاصله)، رمز `books2024`، جواب `12` | سبز: «خوش آمدید، sara! قدرت رمز شما: متوسط» |
| نام `reader`، رمز `my-long-password`، جواب `12` | سبز: «... قدرت رمز شما: قوی» |
| نام `Admin`، رمز `books2024`، جواب `12` | «این نام کاربری رزرو شده است؛ نام دیگری انتخاب کنید.» |
| نام `sara`، رمز `1234`، جواب `12` | «رمز عبور باید حداقل ۸ حرف باشد.» |
| نام `sara`، رمز `books2024`، جواب `75` | «جواب سؤال امنیتی درست نیست.» |
| نام فقط فاصله، رمز `books2024` | «نام کاربری و رمز عبور را وارد کنید.» |
| تایپ در کادر رمز | «طول رمز: n حرف» هم‌زمان به‌روز شود |
| فقط باز کردن صفحه (بدون کلیک) | هیچ پیامی نمایش داده نشود و Console هیچ خطایی نداشته باشد |

## محدودیت‌ها

- `index.html` و `style.css` را تغییر ندهید (باگ آن‌جا نیست).
- کد را از صفر بازنویسی نکنید؛ فقط خط‌های معیوب را اصلاح کنید.
- در کد نهایی هیچ `var`، `alert` یا `==` نباشد.
- برای پیدا کردن باگ‌ها از Console و `console.log` استفاده کنید؛ ولی `console.log`های اضافه را قبل از تحویل پاک کنید.

## امتیازی (تا ۲ نمره)

- طول رمز با رقم فارسی نمایش داده شود (مثلاً «طول رمز: ۹ حرف»).
- با زدن <kbd>Enter</kbd> در هر کدام از کادرها هم فرم بررسی شود.

## نکته استاد

- باگ‌ها مثل دومینو پشت هم پنهان شده‌اند: تا اولی درست نشود، دومی را نمی‌بینید. بعد از هر اصلاح صفحه را دوباره بارگذاری کنید.
- پیام خطای Console شماره خط را هم می‌گوید؛ روی نام فایل در پیام کلیک کنید تا مستقیم به همان خط بروید.
- همه باگ‌ها خطای قرمز نمی‌دهند! بعضی‌ها فقط **نتیجه غلط** تولید می‌کنند؛ برای آن‌ها مقدار متغیرها را با `console.log` چاپ کنید.
