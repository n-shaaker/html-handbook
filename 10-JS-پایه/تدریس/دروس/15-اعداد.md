## ۱) شروع کلاس؛ مسئله قبل از تعریف

اول با **مسئله** شروع کن — نه با لیست property.

«در JavaScript عدد صحیح و اعشاری نوع جدا ندارند؛ هر دو number هستند. همین نوع برای شمارش، قیمت، نمره و نتیجهٔ تقسیم به کار می‌رود. علاوه بر نوشتن معمولی عدد، می‌توانید توان ده را با حرف e بنویسید. در ادامه می‌بینید چرا بعضی جمع‌های اعشاری دقیقاً همان عددی که روی کاغذ انتظار دارید نمی‌شوند و چطور متنی که کاربر تایپ کرده به عدد قابل محاسبه تبدیل می‌شود.»

«25 عدد صحیح است و 3.75 اعشاری، ولی typeof هر دو را "number" گزارش می‌کند. 2.5e3 یعنی ۲٫۵ ضربدر ۱۰ به توان ۳، یعنی ۲۵۰۰. این شکل برای عددهای خیلی بزرگ یا خیلی کوچک خواناتر از نوشتن صفرهای طولانی است.»

«کامپیوتر عددها را در مبنای ۲ ذخیره می‌کند و بعضی کسرهای ساده مثل 0.1 در مبنای ۲ دقیق نوشته نمی‌شوند (مثل 1/3 که در مبنای ۱۰ می‌شود ...0.333). این مشکل مخصوص JavaScript نیست و در اکثر زبان‌ها وجود دارد. (در کد زیر === یعنی «آیا دقیقاً برابر است؟»؛ در درس بعد کامل توضیح داده می‌شود.)»

«جمع 0.1 و 0.2 در حافظهٔ دودویی دقیقاً 0.3 ذخیره نمی‌شود، پس مقایسهٔ سخت‌گیرانه false می‌شود. toFixed(2) عدد را تا دو رقم اعشار گرد می‌کند، ولی نتیجه را به‌صورت متن برمی‌گرداند. اگر بخواهید دوباره با عدد مقایسه کنید، باید همان متن را با Number به عدد برگردانید.»

**روی جزوه این عناوین را دنبال کنید:** *۱۵) اعداد (Numbers)* · *دقت اعشار* · *NaN و Infinity* · *تبدیل متن به عدد*

## ۳) Live Coding — مرحله‌به‌مرحله

«فایل live جدا می‌سازم تا index پروژه قاطی نشود — مثلاً `تدریس/live/` در همین ماژول.»

**مرحله 1 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
let a = 25;
let b = 3.75;
let c = 2.5e3;      // 2.5 × 1000
console.log(a, b, c);   // 25 3.75 2500
```

**مرحله 2 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
console.log(0.1 + 0.2);                  // 0.30000000000000004 ← نه دقیقاً 0.3!
console.log(0.1 + 0.2 === 0.3);          // false
console.log((0.1 + 0.2).toFixed(2));     // 0.30 ← گرد کردن تا 2 رقم اعشار (خروجی رشته است)
console.log(Number((0.1 + 0.2).toFixed(2)) === 0.3);   // true ← بعد از گرد کردن و تبدیل به عدد
```

**مرحله 3 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
console.log(100 / "سیب");             // NaN = Not a Number
console.log(10 / 0);                  // Infinity
console.log(NaN === NaN);             // false ← NaN با هیچ چیز، حتی خودش، برابر نیست!
console.log(Number.isNaN(NaN));       // true  ← روش درست برای تشخیص NaN
console.log(isNaN("سلام"));           // true  ← isNaN قدیمی اول متن را به عدد تبدیل می‌کند
console.log(Number.isNaN("سلام"));    // false ← "سلام" یک رشته است، نه مقدار NaN
```


**در حین تایپ بگو:** «الان فقط یک تغییر — save — refresh — چه فرقی دیدید؟»

**اشتباه عمدی (یک بار):** یک selector اشتباه یا property روی فرزند نادرست — خطا را با کلاس debug کنید.

## پیوست: نکات تکمیلی از جزوه (برای مدرس)

«نکته برای حساب پول: مبلغ‌ها را تا جای ممکن به صورت عدد صحیح (تومان یا ریال) نگه دارید و درصدها را به شکل price * 9 / 100 حساب کنید. فقط در لحظه نمایش، عدد را گرد کنید.»

«NaN نتیجهٔ محاسبه‌ای است که جواب عددی معتبر ندارد، مثل تقسیم عدد بر متن. 10 / 0 در این زبان خطا نمی‌دهد و Infinity می‌شود. چون NaN با هیچ مقداری، حتی با خودش، برابر نیست، برای تشخیصش از Number.isNaN استفاده می‌کنیم. تابع قدیمی‌تر isNaN اول مقدار را به عدد تبدیل می‌کند؛ به همین دلیل متن «سلام» را هم true گزارش می‌کند، در حالی که خود آن متن مقدار NaN نیست.»

«برای اینکه بفهمید ورودی کاربر عدد معتبر است یا نه، اول آن را با Number() تبدیل کنید و بعد Number.isNaN(n) را بررسی کنید.»

«Number() سخت‌گیر است: کل متن باید عدد باشد. parseInt و parseFloat از اول متن تا جایی که عدد است را می‌خوانند و بقیه را رها می‌کنند.»


**نکته مدرس:** بعد از هر save یک ثانیه مکث کنید تا کلاس خروجی را ببیند.

**نکته مدرس:** یک بار property را عمداً غلط بگذارید و با DevTools پیدا کنید.

**نکته مدرس:** از دانشجو بخواهید قبل از refresh پیش‌بینی بگوید.

**نکته مدرس:** DevTools → Elements → راست‌کلیک → Scroll into view برای آیتم‌های off-screen.

**نکته مدرس:** در RTL جهت main axis را با overlay Flex روی صفحه نشان دهید.
