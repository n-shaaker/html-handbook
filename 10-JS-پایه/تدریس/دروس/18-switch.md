## ۱) شروع کلاس؛ مسئله قبل از تعریف

اول با **مسئله** شروع کن — نه با لیست property.

«وقتی یک مقدار را با چند حالت ثابت و مشخص مقایسه می‌کنید، مثل روز هفته یا گزینهٔ یک فهرست، زنجیرهٔ طولانی else if شلوغ می‌شود. switch همان مقدار را یک بار می‌گیرد و هر حالت را در یک case جدا می‌نویسد. این دستور برای بازه‌ها مناسب نیست؛ «بزرگ‌تر از ۱۷» همچنان کار if است، چون case فقط برابری دقیق را بررسی می‌کند.»

«let day = new Date().getDay(); // 0 = یکشنبه ... 6 = شنبه let dayName; switch (day) { case 6: dayName = "شنبه"; break; case 0: dayName = "یکشنبه"; break; case 1: dayName = "دوشنبه"; break; case 2: dayName = "سه‌شنبه"; break; case 3: dayName = "چهارشنبه"; break; case 4: dayName = "پنج‌شنبه"; break; case 5: dayName = "جمعه"; break; default: dayName = "نامعلوم"; // هیچ‌وقت نباید پیش بیاید، ولی نوشتن default عادت خوبی است } console.log("امروز " + dayName + " است."); خروجی این مثال به روزی بستگی دارد که صفحه را باز کرده‌اید.»

«new Date().getDay() شمارهٔ روز هفته را برمی‌گرداند: ۰ یکشنبه است و ۶ شنبه. switch این عدد را با هر case مقایسه می‌کند. اولین مورد برابر، دستورهای خودش را اجرا می‌کند و break از کل switch بیرون می‌آید تا بقیهٔ روزها نوشته نشوند. اگر هیچ شماره‌ای مطابق نباشد، شاخهٔ default اجرا می‌شود. در عمل برای ۰ تا ۶ این شاخه پیش نمی‌آید، ولی اگر بعداً مقدار دیگری به متغیر برسد، به‌جای متن خالی یک پیام مشخص می‌ماند.»

«let level = 2; switch (level) { case 1: console.log("دسترسی: مشاهده"); case 2: console.log("دسترسی: ویرایش"); // از اینجا شروع می‌شود... case 3: console.log("دسترسی: حذف"); // ...و چون break نیست، این هم اجرا می‌شود! } مقدار level برابر ۲ است، پس اجرا از case 2 شروع می‌شود. چون بعد از چاپ «ویرایش» دستور break نیست، برنامه به case 3 هم ادامه می‌دهد و «حذف» را هم چاپ می‌کند. case 1 چاپ نمی‌شود، چون نقطهٔ شروع قبل از آن نیست. این ادامه پیدا کردن را fall-through می‌نامند.»

**روی جزوه این عناوین را دنبال کنید:** *۱۸) دستور Switch* · *چرا break لازم است؟ (Fall-through)* · *چند case با یک نتیجه*

**چرخه این بخش:** نشان بده → دانشجو حدس بزند → یک خط کد → refresh.

## ۳) Live Coding — مرحله‌به‌مرحله

«فایل live جدا می‌سازم تا index پروژه قاطی نشود — مثلاً `تدریس/live/` در همین ماژول.»

**مرحله 1 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
let day = new Date().getDay();   // 0 = یکشنبه ... 6 = شنبه
let dayName;

switch (day) {
  case 6:
    dayName = "شنبه";
    break;
  case 0:
    dayName = "یکشنبه";
    break;
  case 1:
    dayName = "دوشنبه";
    break;
  case 2:
    dayName = "سه‌شنبه";
    break;
  case 3:
    dayName = "چهارشنبه";
    break;
  case 4:
    dayName = "پنج‌شنبه";
    break;
  case 5:
    dayName = "جمعه";
    break;
  default:
    dayName = "نامعلوم";   // هیچ‌وقت نباید پیش بیاید، ولی نوشتن default عادت خوبی است
}

console.log("امروز " + dayName + " است.");
```

**مرحله 2 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
let level = 2;

switch (level) {
  case 1:
    console.log("دسترسی: مشاهده");
  case 2:
    console.log("دسترسی: ویرایش");     // از اینجا شروع می‌شود...
  case 3:
    console.log("دسترسی: حذف");        // ...و چون break نیست، این هم اجرا می‌شود!
}
```

**مرحله 3 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
const fruitSelect = document.getElementById("fruit-select");
const fruitInfo = document.getElementById("fruit-info");

fruitSelect.addEventListener("change", function () {
  const fruit = fruitSelect.value;
  let info;

  switch (fruit) {
    case "سیب":
    case "گلابی":
      info = "میوه پاییزی";
      break;
    case "هندوانه":
    case "گیلاس":
      info = "میوه تابستانی";
      break;
    default:
      info = "فصل این میوه در فهرست ما نیست!";
  }

  fruitInfo.textContent = fruit + ": " + info;
});
```


**در حین تایپ بگو:** «الان فقط یک تغییر — save — refresh — چه فرقی دیدید؟»

**اشتباه عمدی (یک بار):** یک selector اشتباه یا property روی فرزند نادرست — خطا را با کلاس debug کنید.
