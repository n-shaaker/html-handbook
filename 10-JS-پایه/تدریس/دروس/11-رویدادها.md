## ۱) شروع کلاس؛ مسئله قبل از تعریف

اول با **مسئله** شروع کن — نه با لیست property.

«پیش‌نیاز: اول عنصر را پیدا کنید — DOM چیست؟ بعد رویداد وصل کنید. بدون DOM، addEventListener جایی برای نشستن ندارد.»

«رویداد یعنی اتفاقی که در صفحه می‌افتد: کلیک، تایپ، رفتن ماوس روی عنصر یا ارسال فرم. خودبه‌خود بعد از این اتفاق‌ها کدی اجرا نمی‌شود. با addEventListener به یک عنصر می‌گویید: «وقتی این اتفاق افتاد، این تابع را اجرا کن.» تابعی که این‌طور به رویداد وصل می‌شود، شنونده (listener) نام دارد و تا وقتی صفحه باز است منتظر همان اتفاق می‌ماند.»

«آرگومان اول نام رویداد است و باید رشته باشد، مثل "click" . آرگومان دوم تابعی است که موقع رخ دادن رویداد اجرا می‌شود. این تابع را همان لحظه صدا نمی‌زنید؛ فقط آن را تحویل می‌دهید تا مرورگر در زمان مناسب اجرا کند. element همان عنصری است که قبلاً با شناسه‌اش پیدا کرده‌اید.»

«count بیرون از تابع‌ها ساخته شده تا هر دو دکمه به همان عدد دسترسی داشته باشند. با هر کلیک روی دکمهٔ افزایش، count++ یکی به عدد اضافه می‌کند و textContent عدد تازه را در صفحه می‌نویسد. دکمهٔ صفر کردن همان متغیر را به ۰ برمی‌گرداند و نمایش را هم به‌روز می‌کند. اگر عدد را فقط داخل یکی از تابع‌ها بسازید، دکمهٔ دیگر آن را نمی‌بیند.»

**روی جزوه این عناوین را دنبال کنید:** *۱۱) رویدادها (Events)* · *مثال ۱: شمارنده کلیک* · *مثال ۲: رویداد input — نوشتن همزمان* · *مثال ۳: mouseover و mouseout*

**چرخه این بخش:** نشان بده → دانشجو حدس بزند → یک خط کد → refresh.

## ۳) Live Coding — مرحله‌به‌مرحله

«فایل live جدا می‌سازم تا index پروژه قاطی نشود — مثلاً `تدریس/live/` در همین ماژول.»

**مرحله 1 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
element.addEventListener("نام رویداد", function () {
  // کاری که باید انجام شود
});
```

**مرحله 2 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
let count = 0;
const countBtn = document.getElementById("count-btn");
const resetBtn = document.getElementById("reset-btn");
const countText = document.getElementById("count-text");

countBtn.addEventListener("click", function () {
  count++;
  countText.textContent = count;
});

resetBtn.addEventListener("click", function () {
  count = 0;
  countText.textContent = count;
});
```

**مرحله 3 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
const nameInput = document.getElementById("name-input");
const preview = document.getElementById("preview");

nameInput.addEventListener("input", function () {
  preview.textContent = "سلام " + nameInput.value;   // value یعنی متنی که داخل کادر است
});
```


**در حین تایپ بگو:** «الان فقط یک تغییر — save — refresh — چه فرقی دیدید؟»

**اشتباه عمدی (یک بار):** یک selector اشتباه یا property روی فرزند نادرست — خطا را با کلاس debug کنید.

## پیوست: نکات تکمیلی از جزوه (برای مدرس)

«رویداد input با هر تغییر در کادر اجرا می‌شود، حتی با یک حرف. value متنی است که همین حالا داخل کادر قرار دارد. تابع، کلمهٔ «سلام» را به آن متن می‌چسباند و نتیجه را در پاراگراف پیش‌نمایش می‌نویسد. تا وقتی کاربر چیزی ننوشته، value متن خالی است و فقط «سلام» دیده می‌شود.»

«mouseover وقتی نشانگر وارد محدودهٔ جعبه می‌شود اجرا می‌شود و mouseout وقتی از آن بیرون می‌رود. classList.add کلاس را اضافه می‌کند و classList.remove همان کلاس را برمی‌دارد. هم‌زمان متن جعبه هم عوض می‌شود تا وضعیت برای کسی که رنگ را نمی‌بیند هم روشن باشد.»

«تابع شنونده می‌تواند یک پارامتر بگیرد که معمولاً event نامیده می‌شود. این پارامتر شیئی است که مرورگر دربارهٔ همان اتفاق پر می‌کند. event.key نام کلیدی را برمی‌گرداند که فشرده شده، مثل Enter یا a . رویداد keydown لحظهٔ فشردن کلید را می‌گیرد، نه لحظهٔ رها کردن آن را.»

«ماوس روی گوشی و تبلت وجود ندارد؛ پس کار مهم را فقط به mouseover وابسته نکنید و همیشه راه دیگری (مثل click ) هم بگذارید.»


**نکته مدرس:** بعد از هر save یک ثانیه مکث کنید تا کلاس خروجی را ببیند.

**نکته مدرس:** یک بار property را عمداً غلط بگذارید و با DevTools پیدا کنید.

**نکته مدرس:** از دانشجو بخواهید قبل از refresh پیش‌بینی بگوید.

**نکته مدرس:** DevTools → Elements → راست‌کلیک → Scroll into view برای آیتم‌های off-screen.

**نکته مدرس:** در RTL جهت main axis را با overlay Flex روی صفحه نشان دهید.
