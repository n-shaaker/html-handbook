## ۱) شروع کلاس؛ مسئله قبل از تعریف

اول با **مسئله** شروع کن — نه با لیست property.

«حلقه (Loop) یعنی یک کار را چند بار تکرار کنید، بدون اینکه همان دستور را به تعداد تکرار در کد کپی کنید. حلقهٔ for وقتی مناسب است که از قبل بدانید تکرار چند بار، یا از چه شماره‌ای تا چه شماره‌ای، انجام می‌شود. سه بخش داخل پرانتز این محدوده را مشخص می‌کنند: از کجا شروع شود، تا کی ادامه پیدا کند و بعد از هر دور شمارنده چقدر عوض شود.»

«let i = 1 فقط یک بار، قبل از شروع، شمارنده را می‌سازد. پیش از هر دور، شرط i <= 5 بررسی می‌شود. اگر درست باشد، دستور داخل آکولاد اجرا می‌شود و بعد i++ یکی به شمارنده اضافه می‌کند. وقتی i به ۶ برسد شرط غلط می‌شود و حلقه تمام می‌شود. به همین دلیل عددهای ۱ تا ۵ چاپ می‌شوند، نه ۶.»

«سه بخش داخل پرانتز با ; از هم جدا می‌شوند. گام لازم نیست همیشه i++ باشد؛ می‌تواند i += 10 یا i-- (شمارش معکوس) هم باشد.»

«sum بیرون از حلقه ساخته شده تا حاصل هر دور از بین نرود. در هر تکرار، مقدار فعلی i به جمع اضافه می‌شود. اگر sum را داخل حلقه با let می‌ساختید، هر دور از صفر شروع می‌شد و نتیجهٔ نهایی فقط عدد آخر بود. بعد از پایان حلقه، متغیر جمع هنوز وجود دارد و می‌توان آن را چاپ کرد.»

**روی جزوه این عناوین را دنبال کنید:** *۱۹) حلقه For* · *مثال: جمع اعداد ۱ تا ۱۰۰* · *مثال کاربردی: جدول تبدیل دما (گام ۱۰تایی)* · *محدوده متغیر حلقه (let در for)*

**چرخه این بخش:** نشان بده → دانشجو حدس بزند → یک خط کد → refresh.

## ۳) Live Coding — مرحله‌به‌مرحله

«فایل live جدا می‌سازم تا index پروژه قاطی نشود — مثلاً `تدریس/live/` در همین ماژول.»

**مرحله 1 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
for (let i = 1; i <= 5; i++) {
  console.log("تکرار شماره " + i);
}
```

**مرحله 2 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
let sum = 0;
for (let i = 1; i <= 100; i++) {
  sum += i;
}
console.log(sum);   // 5050
```

**مرحله 3 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
for (let c = 0; c <= 40; c += 10) {
  const f = c * 9 / 5 + 32;
  console.log(`${c}°C = ${f}°F`);
}
```


**در حین تایپ بگو:** «الان فقط یک تغییر — save — refresh — چه فرقی دیدید؟»

**اشتباه عمدی (یک بار):** یک selector اشتباه یا property روی فرزند نادرست — خطا را با کلاس debug کنید.

## پیوست: نکات تکمیلی از جزوه (برای مدرس)

«شمارنده از صفر شروع می‌شود، تا ۴۰ ادامه دارد و به‌جای یکی‌یکی، هر بار ۱۰ واحد زیاد می‌شود. داخل هر دور، همان دما با فرمول به فارنهایت تبدیل می‌شود و هر دو عدد در یک رشتهٔ قالبی چاپ می‌شوند. چون گام ۱۰ است، پنج خط دارید: ۰، ۱۰، ۲۰، ۳۰ و ۴۰.»

«متغیری که با let در پرانتز for ساخته شود، فقط داخل حلقه وجود دارد. اگر بعد از حلقه به مقدار نهایی نیاز دارید، متغیر را قبل از حلقه تعریف کنید.»

«در حلقهٔ اول، i جزئی از خود for است و بعد از آکولاد دیگر وجود ندارد؛ به همین دلیل typeof i رشتهٔ "undefined" است و خطا نمی‌دهد. در حلقهٔ دوم، tries قبل از حلقه ساخته شده تا بعد از پایان هم قابل خواندن باشد. وقتی شرط tries <= 3 غلط می‌شود، گام قبلی شمارنده را به ۴ رسانده است؛ پس مقدار باقی‌مانده ۴ است، نه ۳.»

«در کدهای قدیمی for (var i = 0; ...) زیاد می‌بینید. var بیرون از حلقه هم باقی می‌ماند و اگر داخل حلقه رویداد بسازید، همهٔ رویدادها ممکن است آخرین مقدار همان متغیر را ببینند. در کد تازه شمارنده را با let بسازید. var را فقط وقتی نگه دارید که دارید کد قدیمی را می‌خوانید و به این تفاوت آگاهید.»


**نکته مدرس:** بعد از هر save یک ثانیه مکث کنید تا کلاس خروجی را ببیند.

**نکته مدرس:** یک بار property را عمداً غلط بگذارید و با DevTools پیدا کنید.

**نکته مدرس:** از دانشجو بخواهید قبل از refresh پیش‌بینی بگوید.

**نکته مدرس:** DevTools → Elements → راست‌کلیک → Scroll into view برای آیتم‌های off-screen.

**نکته مدرس:** در RTL جهت main axis را با overlay Flex روی صفحه نشان دهید.
