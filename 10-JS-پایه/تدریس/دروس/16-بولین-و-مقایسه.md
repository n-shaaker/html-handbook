## ۱) شروع کلاس؛ مسئله قبل از تعریف

اول با **مسئله** شروع کن — نه با لیست property.

«نوع boolean فقط دو مقدار دارد: true یعنی درست و false یعنی غلط. این نوع خودش به‌تنهایی کم دیده می‌شود؛ بیشتر وقت‌ها نتیجهٔ یک مقایسه یا ترکیب چند شرط است. برنامه با همین دو مقدار تصمیم می‌گیرد کدام مسیر را اجرا کند. در این درس اول مقایسه را یاد می‌گیرید، بعد ترکیب شرط‌ها را، و در پایان مقدارهایی را که بدون مقایسه هم در شرط «غلط» حساب می‌شوند.»

«عدد ۵ و متن "5" از نظر مقدار شبیه هم‌اند، ولی نوعشان فرق دارد. == قبل از مقایسه نوع را یکسان می‌کند، پس نتیجه true می‌شود. === هم مقدار و هم نوع را می‌بیند و false برمی‌گرداند. > بزرگ‌تر بودن را بررسی می‌کند. !== یعنی «برابر نباشند» و چون هر دو طرف عدد ۵ هستند، نتیجه false است.»

«== اگر دو طرف هم‌نوع نباشند، اول یکی را به نوع دیگر تبدیل می‌کند و بعد مقایسه می‌کند (Type Coercion). این تبدیل خودکار گاهی نتیجه‌هایی می‌دهد که انتظارش را ندارید:»

«متن خالی با == به عدد صفر تبدیل می‌شود، پس با ۰ برابر دیده می‌شود. متن "0" هم همین‌طور. اما متن خالی و متن "0" هر دو رشته‌اند و بدون تبدیل با هم برابر نیستند؛ به همین دلیل نتیجهٔ آن خط false است. null == undefined طبق قاعدهٔ همین عملگر true است، ولی === آن دو را یکی نمی‌داند چون نوعشان فرق دارد.»

**روی جزوه این عناوین را دنبال کنید:** *۱۶) بولین و مقایسه (Booleans & Comparisons)* · *عملگرهای مقایسه* · *چرا == خطرناک است؟* · *مقایسه رشته‌ها*

## ۳) Live Coding — مرحله‌به‌مرحله

«فایل live جدا می‌سازم تا index پروژه قاطی نشود — مثلاً `تدریس/live/` در همین ماژول.»

**مرحله 1 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
let x = 5;
console.log(x == "5");     // true  ← فقط مقدار را مقایسه می‌کند
console.log(x === "5");    // false ← نوع هم فرق دارد
console.log(x > 3);       // true
console.log(x !== 5);      // false
```

**مرحله 2 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
console.log(0 == "");             // true  ← متن خالی به 0 تبدیل شد!
console.log(0 == "0");            // true
console.log("" == "0");           // false ← ولی این دو با هم برابر نیستند!
console.log(null == undefined);   // true
console.log(null === undefined);  // false
console.log(0 === "");            // false ← === هیچ تبدیلی انجام نمی‌دهد
```

**مرحله 3 — روی صفحه بگو:** «الان این قطعه را اضافه می‌کنم و نتیجه را با هم می‌بینیم.»

```javascript
console.log("10" < "9");          // true ← چون حرف "1" قبل از "9" است!
console.log(10 < 9);              // false
console.log("apple" === "Apple"); // false ← بزرگی و کوچکی حروف مهم است
```


**در حین تایپ بگو:** «الان فقط یک تغییر — save — refresh — چه فرقی دیدید؟»

**اشتباه عمدی (یک بار):** یک selector اشتباه یا property روی فرزند نادرست — خطا را با کلاس debug کنید.

## پیوست: نکات تکمیلی از جزوه (برای مدرس)

«در مقایسهٔ معمولی از === و !== استفاده کنید تا تبدیل پنهان نتیجه را عوض نکند. اگر لازم است متن را با عدد مقایسه کنید، خودتان اول با Number() تبدیلش کنید: Number(input.value) === 5 . یک استثنای آگاهانه این است که بعضی برنامه‌نویس‌ها برای «مقدار خالی» از value == null استفاده می‌کنند، چون هم null و هم undefined را true می‌کند؛ اگر این شکل را می‌نویسید، باید عمدی باشد.»

«رشته‌ها حرف‌به‌حرف (بر اساس کد هر حرف) مقایسه می‌شوند، نه بر اساس مقدار عددی:»

«مقایسهٔ دو رشته مثل مقایسهٔ دو عدد نیست. حرف‌ها از چپ با کد عددی خودشان سنجیده می‌شوند. کد حرف "1" از کد حرف "9" کوچک‌تر است، پس "10" < "9" true می‌شود، در حالی که همان مقایسه با عدد واقعی false است. بزرگی و کوچکی حروف انگلیسی هم فرق دارد و "apple" با "Apple" برابر نیست.»

«اشتباه رایج: مقایسه دو مقدار input بدون تبدیل به عدد. "10" > "9" نتیجه false می‌دهد، چون هر دو متن هستند.»


**نکته مدرس:** بعد از هر save یک ثانیه مکث کنید تا کلاس خروجی را ببیند.

**نکته مدرس:** یک بار property را عمداً غلط بگذارید و با DevTools پیدا کنید.

**نکته مدرس:** از دانشجو بخواهید قبل از refresh پیش‌بینی بگوید.

**نکته مدرس:** DevTools → Elements → راست‌کلیک → Scroll into view برای آیتم‌های off-screen.

**نکته مدرس:** در RTL جهت main axis را با overlay Flex روی صفحه نشان دهید.
