## ۱) شروع کلاس — مسئله واقعی

«بچه‌ها، فرض کنید برای کافه محله یک صفحه ساده ساختید. HTML را درست نوشتید: عنوان، توضیح، شاید یک عکس. صفحه را باز می‌کنید و… همه‌چیز شبیه یک سند Word قدیمی است: فونت پیش‌فرض مرورگر، بدون فاصله‌گذاری، بدون حس برند.

مشتری می‌گوید: *«می‌خوام آبی برند ما، تیتر وسط، متن خوانا.»*

آیا باید داخل هر `<h1>` بنویسیم `color="blue"` مثل دههٔ ۹۰؟ یا راه بهتری هست؟»

روی صفحه فقط HTML بگذار (هنوز CSS ننویس):

```html
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>کافه کتاب — بدون CSS</title>
</head>
<body>
  <h1>کافه کتاب</h1>
  <p>قهوه تازه، کتاب خوب و فضایی آرام برای مطالعه.</p>
</body>
</html>
```

**در مرورگر:** تیتر بزرگ پیش‌فرض، متن سیاه، پس‌زمینه سفید.

«همین HTML *معنا* دارد؛ ولی *ظاهر* ندارد. HTML می‌گوید این تیتر است و این پاراگراف؛ CSS می‌گوید چطور دیده شوند.»

---

## ۲) اولین CSS — نتیجه فوری

«حالا یک فایل یا بلوک `<style>` اضافه می‌کنیم. هنوز متن HTML را عوض نمی‌کنیم — فقط ظاهر.»

```html
<style>
  body {
    background-color: #e0f2fe;
    padding: 1rem;
    font-family: Tahoma, sans-serif;
  }
  h1 {
    color: #1a3a5c;
    text-align: center;
  }
  p {
    font-size: 1.125rem;
    line-height: 1.7;
  }
</style>
```

**نمایش:** رفرش — همان دو خط متن، اما حس «صفحه کافه» پیدا کرد.

### سؤال کلاسی

«اگر فقط رنگ تیتر را عوض کنیم و HTML دست نخورده بماند، آیا محتوا برای موتور جستجو عوض شده؟»  
**پاسخ:** خیر — متن و ساختار HTML همان است؛ فقط presentation عوض شده.

### اشتباهات رایج

- فکر کردن CSS جایگزین HTML است (هر دو لازم‌اند).  
- انتظار layout پیچیده بدون HTML معنادار (CSS روی عنصرهایی اعمال می‌شود که HTML ساخته).

---

## ۳) CSS یعنی چه؟ (بعد از دیدن نتیجه)

«حالا اسم را می‌دهیم:

**CSS** یعنی **C**ascading **S**tyle **S**heets — برگه‌های سبک *آبشاری*.

مرورگر اول HTML را می‌خواند و درخت عنصرها را می‌سازد. بعد قوانین CSS را می‌خواند و می‌پرسد: *این قانون به کدام عنصر می‌خورد؟* رنگ، فونت، فاصله، پس‌زمینه… همه از اینجا می‌آید.»

**تشبیه:**

«HTML = اسکلت و دیوار خانه. CSS = رنگ دیوار، کف‌پوش، چیدمان مبل. می‌توانید مبل را جابه‌جا کنید بدون اینکه دیوار را بردارید — در وب یعنی همان متن با CSS دیگر، ظاهر متفاوت.»

---

## ۴) Cascading — یک تعارض ساده

«کلمه *آبشاری* یعنی گاهی **چند قانون** برای **یک عنصر** داریم. مرورگر با قواعد مشخص یکی را برنده می‌کند.»

```css
p {
  color: #64748b;
}
p {
  color: #1e40af;
}
```

«هر دو `p` هستند؛ معمولاً **آخرین** قانون در همان فایل برنده می‌شود — پاراگراف آبی تیره. جزئیات انتخابگر و specificity در درس ۳ و دوره میانی عمیق‌تر می‌شود؛ امروز فقط بدانید CSS یک *سیستم قانون* است، نه یک خط جادویی.»

**Live:** یک قانون را comment کنید — رنگ برگردد.

### سؤال کلاسی

«آیا می‌توانیم با CSS متن داخل `<p>` را از «کافه» به «رستوران» عوض کنیم بدون دست زدن به HTML؟»  
**پاسخ:** نه به‌صورت درست و قابل‌اتکا — محتوا HTML است. CSS برای ظاهر است (`content` در سطح پیشرفته استثناست؛ در مقدماتی نمی‌گوییم).

---

## ۵) چرا CSS جدا از HTML؟

«سه دلیل عملی برای مشتری و برای خودتان:

1. **خوانایی:** فایل HTML کوتاه‌تر؛ طراح CSS را جدا ویرایش می‌کند.  
2. **یک فایل، صد صفحه:** `style.css` را یک بار لینک می‌کنید؛ همه صفحات سایت یک ظاهر می‌گیرند.  
3. **دستگاه‌های مختلف:** بعداً با media query موبایل و دسکتاپ را جدا تنظیم می‌کنید — همان HTML.»

روی [`01-intro.html`](../../pages/01-intro.html) بخش «بدون CSS / با CSS» را با کلاس مقایسه کنید.

**Live Coding مرحله ۲ — همان کد جزوه روی جعبه demo:**

در [`01-intro.html`](../../pages/01-intro.html) استایل فقط روی `.demo-intro-styled` است (فایل [`intro.css`](../../css/demos/intro.css)) تا کل صفحه آموزشی آبی نشود:

```css
.demo-intro-styled {
  background-color: lightblue;
  padding: 10px;
}
.demo-intro-styled h1 {
  color: #1a3a5c;
  text-align: center;
}
.demo-intro-styled p {
  font-family: "Inter", "Vazirmatn", Tahoma, sans-serif;
  font-size: 20px;
}
```

«در پروژه خودتان همان قوانین را روی `body`, `h1`, `p` می‌نویسید — محدود کردن به `.demo-intro-styled` فقط برای جزوه است.»

**در مرورگر — DevTools:** F12 → Sources یا Elements → تیک کنار `<style>` / فایل CSS را بردارید — صفحه فوراً به حالت «بدون CSS» برمی‌گردد. دوباره تیک بزنید — «CSS live است؛ HTML دست نخورده.»

## ۵-ب) ارث‌بری ساده (inheritance)

«بعضی propertyها از والد به فرزند **ارث** می‌رسند — مثلاً `font-family` و `color` روی `body`:

```css
body {
  font-family: Tahoma, sans-serif;
  color: #334155;
}
```

`<h1>` و `<p>` بدون قانون جدا همان فونت را می‌گیرند — مگر override کنید:

```css
h1 {
  color: #0c4a6e;
}
```

**Live:** فقط `body { color: red; }` — همه متن قرمز مگر جایی رنگ خاص داده باشید.

### سؤال کلاسی

«`background-color` روی `body` به `<p>` ارث می‌رسد؟»  
**پاسخ:** خیر — پس‌زمینه معمولاً ارث نمی‌شود؛ `p` شفاف است و پس‌زمینه `body` از پشت دیده می‌شود.

### اشتباهات رایج

- شلوغ کردن HTML با attributeهای ظاهری قدیمی (`bgcolor`, `font`) — در پروژه مدرن CSS.  
- کپی کردن همان `<style>` در ۲۰ صفحه به‌جای یک فایل خارجی (درس ۴).

## ۶) پروژه mini جلسه — کافه کتاب

یک صفحه کامل بسازید؛ همه مهارت‌های امروز در یک جا:

```html
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>کافه کتاب</title>
  <style>
    body {
      margin: 0;
      min-height: 100vh;
      background: linear-gradient(180deg, #e0f2fe 0%, #f8fafc 100%);
      font-family: Tahoma, sans-serif;
      padding: 2rem 1rem;
    }
    .hero {
      max-width: 28rem;
      margin-inline: auto;
      text-align: center;
    }
    h1 {
      color: #0c4a6e;
      margin-block: 0 0.75rem;
    }
    .tagline {
      color: #475569;
      font-size: 1.1rem;
      line-height: 1.75;
    }
  </style>
</head>
<body>
  <main class="hero">
    <h1>کافه کتاب</h1>
    <p class="tagline">قهوه تازه، کتاب خوب و فضایی آرام برای مطالعه.</p>
  </main>
</body>
</html>
```

«HTML فقط معنا؛ CSS حس برند. فردا یاد می‌گیریم *ساختار* هر خط CSS چطور نوشته می‌شود — selector و `{ property: value; }`.»

## ۷) جمع‌بندی و سؤالات پایانی

1. HTML و CSS هر کدام چه نقشی دارند؟  
   **راهنما:** ساختار/محتوا در برابر ظاهر.

2. اگر دو قانون `p { color: ... }` پشت سر هم باشد، معمولاً کدام اعمال می‌شود؟  
   **راهنما:** آخرین (در همان منبع و سطح specificity).

3. چرا یک فایل CSS مشترک برای کل سایت بهتر از استایل داخل هر صفحه است؟  
   **راهنما:** نگهداری، یکپارچگی، کش مرورگر.

**پیام پایانی:** «CSS جادو نیست — زبان قانون برای مرورگر است. هر درس بعدی یک لایه از همین ظاهر را دقیق‌تر می‌کند.»
