## ۱) شروع — «کد خودم را نمی‌فهمم»

«سه ماه بعد `style.css` را باز می‌کنید: ۲۰۰ خط rule پشت سر هم. کدام بخش مربوط منو است؟ کدام مربوط footer؟

**کامنت** برای انسان است؛ مرورگر آن را **نادیده** می‌گیرد. CSS مثل آشپزخانهٔ مشترک — برچسب بزنید.»

---

## ۲) syntax درست

```css
/* این یک خط comment است */

/*
  چند خط
  توضیح بخش کارت‌ها
*/

.card {
  padding: 1rem;
}
```

«**`//` در CSS استاندارد comment نیست** — بعضی preprocessorها دارند؛ در فایل خام مرورگر ممکن است rule بعدی را خراب کند. فقط `/* */`.»

---

## ۳) غیرفعال کردن موقت یک rule

«می‌خواهید ببینید بدون `background` چطور است — delete نکنید:**

```css
.card {
  padding: 1rem;
  /* background: #fff; */
  border: 1px solid #e2e8f0;
}
```

**Live:** comment را باز/بسته کنید — رفرش.

### سؤال کلاسی

«اگر `/*` باز کنیم و `*/` نگذاریم چه می‌شود؟»  
**پاسخ:** از همان نقطه تا انتهای فایل (یا تا `*/` بعدی) همه comment — **کل CSS بعدی از بین.**

### اشتباهات رایج

- nest کردن comment در comment (در CSS مشکل‌ساز).  
- comment کردن فقط `{` — syntax به هم می‌ریزد.

---

## ۴) سازماندهی فایل واقعی

```css
/* === پایه: reset و body === */
*, *::before, *::after { box-sizing: border-box; }
body { margin: 0; font-family: Tahoma, sans-serif; }

/* === کامپوننت: کارت === */
.card { ... }
.card__title { ... }

/* === utilities === */
.text-center { text-align: center; }
```

«الگوی جزوه: سرتیتر بخش با `===` — در تیم قرارداد واحد بگذارید.»

---

## ۵) Live — فایل شلوغ را مرتب کنید

به دانشجو یک `style.css` ۴۰ خطی بدون comment بدهید؛ ۵ دقیقه section header اضافه کنند.

---

## ۶) comment برای «چرا» نه «چه»

«کامنت بد: `/* رنگ آبی */` — کامنت خوب: `/* contrast روی #f8fafc تست شده */`»

---

## ۷) Live extended

۲۰ خط CSS بدون ساختار → section header + comment-out rule مشکوک + تست.

---

## ۸) جمع‌بندی

1. comment در CSS با چه syntax؟  
2. چرا `//` توصیه نمی‌شود؟  
3. comment برای debug موقت چطور کمک می‌کند؟  
4. اگر `*/` فراموش شود؟
