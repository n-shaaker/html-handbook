۲) ساختار نوشتن CSS (Syntax)

هر دستور CSS یک «قانون» است. قانون از دو بخش ساخته می‌شود: انتخابگر، که می‌گوید ظاهر روی کدام عنصرها اعمال شود، و بلوک تعریف‌ها، که داخل آکولاد مشخص می‌کند آن عنصرها چه ظاهری بگیرند. 

p {
  color: red;
  text-align: center;
}

در این قانون، انتخابگر p به مرورگر می‌گوید ظاهر روی همه پاراگراف‌ها اعمال شود. داخل آکولاد دو تعریف آمده است. تعریف اول ویژگی color را برابر red می‌گذارد و رنگ متن را قرمز می‌کند. تعریف دوم ویژگی text-align را برابر center می‌گذارد و متن را در وسط جعبه خودش قرار می‌دهد. دونقطه ویژگی را از مقدار جدا می‌کند و نقطه‌ویرگول پایان هر تعریف را نشان می‌دهد. اگر چند تعریف در یک بلوک باشد، مرورگر همه آن‌ها را با هم روی همان عنصرها اعمال می‌کند.

بخش در مثال بالا معنی
Selector (انتخابگر) p مشخص می‌کند این قانون روی کدام عنصرهای صفحه اعمال شود.
Property (ویژگی) color نام چیزی است که می‌خواهیم تغییر کند؛ مثل رنگ متن یا ترازبندی.
Value (مقدار) red نتیجهٔ دلخواه همان ویژگی است؛ در این مثال رنگ قرمز.
Declaration (تعریف) color: red; یک جفت ویژگی و مقدار که با : از هم جدا و با ; تمام می‌شود
Declaration block (بلوک تعریف‌ها) { ... } همه تعریف‌های یک قانون، داخل آکولاد

همه پاراگراف‌ها قرمز و وسط‌چین می‌شوند.

این پاراگراف دوم است و همان ظاهر را گرفته است.

چند قاعده نوشتاری

  • فاصله‌ها و خط‌های جدید برای مرورگر مهم نیستند؛ p{color:red} هم درست است، ولی نوشتن هر تعریف در یک خط، کد را خواناتر می‌کند.
  • نام ویژگی‌ها و مقدارها را با حروف کوچک بنویسید (مثل background-color). کلمه‌های چندبخشی با خط تیره (-) به هم وصل می‌شوند.
  • بعد از آخرین تعریف هم ; بگذارید تا اگر بعداً تعریف تازه‌ای اضافه کردید، خطا پیش نیاید.
  • اگر مرورگر نام ویژگی یا مقداری را نشناسد، فقط همان یک تعریف را نادیده می‌گیرد و بقیه قانون اجرا می‌شود.

اشتباه رایج: فراموش کردن ; در پایان یک تعریف. در این حالت مرورگر آن تعریف و تعریف بعدی را یکی می‌خواند و هر دو از کار می‌افتند. فراموش کردن } در پایان قانون بدتر است: قانون‌های بعدی هم ممکن است خراب شوند.
غلط‌های تایپی هم رایج‌اند: colour به جای color، یا = به جای :.

تمرین: قانونی بنویسید که همه تیترهای h2 سبز و وسط‌چین شوند.
