۵) توضیحات (Comments)

توضیح یا کامنت متنی است که برای خودمان و هم‌تیمی‌ها می‌نویسیم تا بعداً دلیل یک تصمیم در کد روشن باشد. مرورگر هر چه بین /* و */ باشد را هنگام اعمال ظاهر نادیده می‌گیرد؛ پس توضیح نه رنگی عوض می‌کند و نه اندازه‌ای. توضیح می‌تواند یک خط باشد، کنار یک تعریف بنشیند، یا چند خط را در بر بگیرد. 

/* این یک توضیح یک‌خطی است */
p {
  color: red; /* توضیح کنار یک تعریف */
}

/*
  توضیح
  چندخطی
*/

کاربردهای واقعی توضیح

۱. بخش‌بندی فایل: وقتی فایل CSS بلند می‌شود، پیدا کردن قانون مربوط به هدر یا کارت محصول وقت‌گیر است. یک توضیح کوتاه در ابتدای هر بخش، مرز آن قسمت را نشان می‌دهد و جست‌وجو در فایل را ساده می‌کند: 

/* ===== هدر و منوی بالای سایت ===== */
.site-header { ... }

/* ===== کارت محصولات ===== */
.product-card { ... }

/* ===== فوتر ===== */
.site-footer { ... }

۲. توضیح «چرا»: نام ویژگی معمولاً خودش می‌گوید چه کاری انجام می‌شود. توضیح مفید دلیلی را می‌نویسد که از روی کد معلوم نیست؛ مثلاً چرا یک حداقل ارتفاع انتخاب شده تا متن روی تصویر در صفحه باریک بریده نشود: 

.banner {
  min-height: 300px; /* تا متن روی تصویر در موبایل بریده نشود */
}

۳. غیرفعال کردن موقت کد: هنگام پیدا کردن خطا، اگر یک تعریف را پاک کنید ممکن است بعداً مقدار درستش را فراموش کنید. با گذاشتن همان تعریف بین /* و */، مرورگر موقتاً آن را اجرا نمی‌کند و متن اصلی برای برگرداندن سر جایش می‌ماند: 

.card {
  padding: 16px;
  /* border: 2px solid red; */
}

در بیشتر ویرایشگرها (مثل VS Code) با کلیدهای Ctrl + / خط انتخاب‌شده به توضیح تبدیل می‌شود و دوباره برمی‌گردد.

اشتباه رایج: نوشتن توضیح HTML یعنی <!-- --> داخل فایل CSS، یا // که در CSS کار نمی‌کند (و معمولاً قانون بعدی را هم خراب می‌کند).
توضیح تودرتو هم ممکن نیست: اولین */ توضیح را می‌بندد و بقیه متن، کد غلط حساب می‌شود.
یادتان باشد فایل CSS برای همه بازدیدکننده‌ها قابل دیدن است؛ هیچ اطلاعات خصوصی در توضیح‌ها ننویسید.

تمرین: فایل CSS صفحه معرفی‌تان را با توضیح به بخش‌های «عمومی»، «تیترها»، «لینک‌ها» و «جدول» تقسیم کنید. بعد یکی از تعریف‌ها را موقتاً با توضیح غیرفعال کنید و نتیجه را ببینید.
