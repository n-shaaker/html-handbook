- **زمان پیشنهادی:** ۶۰ دقیقه

**هدف پروژه:** نوشتن یک فرم رزرو کامل که هر قانون در یک تابع جدا باشد و تاریخ را هم با کمک `Date` بررسی کند.

## مباحث مرتبط

- [صفحه پروژه منوی نارنج](../../../index.html) و کد آن در [`js/app.js`](../../../js/app.js): بخش «اعتبارسنجی فرم رزرو»
- رویداد `submit` و `preventDefault`، ویژگی `novalidate`، Regex و `test`، `classList`، `focus()`

## صورت مسئله

تلفن «نارنج» هر شب با رزروهای اشتباه زنگ می‌خورد: شماره‌های ناقص، تاریخ‌های گذشته و «۰ نفر»!
فرم رزرو (پوشه `starter`) ویژگی `novalidate` دارد، یعنی مرورگر خودش چیزی را بررسی نمی‌کند و همه بررسی‌ها
با شماست. پیام‌های خطا باید زیر همان کادر نوشته شوند.

هر کادر یک `<small class="field-error" id="...-error">` زیر خودش دارد (مثلاً `name-error` برای کادر `name`).

## الزامات

1. محتوای پوشه `starter` را کپی کنید؛ فقط `app.js` را بنویسید. با ارسال فرم، صفحه دوباره بارگذاری نشود.
2. قانون‌ها (هر کدام در **یک تابع جدا** که متن خطا یا رشته خالی برگرداند):
   - **نام:** بعد از `trim()` حداقل ۳ حرف ← «نام را کامل بنویسید (حداقل ۳ حرف).»
   - **موبایل:** بعد از `trim()` با الگوی `/^09\d{9}$/` جور باشد
     ← «شماره موبایل باید ۱۱ رقم باشد و با ۰۹ شروع شود.»
   - **تاریخ:** خالی نباشد و از امروز عقب‌تر نباشد (امروز قبول است) ← دو پیام جدا برای «خالی» و «گذشته».
   - **تعداد نفرات:** عدد **صحیح** بین ۱ تا ۲۰ ← «تعداد نفرات باید عددی صحیح بین ۱ تا ۲۰ باشد.»
3. با ارسال فرم **همه** کادرها بررسی شوند (نه فقط تا اولین خطا) و خطای هر کادر در `small` زیر خودش نوشته شود.
4. کادر نامعتبر کلاس `invalid` بگیرد و کادر درست این کلاس را نداشته باشد (CSS آماده با همین کلاس کادر را قرمز می‌کند).
5. اگر خطا وجود داشت، **اولین** کادر نامعتبر (به ترتیب فرم) فوکوس بگیرد و `#form-message` بنویسد
   «لطفاً خطاهای فرم را برطرف کنید.» با کلاس `error`.
6. اگر همه درست بود، `#form-message` با کلاس `success` یک خلاصه بنویسد، مثلاً:
   «✔ مریم احمدی عزیز، رزرو ۴ نفر برای دوشنبه ۴ آبان ۱۴۰۵ (تخت سنتی) ثبت شد.» (تاریخ و عدد با `toLocaleDateString` و
   `toLocaleString` فارسی). بعد فرم با `form.reset()` خالی شود.
7. وقتی کاربر شروع به اصلاح یک کادر نامعتبر می‌کند (رویداد `input`)، خطای **همان** کادر پاک شود.
   برای این کار فقط **یک** listener روی خود فرم بنویسید.
8. در تقویم کادر تاریخ، روزهای گذشته قابل انتخاب نباشند (ویژگی `min` را با JavaScript روی تاریخ امروز بگذارید).

### موارد آزمون

| کادر | ورودی | نتیجه مورد انتظار |
| --- | --- | --- |
| نام | `علی` | درست |
| نام | `  ع  ` | خطا (بعد از trim یک حرف است) |
| موبایل | `09123456789` | درست |
| موبایل | `0912345678` (۱۰ رقم) | خطا |
| موبایل | `9123456789` | خطا |
| موبایل | `0912345678a` | خطا |
| تاریخ | (خالی) | خطای «تاریخ رزرو را انتخاب کنید.» |
| تاریخ | دیروز (با تایپ دستی) | خطای «گذشته» |
| تاریخ | امروز | درست |
| نفرات | `0` یا `21` یا (خالی) | خطا |
| نفرات | `2.5` | خطا |
| نفرات | `20` | درست |
| کل فرم | نام خالی و موبایل اشتباه | هر دو خطا هم‌زمان نمایش داده شوند و فوکوس روی **نام** برود |
| کل فرم | همه درست | پیام سبز خلاصه رزرو، فرم خالی می‌شود، هیچ کادری قرمز نیست |

## محدودیت‌ها

- `onclick` داخل HTML، `alert` و `var` ممنوع.
- `novalidate` را از فرم برندارید و از `required`/`pattern` برای انجام کار JavaScript استفاده نکنید.
- پیام‌ها با `textContent` نوشته شوند (نام را کاربر وارد می‌کند).
- رنگ قرمز کادر را با `style` در JavaScript عوض نکنید؛ CSS آماده بر اساس کلاس `invalid` کار می‌کند.

## امتیازی (تا ۲ نمره)

- هر کادر وقتی کاربر از آن بیرون می‌رود (رویداد `change`) هم جداگانه بررسی شود، نه فقط هنگام ارسال فرم.
- یک کادر «توضیحات» (`textarea`، حداکثر ۱۰۰ حرف) به فرم اضافه کنید و زیرش تعداد حرف‌های باقی‌مانده را نشان دهید.

## نکته استاد

- مقدار `input type="date"` همیشه به شکل `2026-10-25` است؛ رشته‌های هم‌قالب را می‌شود مستقیم با `<` مقایسه کرد،
  ولی `new Date()` ساعت هم دارد و مقایسه مستقیمش با تاریخ امروز را خراب می‌کند.
- `Number("")` صفر است و `Number("2.5")` عدد درستی است؛ «صحیح بودن» را جدا بسنجید.
- اگر فقط تا اولین خطا بررسی کنید و `return` کنید، کاربر باید چند بار فرم را بفرستد تا همه خطاها را ببیند.
