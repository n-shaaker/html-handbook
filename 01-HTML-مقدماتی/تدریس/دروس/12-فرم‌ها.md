## ۱) شروع کلاس — مسئله فروشگاه

«صاحب فروشگاه می‌گوید: *«یک فرم تماس بذار — اسم، ایمیل، پیام.»*

دانشجو input گذاشته ولی **submit** می‌زند — در Network **هیچ name=value** نیست. چرا؟

فرم پل **کاربر → سرور** است. HTML فیلدها را **نام‌گذاری** می‌کند؛ backend (بعداً) می‌خواند. امروز HTML side — ولی `name` را جدی بگیرید.»

---

## ۲) اسکلت form

پایه Live: [`live/12-forms.html`](../live/12-forms.html)

```html
<form action="#" method="post">
  ...
  <button type="submit">ارسال</button>
</form>
```

«`action` = URL مقصد ( `#` فعلاً placeholder).  
`method` = **get** (در query string) یا **post** (body) — برای تماس معمولاً post.»

### سؤال کلاسی

«اگر `method="get"` باشد، name=value کجا دیده می‌شود؟»  
**پاسخ:** در URL بعد از `?` — DevTools → Network.

---

## ۳) label — کلیک روی متن = focus فیلد

```html
<label for="email">ایمیل</label>
<input id="email" name="email" type="email">
```

«`for` و `id` **یکسان** — a11y و UX. **هرگز** فقط placeholder به‌جای label.»

**Live:** روی label کلیک — cursor در input.

### اشتباهات رایج

- input بدون `name` — در submit کلاسیک داده نمی‌رود  
- id تکراری در صفحه  
- label بدون for و input بدون wrap

---

## ۴) input type=text و email

```html
<input name="name" type="text" autocomplete="name" required>
<input name="email" type="email" required>
```

«`type="email"` — validation سبک مرورگر (درس ۱۹ عمیق‌تر).  
`required` — HTML5 بدون JS.»

**نمایش:** submit خالی — پیام مرورگر فارسی/انگلیسی.

---

## ۵) textarea

```html
<label for="msg">پیام</label>
<textarea id="msg" name="message" rows="4" required></textarea>
```

«متن چندخطی — **نه** br دستی داخل input.»

---

## ۶) button types

```html
<button type="submit">ارسال</button>
<button type="reset">پاک کردن</button>
<button type="button">فقط JS</button>
```

«داخل form، `<button>` پیش‌فرض **submit** — اگر JS نمی‌خواهید `type="button"` بزنید.»

---

## ۷) checkbox و radio

```html
<fieldset>
  <legend>نوع درخواست</legend>
  <label><input type="radio" name="topic" value="order"> سفارش</label>
  <label><input type="radio" name="topic" value="support"> پشتیبانی</label>
</fieldset>
```

«**radio:** یک `name` — یک انتخاب. **checkbox:** name یکسان یا جدا بسته به backend.»

```html
<label><input type="checkbox" name="newsletter" value="yes"> خبرنامه</label>
```

---

## ۸) select

```html
<label for="city">شهر</label>
<select id="city" name="city">
  <option value="">انتخاب کنید</option>
  <option value="teh">تهران</option>
  <option value="isf">اصفهان</option>
</select>
```

«`value` چیزی است که submit می‌شود؛ متن option برای کاربر.»

---

## ۹) سؤال چالشی

«دو input با `name="email"` — چه می‌شود؟»  
**راه‌حل:** معمولاً آخرین یا هر دو بسته به method — **name یکتا** per field منطقی.
