۱۹) ویژگی‌های تگ form

در درس ۱۲ با عنصرهای اصلی فرم آشنا شدیم. اینجا می‌بینیم فرم داده را کجا می‌فرستد، هر نوع input چه رفتاری دارد و مرورگر پیش از ارسال چه چیزهایی را بررسی می‌کند. این بررسی مرورگر برای کمک به کاربر است و جای بررسی سمت سرور را نمی‌گیرد. 

<form action="/register" method="post" target="_blank" autocomplete="on">
  ...
</form>
ویژگی کاربرد
action action نشانی صفحه یا برنامهٔ سمت سرور است که داده‌ها را دریافت می‌کند.
method="get" داده‌ها به انتهای آدرس اضافه می‌شوند (?name=sara). مناسب جستجو. برای اطلاعات حساس نه.
method="post" داده‌ها در بدنه درخواست ارسال می‌شوند و در نوار نشانی دیده نمی‌شوند. مناسب ثبت‌نام، ورود و اطلاعات حساس. (توجه: post به‌تنهایی داده را رمزنگاری نمی‌کند؛ امنیت واقعی با https تأمین می‌شود.)
target target می‌گوید پاسخ فرم کجا باز شود. _self پیش‌فرض است و همان زبانه را عوض می‌کند. _blank زبانهٔ تازه باز می‌کند.
autocomplete با on مرورگر می‌تواند مقدارهای قبلی را پیشنهاد دهد و با off این پیشنهاد برای همان فرم کمتر می‌شود. مرورگرها همیشه این درخواست را مو به مو اجرا نمی‌کنند.
novalidate ویژگی بولی novalidate بررسی خودکار مرورگر را برای همین فرم خاموش می‌کند. داده همچنان ارسال می‌شود و سرور باید خودش آن را بررسی کند.

خطای متداول: فراموش کردن ویژگی name روی فیلدها. فیلدی که name نداشته باشد ارسال نمی‌شود. name نام داده است و value مقدار آن. id فقط فیلد را در صفحه پیدا می‌کند و جای name را نمی‌گیرد.

این فرم را پر کنید و ارسال کنید، سپس به نوار نشانی نگاه کنید. چون روش get است، نام و مقدار فیلد به انتهای نشانی اضافه می‌شود:

<form action="" method="get">
  <label for="q">جستجو:</label>
  <input type="search" id="q" name="q">
  <button type="submit">برو</button>
</form>

همه انواع input

با تغییر ویژگی type، همان عنصر input شکل و رفتار متفاوتی پیدا می‌کند. نوع، هم ظاهر را عوض می‌کند و هم به مرورگر می‌گوید چه مقداری معتبر است. همه را در جدول زنده امتحان کنید:

type نمونه زنده کاربرد
text متن یک‌خطی است. اگر type ننویسید، همین حالت پیش‌فرض است.
password گذرواژه را پنهان نشان می‌دهد. این پنهان‌سازی فقط ظاهری است.
email رایانامه را می‌گیرد، شکل کلی آن را بررسی می‌کند و در تلفن همراه معمولاً صفحه‌کلید دارای @ باز می‌کند.
number عدد می‌گیرد و معمولاً دکمهٔ کم و زیاد نشان می‌دهد. بازه را با min و max محدود می‌کنند.
tel شمارهٔ تلفن را می‌گیرد. مرورگر قالب بین‌المللی را سخت‌گیرانه بررسی نمی‌کند، اما در تلفن همراه معمولاً صفحه‌کلید عددی باز می‌کند.
url نشانی وب را می‌گیرد و وجود پروتکل را معمولاً لازم می‌داند.
search کادر جستجو است. از نظر ارسال داده شبیه متن است، اما بعضی مرورگرها دکمهٔ پاک کردن نشان می‌دهند.
date تاریخ را با انتخاب‌گر مرورگر می‌گیرد. شکل نمایش به زبان و مرورگر بستگی دارد.
time ساعت را جدا از تاریخ می‌گیرد.
datetime-local تاریخ و ساعت محلی را با هم می‌گیرد و منطقهٔ زمانی را در خود مقدار ذخیره نمی‌کند.
month / week ماه یا هفته را می‌گیرد. نمونهٔ زنده month است. در بعضی مرورگرها، مثل Firefox، این نوع‌ها هنوز کادر متنی ساده‌اند.
color یک رنگ را انتخاب می‌کند و مقدار آن معمولاً به شکل HEX فرستاده می‌شود.
range مقدار را با یک لغزنده بین min و max می‌گیرد، مثل تنظیم صدا.
file به کاربر اجازه می‌دهد پرونده‌ای را برای ارسال انتخاب کند. خود HTML پرونده را ذخیره نمی‌کند.
checkbox چند انتخاب مستقل را ممکن می‌کند. هر خانه جداگانه تیک می‌خورد.
radio فقط یک گزینه از گروهی که name یکسان دارند انتخاب می‌شود.
hidden (دیده نمی‌شود)
<input type="hidden" name="product_id" value="1024">		 داده‌ای را می‌فرستد که در صفحه دیده نمی‌شود، مثل شناسهٔ کالا. این مقدار با ابزار توسعه‌دهنده قابل تغییر است و نباید مبنای امنیت باشد.
submit فرم را ارسال می‌کند. عنصر button داخل فرم هم اگر نوع دیگری نداشته باشد همین کار را می‌کند.
reset فیلدها را به مقدار اولیهٔ صفحه برمی‌گرداند، نه لزوماً به خالی.
button دکمه‌ای است که فرم را ارسال نمی‌کند و تا وقتی JavaScript به آن رفتار ندهد کاری انجام نمی‌دهد.

radio — یک گروه با name یکسان

دکمه‌های رادیویی فقط وقتی «یکی از چند» می‌شوند که name یکسان داشته باشند. اگر نام‌ها فرق کند، هر کدام جدا انتخاب می‌شود. value مشخص می‌کند چه چیزی به سرور برسد. متن کنار دکمه فقط برای کاربر است. 

<fieldset>
  <legend>روش ارسال سفارش:</legend>
  <input type="radio" id="post" name="shipping" value="post" checked>
  <label for="post">پست پیشتاز</label>
  <input type="radio" id="courier" name="shipping" value="courier">
  <label for="courier">پیک (فقط تهران)</label>
  <input type="radio" id="pickup" name="shipping" value="pickup">
  <label for="pickup">تحویل حضوری</label>
</fieldset>
روش ارسال سفارش:

قرار دادن گروه radio یا checkbox داخل fieldset با legend باعث می‌شود صفحه‌خوان پرسش اصلی («روش ارسال سفارش») را همراه هر گزینه بخواند.

checkbox — چند انتخاب

<fieldset>
  <legend>مهارت‌های شما:</legend>
  <input type="checkbox" id="html" name="skills" value="html" checked>
  <label for="html">HTML</label>
  <input type="checkbox" id="css" name="skills" value="css">
  <label for="css">CSS</label>
  <input type="checkbox" id="js" name="skills" value="js">
  <label for="js">JavaScript</label>
</fieldset>
مهارت‌های شما:

ویژگی‌های input

ویژگی کاربرد نمونه زنده
value مقدار اولیهٔ فیلد است و اگر کاربر آن را عوض نکند، همین مقدار ارسال می‌شود.
placeholder متن راهنمای کم‌رنگ داخل کادر است و با شروع تایپ ناپدید می‌شود. جای label را نمی‌گیرد.
readonly فیلد را فقط‌خواندنی می‌کند. کاربر مقدار را عوض نمی‌کند، اما مقدار هنگام ارسال فرستاده می‌شود.
disabled فیلد را غیرفعال می‌کند. نه قابل ویرایش است و نه مقدارش ارسال می‌شود.
required پر کردن فیلد را پیش از ارسال اجباری می‌کند. اگر خالی بماند، مرورگر فرم را نمی‌فرستد. (مثال پایین)
maxlength / minlength حداکثر و حداقل تعداد نویسه را مشخص می‌کند. این محدودیت با تعداد نویسه است، نه با تعداد کلمه.
min / max / step بازه و گام مقدار عددی یا تاریخی را مشخص می‌کند. step فاصلهٔ مقدارهای مجاز است.
pattern الگوی مجاز را با عبارت باقاعده (Regex) مشخص می‌کند و فقط وقتی فیلد خالی نباشد بررسی می‌شود. (مثال پایین)
size عرض کادر را بر حسب تعداد نویسه پیشنهاد می‌کند. اندازهٔ دقیق ظاهری را CSS بهتر کنترل می‌کند.
multiple اجازه می‌دهد چند پرونده، یا در email چند نشانی، انتخاب شود.
autofocus با باز شدن صفحه، مکان‌نما را داخل این فیلد می‌گذارد. در هر صفحه فقط یکی از این ویژگی معنا دارد. —
checked وضعیت انتخاب‌شدهٔ اولیه را برای checkbox و radio مشخص می‌کند.

اعتبارسنجی بدون JavaScript

مرورگر قبل از ارسال، فیلدها را بررسی می‌کند. فرم زیر را خالی یا اشتباه ارسال کنید تا پیام خطا را ببینید: 

<form action="" method="get">
  <p>
    <label for="uname">نام کاربری (۴ تا ۱۰ حرف انگلیسی):</label><br>
    <input id="uname" name="uname" required pattern="[A-Za-z]{4,10}"
           title="فقط ۴ تا ۱۰ حرف انگلیسی">
  </p>
  <p>
    <label for="mail">ایمیل:</label><br>
    <input type="email" id="mail" name="mail" required>
  </p>
  <p>
    <label for="mobile">شماره موبایل:</label><br>
    <input type="tel" id="mobile" name="mobile" pattern="09[0-9]{9}"
           placeholder="09121234567" title="۱۱ رقم و شروع با ۰۹">
  </p>
  <p>
    <label for="age">سن (۱۸ تا ۹۹):</label><br>
    <input type="number" id="age" name="age" min="18" max="99">
  </p>
  <button type="submit">ثبت‌نام</button>
</form>





pattern فقط وقتی بررسی می‌شود که فیلد خالی نباشد. برای اجباری کردن، required هم لازم است. بسیاری از مرورگرها متن title را کنار پیام خطای الگوی نامعتبر نشان می‌دهند، اما متن دقیق پیام به مرورگر بستگی دارد. title را راهنمای قالب بنویسید، نه تنها راه توضیح خطا.

نکته امنیتی: اعتبارسنجی HTML فقط برای راحتی کاربر است و با تغییر کد صفحه یا خاموش کردن JavaScript و حتی بدون آن، قابل دور زدن است. سرور همیشه باید داده‌ها را دوباره بررسی کند. مرورگر جایگزین بررسی سمت سرور نیست.

عناصر دیگر فرم

<fieldset> و <legend>

fieldset فیلدهای مرتبط را در یک گروه می‌گذارد و legend عنوان همان گروه است. صفحه‌خوان این عنوان را همراه فیلدهای داخل گروه می‌خواند.

<fieldset>
  <legend>اطلاعات شخصی</legend>
  <label for="fn">نام:</label>
  <input id="fn" name="fname">
  <label for="ln">نام خانوادگی:</label>
  <input id="ln" name="lname">
</fieldset>
اطلاعات شخصی

<select>، <optgroup>، selected و multiple

optgroup گزینه‌ها را دسته‌بندی می‌کند و label آن فقط عنوان دسته است و خودش انتخاب نمی‌شود. selected گزینهٔ پیش‌فرض را مشخص می‌کند. value مقداری است که ارسال می‌شود و متن داخل option فقط برای نمایش است. با multiple روی select، کاربر می‌تواند چند گزینه را با هم انتخاب کند. در بسیاری از رایانه‌ها این کار با نگه داشتن Ctrl انجام می‌شود و در مک با Command. 

<label for="city">شهر:</label>
<select id="city" name="city">
  <optgroup label="شمال">
    <option value="rasht">رشت</option>
    <option value="sari">ساری</option>
  </optgroup>
  <optgroup label="مرکز">
    <option value="tehran" selected>تهران</option>
    <option value="isfahan">اصفهان</option>
  </optgroup>
</select>

<datalist>

عنصر datalist فهرست پیشنهادی برای یک input است. کاربر می‌تواند یکی از پیشنهادها را انتخاب کند یا چیز دیگری تایپ کند. این با select فرق دارد، چون select معمولاً فقط گزینه‌های خودش را می‌پذیرد. اتصال با ویژگی list انجام می‌شود و مقدار آن باید برابر id همان datalist باشد. 

<label for="browser">مرورگر شما:</label>
<input list="browsers" id="browser" name="browser">
<datalist id="browsers">
  <option value="Chrome">
  <option value="Firefox">
  <option value="Edge">
  <option value="Safari">
</datalist>

<textarea> با rows و cols

rows تعداد خطوط قابل مشاهده و cols عرض تقریبی بر حسب نویسه است. برخلاف input، مقدار اولیه textarea بین تگ آغازین و پایانی نوشته می‌شود، نه در value. 

<label for="bio">درباره شما:</label><br>
<textarea id="bio" name="bio" rows="4" cols="40" placeholder="درباره خودتان بنویسید..."></textarea>

انواع button

type="submit" فرم را ارسال می‌کند (پیش‌فرض دکمه داخل فرم)
type="reset" فیلدها را به مقدار اولیه برمی‌گرداند و لزوماً آن‌ها را خالی نمی‌کند.
type="button" هیچ کاری نمی‌کند تا JavaScript به آن رفتار بدهد

خطای متداول: دکمه‌ای که فقط برای JavaScript است را داخل فرم بدون type="button" می‌گذارند. نوع پیش‌فرض button داخل فرم submit است، پس با کلیک، فرم ناخواسته ارسال و صفحه دوباره بارگذاری می‌شود.

تمرین: یک فرم «ثبت‌نام در دوره» بسازید با: نام (اجباری)، ایمیل (اجباری)، تاریخ تولد، انتخاب دوره با select، سطح با radio، روزهای آزاد با checkbox، رنگ دلخواه با color، توضیحات با textarea، و دکمه‌های ارسال و پاک کردن. بخش‌ها را با fieldset گروه‌بندی کنید.

مطالعه بیشتر: form (MDN)، input و انواع آن (MDN)، Constraint validation (MDN)، Web forms (MDN)
