۲۳) طراحی واکنش‌گرا (Responsive)

صفحهٔ واکنش‌گرا روی موبایل، تبلت و رایانه درست خوانده می‌شود و لازم نیست کاربر برای دیدن محتوا مدام بزرگ‌نمایی کند. بخش اصلی این کار با CSS انجام می‌شود، اما چند تصمیم HTML پایهٔ آن است. پنج مورد زیر را از همان اول در نظر بگیرید:

۱) تگ viewport (همیشه!)

<meta name="viewport" content="width=device-width, initial-scale=1.0">

بدون این خط، بسیاری از مرورگرهای موبایل صفحه را مثل یک نمایشگر حدود ۹۸۰ پیکسل فرض می‌کنند و بعد آن را کوچک نشان می‌دهند، برای همین متن ریز می‌شود. width=device-width عرض صفحه را با عرض دستگاه یکی می‌کند و initial-scale=1.0 بزرگ‌نمایی اولیه را روی ۱ می‌گذارد.

۲) تصویر انعطاف‌پذیر

<img src="photo.jpg" alt="..." style="max-width: 100%; height: auto;">

max-width: 100% یعنی تصویر از عرض ظرف خودش پهن‌تر نشود. height: auto نسبت تصویر را حفظ می‌کند تا عکس له نشود. این قاعده تصویر را بزرگ‌تر از اندازهٔ اصلی پرونده نمی‌کند، مگر اینکه CSS دیگری آن را بکشد.

۳) تصویر متناسب با صفحه — srcset

<img src="backpack-500.jpg"
     srcset="backpack-500.jpg 500w, backpack-1000.jpg 1000w"
     sizes="(max-width: 600px) 500px, 1000px"
     alt="کوله‌پشتی سفری ضدآب، رنگ سرمه‌ای">

در srcset هر پرونده همراه با عرض واقعی‌اش معرفی می‌شود. 500w یعنی عرض ذاتی تصویر ۵۰۰ پیکسل است، نه عرض نمایش. sizes می‌گوید تصویر در هر عرض صفحه تقریباً چقدر جا می‌گیرد. مرورگر با این دو اطلاعات، پروندهٔ مناسب را انتخاب می‌کند تا روی صفحهٔ کوچک حجم کمتری بارگیری شود. src پشتیبان مرورگرهایی است که srcset را نمی‌شناسند. روش دیگر، عنصر picture در درس ۲۰ است که وقتی خود تصویر باید عوض شود، مناسب‌تر است.

۴) واحدهای نسبی

به‌جای عرض ثابت مثل width: 900px، از درصد، max-width، rem و vw استفاده کنید. vw واحدی نسبت به عرض پنجره است و 4vw یعنی چهار درصد عرض پنجره. این واحد برای عنوان‌های خیلی بزرگ باید با احتیاط به‌کار برود، چون در صفحهٔ خیلی باریک ممکن است متن بیش از حد کوچک شود. 

<h3 style="font-size: 4vw;">این تیتر با عرض پنجره بزرگ و کوچک می‌شود</h3>

این تیتر با عرض پنجره بزرگ و کوچک می‌شود

۵) چیدمان منعطف و Media Query

با CSS، و معمولاً Flexbox یا Grid، ستون‌ها در صفحهٔ پهن کنار هم و در صفحهٔ باریک زیر هم قرار می‌گیرند. پنجره را باریک کنید:

<div class="row">
  <div>🍕 پیتزا مخصوص — ۲۸۰ هزار تومان</div>
  <div>🍔 همبرگر ذغالی — ۲۱۰ هزار تومان</div>
  <div>🥗 سالاد سزار — ۱۶۰ هزار تومان</div>
</div>

<style>
  .row       { display: flex; flex-wrap: wrap; gap: 10px; }
  .row > div { flex: 1 1 200px; }

  /* فقط در صفحه‌های کوچک‌تر از ۶۰۰ پیکسل */
  @media (max-width: 600px) {
    body { font-size: 14px; }
  }
</style>
🍕 پیتزا مخصوص — ۲۸۰ هزار تومان
🍔 همبرگر ذغالی — ۲۱۰ هزار تومان
🥗 سالاد سزار — ۱۶۰ هزار تومان

flex: 1 1 200px یعنی هر ستون حداقل حدود ۲۰۰ پیکسل جا می‌خواهد؛ اگر جا نبود، با کمک flex-wrap: wrap به خط بعد می‌رود. @media هم قانون‌هایی را فقط در عرض‌های مشخص اعمال می‌کند. (جزئیات این ویژگی‌ها در درس CSS آموزش داده می‌شود.)

نکته: در مرورگر F12 را بزنید و با Ctrl + Shift + M حالت موبایل را فعال کنید تا صفحه را در اندازه‌های مختلف ببینید.

دسترس‌پذیری (Accessibility)

صفحه باید برای کسانی هم قابل استفاده باشد که صفحه را نمی‌بینند و با صفحه‌خوان می‌شنوند، یا فقط با صفحه‌کلید کار می‌کنند. دسترس‌پذیری یک لایهٔ جدا بعد از اتمام طراحی نیست. همان عنصرهای معنایی و متن‌های جایگزین که در درس‌های قبل دیدید، پایهٔ آن هستند.

قانون چرا
برای تصویر محتوایی همیشه alt معنادار بنویسید. صفحه‌خوان همان متن را به‌جای تصویر می‌خواند.
روی عنصر html زبان را با lang="fa" مشخص کنید. صفحه‌خوان با دانستن زبان، تلفظ درست را انتخاب می‌کند.
از عنصرهای معنایی مانند header، nav و main استفاده کنید. کاربر صفحه‌خوان می‌تواند مستقیم به بخش‌های اصلی بپرد.
عنوان‌ها را به‌ترتیب h1، h2 و h3 بچینید. از همین ترتیب، فهرست صفحه برای صفحه‌خوان ساخته می‌شود.
برای هر فیلد فرم یک label متصل بگذارید. کاربر می‌فهمد هر فیلد برای چیست، حتی اگر فقط برچسب‌ها را بشنود.
برای عمل و رفتن به صفحه از button و a واقعی استفاده کنید. این عنصرها با Tab و Enter کار می‌کنند. div کلیک‌پذیر به‌خودی‌خود این رفتار را ندارد.
متن پیوند را گویا بنویسید. عبارت «اینجا کلیک کنید» وقتی جدا از جمله خوانده شود معنایی ندارد.
میان متن و پس‌زمینه تضاد رنگی کافی بگذارید. متن برای کم‌بینایان و زیر نور زیاد خوانا می‌ماند.
اطلاعات را فقط با رنگ نرسانید. کاربر کوررنگ ممکن است «فیلد قرمز» را تشخیص ندهد. کنار رنگ، متن خطا هم بنویسید.
برای ویدیو زیرنویس track بگذارید. کاربر ناشنوا، یا کسی که بدون صدا تماشا می‌کند، محتوا را از دست نمی‌دهد.

امتحان کنید: ماوس را کنار بگذارید و فقط با Tab، Shift+Tab و Enter در صفحه خودتان حرکت کنید. آیا همه‌چیز در دسترس است؟

راهنمای سبک کدنویسی (Style Guide)

کد خوانا اشکال‌یابی و کار گروهی را ساده‌تر می‌کند. موردهای زیر قرارداد رایج میان توسعه‌دهندگان هستند. بعضی از آن‌ها در HTML الزام سخت نیستند، اما رعایت‌شان کد را یکدست می‌کند:

HTML و XHTML

XHTML نسخهٔ سخت‌گیرتری از HTML بود: عنصرهای دارای محتوا باید بسته می‌شدند، عنصر تهی را با اسلش می‌نوشتند، مثل <br />، و نام‌ها با حروف کوچک بودند. HTML5 این سخت‌گیری‌ها را اجباری نمی‌کند. اسلش پایانی در <br /> وقتی صفحه به‌صورت HTML سرو شود معنای XML ندارد و اختیاری است. حروف کوچک و بستن عنصرهای دارای محتوا هنوز عادت خوبی است.

بررسی درستی کد

کد را در W3C Validator بررسی کنید تا خطاهایی مثل عنصر بسته‌نشده یا ویژگی اشتباه پیدا شود. برای دیدن ساختار صفحه در مرورگر روی عنصر راست‌کلیک کنید و Inspect را بزنید. اعتبارسنج خطاهای HTML را پیدا می‌کند، اما به‌تنهایی نمی‌گوید طراحی یا متن آموزشی شما خوب است.

تمرین: یکی از صفحه‌هایی که تا حالا ساخته‌اید را با جدول بالا بازبینی کنید، در W3C Validator بررسی و خطاهایش را رفع کنید. سپس آن را در حالت موبایل (Ctrl+Shift+M) امتحان کنید.
