۸) توابع Callback و کد ناهمگام

Callback تابعی است که آن را به تابع دیگری می‌دهید تا در زمان مناسب صدایش بزند. گاهی این صدا زدن همان لحظه است، مثل وقتی که map برای هر عضو یک تابع را اجرا می‌کند. گاهی صدا زدن بعداً است، وقتی کاری مثل تایمر یا پاسخ شبکه تمام شده باشد. تفاوت این دو را اول ببینید، چون شکل نوشتن callback در هر دو شبیه است ولی زمان اجرا فرق دارد.

همگام (Synchronous) در مقابل ناهمگام (Asynchronous)

همگامناهمگام
خط‌به‌خط؛ هر خط منتظر خط قبل می‌ماندکار طولانی شروع می‌شود و برنامه منتظر نمی‌ماند
map، forEach، sortsetTimeout، دانلود از سرور، خواندن فایل
callback همان لحظه اجرا می‌شودcallback بعداً، وقتی کار تمام شد، اجرا می‌شود

Callback همگام

function processUser(name, callback) {
  const formatted = name.trim().toUpperCase();
  callback(formatted);
}

processUser("  sara ", (result) => {
  console.log("نتیجه:", result);
});

processUser نام را تمیز و بزرگ می‌کند، ولی خودش نتیجه را چاپ نمی‌کند. تابعی که شما به‌عنوان callback می‌دهید بعد از آماده‌شدن متن صدا زده می‌شود و نتیجه را تحویل می‌گیرد. این جدایی باعث می‌شود همان پردازش را با کارهایی غیر از چاپ هم استفاده کنید.






Callback ناهمگام: شبیه‌سازی گرفتن داده از سرور



function getUser(id, callback) {
  log(`در حال دریافت کاربر ${id}...`);
  setTimeout(() => {
    const user = { id: id, name: "سارا" };
    callback(user);                  // وقتی داده آماده شد
  }, 1000);
}

getUser(7, (user) => {
  log("کاربر رسید:", user);
});
log("این خط زودتر چاپ می‌شود!");

// ترتیب خروجی:
// در حال دریافت کاربر 7...
// این خط زودتر چاپ می‌شود!
// کاربر رسید: {"id":7,"name":"سارا"}   ← یک ثانیه بعد



setTimeout شبیه‌سازی کاری است که طول می‌کشد، مثل پاسخ سرور. خط بعد از getUser منتظر تایمر نمی‌ماند و زودتر اجرا می‌شود. وقتی زمان بگذرد، شیء کاربر ساخته می‌شود و به callback داده می‌شود. به همین دلیل پیام «کاربر رسید» بعد از پیام همگام دیده می‌شود.











مشکل: جهنم Callback (Callback Hell)



وقتی چند کار ناهمگام باید پشت سر هم انجام شوند (هر مرحله به نتیجه مرحله قبل نیاز دارد)، callbackها تو در تو می‌شوند و خواندن و مدیریت خطا سخت می‌شود. کد زیر فقط برای نشان دادن شکل مشکل است (توابع آن فرضی‌اند):



getUser(1, (user) => {
  getOrders(user.id, (orders) => {
    getOrderDetails(orders[0], (details) => {
      getShipping(details.shipId, (shipping) => {
        console.log(shipping);       // هرم وحشت 😱
      });
    });
  });
});



راه‌حل این مشکل Promise و async/await است که در دو درس بعد می‌بینیم.



الگوی رایج: callback خطا و موفقیت



function divideLater(a, b, onSuccess, onError) {
  setTimeout(() => {
    if (b === 0) onError("تقسیم بر صفر!");
    else onSuccess(a / b);
  }, 500);
}

divideLater(10, 2, r => log("✔", r), e => log("✖", e));   // ✔ 5
divideLater(10, 0, r => log("✔", r), e => log("✖", e));   // ✖ تقسیم بر صفر!



به‌جای یک callback، دو تابع جدا برای موفقیت و خطا گرفته شده است. داخل تایمر، اگر مقسوم‌علیه صفر باشد onError صدا زده می‌شود و وگرنه onSuccess حاصل تقسیم را می‌گیرد. هر دو مسیر غیرهمگام‌اند و حدود نیم ثانیه بعد اجرا می‌شوند.











در Node.js و کتابخانه‌های قدیمی الگوی دیگری هم رایج است به اسم error-first callback: یک callback که پارامتر اولش خطاست: callback(err, result). اگر err مقدار داشت یعنی کار ناموفق بوده است.



اشتباه رایج: انتظار داشتن نتیجه با return از تابع ناهمگام: const user = getUser(7). چون داده بعداً می‌رسد و getUser چیزی return نمی‌کند، user برابر undefined است؛ باید از callback (یا Promise) استفاده کنید.



تمرین: تابع loadImage(name, callback) بنویسید که بعد از زمان تصادفی بین ۵۰۰ تا ۲۰۰۰ میلی‌ثانیه (راهنما: 500 + Math.random() * 1500) callback را با پیام «تصویر name بارگذاری شد» صدا بزند. سه تصویر را پشت سر هم بارگذاری کنید و با چند بار اجرا ببینید ترتیب رسیدن‌شان ثابت نیست. سپس کاری کنید که پیام «همه تصویرها آماده شد» فقط بعد از رسیدن هر سه چاپ شود (راهنما: یک شمارنده).
