۳) متدهای call، apply و bind

در یک تابع معمولی، مقدار this موقع صدا زدن تعیین می‌شود (نه موقع نوشتن): در obj.method() مقدار this همان obj است. این سه متد به ما اجازه می‌دهند خودمان تعیین کنیم this داخل یک تابع چه چیزی باشد.

متدکاراجرا می‌شود؟
fn.call(obj, a, b)this = obj، آرگومان‌ها جدا جدابله، همان لحظه
fn.apply(obj, [a, b])this = obj، آرگومان‌ها در یک آرایهبله، همان لحظه
fn.bind(obj, a)یک تابع جدید با this ثابت می‌سازدخیر؛ بعداً صدا می‌زنیم

call و apply

function introduce(city, job) {
  return `من ${this.name} هستم، از ${city}، ${job}.`;
}

const sara = { name: "سارا" };
const ali = { name: "علی" };

console.log(introduce.call(sara, "شیراز", "برنامه‌نویس"));   // من سارا هستم، از شیراز، برنامه‌نویس.
console.log(introduce.apply(ali, ["تبریز", "طراح"]));        // من علی هستم، از تبریز، طراح.

call تابع را صدا می‌زند و آرگومان اول را به‌عنوان this می‌گذارد. آرگومان‌های بعدی، آرگومان‌های خود تابع هستند. apply همین کار را می‌کند، با این فرق که آرگومان‌های تابع را در یک آرایه می‌گیرد. در هر دو خط، this.name از شیئی می‌آید که به call یا apply داده‌اید، نه از جایی که تابع نوشته شده است.






قرض گرفتن متد



const person = {
  fullName() { return this.first + " " + this.last; }
};
const user = { first: "مریم", last: "کریمی" };

console.log(person.fullName.call(user));   // مریم کریمی



متد fullName روی person نوشته شده، ولی call آن را با this برابر user اجرا می‌کند. به همین دلیل first و last از user خوانده می‌شوند. این کار وقتی مفید است که یک متد را روی شیء دیگری که شکل مشابه دارد اجرا کنید.



مثال معروف apply در گذشته: Math.max.apply(null, [3, 9, 4]). امروزه همین را با Spread ساده‌تر می‌نویسیم: Math.max(...[3, 9, 4]).










bind — مشکل گم شدن this



const timer = {
  seconds: 10,
  show() { return "ثانیه: " + this.seconds; }
};

const lost = timer.show;               // متد از شیء جدا شد
console.log(lost());                   // ثانیه: undefined ← this دیگر timer نیست

const fixed = timer.show.bind(timer);  // this برای همیشه timer است
console.log(fixed());                  // ثانیه: 10



ریختن متد در متغیر lost ارتباط آن را با timer قطع می‌کند و this.seconds دیگر آن شیء نیست. bind تابع تازه‌ای می‌سازد که this آن از قبل روی timer قفل شده است. برخلاف call، bind همان لحظه تابع را اجرا نمی‌کند.










در اسکریپت معمولی، this در lost() شیء سراسری window است و چون window.seconds وجود ندارد، undefined چاپ می‌شود. در حالت strict (مثلاً داخل ماژول‌ها و کلاس‌ها) this برابر undefined است و همین خط خطای TypeError: Cannot read properties of undefined می‌دهد.



bind در رویدادها



const player = {
  name: "بازیکن ۱",
  score: 0,
  addPoint() {
    this.score++;
    scoreText.textContent = `${this.name}: ${this.score} امتیاز`;
  }
};

// بدون bind، this داخل addPoint خود دکمه می‌شد
pointBtn.addEventListener("click", player.addPoint.bind(player));






بازیکن ۱: 0 امتیاز





امروزه در بیشتر موارد به جای bind از تابع پیکانی استفاده می‌شود: btn.addEventListener("click", () => player.addPoint()).



اشتباه رایج: استفاده از bind، call یا apply برای تغییر this یک تابع پیکانی. تابع پیکانی this خودش را ندارد (this محیط بیرونی را استفاده می‌کند) و این سه متد this آن را عوض نمی‌کنند. به همین دلیل متدهای شیء را هم نباید پیکانی نوشت: { name: "سارا", hi: () => this.name } اسم را برنمی‌گرداند.



اشتباه رایج: فرستادن متد به عنوان callback: setTimeout(timer.show, 1000). متد از شیء جدا می‌شود و this گم می‌شود؛ بنویسید setTimeout(() => timer.show(), 1000) یا setTimeout(timer.show.bind(timer), 1000).



تمرین: تابع معمولی describe(prefix) بنویسید که prefix + this.title برگرداند. دو شیء کتاب بسازید (مثلاً { title: "بوف کور" } و { title: "کلیدر" }). تابع را با call برای هر دو کتاب صدا بزنید، یک بار هم با apply، و سپس با bind نسخه‌ای به اسم describeFirst بسازید که همیشه برای کتاب اول کار کند.
