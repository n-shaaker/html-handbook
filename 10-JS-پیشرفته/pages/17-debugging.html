۱۷) اشکال‌زدایی و نکات حرفه‌ای (Debugging & Best Practices)

خطا فقط یک جملهٔ قرمز نیست. کنسول نوع مشکل، محل آن در فایل و مقدار متغیرها را نشان می‌دهد، اگر بدانید هر دستور کنسول چه چیزی را برجسته می‌کند. این درس ابزارهای دیدن خروجی و خواندن پیام خطا را جدا می‌کند تا وقتی برنامه می‌ایستد، از روی پیام به همان خط برسید.

function calculateTotal(items) {
  let total = 0;
  for (const item of items) {
    debugger;               // اگر DevTools باز باشد، اجرا اینجا متوقف می‌شود
    total += item.price * item.qty;
  }
  return total;
}











مدیریت خطا: throw و try...catch



وقتی تابع با ورودی نامعتبر روبه‌رو می‌شود، بهتر است به جای برگرداندن یک مقدار عجیب، با throw خطا «پرتاب» کند. کدی که تابع را صدا می‌زند با try...catch خطا را می‌گیرد و پیام مناسب نشان می‌دهد. نوع خطا (TypeError، RangeError، ...) هم کمک می‌کند بفهمیم مشکل از کجاست.



function parsePrice(text) {
  const n = Number(text);
  if (text.trim() === "" || Number.isNaN(n)) {
    throw new TypeError(`«${text}» عدد نیست`);
  }
  if (n < 0) throw new RangeError("قیمت نمی‌تواند منفی باشد");
  return n;
}

for (const input of ["250000", "abc", "-5"]) {
  try {
    console.log("✔", parsePrice(input));
  } catch (err) {
    console.log("✖", err.name + ":", err.message);
  }
}



تابع اول متن را به عدد تبدیل می‌کند. متن خالی یا غیرعددی TypeError می‌سازد و عدد منفی RangeError. حلقه هر ورودی را جدا در try می‌گذارد تا خطای یکی، بررسی بقیه را متوقف نکند. جدا کردن نوع خطا کمک می‌کند پیام مناسب همان مشکل را نشان دهید، نه یک خطای کلی.










اشتباه رایج: catch خالی: try { ... } catch (e) {}. خطا بی‌صدا قورت داده می‌شود و پیدا کردن باگ بسیار سخت می‌شود. حداقل خطا را با console.error(e) چاپ کنید و به کاربر پیامی بدهید. همچنین فقط اطراف کدی که واقعاً ممکن است خطا بدهد (fetch، JSON.parse، ورودی کاربر) try بگذارید، نه کل برنامه.



خواندن پیام خطا



Uncaught TypeError: Cannot read properties of undefined (reading 'name')
    at showUser (app.js:12:25)



این متن، خروجی معمول کنسول برای خطایی است که برنامه متوقف شده. نوع خطا TypeError است و می‌گوید تلاش شده ویژگی name از مقداری خوانده شود که undefined است. بخش at showUser نام تابع، نام فایل و شمارهٔ خط را نشان می‌دهد تا همان نقطه را در ویرایشگر باز کنید.

نکات حرفه‌ای (Best Practices)



    

  • از const استفاده کنید و فقط در صورت نیاز let. از var استفاده نکنید (فقط در کدهای قدیمی می‌بینیدش؛ مشکلش را در درس closure دیدیم).
    • 

  • همیشه === به جای ==.
    • 

  • اسم‌های معنادار: userList نه ul2.
    • 

  • توابع کوچک که فقط یک کار انجام می‌دهند.
    • 

  • متغیر سراسری کم؛ داده را داخل توابع، ماژول‌ها یا کلاس‌ها نگه دارید.
    • 

  • متن کاربر را با textContent نمایش دهید نه innerHTML.
    • 

  • JavaScript را در فایل جدا بنویسید و از رویدادهای اینلاین (onclick="") پرهیز کنید.
    • 

  • کد را مرتب (فاصله‌گذاری یکسان) بنویسید؛ افزونه Prettier در VS Code این کار را خودکار می‌کند. افزونه ESLint هم بسیاری از باگ‌ها (متغیر تعریف‌نشده، متغیر بلااستفاده و ...) را قبل از اجرا نشان می‌دهد.
    • 

  • خطاها را مدیریت کنید (try...catch برای fetch، JSON.parse و localStorage) و پیام خطای قابل فهم به کاربر نشان دهید.
    • 

  • ورودی کاربر را قبل از استفاده بررسی کنید (خالی نبودن، عدد بودن، قالب درست با RegExp).
    • 




اشتباه رایج: پاک نکردن console.logها و debuggerها قبل از تحویل نهایی پروژه.
