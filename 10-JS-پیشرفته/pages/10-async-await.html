۱۰) async و await

async/await همان Promise را با شکلی می‌نویسد که از بالا به پایین خوانده می‌شود. async تابع را طوری علامت می‌زند که همیشه یک Promise برگرداند. await داخل همان تابع می‌ایستد تا Promise تمام شود و مقدارش را به شما بدهد. بقیهٔ برنامه در این فاصله متوقف نمی‌شود؛ فقط ادامهٔ همان تابع عقب می‌افتد. خطا را هم با try/catch می‌گیرید، شبیه کد همگام.

کلمهکار
asyncقبل از تابع می‌آید؛ تابع همیشه یک Promise برمی‌گرداند
awaitفقط داخل تابع async؛ منتظر می‌ماند تا Promise تمام شود و نتیجه‌اش را برمی‌گرداند

مقایسه then با await

// با then
function showUserThen() {
  getUser(1)
    .then(user => log("then:", user.name))
    .catch(err => log(err.message));
}

// با async/await
async function showUserAwait() {
  try {
    const user = await getUser(1);
    log("await:", user.name);
  } catch (err) {
    log(err.message);
  }
}

هر دو تابع همان getUser(1) را می‌خوانند. شکل then ادامهٔ کار را داخل callback می‌گذارد و خطا را با catch می‌گیرد. شکل await همان انتظار را مثل یک خط معمولی می‌نویسد و خطا را با try/catch می‌گیرد. await فقط داخل تابع async مجاز است و تا آماده شدن Promise، بقیهٔ همان تابع را عقب می‌اندازد.

مثال: چند مرحله پشت سر هم

const wait = ms => new Promise(r => setTimeout(r, ms));

async function makeTea() {
  log("۱. آب را جوش می‌آوریم...");
  await wait(1000);
  log("۲. چای را دم می‌کنیم...");
  await wait(1000);
  log("۳. چای را می‌ریزیم ☕");
  return "چای آماده است";
}

makeTea().then(result => log("نتیجه:", result));
log("(این خط منتظر چای نمی‌ماند)");

// ترتیب خروجی:
// ۱. آب را جوش می‌آوریم...      ← بخش همگام makeTea تا اولین await
// (این خط منتظر چای نمی‌ماند)
// ۲. چای را دم می‌کنیم...        ← ۱ ثانیه بعد
// ۳. چای را می‌ریزیم ☕          ← ۲ ثانیه بعد
// نتیجه: چای آماده است

هر await wait(1000) ادامهٔ makeTea را حدود یک ثانیه متوقف می‌کند، ولی خط بعد از صدا زدن makeTea() منتظر چای نمی‌ماند. بخش قبل از اولین await همان لحظه اجرا می‌شود. return داخل تابع async به Promise تبدیل می‌شود و then متن نهایی را می‌گیرد.

await فقط همان تابع async را متوقف می‌کند، نه کل برنامه. تابع async تا اولین await به صورت همگام اجرا می‌شود؛ بعد کنترل به کدی که آن را صدا زده برمی‌گردد. مقداری هم که با return برمی‌گرداند، در قالب یک Promise تحویل داده می‌شود؛ برای همین از .then (یا await) برای گرفتن «چای آماده است» استفاده کردیم.






مدیریت خطا با try...catch



function getUser(id) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (id > 0) resolve({ id, name: "کاربر " + id });
      else reject(new Error("شناسه نامعتبر است"));
    }, 700);
  });
}

async function loadUser(id) {
  try {
    log(`در حال دریافت کاربر ${id}...`);
    const user = await getUser(id);
    log("✔", user);
  } catch (err) {
    log("✖", err.message);
  } finally {
    log("— تمام —");
  }
}



getUser اگر شناسه مثبت باشد شیء کاربر را resolve می‌کند و اگر نباشد reject. await در حالت موفقیت مقدار را در user می‌ریزد و در حالت شکست به catch می‌رود. finally چه کاربر پیدا شود و چه شناسه نامعتبر باشد اجرا می‌شود.












پشت سر هم یا هم‌زمان؟



async function sequential() {
  log("شروع پشت سر هم...");
  const start = performance.now();          // زمان فعلی با دقت میلی‌ثانیه
  await wait(1000);                         // ۱ ثانیه
  await wait(1000);                         // ۱ ثانیه دیگر؛ تازه بعد از قبلی شروع می‌شود
  log(`پشت سر هم: ${Math.round(performance.now() - start)} میلی‌ثانیه`);   // حدود 2000
}

async function parallel() {
  log("شروع هم‌زمان...");
  const start = performance.now();
  await Promise.all([wait(1000), wait(1000)]);   // هر دو با هم شروع می‌شوند
  log(`هم‌زمان: ${Math.round(performance.now() - start)} میلی‌ثانیه`);      // حدود 1000
}



در حالت پشت‌سرهم، await دوم تازه بعد از تمام شدن اولی شروع می‌شود، پس زمان‌ها جمع می‌شوند. در حالت هم‌زمان، Promise.all هر دو انتظار را با هم شروع می‌کند و await تا وقتی هر دو تمام شوند صبر می‌کند. performance.now اختلاف زمان را به میلی‌ثانیه نشان می‌دهد.












اگر کارها به هم وابسته نیستند (مثلاً گرفتن کاربر و گرفتن اخبار)، آن‌ها را با Promise.all هم‌زمان شروع کنید تا سریع‌تر تمام شوند.



اشتباه رایج: استفاده از await بیرون از تابع async (در اسکریپت معمولی). خطای SyntaxError: await is only valid in async functions and the top level bodies of modules می‌گیرید. فقط در ماژول‌ها (type="module") await در سطح بالای فایل مجاز است.



اشتباه رایج: فراموش کردن await: const user = getUser(1). در این حالت user یک Promise است نه خود داده؛ user.name برابر undefined می‌شود.



اشتباه رایج: استفاده از await داخل forEach:
ids.forEach(async id => { await getUser(id); }).
forEach منتظر callbackهای async نمی‌ماند و کد بعد از حلقه زودتر اجرا می‌شود. برای اجرای پشت سر هم از for (const id of ids) { await getUser(id); } و برای اجرای هم‌زمان از await Promise.all(ids.map(id => getUser(id))) استفاده کنید.



تمرین: تمرین درس قبل (checkStock) را با async/await و try...catch بازنویسی کنید: تابع async function showStock(item) بنویسید که نتیجه را چاپ کند و در صورت خطا پیام خطا را نشان دهد. سپس موجودی سه کالا را با Promise.all هم‌زمان بررسی کنید و زمان کل را با performance.now() اندازه بگیرید (باید حدود ۱ ثانیه باشد نه ۳ ثانیه).
