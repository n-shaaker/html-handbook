۱۱) دریافت داده از سرور (Fetch API)

fetch از مرورگر به یک نشانی درخواست می‌فرستد و پاسخ را به‌صورت Promise برمی‌گرداند. با آن هم داده می‌خوانید و هم، اگر سرور اجازه بدهد، داده می‌فرستید. چون نتیجه Promise است، معمولاً داخل تابع async با await نوشته می‌شود. رسیدن پاسخ به‌تنهایی یعنی همه‌چیز درست بوده است؛ وضعیت‌هایی مثل ۴۰۴ را باید جدا بررسی کنید.

async function getPosts() {
  const response = await fetch("https://jsonplaceholder.typicode.com/posts?_limit=3");
  const data = await response.json();     // تبدیل بدنه پاسخ از JSON به شیء
  console.log(data);                      // آرایه‌ای از ۳ پست
}

fetch درخواست را می‌فرستد و یک Promise برمی‌گرداند که با رسیدن پاسخ resolve می‌شود. await همان پاسخ را در response می‌گذارد. response.json بدنه را از متن JSON به مقدار JavaScript تبدیل می‌کند و خودش هم Promise است، پس آن را هم await می‌کنیم. این تابع وضعیت HTTP را بررسی نکرده است؛ آن بررسی در تابع بعدی است.

مرحلهتوضیح
await fetch(url)درخواست می‌فرستد و شیء Response برمی‌گرداند (به محض رسیدن سرآیندها، قبل از دانلود کامل بدنه)
response.okاگر کد وضعیت ۲۰۰ تا ۲۹۹ باشد true
response.statusکد وضعیت: ۲۰۰ موفق، ۲۰۱ ساخته شد، ۴۰۴ پیدا نشد، ۵۰۰ خطای سرور
await response.json()بدنه پاسخ را می‌خواند و به شیء/آرایه تبدیل می‌کند (اگر JSON معتبر نباشد خطای SyntaxError می‌دهد)

کد بالا برای شروع خوب است ولی در پروژه واقعی ناقص است: اگر اینترنت قطع باشد، سرور خطای ۴۰۴/۵۰۰ بدهد یا اصلاً جواب ندهد، کاربر هیچ پیامی نمی‌بیند. در ادامه یک تابع کمکی کامل می‌نویسیم.

تابع کمکی fetchJSON: بررسی response.ok و پیام خطای فارسی

async function fetchJSON(url, options = {}) {
  let response;
  try {
    response = await fetch(url, options);
  } catch (err) {
    // fetch فقط وقتی خطا می‌دهد که اصلاً پاسخی نرسد (قطعی شبکه، مسدود شدن)
    throw new Error("اتصال به سرور برقرار نشد؛ اتصال اینترنت خود را بررسی کنید.");
  }

  if (!response.ok) {                     // ۴۰۴ و ۵۰۰ را خودمان باید خطا حساب کنیم
    throw new Error(`سرور خطا داد (کد ${response.status}).`);
  }
  return response.json();
}

اگر شبکه قطع باشد یا درخواست اصلاً به پاسخ نرسد، fetch reject می‌شود و catch پیام اتصال را می‌سازد. پاسخ 404 یا 500 معمولاً reject نمی‌شود؛ response.ok برای وضعیت‌های ۲۰۰ تا ۲۹۹ true است و بقیه را خودمان باید خطا حساب کنیم. فقط بعد از این بررسی، بدنه به JSON تبدیل می‌شود.

مثال زنده: فهرست کاربران با حالت «در حال بارگذاری» و خطا

const API = "https://jsonplaceholder.typicode.com";

async function loadUsers(url) {
  statusEl.textContent = "در حال بارگذاری...";
  list.innerHTML = "";
  // جلوی کلیک دوباره در حین بارگذاری
  loadBtn.disabled = true;
  badBtn.disabled = true;

  try {
    const users = await fetchJSON(url);
    users.forEach(user => {
      const li = document.createElement("li");
      li.textContent = `${user.name} — ${user.email} — ${user.address.city}`;
      list.append(li);
    });
    statusEl.textContent = `✔ ${users.length} کاربر دریافت شد.`;
  } catch (err) {
    statusEl.textContent = "✖ " + err.message;
  } finally {
    loadBtn.disabled = false;
    badBtn.disabled = false;
  }
}

loadBtn.addEventListener("click", () => loadUsers(`${API}/users`));
badBtn.addEventListener("click", () => loadUsers(`${API}/no-such-page`));     // خطای ۴۰۴

    این مثال به اینترنت نیاز دارد. jsonplaceholder.typicode.com یک API رایگان و قدیمی برای تمرین است که داده‌های ساختگی (کاربر، پست، نظر و ...) برمی‌گرداند. برای دیدن پیام «اتصال برقرار نشد»، اینترنت را قطع کنید یا در DevTools زبانه Network گزینه Offline را انتخاب کنید و دوباره روی «دریافت کاربران» کلیک کنید.

    اشتباه رایج: انتظار داشتن اینکه fetch برای خطای ۴۰۴ یا ۵۰۰ به catch برود. fetch فقط وقتی خطا می‌دهد که پاسخی نرسد (قطعی شبکه یا مسدود شدن توسط CORS)؛ اگر سرور با کد ۴۰۴ یا ۵۰۰ جواب بدهد، از نظر fetch «موفق» است. پس همیشه response.ok را خودتان بررسی کنید و throw کنید.

    مرورگر فقط وقتی اجازه خواندن پاسخ یک دامنه دیگر را می‌دهد که آن سرور با سرآیندهای CORS اجازه داده باشد. jsonplaceholder این اجازه را به همه داده است؛ اما اگر برای یک سایت دلخواه fetch بزنید و خطای CORS در Console دیدید، مشکل از کد شما نیست و باید سمت سرور حل شود.

    ارسال داده (POST)

    async function createPost() {
  const result = await fetchJSON(`${API}/posts`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },   // به سرور می‌گوییم بدنه JSON است
    body: JSON.stringify({ title: "سلام", body: "اولین پست من", userId: 1 })
  });
  log(result);     // سرور شیء ساخته‌شده را با id برمی‌گرداند (کد وضعیت 201)
}

// خروجی: {"title":"سلام","body":"اولین پست من","userId":1,"id":101}

    شیء دوم fetch روش و بدنه را مشخص می‌کند. POST یعنی ساختن منبع تازه. سرآیند Content-Type می‌گوید بدنه JSON است و JSON.stringify شیء را به متن همان قالب تبدیل می‌کند. تابع کمکی، پاسخ را بررسی می‌کند و شیئی را که سرور با شناسهٔ تازه برگردانده در خروجی می‌گذارد.

    

    


    jsonplaceholder داده را واقعاً ذخیره نمی‌کند؛ فقط پاسخی شبیه یک سرور واقعی برمی‌گرداند. برای همین هر بار id برابر 101 است.

    اشتباه رایج: فراموش کردن await قبل از response.json(). این متد هم Promise برمی‌گرداند. (در fetchJSON بالا چون نتیجه را مستقیم return می‌کنیم، کسی که await fetchJSON(...) می‌نویسد منتظر آن هم می‌ماند.)
    


    اشتباه رایج: فرستادن شیء بدون JSON.stringify در body، یا فراموش کردن سرآیند "Content-Type": "application/json". در حالت اول متن "[object Object]" فرستاده می‌شود و در حالت دوم بسیاری از سرورها بدنه را JSON تشخیص نمی‌دهند.
    


    تمرین: با آدرس https://jsonplaceholder.typicode.com/posts?userId=1 پست‌های کاربر ۱ را با تابع fetchJSON بگیرید و برای هر کدام یک کارت (عنوان و متن، با textContent) بسازید. یک input عددی (۱ تا ۱۰) بگذارید که با تغییر شماره کاربر، پست‌های همان کاربر نمایش داده شود. در حین بارگذاری پیام «در حال بارگذاری...» و در صورت خطا پیام فارسی مناسب نشان دهید.
