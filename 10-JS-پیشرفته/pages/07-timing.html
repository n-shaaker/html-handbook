۷) زمان‌بندی (setTimeout، setInterval و debounce)

بعضی کارها نباید همین لحظه یا فقط یک بار انجام شوند: صبر کردن، تکرار هر ثانیه، یا محدود کردن تعداد اجرای یک رویداد شلوغ. تابع‌های زمان‌بندی، تابع شما را به صف مرورگر می‌سپارند و اجرای خط‌های بعدی را متوقف نمی‌کنند. شناسه‌ای که برمی‌گردانند برای لغو همان زمان‌بندی لازم است.

تابعکار
setTimeout(fn, ms)fn را یک بار بعد از ms میلی‌ثانیه اجرا کن
setInterval(fn, ms)fn را هر ms میلی‌ثانیه تکرار کن
clearTimeout(id)لغو setTimeout
clearInterval(id)توقف setInterval

setTimeout

log("۱. شروع");

setTimeout(() => {
  log("۳. بعد از ۱.۵ ثانیه");
}, 1500);

log("۲. این خط منتظر نمی‌ماند!");

setTimeout تابع را همین حالا اجرا نمی‌کند؛ آن را برای حدود ۱۵۰۰ میلی‌ثانیهٔ بعد در صف می‌گذارد و ادامهٔ برنامه را متوقف نمی‌کند. به همین دلیل پیام دوم قبل از پیام سوم چاپ می‌شود. زمان داده‌شده حداقل انتظار است، نه ضمانت دقیق، چون اگر برنامه مشغول باشد اجرا کمی دیرتر شروع می‌شود.






در این مثال‌ها از تابع log به جای console.log استفاده شده چون خروجی بعد از چند ثانیه می‌آید. کار هر دو یکی است.



JavaScript برای setTimeout صبر نمی‌کند؛ کار را «زمان‌بندی» می‌کند و سراغ خط بعد می‌رود. این اولین آشنایی ما با کد ناهمگام (Asynchronous) است. حتی setTimeout(fn, 0) هم بعد از تمام شدن کدهای همگام فعلی اجرا می‌شود (جزئیات در درس ۹، بخش «ترتیب اجرا»).



عدد ms «حداقل» زمان انتظار است نه زمان دقیق. اگر مرورگر مشغول کار دیگری باشد (یا زبانه در پس‌زمینه باشد)، اجرا دیرتر انجام می‌شود. برای همین در کرنومتر زیر برای کارهای دقیق (مثل زمان‌سنجی آزمون) بهتر است زمان شروع را با Date.now() نگه دارید و اختلاف را حساب کنید.



مثال زنده: کرنومتر با setInterval



let seconds = 0;
let timerId = null;

startBtn.addEventListener("click", () => {
  if (timerId !== null) return;          // جلوی چند بار شروع شدن را بگیر
  timerId = setInterval(() => {
    seconds++;
    display.textContent = format(seconds);
  }, 1000);
});

stopBtn.addEventListener("click", () => {
  clearInterval(timerId);
  timerId = null;
});

resetBtn.addEventListener("click", () => {
  clearInterval(timerId);
  timerId = null;
  seconds = 0;
  display.textContent = format(0);
});

function format(s) {
  const m = String(Math.floor(s / 60)).padStart(2, "0");
  const r = String(s % 60).padStart(2, "0");
  return `${m}:${r}`;
}



setInterval تابع را هر ۱۰۰۰ میلی‌ثانیه تکرار می‌کند و شناسهٔ تایمر را برمی‌گرداند. اگر شناسه از قبل باشد، کلیک دوباره تایمر دوم نمی‌سازد. دکمهٔ توقف با clearInterval همان شناسه را لغو می‌کند و متغیر را خالی می‌کند تا شروع بعدی ممکن باشد. صفر کردن، هم عدد را صفر می‌کند و هم اگر تایمر هنوز روشن باشد آن را خاموش می‌کند.

مثال زنده: پیام موقت (Toast) با setTimeout



let hideId = null;

toastBtn.addEventListener("click", () => {
  toast.classList.remove("hidden");
  clearTimeout(hideId);       // اگر پیام قبلی هنوز باز است، تایمر قبلی را لغو کن
  hideId = setTimeout(() => toast.classList.add("hidden"), 2000);
});



هر کلیک پیام را نشان می‌دهد و یک تایمر دوثانیه‌ای برای پنهان کردن می‌سازد. اگر تایمر قبلی هنوز نرسیده باشد، clearTimeout آن را لغو می‌کند تا پیام زودتر از دو ثانیهٔ آخرین کلیک مخفی نشود. بدون این لغو، تایمرهای قدیمی هر کدام جداگانه کلاس را برمی‌داشتند.






✔ تغییرات ذخیره شد (بعد از ۲ ثانیه محو می‌شود)





بدون clearTimeout، اگر کاربر دو بار پشت سر هم کلیک کند، تایمر کلیک اول پیام را زودتر از موعد پنهان می‌کند.



مثال زنده: جستجو با debounce



فرض کنید با هر حرفی که کاربر در کادر جستجو تایپ می‌کند، یک درخواست به سرور بفرستیم؛ برای کلمه «کرمانشاه» ۸ درخواست بی‌فایده! debounce یعنی «صبر کن تا کاربر تایپ کردن را تمام کند (مثلاً ۵۰۰ میلی‌ثانیه چیزی ننویسد)، بعد فقط یک بار اجرا کن». هر حرف جدید، تایمر قبلی را لغو می‌کند و تایمر تازه‌ای می‌سازد.



function debounce(fn, delay) {
  let timerId;                              // closure: بین همه صدا زدن‌ها مشترک است
  return (...args) => {
    clearTimeout(timerId);                  // تایمر قبلی لغو شود
    timerId = setTimeout(() => fn(...args), delay);
  };
}

const cities = ["تهران", "تبریز", "شیراز", "اصفهان", "مشهد", "کرج", "کرمان", "کرمانشاه", "رشت", "یزد"];
let keys = 0;
let searches = 0;

function search(query) {
  searches++;                               // در پروژه واقعی: این‌جا fetch می‌زنیم
  const q = query.trim();
  const found = q ? cities.filter(c => c.includes(q)) : [];
  results.textContent = `«${q}»: ${found.join("، ") || "نتیجه‌ای نیست"}`;
  stats.textContent = `${keys} بار تایپ ← فقط ${searches} بار جستجو`;
}

const debouncedSearch = debounce(search, 500);

searchInput.addEventListener("input", () => {
  keys++;
  debouncedSearch(searchInput.value);
});













throttle خویشاوند debounce است: «حداکثر هر X میلی‌ثانیه یک بار اجرا کن، هر چقدر هم رویداد بیاید». debounce برای جستجو و ذخیره خودکار فرم مناسب است (منتظر پایان کار کاربر)؛ throttle برای رویدادهای پشت سر همی مثل scroll، resize و mousemove (به‌روزرسانی منظم در حین کار). یک پیاده‌سازی ساده:



function throttle(fn, interval) {
  let last = 0;
  return (...args) => {
    const now = Date.now();
    if (now - last >= interval) {
      last = now;
      fn(...args);
    }
  };
}

window.addEventListener("scroll", throttle(() => console.log(window.scrollY), 200));



Throttle تابعی برمی‌گرداند که fn را حداکثر یک بار در هر بازهٔ زمانی صدا می‌زند. last زمان آخرین اجرای واقعی را نگه می‌دارد. اگر از آن زمان به اندازهٔ interval نگذشته باشد، این دور نادیده گرفته می‌شود. برای رویدادهایی مثل اسکرول که خیلی تند تکرار می‌شوند، این کار از اجرای بی‌وقفهٔ تابع سنگین جلوگیری می‌کند.



اشتباه رایج: نوشتن setTimeout(myFunc(), 1000). با پرانتز، تابع همان لحظه اجرا می‌شود و نتیجه آن (معمولاً undefined) به setTimeout داده می‌شود؛ درستش setTimeout(myFunc, 1000) است. اگر آرگومان لازم دارید: setTimeout(() => myFunc(5), 1000).



اشتباه رایج: ساختن interval جدید بدون متوقف کردن قبلی. اگر در کرنومتر بالا شرط if (timerId !== null) return; نبود، هر کلیک روی «شروع» یک interval تازه می‌ساخت؛ کرنومتر تند و تندتر می‌شد و دکمه «توقف» فقط آخرین interval را متوقف می‌کرد.



اشتباه رایج: ساختن تابع debounce داخل listener: input.addEventListener("input", () => debounce(search, 500)()). این‌طوری با هر حرف یک debounce تازه (با timerId تازه) ساخته می‌شود و هیچ تایمری لغو نمی‌شود. debounce را یک بار بسازید و نتیجه‌اش را استفاده کنید.



تمرین:

۱) یک «شمارش معکوس» بسازید: کاربر تعداد ثانیه را در یک input وارد کند و دکمه «شروع» را بزند؛ با setInterval هر ثانیه یکی کم شود و روی صفحه نمایش داده شود، در صفر با clearInterval متوقف شود و پیام «تمام!» بدهد. ورودی خالی یا منفی را نپذیرید.

۲) یک textarea بسازید که متنش با debounce (۱ ثانیه بعد از آخرین تایپ) در Console چاپ شود و کنارش پیام «ذخیره شد» ظاهر شود.
