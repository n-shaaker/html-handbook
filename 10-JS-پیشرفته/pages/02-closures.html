۲) بستارها (Closures)

Closure یعنی تابع، متغیرهای محیطی را که در آن ساخته شده «به خاطر می‌سپارد»؛ حتی بعد از اینکه تابع بیرونی تمام شده باشد. تابع داخلی به خود متغیر (نه یک کپی از مقدارش) دسترسی دارد؛ پس اگر متغیر تغییر کند، تابع مقدار جدید را می‌بیند.

function makeCounter() {
  let count = 0;               // این متغیر از بیرون قابل دسترسی نیست

  return function () {
    count++;                   // ولی تابع داخلی آن را به خاطر دارد
    return count;
  };
}

const counterA = makeCounter();
const counterB = makeCounter();

console.log(counterA());   // 1
console.log(counterA());   // 2
console.log(counterA());   // 3
console.log(counterB());   // 1  ← شمارنده جدا

متغیر count داخل makeCounter ساخته می‌شود و بعد از پایان آن تابع هم، تا وقتی تابع برگشتی زنده است، از بین نمی‌رود. هر بار صدا زدن تابع برگشتی یکی به همان count اضافه می‌کند. counterA و counterB دو بار جدا makeCounter را صدا زده‌اند، پس هر کدام شمارندهٔ خودش را دارد.






داده خصوصی (Private) با closure



مثال کاربردی: کیف پول که موجودی‌اش فقط از راه متدها قابل تغییر است و کسی نمی‌تواند از بیرون بنویسد balance = 1000000.



function createWallet(initial) {
  let balance = initial;            // خصوصی؛ فقط متدهای زیر به آن دسترسی دارند

  return {
    deposit(amount) { balance += amount; return balance; },
    withdraw(amount) {
      if (amount > balance) return "موجودی کافی نیست";
      balance -= amount;
      return balance;
    },
    getBalance() { return balance; }
  };
}

const wallet = createWallet(1000);
console.log(wallet.deposit(500));     // 1500
console.log(wallet.withdraw(2000));   // موجودی کافی نیست
console.log(wallet.getBalance());     // 1500
console.log(wallet.balance);          // undefined ← مستقیم قابل دسترسی نیست



موجودی در متغیر balance است و جزو ویژگی‌های شیء برگشتی نیست. فقط متدهایی که داخل همین تابع ساخته شده‌اند به آن دسترسی دارند. deposit مبلغ را اضافه می‌کند و withdraw اگر موجودی کافی نباشد برداشت را انجام نمی‌دهد. خواندن wallet.balance مقدار undefined می‌دهد، چون چنین ویژگی‌ای روی شیء تعریف نشده است.










مثال زنده: دو شمارنده مستقل



function setupCounter(button, display) {
  let clicks = 0;                     // هر شمارنده متغیر خودش را دارد
  button.addEventListener("click", () => {
    clicks++;
    display.textContent = clicks;
  });
}

setupCounter(btnA, displayA);
setupCounter(btnB, displayB);



هر بار صدا زدن setupCounter یک متغیر clicks تازه می‌سازد. تابع کلیک همان متغیر را به یاد می‌آورد، چون داخل همان محدوده ساخته شده است. دو دکمه دو شمارندهٔ جدا دارند و کلیک یکی، عدد دیگری را زیاد نمی‌کند.

closure در حلقه: let در مقابل var



const fns = [];
for (let i = 1; i <= 3; i++) {
  fns.push(() => i);       // هر دور حلقه i جدای خودش را دارد
}
console.log(fns.map(f => f()));    // [1, 2, 3]

const fns2 = [];
for (var j = 1; j <= 3; j++) {
  fns2.push(() => j);      // همه یک j مشترک دارند
}
console.log(fns2.map(f => f()));   // [4, 4, 4]










چرا [4, 4, 4]؟ var محدوده بلوکی ندارد؛ پس در کل حلقه فقط یک متغیر j وجود دارد و هر سه تابع به همان یک متغیر دسترسی دارند. توابع بعد از تمام شدن حلقه صدا زده می‌شوند و آن موقع j به 4 رسیده است (شرط j <= 3 با j = 4 غلط شد و حلقه تمام شد). اما let در حلقه for، برای هر دور یک متغیر i تازه می‌سازد و هر تابع i دور خودش را به خاطر می‌سپارد.



اشتباه رایج (سؤال معروف مصاحبه): استفاده از var در حلقه همراه با کد ناهمگام:
for (var i = 1; i <= 3; i++) { setTimeout(() => console.log(i), 100); }
سه بار 4 چاپ می‌کند، نه 1، 2، 3. راه‌حل ساده: به جای var از let استفاده کنید.



هر بار که تابعی داخل تابع دیگر بنویسید و از متغیرهای بیرونی استفاده کند، یک closure ساخته‌اید. تابع رویدادی که به متغیر بیرونی دسترسی دارد هم closure است.



اشتباه رایج: انتظار داشتن اینکه دو بار صدا زدن makeCounter() یک شمارنده مشترک بسازد. هر بار صدا زدن، یک محیط جدید و مستقل می‌سازد.
