۹) وعده‌ها (Promises)

Promise شیئی است که نتیجهٔ یک کار ناهمگام را نگه می‌دارد؛ کاری که همین لحظه تمام نمی‌شود، مثل انتظار یا درخواست شبکه. به‌جای دادن نتیجهٔ مستقیم، شیء وعده می‌دهد که بعداً یا مقدار موفق را تحویل می‌دهد یا دلیل شکست را. تا آن لحظه، برنامه می‌تواند به خط‌های بعدی برسد و هر وقت نتیجه آماده شد با then یا catch به آن واکنش نشان دهد. یک Promise در هر لحظه یکی از این سه حالت را دارد:

حالتیعنی
pendingدر انتظار؛ کار هنوز تمام نشده
fulfilledموفق؛ با resolve(value) تمام شد
rejectedناموفق؛ با reject(error) تمام شد

ساختن و مصرف Promise

function orderPizza(type) {
  return new Promise((resolve, reject) => {
    log(`سفارش ${type} ثبت شد...`);
    setTimeout(() => {
      if (type === "آناناس") {
        reject(new Error("این پیتزا را نداریم!"));
      } else {
        resolve(`پیتزا ${type} آماده است 🍕`);
      }
    }, 1200);
  });
}

orderPizza("پپرونی")
  .then(message => log("✔", message))
  .catch(error => log("✖", error.message))
  .finally(() => log("— پایان سفارش —"));

سازندهٔ Promise تابعی می‌گیرد که resolve و reject را در اختیارش می‌گذارد. اگر نوع پیتزا قابل‌قبول باشد، resolve نتیجهٔ موفق را می‌فرستد و then آن را می‌گیرد. نوع غیرمجاز reject می‌شود و به catch می‌رود. finally در هر دو حالت اجرا می‌شود و برای کاری است که باید آخر سر انجام شود.








متدکی اجرا می‌شود


.then(fn)وقتی Promise موفق شد؛ fn مقدار resolve را می‌گیرد


.catch(fn)وقتی Promise (یا هر then قبلی) خطا داد


.finally(fn)در هر صورت، آخر کار





زنجیره then — خداحافظی با Callback Hell



// بعد از ms میلی‌ثانیه، با value موفق می‌شود
function wait(ms, value) {
  return new Promise(resolve => {
    setTimeout(() => resolve(value), ms);
  });
}

wait(500, 1)
  .then(n => { log("مرحله اول:", n); return wait(500, n + 1); })
  .then(n => { log("مرحله دوم:", n); return wait(500, n + 1); })
  .then(n => { log("مرحله سوم:", n); })
  .catch(err => log("خطا:", err));



wait بعد از مدت مشخص با یک مقدار resolve می‌شود. هر then می‌تواند Promise تازه‌ای برگرداند تا مرحلهٔ بعد منتظر همان بماند. اگر یکی از مرحله‌ها خطا بدهد، زنجیره به catch می‌رود و thenهای بعدی اجرا نمی‌شوند.











هر then یک Promise جدید برمی‌گرداند؛ برای همین می‌شود آن‌ها را پشت سر هم نوشت. اگر داخل then یک Promise را return کنید، then بعدی منتظر تمام شدن آن می‌ماند. یک catch در آخر، خطای همه مرحله‌ها را می‌گیرد.



ترتیب اجرا: کد همگام، microtask و تایمر



JavaScript اول همه کدهای همگام فعلی را تا آخر اجرا می‌کند. بعد سراغ صف microtaskها می‌رود (callbackهای then/catch/finally و ادامه توابع async بعد از await) و همه آن‌ها را خالی می‌کند. فقط بعد از آن نوبت تایمرها (setTimeout و setInterval) و رویدادها می‌رسد. به این چرخه Event Loop می‌گویند.



log("1: همگام");
setTimeout(() => log("4: setTimeout با تأخیر 0"), 0);
Promise.resolve().then(() => log("3: then (microtask)"));
log("2: همگام");



دو log همگام همان لحظه و به ترتیب اجرا می‌شوند. then یک microtask است و قبل از تایمر صف اجرا می‌شود، حتی اگر تأخیر تایمر صفر باشد. به همین دلیل ترتیب، همگام، بعد then، و در آخر timeout است. صفر در setTimeout یعنی «در اولین فرصت بعد از کار همگام»، نه «همین لحظه».










با اینکه setTimeout زودتر نوشته شده و تأخیرش صفر است، بعد از then اجرا می‌شود؛ چون microtaskها همیشه قبل از تایمر بعدی اجرا می‌شوند.



چند Promise با هم





متدنتیجه


Promise.all([...])منتظر همه؛ اگر یکی خطا داد، کل کار خطا می‌شود


Promise.allSettled([...])منتظر همه؛ نتیجه موفق و ناموفق هر کدام را می‌دهد


Promise.race([...])اولین Promise که تمام شود (موفق یا ناموفق)


Promise.any([...])اولین Promise موفق





const p1 = wait(800, "کاربر");
const p2 = wait(400, "سفارش‌ها");
const p3 = wait(600, "پیام‌ها");

Promise.all([p1, p2, p3]).then(results => {
  log("همه رسیدند:", results);
});

Promise.race([p1, p2, p3]).then(first => {
  log("اولین:", first);
});

// خروجی (ترتیب زمانی):
// اولین: سفارش‌ها                       ← بعد از ۴۰۰ میلی‌ثانیه
// همه رسیدند: ["کاربر","سفارش‌ها","پیام‌ها"]  ← بعد از ۸۰۰ میلی‌ثانیه، به ترتیب آرایه ورودی



Promise.all وقتی همه موفق شوند یک آرایه به ترتیب همان ورودی‌ها می‌دهد، نه به ترتیب تمام شدن. اگر یکی رد شود، کل all رد می‌شود. Promise.race با اولین موردی که تمام شود، چه موفق و چه ناموفق، نتیجه را مشخص می‌کند. اینجا کوتاه‌ترین انتظار مال «سفارش‌ها» است.











نتیجه Promise.all به ترتیب آرایه ورودی است، نه به ترتیب زمان رسیدن. «سفارش‌ها» زودتر از همه رسید ولی در جایگاه دوم آرایه نتیجه است.



وقتی یکی از Promiseها خطا بدهد



فرض کنید از سه سرور داده می‌گیریم و سرور B خراب است. هر چهار متد را روی همین وضعیت امتحان می‌کنیم:



// بعد از ms میلی‌ثانیه، با خطا تمام می‌شود
function fail(ms, message) {
  return new Promise((resolve, reject) => {
    setTimeout(() => reject(new Error(message)), ms);
  });
}

// هر بار سه درخواست تازه می‌سازد: A بعد از 300، B (خطا) بعد از 100، C بعد از 500 میلی‌ثانیه
function makeRequests() {
  return [wait(300, "سرور A"), fail(100, "سرور B خراب است"), wait(500, "سرور C")];
}

Promise.all(makeRequests())
  .then(r => log("all:", r))
  .catch(err => log("all ✖:", err.message));

Promise.allSettled(makeRequests()).then(results => {
  results.forEach(r => {
    if (r.status === "fulfilled") {
      log("allSettled:", r.status, r.value);
    } else {
      log("allSettled:", r.status, r.reason.message);
    }
  });
});

Promise.race(makeRequests())
  .then(v => log("race:", v))
  .catch(err => log("race ✖:", err.message));

Promise.any(makeRequests())
  .then(v => log("any:", v))
  .catch(err => log("any ✖: همه ناموفق بودند"));

// خروجی:
// all ✖: سرور B خراب است          ← اولین خطا کل کار را خراب کرد (۱۰۰ms)
// race ✖: سرور B خراب است         ← اولین Promise تمام‌شده، خطا بود (۱۰۰ms)
// any: سرور A                     ← اولین موفق (۳۰۰ms)
// allSettled: fulfilled سرور A    ← گزارش کامل همه، بعد از تمام شدن همه (۵۰۰ms)
// allSettled: rejected سرور B خراب است
// allSettled: fulfilled سرور C



fail بعد از مدت مشخص reject می‌شود. Promise.all با اولین رد شدن، شکست می‌خورد و نتیجه‌های موفق دیگر را به شما نمی‌دهد. allSettled منتظر همه می‌ماند و برای هر کدام وضعیت fulfilled یا rejected را جدا برمی‌گرداند تا بتوانید ببینید کدام سرور خراب بوده و کدام پاسخ داده است.













کی از کدام استفاده کنیم؟مثال


Promise.allهمه داده‌ها لازم‌اند؛ بدون یکی صفحه کامل نمی‌شود (پروفایل + سفارش‌ها)


Promise.allSettledهر کدام جدا مهم است؛ می‌خواهیم گزارش موفق و ناموفق‌ها را بدهیم (آپلود چند فایل)


Promise.raceساختن مهلت زمانی (timeout): مسابقه بین درخواست و یک تایمر


Promise.anyچند منبع یکسان داریم و سریع‌ترین پاسخ موفق کافی است (چند سرور آینه)





اشتباه رایج: فراموش کردن return داخل then وقتی Promise جدید می‌سازید. در این حالت then بعدی منتظر نمی‌ماند و مقدار undefined می‌گیرد. دقت کنید تابع پیکانی با آکولاد (n => { wait(500) }) چیزی برنمی‌گرداند؛ بدون آکولاد (n => wait(500)) خودکار return می‌کند.



اشتباه رایج: نگذاشتن catch در آخر زنجیره. Promise ردشده‌ای که کسی آن را نگیرد، در Console خطای Uncaught (in promise) می‌دهد و کاربر هیچ پیامی نمی‌بیند.



تمرین: تابع checkStock(item) بسازید که یک Promise برگرداند: اگر item در آرایه ["لپ‌تاپ", "موبایل", "هدفون"] بود بعد از ۱ ثانیه با پیام «item موجود است» resolve و وگرنه با new Error("item ناموجود است") reject شود. نتیجه را با then/catch در صفحه نشان دهید. سپس موجودی سه کالا (یکی ناموجود) را با Promise.allSettled بررسی کنید و برای هر کالا ✔ یا ✖ چاپ کنید.
