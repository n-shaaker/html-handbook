۱۵) انتشار رویداد و Event Delegation

رویداد فقط روی همان عنصری که کلیک شده تمام نمی‌شود؛ در درخت DOM بالا می‌رود. اگر این مسیر را بشناسید، می‌توانید یک شنونده روی پدر بگذارید تا کلیک فرزندان، حتی فرزندان تازه‌ساخته‌شده، را همان‌جا مدیریت کنید. به این روش واگذاری رویداد می‌گویند.

انتشار رویداد (Bubbling)

وقتی روی یک عنصر کلیک می‌کنید، رویداد اول روی خود آن عنصر اجرا می‌شود و بعد مثل حباب به سمت پدرها بالا می‌رود: پدر، پدربزرگ، ... تا document.

outer.addEventListener("click", () => log("outer (پدربزرگ)"));
middle.addEventListener("click", () => log("middle (پدر)"));
inner.addEventListener("click", (event) => {
  log("inner (خود دکمه)");
  if (stopCheck.checked) {
    event.stopPropagation();          // رویداد از این‌جا بالاتر نمی‌رود
    log("— stopPropagation: رویداد بالاتر نرفت —");
  }
});

// پاک کردن خروجی قبلی؛ با true در مرحله capture و قبل از همه اجرا می‌شود
outer.addEventListener("click", () => (outBox.textContent = ""), true);

// خروجی کلیک روی دکمه: inner، سپس middle، سپس outer (از داخل به بیرون)

کلیک روی دکمهٔ درونی اول شنوندهٔ همان عنصر را اجرا می‌کند، بعد به پدر و بعد به پدربزرگ می‌رسد. این مسیر را bubbling می‌نامند. stopPropagation ادامهٔ همین مسیر را قطع می‌کند. آرگومان true در شنوندهٔ دیگر یعنی آن تابع در مسیر رفت، از بیرون به داخل، اجرا شود و اینجا برای پاک کردن خروجی قبل از بقیه به کار رفته است.

با event.stopPropagation() جلوی بالا رفتن رویداد را می‌گیریم. تیک گزینه بالا را بزنید و دوباره کلیک کنید. روی خود کادرهای middle و outer هم کلیک کنید تا ببینید رویداد فقط از عنصر کلیک‌شده به بالا می‌رود. از stopPropagation کم استفاده کنید؛ چون listenerهای دیگر (مثلاً بستن منو با کلیک روی صفحه) را هم از کار می‌اندازد.

Event Delegation — یک listener برای همه



به جای اینکه روی تک‌تک فرزندها listener بگذاریم، یکی روی پدر می‌گذاریم و با event.target می‌فهمیم روی کدام فرزند کلیک شده. مزیت‌ها:



    

  • کد کمتر و حافظه کمتر (یک listener به جای صدها).
    • 

  • برای عنصرهایی که بعداً اضافه می‌شوند هم خودبه‌خود کار می‌کند.
    • 




let counter = 3;

list.addEventListener("click", (event) => {
  const deleteBtn = event.target.closest(".delete");
  if (deleteBtn) {
    deleteBtn.closest("li").remove();
    return;
  }

  const li = event.target.closest("li");
  if (li && list.contains(li)) li.classList.toggle("done");
});

addBtn.addEventListener("click", () => {
  counter++;
  list.insertAdjacentHTML("beforeend",
    `<li><span>آیتم جدید ${counter}</span><button class="btn danger delete">حذف</button></li>`);
});



یک شنونده روی خود فهرست کافی است، حتی برای دکمه‌هایی که بعداً ساخته می‌شوند. event.target عنصری است که کلیک دقیقاً روی آن بوده. closest از آنجا بالا می‌رود تا دکمهٔ حذف یا خود li را پیدا کند. اگر دکمهٔ حذف باشد ردیف حذف می‌شود و تابع برمی‌گردد تا تغییر کلاس انجام نشود.

event.target.closest("selector") بهترین دوست Event Delegation است: از خود target شروع می‌کند و به سمت پدرها بالا می‌رود تا اولین عنصری را که با selector جور است پیدا کند؛ پس حتی اگر روی یک تگ داخلی (مثل span داخل li) کلیک شود، li را پیدا می‌کند. اگر چیزی پیدا نکند null برمی‌گرداند. شرط list.contains(li) مطمئن می‌شود li پیداشده داخل همین فهرست است (برای وقتی که خود فهرست داخل یک li دیگر باشد).



Capturing — مسیر برعکس



هر رویداد سه مرحله دارد: capture (از document به سمت پایین تا عنصر هدف)، target (روی خود عنصر) و bubble (برگشت به سمت بالا). listenerها به‌طور پیش‌فرض در مرحله bubble اجرا می‌شوند؛ با پارامتر سوم true (یا { capture: true }) در مرحله capture اجرا می‌شوند. در مثال اول همین صفحه، listener پاک‌کننده خروجی به همین دلیل قبل از همه اجرا می‌شود.



// پارامتر سوم true یعنی در مرحله رفت (از بالا به پایین) اجرا شو
outer.addEventListener("click", handler, true);



پارامتر سوم true شنونده را در مرحلهٔ capture ثبت می‌کند، یعنی هنگام رفتن رویداد از پدرها به سمت عنصر هدف. حالت پیش‌فرض false است و شنونده در راه برگشت اجرا می‌شود. از capture وقتی استفاده می‌کنید که باید قبل از شنونده‌های درونی کاری انجام شود.



اشتباه رایج: استفاده از event.target به جای closest. اگر داخل دکمه یک آیکون یا span باشد، target همان span است نه دکمه و شرطی مثل event.target.classList.contains("delete") کار نمی‌کند.



اشتباه رایج: گذاشتن متن واردشده توسط کاربر داخل innerHTML یا insertAdjacentHTML. اگر کاربر بنویسد <img src=x onerror="alert(1)">، کد او اجرا می‌شود (حمله XSS). در مثال بالا فقط یک عدد داخل HTML گذاشته‌ایم؛ برای متن کاربر عنصر را با createElement بسازید و متن را با textContent بگذارید.



تمرین: یک جدول با ۲۰ ردیف (مثلاً نام و نمره ۲۰ دانشجو، ساخته‌شده با حلقه) بسازید و فقط با یک listener روی table کار کنید: با کلیک روی هر ردیف (tr) کلاس انتخاب آن را toggle کنید و متن ردیف را در Console چاپ کنید. کلیک روی سرستون (th) نباید کاری بکند (راهنما: closest("tbody tr")).
