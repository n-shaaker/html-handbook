## ۰–۱۰ | مرور HTML

یک فرم جلسهٔ قبل را باز کنید و بپرسید کدام عنصرها معنایی‌اند و کدام فیلد `name` ندارد. اگر `name` نباشد، همان فیلد در دادهٔ ارسالی غایب است.

## ۱۰–۳۵ | آموزش

روی `teach/selectors-demo.html`:

1. **سه روش اعمال CSS:** Inline (`style="..."`)، Internal (`<style>`)، External (`<link rel="stylesheet">`). External استاندارد است چون یک فایل CSS برای همهٔ صفحات استفاده و کش می‌شود.
2. **انتخاب‌گرها:** انتخاب‌گر عنصر مثل `p` همهٔ پاراگراف‌ها را هدف می‌گیرد. انتخاب‌گر کلاس مثل `.highlight` فقط عنصرهایی را که آن کلاس را دارند. انتخاب‌گر شناسه مثل `#warning` یک عنصر یکتا را. انتخاب‌گر ترکیبی مثل `.field label` فقط `label`هایی را که داخل عنصری با کلاس `field` هستند. شبه‌کلاس حالت عنصر را هدف می‌گیرد؛ `:hover` وقتی نشانگر روی عنصر است و `:focus` وقتی عنصر با صفحه‌کلید یا کلیک فعال شده است.
3. **Cascade و Specificity:**
   - وقتی چند قانون روی یک عنصر اثر می‌گذارند، اول **Specificity** مقایسه می‌شود: ID (۱-۰-۰) > Class/شبه‌کلاس (۰-۱-۰) > Element (۰-۰-۱)
   - اگر Specificity برابر بود، قانونی که **بعدتر** نوشته شده برنده است
   - استایل Inline از همهٔ selectorها قوی‌تر است و فقط `!important` بر آن غلبه می‌کند
4. **وراثت (Inheritance):** ویژگی‌های متنی مثل `color` و `font-family` از والد به فرزند می‌رسند؛ `margin`، `padding` و `border` به ارث نمی‌رسند
5. **واحد و رنگ:** `px` پیکسل ثابت است. `rem` نسبت به اندازهٔ قلم عنصر ریشه (`html`) حساب می‌شود، پس اگر کاربر قلم مرورگر را بزرگ کند، فاصله و متنی که با `rem` نوشته شده هم بزرگ می‌شود و خواندن آسان‌تر می‌ماند. رنگ را با کد هگز مثل `#2563eb` یا تابع `rgb()` می‌نویسید. متغیر CSS، مثل `--primary`، یک مقدار را یک‌جا نام‌گذاری می‌کند تا عوض کردن پالت، ده‌ها قانون را یکی‌یکی تغییر ندهد.

قانون کلاس از این جلسه به بعد: CSS را در فایل خارجی بنویسید و برای ظاهر از کلاس استفاده کنید. شناسه را برای استایل مصرف نکنید و آن را برای مقصد پیوندهای `#` و برای انتخاب عنصر در JavaScript نگه دارید.

اشتباه‌هایی که باید هنگام دیدن کد دانشجو اصلاح کنید:

- `!important` را برای «درست شدن» جنگِ اختصاصی‌بودن به کار نبرید. این کلمه قانون را از آبشار خارج می‌کند و قانون بعدی را هم مجبور به `!important` می‌کند. به‌جای آن، انتخاب‌گر را دقیق‌تر یا مرتب‌تر بنویسید.
- اگر ظاهر صفحه هیچ تغییری نکرد، اول مسیر `href` فایل CSS را چک کنید. در DevTools، تب Network نشان می‌دهد آن فایل بار شده یا درخواستش خطا داده است.
- جا افتادن `;` پایان یک اعلان، اعلان بعدی را هم نامعتبر می‌کند و مرورگر هر دو را نادیده می‌گیرد.
- حذف `outline` در `:focus` بدون یک جایگزین دیده‌شدنی، کاربر صفحه‌کلید را گم می‌کند چون دیگر معلوم نیست کدام عنصر فعال است.

## ۳۵–۶۵ | Live Coding

فایل‌ها: `live/contact.html` + `live/styles.css`

ترتیب نوشتن را این‌طور پیش ببرید تا هر لایه روی لایهٔ قبلی دیده شود: متغیرها و بازنشانی اولیه، سپس حروف و اندازهٔ متن، سپس رنگ، سپس پس‌زمینه، سپس فاصله‌ها، سپس دکمه‌ها، و در پایان حالت‌های `:hover` و `:focus-visible`. `:focus-visible` حلقهٔ تمرکز را عمدتاً برای کسی نشان می‌دهد که با صفحه‌کلید حرکت می‌کند، نه برای هر کلیک ماوس.

در DevTools، بخش Elements و سپس Styles، قانون‌های خط‌خورده همان‌هایی هستند که در آبشار بازنده شده‌اند. روی یکی از خط‌خوردگی‌ها بایستید و بگویید کدام قانون قوی‌تر بوده است.

## ۶۵–۱۰۰ | تمرین

دانشجو فرم تماس جلسهٔ قبل را با یک فایل جدا به نام `styles.css` ظاهر دهد و دست‌کم سه متغیر CSS تعریف کند تا رنگ‌های تکراری از یک جا بیایند.

## ۱۰۰–۱۲۰ | بررسی Specificity + جمع‌بندی

چالش کلاسی این است که پیش از اجرا بپرسید «این متن چه رنگی می‌شود؟» و سه یا چهار قانون رقیب را روی تخته بنویسید. بعد همان قانون‌ها را در DevTools نشان دهید تا پیش‌بینی با قانون برنده‌شده یکی شود.

## تکلیف

1. صفحهٔ معرفی جلسهٔ ۱ یا فرم تماس جلسهٔ ۲ را با CSS خارجی استایل دهید تا ظاهر از ساختار HTML جدا بماند.
2. یک پالت دست‌کم چهاررنگ را در `:root` به‌صورت متغیر تعریف کنید تا کل صفحه از همان نام‌ها رنگ بگیرد. `:root` همان عنصر `html` است، با این تفاوت که متغیرهای سراسری را آن‌جا می‌گذارند.
3. برای پیوندها و دکمه‌ها حالت `:hover` و `:focus-visible` بنویسید تا هم کاربر ماوس بازخورد ببیند و هم کاربر صفحه‌کلید جای تمرکز را گم نکند.
4. در یک کامنت انگلیسی توضیح دهید چرا یکی از قانون‌هایتان در آبشار برنده شده است؛ به اختصاصی‌بودن یا به ترتیب نوشتن اشاره کنید.
