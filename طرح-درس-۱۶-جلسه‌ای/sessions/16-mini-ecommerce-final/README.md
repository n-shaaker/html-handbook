**مدت:** ۱۲۰ دقیقه

**خروجی:** فروشگاه کوچک با جست‌وجو، فیلتر، سبد خرید، ماندگاری در LocalStorage، و فرستادن مخزن به سرور گیت

## معماری

- **دادهٔ ثابت:** آرایهٔ `PRODUCTS` در `data.js` است و پیش از `app.js` بارگذاری می‌شود تا وقتی منطق برنامه اجرا شد، فهرست محصولات وجود داشته باشد. در پروژهٔ واقعی همین آرایه از API می‌آید. جدا نگه داشتن داده از منطق باعث می‌شود بتوانید منبع را عوض کنید بدون آنکه رسم کارت را از نو بنویسید.
- **وضعیت سبد:** آرایهٔ `cart` فقط `{ id, qty }` را نگه می‌دارد، نه کل محصول را. نام و قیمت همیشه از `PRODUCTS` خوانده می‌شوند. اگر قیمت در فهرست عوض شود، سبد قیمت کهنه نشان نمی‌دهد، چون قیمت را کپی نکرده است.
- **جریان به‌روزرسانی:** هر تغییر سبد اول `saveCart()` را صدا می‌زند و بعد `renderCart()` را. جست‌وجو و فیلتر فقط `renderProducts()` را صدا می‌زنند، چون سبد را عوض نمی‌کنند. اگر این دو مسیر قاطی شوند، یا سبد بی‌دلیل از نو ذخیره می‌شود یا فهرست محصولات بعد از افزودن به سبد تازه نمی‌شود.

## نکته‌های فنی

- **جمع قیمت:** قیمت‌ها عدد صحیح تومان هستند، پس جمع دقیق است. اگر روزی قیمت اعشاری داشتید، مثلاً دلار، محاسبه را با کوچک‌ترین واحد پول و عدد صحیح انجام دهید. در عدد اعشاری دودویی، `0.1 + 0.2` دقیقاً `0.3` نمی‌شود و جمع سبد به‌مرور خطای گرد کردن نشان می‌دهد.
- **شکل عدد:** `toLocaleString("fa-IR")` رقم فارسی و جداکنندهٔ هزارگان می‌دهد، مثلاً `1280000` به شکل `۱٬۲۸۰٬۰۰۰`. این فقط نمایش است. در محاسبه همان عدد جاوااسکریپت را جمع کنید، نه رشتهٔ فارسی را.
- **خواندن امن LocalStorage:** هنگام بارگذاری فقط قلم‌هایی بمانند که محصولشان هنوز در `PRODUCTS` هست و `qty` آن‌ها عدد صحیح مثبت است. دادهٔ خراب اگر به جمع برسد، حاصل را `NaN` می‌کند و کل مبلغ سبد بی‌معنی می‌شود.
- **جست‌وجوی فارسی:** حرف «ي» و «ك» عربی را پیش از مقایسه به «ی» و «ک» فارسی تبدیل کنید. کیبوردها این دو شکل را متفاوت می‌فرستند و بدون یکسان‌سازی، محصولی که در داده هست با تایپ کاربر پیدا نمی‌شود.
- **دسترس‌پذیری:** دکمه‌های افزایش، کاهش و حذف `aria-label` کامل داشته باشند، چون نماد `+` و `−` به‌تنهایی نمی‌گوید این دکمه مال کدام کالا است. تعداد نتیجه‌ها و تعداد کالاهای سبد را با `aria-live` اعلام کنید. خود شبکهٔ محصولات را زنده نکنید، چون با هر حرف تایپ، صفحه‌خوان تمام کارت‌ها را از نو می‌خواند.
- **امنیت:** همهٔ متن‌ها، از جمله نام محصول و عبارت جست‌وجو، با `textContent` ساخته شوند تا ورودی کاربر به‌صورت HTML اجرا نشود.

## Git

```bash
git add .
git commit -m "Complete mini ecommerce final project"
git branch -M main
git remote add origin <YOUR_REPO_URL>
git push -u origin main
```

`<YOUR_REPO_URL>` را با نشانی مخزنی عوض کنید که در گیت‌هاب یا سرویس مشابه ساخته‌اید، مثلاً `https://github.com/USERNAME/mini-shop.git`. `git remote` نام کوتاهِ آن نشانی است و اینجا `origin` نام رایج مخزن اصلی است. اگر پیام `remote origin already exists` را دیدید، نشانی را با `git remote set-url origin <URL>` عوض کنید، نه با `remote add` دوباره. `git push -u` شاخهٔ محلی `main` را به همان شاخه در سرور می‌فرستد و ارتباط را برای دفعهٔ بعد ذخیره می‌کند. برای انتشار رایگان خود صفحه می‌توانید GitHub Pages را از تنظیمات مخزن روشن کنید.

## تکلیف برای ادامهٔ پروژه

1. مرتب‌سازی محصولات بر اساس قیمت را با یک `select` تازه اضافه کنید، یک گزینه برای ارزان‌ترین و یکی برای گران‌ترین. مرتب‌سازی را روی کپی فهرست فیلترشده انجام دهید تا آرایهٔ `PRODUCTS` جابه‌جا نشود.
2. محصولات را به‌جای `data.js` از `https://fakestoreapi.com/products` با `fetch` بخوانید و سه حالت بارگذاری، خطا و فهرست خالی را نشان دهید. شکل فیلدهای این API با شیء فعلی یکی نیست، پس موقع رسم، نام فیلدها را با پاسخ واقعی تطبیق دهید.
3. یک کد تخفیف ساده بگذارید، مثلاً `OFF10` برابر ده درصد. مبلغ تخفیف و جمع نهایی هر دو دیده شوند و تخفیف روی جمع سبد حساب شود، نه روی یک قلم به‌تنهایی، مگر آنکه خودتان این قاعده را در رابط بنویسید.
4. یک بخش «تکمیل خرید» با فرم نشانی بسازید و همان اعتبارسنجی جلسهٔ ۱۲ را به کار ببرید: برچسب، بررسی فیلد خالی، و جلوگیری از ارسال پیش‌فرض فرم تا خطا زیر همان فیلد بماند.
