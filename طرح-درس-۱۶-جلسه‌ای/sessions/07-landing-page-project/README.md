## معیار تمام شدن

صفحه وقتی تمام است که همهٔ موردهای زیر برقرار باشد. هر مورد را با یک کار مشخص امتحان کنید، نه با نگاه کلی به ظاهر.

- همهٔ بخش‌ها وجود داشته باشند: ناوبری، قهرمان (Hero، یعنی بخش اول با پیام اصلی)، ویژگی‌ها، محصولات، دعوت به اقدام (CTA، یعنی جایی که از کاربر یک کار مشخص می‌خواهید) و پاورقی.
- پیوندهای نوار ناوبری به `id` واقعی همان بخش‌ها بروند. با `scroll-padding-top` روی `html`، عنوان بخش زیر هدر چسبان پنهان نشود.
- در عرض‌های ۳۷۵، ۷۶۸ و ۱۲۸۰ پیکسل اسکرول افقی نباشد. این را در نوار دستگاه DevTools امتحان کنید.
- همهٔ تصویرها `alt` معنادار و همچنین `width` و `height` داشته باشند تا هم جایگزین متنی داشته باشند و هم جای عکس از قبل رزرو شود.
- دکمه‌ها و پیوندها حالت `:hover` و `:focus-visible` داشته باشند. متن روی زمینهٔ تیره آن‌قدر روشن باشد که خوانده شود.
- فرم دعوت به اقدام فیلد ایمیل را با `label` معرفی کند، حتی اگر آن برچسب را برای ظاهر با کلاس visually-hidden از دید پنهان کرده باشید. صفحه‌خوان همچنان برچسب را می‌خواند.
- سند در [اعتبارسنج W3C](https://validator.w3.org/#validate_by_input) خطا ندهد.

## نکته‌های فنی که هنگام ساختن باید بگویید

- **هدر چسبان:** با `position: sticky`، `top: 0` و `z-index: 10` نوار بالا هنگام اسکرول سر جایش می‌ماند و روی محتوا قرار می‌گیرد. `z-index` ترتیب روی‌هم‌افتادن را تعیین می‌کند و عدد بزرگ‌تر جلوتر دیده می‌شود. روی `html` مقدار `scroll-padding-top` بگذارید تا با کلیک روی پیوند `#features`، عنوان بخش زیر همین هدر نرود.
- **بخش قهرمان:** یک پیام اصلی و یک اقدام اصلی کافی است. اگر چند دکمهٔ هم‌وزن بگذارید، کاربر نمی‌فهمد کدام کار را باید بکند. تصویر پس‌زمینه را با گرادیان تیره بپوشانید تا متن سفید روی عکس شلوغ هم کنتراست کافی داشته باشد.
- **`clamp()`** اندازهٔ قلم تیتر را بین یک حداقل و یک حداکثر، متناسب با عرض صفحه، تنظیم می‌کند. مثلاً تیتر در موبایل از حد خوانا کوچک‌تر نمی‌شود و در دسکتاپ بی‌جهت غول‌آسا نمی‌شود.
- **`.visually-hidden`:** متن را از دید پنهان می‌کند ولی در دسترس صفحه‌خوان می‌ماند. `display: none` این کار را نمی‌کند، چون عنصر را از درخت دسترس‌پذیری هم حذف می‌کند.
- **`prefers-reduced-motion`:** پرس‌وجویی است که می‌پرسد آیا کاربر در سیستم‌عامل حرکت و انیمیشن را کم کرده است یا نه. اگر کرده باشد، اسکرول نرم را خاموش کنید تا صفحه برای او جهش ناگهانی نداشته باشد.

## Git در پانزده دقیقهٔ آخر

اگر این تنظیم یک‌بارهٔ نام و ایمیل قبلاً انجام نشده، فقط یک بار روی همان کامپیوتر اجرا شود:

```bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
```

این دو مقدار روی commitهایی که همین کامپیوتر می‌سازد نوشته می‌شود تا معلوم باشد تغییر مال کیست. داخل پوشهٔ پروژه این دنباله را اجرا کنید و خروجی هر دستور را با هم بخوانید:

```bash
git init
# .gitignore already exists in live/ (OS junk files, editor settings)
git status          # see what will be tracked
git add .
git commit -m "Initial landing page"
git log --oneline   # confirm the commit
```

سه ناحیه را با همین دستورها نشان دهید. پوشهٔ کار همان فایل‌های روی دیسک است. `git add` تغییر را به ناحیهٔ آماده‌سازی (staging) می‌برد، یعنی فهرست آنچه در عکس بعدی تاریخچه می‌آید. `git commit` آن عکس را در تاریخچه ثبت می‌کند. پیام commit کوتاه، انگلیسی، و توصیف همان تغییر باشد، مثل `Initial landing page`، نه کلمه‌ای مبهم.

اشتباه‌هایی که همان‌جا اصلاح کنید: اجرای `git init` در پوشهٔ اشتباه، مثلاً روی Desktop، که پوشه‌های بی‌ربط را هم وارد مخزن می‌کند. زدن `git commit` بدون `git add`، که چیزی برای ثبت ندارد و commit ساخته نمی‌شود. پیامی مثل `"update"` که بعداً معلوم نمی‌کند چه چیزی تغییر کرده است.

## تکلیف

1. صفحه را شخصی کنید: نام برند، رنگ‌ها، متن‌ها و تصویرها مال خود دانشجو باشد تا فقط فایل کلاس را تحویل نداده باشد.
2. یک بخش «نظر مشتریان» با `blockquote` برای نقل قول و `figure` همراه `figcaption` برای منبع نظر اضافه کنید. `figure` محتوای خودبسنده مثل نقل‌قول یا تصویر است و `figcaption` شرح آن است.
3. دست‌کم سه commit جدا با پیام معنادار بسازید. مثلاً commit سوم می‌تواند `"Add testimonials section"` باشد تا تاریخچه نشان دهد هر بخش کی اضافه شده است.
