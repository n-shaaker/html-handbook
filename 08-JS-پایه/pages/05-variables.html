۵) متغیرها (Variables: let، const، var)

متغیر مثل یک جعبهٔ برچسب‌دار است: یک اسم انتخاب می‌کنید و یک مقدار را داخل آن می‌گذارید تا بعداً همان مقدار را با آن اسم بخوانید یا، اگر اجازه داده باشید، عوض کنید. بدون متغیر باید عدد و متن را هر بار از نو در کد بنویسید و اگر مقدار عوض شود، همهٔ جاها را دستی اصلاح کنید.

let name = "سارا";
const birthYear = 1380;
let age = 1405 - birthYear;

console.log(name);
console.log(age);





let name جعبه‌ای می‌سازد که بعداً می‌توان مقدارش را عوض کرد و الان متن «سارا» را نگه می‌دارد. const birthYear سال تولد را نگه می‌دارد و چون این عدد در طول برنامه عوض نمی‌شود، با const ساخته شده است. خط سوم سن تقریبی را از تفریق دو عدد حساب می‌کند و در age می‌گذارد. دو console.log مقدار ذخیره‌شده را در Console نشان می‌دهند.



سه کلمه برای ساختن متغیر





کلمهمقدار بعداً عوض شود؟کی استفاده کنیم؟


constخیرپیش‌فرض شما؛ هر وقت مقدار عوض نمی‌شود


letبلهوقتی مقدار تغییر می‌کند (شمارنده، جمع و ...)


varبلهروش قدیمی؛ در کد جدید استفاده نکنید





مثال: let قابل تغییر است، const نه



let score = 10;
score = 15;           // ✔ مشکلی نیست
console.log(score);

const pi = 3.14;
pi = 3;               // ✖ خطا: نمی‌شود به const مقدار جدید داد










وقتی متغیر با let ساخته شده باشد، می‌توانید بعداً فقط نام آن را بنویسید و با = مقدار تازه بدهید؛ دیگر let را تکرار نمی‌کنید. const هم در لحظهٔ ساخت مقدار می‌گیرد، ولی تلاش برای دادن مقدار جدید به همان نام خطا تولید می‌کند و اجرای بقیهٔ کد متوقف می‌شود.



خط آخر عمداً خطا دارد. مرورگر پیام TypeError: Assignment to constant variable. را نشان می‌دهد و اجرای بقیه کد متوقف می‌شود. نکته دیگر: const باید همان لحظه تعریف مقدار بگیرد؛ const pi; به‌تنهایی خطای نحوی است.



تعریف بدون مقدار و چند متغیر در یک خط



let city;                       // مقدار ندارد → undefined
console.log(city);

let a = 1, b = 2, c = 3;
console.log(a + b + c);










اگر let را بدون مقدار بنویسید، متغیر ساخته می‌شود ولی هنوز چیزی داخلش نیست؛ JavaScript این حالت را undefined می‌نامد. در خط سوم سه متغیر در یک دستور ساخته شده‌اند و هر کدام مقدار خودش را دارد. این شکل کوتاه است، ولی اگر هر متغیر توضیح جدا لازم داشته باشد، نوشتن هر کدام در یک خط خواناتر است.



محدوده (Scope): چرا var را کنار گذاشتیم؟



متغیری که با let یا const داخل یک بلوک { } ساخته شود، فقط داخل همان بلوک وجود دارد (Block Scope). اما var به بلوک اهمیت نمی‌دهد و بیرون از آن هم دیده می‌شود؛ همچنین می‌شود یک متغیر var را دوباره تعریف کرد بدون اینکه خطایی بگیرید. این دو رفتار منشأ باگ‌های زیادی هستند.



{
  var discountA = 10;
  let discountB = 20;
}
console.log(discountA);   // 10 ← var از بلوک بیرون «نشت» کرده
console.log(discountB);   // ✖ ReferenceError: discountB is not defined










آکولاد یک بلوک می‌سازد. discountB با let فقط تا پایان همان بلوک زنده است و بیرون از آن، برنامه اصلاً چنین نامی را نمی‌شناسد. discountA با var از بلوک بیرون نشت می‌کند و هنوز قابل خواندن است. همین تفاوت یکی از دلیل‌هایی است که در کد تازه از var استفاده نمی‌کنیم.



قوانین نام‌گذاری



    

  • فقط حروف، عدد، _ و $ مجاز است (فاصله و خط تیره مجاز نیست). از حروف انگلیسی استفاده کنید؛ نام فارسی با اینکه گاهی کار می‌کند، رسم نیست.
    • 

  • بزرگی و کوچکی حروف مهم است: age و Age دو متغیر جدا هستند.
    • 

  • نام نباید با عدد شروع شود: 2name غلط است.
    • 

  • کلمه‌های رزرو شده مثل let، if، function را نمی‌شود اسم متغیر گذاشت.
    • 

  • نام باید معنادار باشد: totalPrice بهتر از tp است.
    • 




قانون ساده: همیشه با const شروع کنید. اگر دیدید لازم است مقدار عوض شود، آن را let کنید.



اشتباه رایج: استفاده از متغیر قبل از تعریف آن با let یا const. نتیجه خطای Cannot access 'x' before initialization است.



اشتباه رایج: تعریف دوباره یک متغیر با let در همان محدوده: let score = 1; let score = 2; خطای Identifier 'score' has already been declared می‌دهد. برای تغییر مقدار، دیگر let ننویسید: score = 2;



تمرین: برای یک سبد خرید متغیرهای productName (مثلاً «کتاب»)، price و count را بسازید و قیمت کل را در متغیر total حساب و چاپ کنید. سپس کاربر یک عدد دیگر به سبد اضافه می‌کند: count را یکی بیشتر کنید و total را دوباره حساب و چاپ کنید. کدام متغیرها باید const و کدام let باشند؟ چرا؟
