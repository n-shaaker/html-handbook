۳) نمایش خروجی (Output)

تا وقتی نتیجهٔ یک محاسبه را جایی نشان ندهید، کاربر و حتی خودتان نمی‌فهمید برنامه چه کرده است. JavaScript چند راه برای نمایش نتیجه دارد. انتخاب راه به این بستگی دارد که پیام برای کاربر صفحه است یا فقط برای خود برنامه‌نویس در حال آزمایش:

روشکجا نمایش می‌دهدکاربرد
element.textContentداخل یک عنصر HTMLنمایش به کاربر (اصلی‌ترین روش)
element.innerHTMLداخل عنصر، همراه با تگ HTMLوقتی تگ هم لازم است
console.log()Console مرورگر (F12)تست و پیدا کردن خطا توسط برنامه‌نویس
alert()پنجره هشدارپیام فوری (کم استفاده کنید)
document.write()مستقیم در صفحهفقط برای تست؛ استفاده نکنید

مثال ۱: textContent و innerHTML

const a = document.getElementById("out-text");
const b = document.getElementById("out-html");

a.textContent = "<strong>سلام</strong>";   // تگ به صورت متن نمایش داده می‌شود
b.innerHTML  = "<strong>سلام</strong>";   // تگ اجرا می‌شود و متن پررنگ می‌شود

textContent:

innerHTML:

getElementById هر عنصر را با شناسه‌اش پیدا می‌کند. textContent هر چه به آن بدهید را به‌صورت متن خام می‌نویسد؛ پس علامت‌های <strong> روی صفحه دیده می‌شوند و پررنگ نمی‌شوند. innerHTML همان رشته را به‌عنوان HTML تفسیر می‌کند و مرورگر تگ را اجرا می‌کند. وقتی فقط می‌خواهید یک جمله نشان دهید، textContent انتخاب روشن‌تری است.

مثال ۲: console.log

console.log("سلام دنیا");
console.log(5 + 6);              // 11 ← اول حساب می‌کند، بعد چاپ
console.log("جمع:", 10 + 20);    // جمع: 30





console.log مقدار را در Console مرورگر می‌نویسد، نه روی صفحه. اگر داخل پرانتز یک عبارت محاسباتی باشد، اول همان عبارت حساب می‌شود و بعد نتیجه چاپ می‌شود. اگر چند مقدار را با کاما جدا کنید، کنار هم و با یک فاصله نشان داده می‌شوند. این روش برای آزمایش کد است؛ کاربر عادی صفحه آن را نمی‌بیند.



در این دوره خروجی console.log هر مثال در جعبه سیاه Console نشان داده می‌شود. همان خروجی در Console واقعی مرورگر (F12) هم چاپ می‌شود.



مثال ۳: alert



const alertButton = document.getElementById("alert-btn");

alertButton.addEventListener("click", function () {
  alert("این یک پیام هشدار است!");
});









اینجا هم مثل مثال‌های قبل، دکمه را با شناسه‌اش پیدا می‌کنیم و با addEventListener به کلیک گوش می‌دهیم. alert یک پنجرهٔ جدا باز می‌کند و تا وقتی کاربر آن را نبندد، بقیهٔ صفحه منتظر می‌ماند. برای پیام‌های معمولی صفحه مناسب نیست، چون جریان کار کاربر را قطع می‌کند.



document.write — چرا نه؟



document.write("سلام");   // اگر بعد از بارگذاری صفحه اجرا شود، کل صفحه پاک می‌شود!



document.write متن را همان جایی که مرورگر در حال خواندن HTML است می‌نویسد. اگر بعد از کامل شدن صفحه (مثلاً با کلیک یا در فایلی با defer) اجرا شود، کل محتوای صفحه را پاک می‌کند و فقط متن جدید می‌ماند. مرورگرها هم استفاده از آن را توصیه نمی‌کنند؛ به جایش از textContent استفاده کنید.



console.log می‌تواند چند مقدار را با کاما بگیرد و آن‌ها را با یک فاصله کنار هم چاپ کند؛ مثل خط سوم مثال ۲. کاربر عادی Console را نمی‌بیند؛ پس پیام‌های مهم را همیشه داخل صفحه نشان دهید.



اشتباه رایج: استفاده از innerHTML برای نوشتن متنی که کاربر تایپ کرده. اگر کاربر تگ HTML (یا کد مخرب) بنویسد، مرورگر آن را اجرا می‌کند؛ به این مشکل امنیتی XSS می‌گویند. برای متن ساده همیشه textContent امن‌تر است.



تمرین: یک پاراگراف با id برابر result بسازید و با JavaScript داخلش بنویسید «امروز JavaScript یاد گرفتم». هم‌زمان با console.log سال جاری (مثلاً 1405) را در Console چاپ کنید.
