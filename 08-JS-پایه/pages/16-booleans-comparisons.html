۱۶) بولین و مقایسه (Booleans & Comparisons)

نوع boolean فقط دو مقدار دارد: true یعنی درست و false یعنی غلط. این نوع خودش به‌تنهایی کم دیده می‌شود؛ بیشتر وقت‌ها نتیجهٔ یک مقایسه یا ترکیب چند شرط است. برنامه با همین دو مقدار تصمیم می‌گیرد کدام مسیر را اجرا کند. در این درس اول مقایسه را یاد می‌گیرید، بعد ترکیب شرط‌ها را، و در پایان مقدارهایی را که بدون مقایسه هم در شرط «غلط» حساب می‌شوند.

عملگرهای مقایسه

عملگرمعنیمثال (x = 5)نتیجه
==برابر (مقدار)x == "5"true
===برابر (مقدار و نوع)x === "5"false
!=نابرابرx != 8true
!==نابرابر (مقدار یا نوع)x !== "5"true
> / <بزرگ‌تر / کوچک‌ترx > 3true
>= / <=بزرگ‌تر یا مساوی / کوچک‌تر یا مساویx <= 5true
let x = 5;
console.log(x == "5");     // true  ← فقط مقدار را مقایسه می‌کند
console.log(x === "5");    // false ← نوع هم فرق دارد
console.log(x > 3);       // true
console.log(x !== 5);      // false





عدد ۵ و متن "5" از نظر مقدار شبیه هم‌اند، ولی نوعشان فرق دارد. == قبل از مقایسه نوع را یکسان می‌کند، پس نتیجه true می‌شود. === هم مقدار و هم نوع را می‌بیند و false برمی‌گرداند. > بزرگ‌تر بودن را بررسی می‌کند. !== یعنی «برابر نباشند» و چون هر دو طرف عدد ۵ هستند، نتیجه false است.



چرا == خطرناک است؟



== اگر دو طرف هم‌نوع نباشند، اول یکی را به نوع دیگر تبدیل می‌کند و بعد مقایسه می‌کند (Type Coercion). این تبدیل خودکار گاهی نتیجه‌هایی می‌دهد که انتظارش را ندارید:



console.log(0 == "");             // true  ← متن خالی به 0 تبدیل شد!
console.log(0 == "0");            // true
console.log("" == "0");           // false ← ولی این دو با هم برابر نیستند!
console.log(null == undefined);   // true
console.log(null === undefined);  // false
console.log(0 === "");            // false ← === هیچ تبدیلی انجام نمی‌دهد










متن خالی با == به عدد صفر تبدیل می‌شود، پس با ۰ برابر دیده می‌شود. متن "0" هم همین‌طور. اما متن خالی و متن "0" هر دو رشته‌اند و بدون تبدیل با هم برابر نیستند؛ به همین دلیل نتیجهٔ آن خط false است. null == undefined طبق قاعدهٔ همین عملگر true است، ولی === آن دو را یکی نمی‌داند چون نوعشان فرق دارد.



در مقایسهٔ معمولی از === و !== استفاده کنید تا تبدیل پنهان نتیجه را عوض نکند. اگر لازم است متن را با عدد مقایسه کنید، خودتان اول با Number() تبدیلش کنید: Number(input.value) === 5. یک استثنای آگاهانه این است که بعضی برنامه‌نویس‌ها برای «مقدار خالی» از value == null استفاده می‌کنند، چون هم null و هم undefined را true می‌کند؛ اگر این شکل را می‌نویسید، باید عمدی باشد.



مقایسه رشته‌ها



رشته‌ها حرف‌به‌حرف (بر اساس کد هر حرف) مقایسه می‌شوند، نه بر اساس مقدار عددی:



console.log("10" < "9");          // true ← چون حرف "1" قبل از "9" است!
console.log(10 < 9);              // false
console.log("apple" === "Apple"); // false ← بزرگی و کوچکی حروف مهم است










مقایسهٔ دو رشته مثل مقایسهٔ دو عدد نیست. حرف‌ها از چپ با کد عددی خودشان سنجیده می‌شوند. کد حرف "1" از کد حرف "9" کوچک‌تر است، پس "10" < "9" true می‌شود، در حالی که همان مقایسه با عدد واقعی false است. بزرگی و کوچکی حروف انگلیسی هم فرق دارد و "apple" با "Apple" برابر نیست.



اشتباه رایج: مقایسه دو مقدار input بدون تبدیل به عدد. "10" > "9" نتیجه false می‌دهد، چون هر دو متن هستند.



عملگرهای منطقی





عملگرمعنیمثالنتیجه


&&و (هر دو درست باشند)true && falsefalse


||یا (حداقل یکی درست باشد)true || falsetrue


!نقیض (برعکس)!truefalse





let age = 22;
let hasTicket = true;

console.log(age >= 18 && hasTicket);   // true  ← هر دو شرط درست است
console.log(age < 12 || age > 60);     // false ← هیچ‌کدام درست نیست (تخفیف کودک/سالمند ندارد)
console.log(!hasTicket);                // false










&& فقط وقتی true است که هر دو طرف درست باشند؛ اینجا هم سن کافی است و هم بلیت وجود دارد. || اگر حداقل یکی درست باشد true می‌شود. چون ۲۲ نه کمتر از ۱۲ است و نه بیشتر از ۶۰، هر دو طرف غلط‌اند و نتیجه false است. علامت ! مقدار بولین را برعکس می‌کند.



مثال کاربردی: بررسی فرم ورود



let username = "  sara_ahmadi ";
let password = "Sara1405";

const cleanUser = username.trim();
const isUserValid = cleanUser.length >= 3;
const isPassValid = password.length >= 8 && password !== cleanUser;

console.log("نام کاربری معتبر:", isUserValid);           // true
console.log("رمز معتبر:", isPassValid);                   // true
console.log("اجازه ورود:", isUserValid && isPassValid);  // true










trim فاصله‌های اطراف نام کاربری را برمی‌دارد تا فاصلهٔ اضافه باعث رد شدن فرم نشود. طول نام بعد از این پاک‌سازی باید حداقل ۳ باشد. رمز باید حداقل ۸ نویسه داشته باشد و عین نام کاربری نباشد. اجازهٔ ورود فقط وقتی true است که هر دو بررسی با && درست باشند.



&& و || «اتصال کوتاه» (Short-circuit) دارند: در a && b اگر a غلط باشد، b اصلاً بررسی نمی‌شود؛ در a || b اگر a درست باشد، b بررسی نمی‌شود. اولویت هم مهم است: ! قبل از && و && قبل از || اجرا می‌شود؛ هر جا شک داشتید پرانتز بگذارید.



Truthy و Falsy



هر مقداری وقتی در شرط قرار بگیرد به true یا false تبدیل می‌شود. مقدارهای زیر falsy هستند (به false تبدیل می‌شوند) و همه مقدارهای دیگر truthy‌اند:





مقدار falsyتوضیح


falseخود false


0 و -0صفر (و همچنین 0n از نوع bigint)


""رشته خالی (بدون حتی یک فاصله)


null و undefined«خالی» و «تعریف‌نشده»


NaNعدد نامعتبر





console.log(Boolean(false), Boolean(0), Boolean(""));            // false false false
console.log(Boolean(null), Boolean(undefined), Boolean(NaN));    // false false false

console.log(Boolean("0"), Boolean(" "), Boolean([]), Boolean("false"));   // true true true true ← همه truthy!










Boolean نشان می‌دهد هر مقدار در شرط چه تعبیری دارد. صفر، متن خالی، null، undefined و NaN غلط حساب می‌شوند. متن "0"، متنی که فقط فاصله دارد، آرایهٔ خالی و حتی متن "false" غلط نیستند، چون رشتهٔ غیرخالی و آرایه مقدار دارند. اگر بخواهید «عدد صفر» را از «مقدار نبودن» جدا کنید، به تبدیل بولین تکیه نکنید و خود عدد را مقایسه کنید.



کاربرد: if (username) یعنی «اگر نام کاربری خالی نیست». ولی مراقب باشید: عدد 0 هم falsy است؛ پس برای ورودی عددی که ممکن است صفر باشد از این روش استفاده نکنید.



اشتباه رایج: نوشتن = به جای === در شرط. if (x = 5) مقدار x را عوض می‌کند و همیشه درست است!



تمرین: (۱) متغیر score بسازید و با یک عبارت بررسی و چاپ کنید که نمره قبولی است یا نه، یعنی بین ۱۰ تا ۲۰ (score >= 10 && score <= 20). (۲) قبل از اجرا حدس بزنید خروجی هر خط چیست، بعد امتحان کنید: "5" === 5، "5" == 5، Boolean("0")، !""، "b" > "a". (۳) متغیرهای age و hasCard بسازید و عبارتی بنویسید که بگوید کاربر تخفیف دانشجویی می‌گیرد یا نه: سن بین ۱۸ تا ۳۰ و داشتن کارت دانشجویی.
