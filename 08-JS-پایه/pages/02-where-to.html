۲) محل نوشتن JavaScript (Where To)

مرورگر کد JavaScript را خودش حدس نمی‌زند؛ باید به او بگوییم این کد کجاست و چه وقت اجرا شود. کد را داخل تگ <script> می‌نویسیم. سه روش برای قرار دادن این تگ وجود دارد و انتخاب روش روی تمیزی پروژه و زمان اجرای کد اثر می‌گذارد.

روش ۱: داخل تگ script در همان صفحه (داخلی)

<body>
  <p id="demo"></p>

  <script>
    document.getElementById("demo").textContent = "سلام از داخل صفحه!";
  </script>
</body>

در این روش، کد و صفحه در یک فایل هستند. مرورگر وقتی به تگ script می‌رسد آن را اجرا می‌کند. document.getElementById("demo") پاراگرافی را که بالاتر با همان شناسه ساخته شده پیدا می‌کند و textContent متن داخلش را می‌نویسد. چون اسکریپت بعد از آن پاراگراف آمده، عنصر از قبل وجود دارد.

روش ۲: فایل جداگانه (خارجی) — روش پیشنهادی

کد را در یک فایل با پسوند .js می‌نویسیم و با ویژگی src به صفحه وصل می‌کنیم:

project/
├── index.html
├── css/
│   └── style.css
└── js/
    └── app.js

پوشهٔ css ظاهر صفحه را نگه می‌دارد و پوشهٔ js رفتار صفحه را. جدا کردن فایل‌ها باعث می‌شود HTML فقط ساختار بماند و همان فایل JavaScript را بتوان در چند صفحه استفاده کرد.

<head>
  <link rel="stylesheet" href="css/style.css">
  <script src="js/app.js" defer></script>
</head>

ویژگی src آدرس فایل را نسبت به همین صفحهٔ HTML می‌گوید. defer به مرورگر می‌گوید فایل را دانلود کند، ولی اجرای آن را تا وقتی ساختار HTML کامل شود عقب بیندازد. بدون این ویژگی، اگر اسکریپت داخل head باشد، ممکن است پیش از ساخته شدن عنصرها اجرا شود و چیزی برای تغییر پیدا نکند.

// فایل js/app.js  (داخل فایل js دیگر تگ script نمی‌نویسیم)
document.getElementById("demo").textContent = "سلام از فایل خارجی! (این متن در HTML نبود)";

همین صفحه یک فایل خارجی به اسم js/demos/where-to.js دارد که این خروجی را نوشته:

داخل فایل .js دیگر تگ script نمی‌نویسیم؛ فقط دستورهای JavaScript. خط بالا همان کاری را می‌کند که در روش داخلی دیدید: عنصر demo را پیدا می‌کند و متنش را عوض می‌کند. تفاوت فقط محل نگهداری کد است.

مسیر src نسبت به همان فایل HTML نوشته می‌شود. اگر صفحه داخل پوشه pages باشد، مسیر می‌شود ../js/app.js (دو نقطه یعنی «یک پوشه بالاتر»).

defer چیست؟

مرورگر صفحه را از بالا به پایین می‌خواند. اگر اسکریپت قبل از ساخته شدن عنصرها اجرا شود، getElementById چیزی پیدا نمی‌کند. با defer می‌گوییم: «فایل را دانلود کن، ولی بعد از ساخته شدن کامل HTML اجرا کن».

محل scriptنتیجه
داخل head بدون deferقبل از ساخته شدن عنصرها اجرا می‌شود؛ معمولاً خطا
داخل head با deferبعد از ساخته شدن HTML اجرا می‌شود (پیشنهادی)
آخر body، قبل از </body>عنصرها ساخته شده‌اند؛ روش قدیمی‌تر ولی درست

اگر چند اسکریپت defer داشته باشید، به همان ترتیبی که در HTML نوشته شده‌اند اجرا می‌شوند. برای همین در صفحه‌های این دوره اول log.js و بعد فایل مثال درس آمده است. (ویژگی دیگری به اسم async هم هست که ترتیب را تضمین نمی‌کند؛ فعلاً با همان defer کار کنید.)

روش ۳: داخل ویژگی‌های HTML (اینلاین)

<button onclick="alert('سلام')">کلیک</button>   <!-- پیشنهاد نمی‌شود -->

در این روش کد JavaScript با HTML قاطی می‌شود. در این دوره، مثل دوره CSS که از style="..." استفاده نکردیم، از onclick="..." هم استفاده نمی‌کنیم و رویدادها را با addEventListener در فایل خارجی می‌نویسیم.

مزیت فایل خارجی: HTML تمیزتر می‌ماند، یک فایل JS را می‌توان در چند صفحه استفاده کرد و مرورگر فایل را کش (ذخیره) می‌کند.

اشتباه رایج: نوشتن تگ <script> داخل فایل .js. فایل خارجی فقط کد خالص JavaScript دارد.

اشتباه رایج: اسکریپت را داخل head بگذارید ولی defer را فراموش کنید. نتیجه خطایی مثل Cannot set properties of null است، چون وقتی کد اجرا می‌شود عنصر هنوز ساخته نشده و getElementById مقدار null برمی‌گرداند.

تمرین: یک پوشه js بسازید و داخلش فایل app.js. با defer آن را به یک صفحه HTML وصل کنید و داخلش بنویسید console.log("فایل وصل شد");. در Console مرورگر پیام را ببینید.
