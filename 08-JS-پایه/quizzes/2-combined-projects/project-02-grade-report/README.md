## صورت مسئله

آموزشگاه «پرتو» می‌خواهد مربی‌ها بعد از هر آزمون، نمره هر دانشجو را در یک صفحه ساده وارد کنند و
یک «کارت کارنامه» رنگی ببینند که وضعیت دانشجو را با یک نگاه نشان دهد. صفحه را طوری بنویسید که
نمره‌های اشتباه (مثل ۲۱ یا منفی) را قبول نکند.

## الزامات

1. سه فایل `index.html`، `style.css` و `app.js`؛ یک کادر متنی «نام دانشجو»، یک کادر عددی «نمره (۰ تا ۲۰)»
   با `step="0.01"` و یک دکمه «نمایش کارنامه». هر کادر `label` داشته باشد.
2. تابعی به نام `getStatus(score)` که **فقط با `if...else if...else`** وضعیت را برگرداند:
   - نمره ۱۷ و بالاتر ← «عالی»
   - ۱۴ تا کمتر از ۱۷ ← «خوب»
   - ۱۰ تا کمتر از ۱۴ ← «قابل قبول»
   - کمتر از ۱۰ ← «مردود»
3. تابعی به نام `getStatusStyle(status)` که **با `switch`** روی متن وضعیت، یک **شیء** با دو ویژگی برگرداند:
   `className` (نام کلاس CSS) و `emoji`. مثلاً برای «عالی»: `{ className: "status-excellent", emoji: "🏆" }`.
   برای چهار وضعیت چهار کلاس و چهار رنگ متفاوت در CSS تعریف کنید.
4. خروجی یک کارت با **Template Literal** باشد؛ مثلاً: «سارا رضایی — نمره: ۱۶٫۵ — وضعیت: خوب 👍».
   نمره با رقم فارسی (`toLocaleString("fa-IR")`) نمایش داده شود.
5. کلاس رنگی کارت با `classList` عوض شود و با هر بار نمایش، کلاس وضعیت قبلی **حذف** شود (کارت نباید هم‌زمان دو رنگ داشته باشد).
6. فاصله‌های اول و آخر نام با `trim()` حذف شود. نام خالی یا فقط فاصله پذیرفته نشود.
7. پیام‌های خطا (در صفحه، نه `alert`)؛ در صورت خطا کارت قبلی پنهان شود:
   - نام خالی ← «نام دانشجو را وارد کنید.»
   - نمره خالی ← «نمره را وارد کنید.»
   - کمتر از ۰ یا بیشتر از ۲۰ ← «نمره باید بین ۰ تا ۲۰ باشد.»
8. ناحیه خروجی `aria-live="polite"` داشته باشد.

### موارد آزمون (نام: «سارا رضایی»)

| نمره | خروجی مورد انتظار |
| --- | --- |
| 20 | عالی 🏆 (کلاس `status-excellent`) |
| 17 | عالی 🏆 — مرز دقیق، باید «عالی» باشد نه «خوب» |
| 16.99 | خوب 👍 |
| 14 | خوب 👍 |
| 10 | قابل قبول 🙂 |
| 9.75 | مردود 📚 |
| 0 | مردود 📚 — صفر یک نمره معتبر است، نه «خالی» |
| -1 | «نمره باید بین ۰ تا ۲۰ باشد.» |
| 21 | «نمره باید بین ۰ تا ۲۰ باشد.» |
| (خالی) | «نمره را وارد کنید.» |
| نام: «   » ، نمره: 15 | «نام دانشجو را وارد کنید.» |

ایموجی‌ها پیشنهادی‌اند؛ می‌توانید ایموجی دیگری انتخاب کنید، ولی برای هر وضعیت یکی باشد.

## محدودیت‌ها

- `onclick` داخل HTML، `alert` و `var` ممنوع.
- فایل `app.js` با `defer` وصل شود.
- در `getStatus` از `switch` و در `getStatusStyle` از `if` استفاده نکنید (هدف، تمرین هر دو ساختار است).
- همه مقایسه‌ها با `===` و `!==` باشند.
- متن کارت با `textContent` نوشته شود، نه `innerHTML` (نام را کاربر وارد می‌کند).

## امتیازی (تا ۲ نمره)

- با زدن <kbd>Enter</kbd> در کادر نمره هم کارنامه نمایش داده شود (رویداد `keydown` و `event.key`).

## نکته استاد

- ترتیب شرط‌ها مهم است: اگر اول `score >= 10` را بررسی کنید، نمره ۱۹ هم «قابل قبول» می‌شود!
- در `switch` فراموش کردن `break` (یا `return`) باعث می‌شود اجرا به `case` بعدی «سُر بخورد».
- `Number("")` صفر است؛ پس اگر خالی بودن کادر را جدا بررسی نکنید، کادر خالی «مردود» می‌شود.
