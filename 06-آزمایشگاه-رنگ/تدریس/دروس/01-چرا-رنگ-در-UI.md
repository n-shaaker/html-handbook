## ۱) شروع کلاس؛ ایجاد سؤال در ذهن دانشجو

اول کلاس این‌طور شروع کن:

«بچه‌ها، فرض کنید روی صفحه پرداخت دو پیام دارید: یکی می‌گوید پرداخت موفق بود، یکی می‌گوید خطا رخ داد.

طراح فقط روی متن‌ها `color: green` و `color: red` گذاشته — پس‌زمینه سفید، بدون آیکون، بدون حاشیه.

حالا این صفحه را در نور آفتاب یا روی مانیتور که کنtrast کم دارد باز کنید. آیا همه کاربران — مخصوصاً کسانی که تمایز رنگ را سخت می‌بینند — **فوراً** می‌فهمند کدام پیام خطاست؟»

یک اسلاید یا دو `div` ساده روی صفحه نشان بده (هنوز CSS کامل نزن):

```html
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Live — فقط رنگ متن</title>
  <style>
    body { font-family: Tahoma, sans-serif; padding: 1.5rem; }
    .msg { padding: 1rem; margin-bottom: 1rem; background: #fff; }
    .msg--ok { color: #22c55e; }
    .msg--bad { color: #ef4444; }
  </style>
</head>
<body>
  <p class="msg msg--ok">پرداخت موفق — رسید ارسال شد.</p>
  <p class="msg msg--bad">خطا — دوباره تلاش کنید.</p>
</body>
</html>
```

بعد بگو:

«رنگ اولین چیزی نیست که کاربر **کلمه به کلمه** می‌خواند، ولی اولین چیزی است که **حس** می‌کند: اعتماد، فوریت، آرامش. در UI سه نقش اصلی دارد — امروز روی همین سه نقش تمرکز می‌کنیم، نه روی حفظ نام رنگ‌ها.»

**در مرورگر:** هر دو بلوک شبیه «متن معمولی روی سفید» به نظر می‌رسند؛ تفاوت فقط hue است. این نقطه ورود درس است.

## ۲) سه نقش رنگ در UI

روی تخته یا جدول زنده:

1. **سلسله‌مراتب (Hierarchy)** — عنوان پررنگ‌تر یا بزرگ‌تر، متن ثانویه کمرنگ‌تر، پس‌زمینه خنثی. کاربر بدون خواندن همه جمله می‌فهمد کجا را اول ببیند.
2. **معنا (Meaning)** — سبز موفقیت، قرمز خطا، آبی لینک. *توجه:* فرهنگ و برند هم نقش دارند؛ سبز همیشه «خوب» نیست (مثلاً در بعضی زمینه‌ها «در حال انجام» است).
3. **دسترس‌پذیری (Accessibility)** — اگر **فقط** رنگ تفاوت را نشان دهد، کاربران کم‌بین رنگ یا در نور بد گیر می‌کنند. همیشه **کنtrast متن/پس‌زمینه** و در صورت امکان **آیکون، حاشیه، یا متن اضافه** در نظر بگیرید.

از جزوه [`01-why-color.html`](../../pages/01-why-color.html) جدول «هدف / نکته جونیور» را با کلاس مرور کن:

- خوانایی — تقریباً نسبت ۴٫۵:۱ برای متن عادی (WCAG سطح AA؛ جزئیات در درس کنtrast).
- سلسله‌مراتب — یک رنگ برند + خاکستری‌ها؛ از رنگ‌های زیاد پرهیز.
- حالت‌ها — hover / focus / error رنگ یا تیرگی جدا بگیرند.

### سؤال کلاسی

- «اگر فقط رنگ متن را برای خطا قرمز کنیم، چه چیزی هنوز کم است؟»  
  **پاسخ:** پس‌زمینه یا حاشیه متمایز، آیکون یا عنوان واضح، و کنtrast کافی بین متن و پس‌زمینه.

- «سلسله‌مراتب یعنی حتماً رنگ‌های بیشتر؟»  
  **پاسخ:** نه؛ معمولاً **کمتر** رنگ و **کنtrast بیشتر** بین سطوح (عنوان / بدنه / فرعی) بهتر است.

## ۳) Live Coding — کارت وضعیت کامل

«HTML را با `lang="fa"` و `dir="rtl"` می‌نویسم؛ دو کارت success و error **کنار هم** — این بار پس‌زمینه، حاشیه و رنگ متن را با هم تنظیم می‌کنم.»

فایل پیشنهادی: `تدریس/live/01-color-roles.html`

```html
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>نقش رنگ در UI</title>
  <link rel="stylesheet" href="01-color-roles.css">
</head>
<body>
  <main class="layout">
    <article class="card card--success" role="status">
      <h2 class="card__title">پرداخت موفق</h2>
      <p class="card__body">رسید برای شما ایمیل شد.</p>
    </article>
    <article class="card card--error" role="alert">
      <h2 class="card__title">خطا در پرداخت</h2>
      <p class="card__body">لطفاً دوباره تلاش کنید یا با پشتیبانی تماس بگیرید.</p>
    </article>
    <article class="card card--neutral">
      <h2 class="card__title">در حال بررسی</h2>
      <p class="card__body">تراکنش شما در صف است.</p>
    </article>
  </main>
</body>
</html>
```

```css
.layout {
  display: grid;
  gap: 1rem;
  max-width: 28rem;
  margin: 2rem auto;
  padding: 0 1rem;
  font-family: Tahoma, sans-serif;
}

.card {
  padding: 1rem 1.25rem;
  border-radius: 8px;
  border-inline-start: 4px solid;
  background: #f8fafc;
  color: #0f172a;
}

.card__title {
  margin: 0 0 0.35rem;
  font-size: 1.125rem;
}

.card__body {
  margin: 0;
  font-size: 0.95rem;
  line-height: 1.6;
}

.card--success {
  background: #ecfdf5;
  border-color: #059669;
  color: #065f46;
}

.card--error {
  background: #fef2f2;
  border-color: #dc2626;
  color: #991b1b;
}

.card--neutral {
  background: #f1f5f9;
  border-color: #64748b;
  color: #334155;
}
```

بعد از ذخیره بگو:

«پس‌زمینه، حاشیه سمت راست (در RTL همان `border-inline-start`) و رنگ متن را **با هم** تنظیم کردیم — نه فقط یک `color: red`. برای خطا از `role="alert"` هم استفاده کردیم تا فناوری کمکی بتواند اهمیت را بفهمد.»

**نمایش:** کارت خطا را با نسخه «فقط color» از بخش ۱ مقایسه کن — تفاوت را از عقب اتاق هم بپرس.

## ۴) سلسله‌مراتب داخل یک کارت محصول

«حالا همان ایده سلسله‌مراتب را روی یک کارت فروش می‌بینیم — بدون رنگ اضافه.»

```html
<article class="product">
  <h2 class="product__name">کافه لاته</h2>
  <p class="product__meta">۲۰۰ میلی‌لیتر · داغ</p>
  <p class="product__price">۸۵٬۰۰۰ تومان</p>
</article>
```

```css
.product {
  padding: 1rem;
  border: 1px solid #e2e8f0;
  border-radius: 8px;
  background: #fff;
}
.product__name {
  margin: 0 0 0.25rem;
  color: #0f172a;
  font-size: 1.25rem;
}
.product__meta {
  margin: 0 0 0.75rem;
  color: #64748b;
  font-size: 0.875rem;
}
.product__price {
  margin: 0;
  color: #0f766e;
  font-weight: 700;
  font-size: 1.125rem;
}
```

«نام تیره، توضیح خاکستری، قیمت با رنگ برند — کاربر بدون خواندن همه متن می‌فهمد کجا قیمت است. اگر همه را `#333` می‌گذاشتیم، سلسله‌مراتب از بین می‌رفت.»

### اشتباهات رایج

- استفاده از رنگ‌های نئون برای متن طولانی (خستگی چشم).
- قرار دادن متن خاکستری روشن روی سفید «چون مینیمال است» — کنtrast از دست می‌رود.
- تفکیک وضعیت **فقط** با رنگ، بدون آیکون، حاشیه یا عنوان.

## ۵) دکمه‌ها — فعال، hover، غیرفعال

«یک دکمه غیرفعال خاکستری کنار دکمه اصلی — اگر کنtrast کم باشد، کاربر فکر می‌کند دکمه «کار می‌کند ولی کلیکش ثبت نشده».»

```html
<div class="actions">
  <button type="button" class="btn btn--primary">پرداخت</button>
  <button type="button" class="btn btn--primary" disabled>پرداخت (غیرفعال)</button>
</div>
```

```css
.actions { display: flex; gap: 0.75rem; flex-wrap: wrap; margin-top: 1.5rem; }

.btn {
  padding: 0.5rem 1rem;
  border-radius: 6px;
  border: none;
  font-family: inherit;
  cursor: pointer;
}
.btn--primary {
  background: #2563eb;
  color: #fff;
}
.btn--primary:hover:not(:disabled) {
  background: #1d4ed8;
}
.btn--primary:disabled {
  background: #cbd5e1;
  color: #94a3b8;
  cursor: not-allowed;
}
```

**Live:** `:disabled` را بردار — هر دو دکمه آبی می‌شوند؛ بعد دوباره `disabled` بگذار.

### سؤال کلاسی

- «اگر فقط رنگ دکمه حذف را قرمز کنیم ولی پس‌زمینه هم قرمز تیره باشد، چه مشکلی پیش می‌آید؟»  
  **پاسخ:** کنtrast متن و پس‌زمینه از بین می‌رود؛ دکمه ناخوانا می‌شود و معمولاً WCAG را رد می‌کند.

- «برای لینک داخل پاراگراف، چرا گاهی underline بهتر از رنگ متفاوت تنهاست؟»  
  **پاسخ:** underline (یا `border-bottom`) برای کسانی که تمایز hue را سخت می‌بینند قابل اتکاتر است.

## ۷) mini-project جلسه — سه کارت وضعیت

«یک فایل `status-cards.html` بسازید: success، error، neutral — هر کدام عنوان + یک جمله. حداقل سه لایه رنگ (پس‌زمینه، حاشیه، متن) داشته باشند. یک کارت را عمداً «فقط color متن» بگذارید و با بقیه مقایسه کنید.»

## ۸) جمع‌بندی مدرس و سؤالات پایانی

1. سه نقش اصلی رنگ در UI چیست؟  
   **پاسخ راهنما:** سلسله‌مراتب، معنا، دسترس‌پذیری (همراه کنtrast).

2. چرا کارت خطا فقط با `color: red` کافی نیست؟  
   **پاسخ راهنما:** خوانایی و تشخیص برای همه کاربران؛ نیاز به پس‌زمینه/حاشیه/متن یا آیکون.

3. برای متن ثانویه (caption) چه اشتباهی رایج است؟  
   **پاسخ راهنما:** خاکستری خیلی روشن روی سفید.

**پیام پایانی:**

«هدف این جلسه حفظ لیست رنگ‌ها نبود. هدف این بود که هر بار رنگ می‌گذارید بپرسید: این رنگ **سلسله‌مراتب** می‌سازد، **معنا** می‌دهد، یا برای **همه** خواناست؟»

## تمرین‌ها (ساده → چالشی)

### ساده
1. دو پیام موفق/خطا را فقط با `color` بسازید؛ بعد نسخه کارت کامل را اضافه کنید و تفاوت را برای همکلاسی توضیح دهید.
2. یک کارت محصول با سه سطح رنگ (نام، meta، قیمت) طراحی کنید.

### متوسط
3. دکمه primary و disabled با hover درست — `:disabled` را تست کنید.
4. برای لینک داخل پاراگراف، نسخه «فقط رنگ آبی» و نسخه «رنگ + underline» بسازید.

### چالشی
5. سه کارت وضعیت را طوری طراحی کنید که در حالت grayscale (فیلتر `grayscale(100%)` در DevTools) هنوز قابل تشخیص باشند — با حاشیه و پس‌زمینه، نه فقط hue.
