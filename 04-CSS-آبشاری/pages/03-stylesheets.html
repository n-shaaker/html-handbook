۳) چند فایل CSS و ترتیب لینک

آبشار فقط داخل یک فایل نیست. مرورگر همهٔ CSS صفحه را، از هر فایلی که با link آمده باشد، به ترتیب ظاهر شدن در سند جمع می‌کند. اگر دو فایل خارجی برای همان ویژگی و همان عنصر قانون هم‌قدرت داشته باشند، فایلی که دیرتر در head لینک شده برنده است؛ درست مثل قانونی که پایین‌تر در یک فایل نوشته شده باشد.

این برتری باز هم ویژگی‌به‌ویژگی است. اگر فایل دوم فقط color را عوض کند، font-size و font-weight فایل اول روی همان عنصر می‌مانند. و اگر انتخابگر فایل اول قوی‌تر باشد، دیرتر لینک شدن فایل دوم آن را شکست نمی‌دهد. 

<!-- در head -->
<link rel="stylesheet" href="../css/demos/sheet-a.css">
<link rel="stylesheet" href="../css/demos/sheet-b.css">
/* sheet-a.css */
.demo-sheets .msg {
  color: #c92a2a;
  font-size: 20px;
  font-weight: bold;
}

.demo-sheets .from-a {
  background-color: #ffe0b2;
  padding: 10px;
}
/* sheet-b.css */
.demo-sheets .msg {
  color: #0b6e4f;
}

.demo-sheets .from-b {
  background-color: #c3fae8;
  padding: 10px;
}

متن سبز است → فایل B دیرتر آمده و برنده شده. درشتی و ضخامت متن هنوز از فایل A می‌آید.

این پس‌زمینه فقط در فایل A تعریف شده.
این پس‌زمینه فقط در فایل B تعریف شده.

اگر قانونی فقط در یک فایل باشد، همان اعمال می‌شود. تداخل فقط وقتی پیش می‌آید که هر دو فایل برای همان ویژگی همان عنصر مقدار بدهند. برای همین font-size و font-weight فایل A روی .msg باقی می‌مانند.

از دید مرورگر، همه CSSهای صفحه (فایل‌های link، تگ‌های style و فایل‌هایی که با @import آورده می‌شوند) پشت سر هم در یک صف قرار می‌گیرند؛ به همان ترتیبی که در سند آمده‌اند. پس اگر یک تگ style بعد از link بیاید، در قدرت برابر از آن برنده است. یادتان باشد ترتیب فقط وقتی مهم است که قدرت انتخابگرها برابر باشد؛ انتخابگر قوی‌تر در فایل اول همچنان از انتخابگر ضعیف‌تر در فایل دوم برنده است.

اشتباه رایج: جابه‌جا لینک کردن فایل‌ها و تعجب از اینکه رنگ یا اندازه عوض شده است. ترتیب linkها، در قدرت برابر، همان نقش ترتیب قوانین داخل یک فایل را دارد: منبع دیرتر، ویژگی‌های مشترک را بازنویسی می‌کند.

تمرین: در این صفحه جای دو link مربوط به sheet-a و sheet-b را عوض کنید. رنگ .msg چه می‌شود؟
