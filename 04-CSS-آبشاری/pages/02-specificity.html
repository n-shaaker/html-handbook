۲) قدرت انتخابگر (Specificity)

ترتیب نوشتن فقط وقتی معنی دارد که انتخابگرها هم‌قدرت باشند. اگر قدرت فرق کند، ترتیب دیگر تعیین‌کننده نیست: انتخابگر قوی‌تر حتی اگر بالاتر در فایل نوشته شده باشد برنده است. قدرت انتخابگر را Specificity می‌نامند؛ یعنی مرورگر می‌سنجد این قانون چقدر دقیق عنصر را هدف گرفته است.

قدرت انتخابگر چطور حساب می‌شود؟

قدرت هر انتخابگر یک سه‌تایی است به شکل (id, کلاس, نوع). این سه عدد را با هم جمع نمی‌کنیم. مرورگر آن‌ها را مثل سه ستون جدا مقایسه می‌کند: اول تعداد شناسه‌ها، بعد تعداد کلاس‌ها، و فقط اگر آن دو ستون برابر بودند تعداد نام تگ‌ها. برای همین یک id تنها همیشه از هر تعداد کلاس قوی‌تر است و ستون‌ها روی هم سرریز نمی‌کنند.

  • ستون اول تعداد شناسه‌ها را می‌شمارد. هر #id در انتخابگر یک واحد به این ستون اضافه می‌کند و همین ستون از دو ستون دیگر مهم‌تر است.
  • ستون دوم کلاس‌ها (مثل .note)، انتخابگرهای صفت (مثل [type="text"]) و شبه‌کلاس‌ها (مثل :hover) را با هم می‌شمارد. این سه از نظر قدرت در یک گروه هستند.
  • ستون سوم نام تگ‌ها (مثل p) و شبه‌عنصرها (مثل ::before) را می‌شمارد. این ستون فقط وقتی دو انتخابگر را از هم جدا می‌کند که دو ستون قبلی‌شان برابر باشد.

دو انتخابگر را ستون به ستون از چپ مقایسه می‌کنیم: هر کدام در ستون id بیشتر داشت برنده است؛ اگر برابر بود، ستون کلاس؛ و اگر باز برابر بود، ستون نوع. انتخابگر همگانی * و ترکیب‌کننده‌ها (فاصله، >، +، ~) هیچ امتیازی ندارند. 

/* specificity.css */
.demo-spec p {          /* (0, 1, 1) */
  color: #c92a2a;
  font-size: 18px;
}

.demo-spec .note {      /* (0, 2, 0) */
  color: #1a5fb4;
}

.demo-spec #special {   /* (1, 1, 0) */
  color: #0b6e4f;
  font-weight: bold;
}

پیشوند .demo-spec مثال را به کادر نتیجه محدود می‌کند و یک کلاس به ستون دوم همه انتخابگرها اضافه کرده است؛ برای همین اعداد بالا را دقیق با همین پیشوند حساب کرده‌ایم.

فقط تگ p با قدرت (0, 1, 1) → قرمز

کلاس note با قدرت (0, 2, 0) → آبی (ستون کلاس بیشتر است)

id special با قدرت (1, 1, 0) → سبز (ستون id بیشتر است)

سه ستون قدرت

نام تگ مثل p → (0, 0, 1)
کلاس مثل .note → (0, 1, 0)
شناسه مثل #special → (1, 0, 0)
انتخابگر قدرت (id, کلاس, نوع) توضیح
* (0, 0, 0) انتخابگر همگانی امتیاز ندارد
p (0, 0, 1) یک نام تگ
ul li a (0, 0, 3) سه نام تگ؛ فاصله‌ها امتیاز ندارند
p::first-line (0, 0, 2) شبه‌عنصر در ستون نوع حساب می‌شود
.note (0, 1, 0) یک کلاس
a:hover (0, 1, 1) شبه‌کلاس + نام تگ
input[type="email"] (0, 1, 1) انتخابگر صفت + نام تگ
.card .title (0, 2, 0) دو کلاس
#special (1, 0, 0) یک id
#menu .item a (1, 1, 1) id + کلاس + نام تگ
li:not(.done) (0, 1, 1) :not() خودش امتیاز ندارد؛ قدرت آرگومانش حساب می‌شود
:where(.card) p (0, 0, 1) هر چه داخل :where() باشد امتیاز صفر دارد
style="..." از همه انتخابگرها قوی‌تر استایل درون‌خطی انتخابگر نیست و جدا از این جدول، بالاتر از همه است

ترتیب قدرت ساده برای شروع: id > class > نام تگ. وقتی قدرت فرق دارد، قانون قوی‌تر برنده است؛ حتی اگر زودتر آمده باشد. فقط وقتی هر سه ستون برابر باشند، ترتیب نوشتن (مثال ۱) تعیین‌کننده است.

اشتباه رایج ۱: حساب کردن قدرت به‌صورت «تگ = ۱، کلاس = ۱۰، id = ۱۰۰» و جمع زدن آن‌ها. ستون‌ها روی هم سرریز نمی‌کنند: انتخابگری با ۱۱ کلاس (0, 11, 0) هنوز از یک id تنها (1, 0, 0) ضعیف‌تر است.

اشتباه رایج ۲: زیاد استفاده کردن از id برای استایل. بعداً برای override کردن سخت می‌شود. برای ظاهر معمولاً کلاس بهتر است و انتخابگرها را تا حد ممکن کوتاه نگه دارید.
