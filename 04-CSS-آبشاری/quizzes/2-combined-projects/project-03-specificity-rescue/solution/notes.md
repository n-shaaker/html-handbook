# یادداشت بازنویسی CSS — پروژه ۳ (پاسخ استاد)

## ریشه مشکل

همه دردسرها از یک قانون شروع شد:

```css
#app .card a { color: #1a5fb4; text-decoration: underline; }   /* (1, 1, 1) */
```

این قانون **همه** لینک‌های داخل کارت را می‌گیرد، از جمله دکمه‌ها. چون یک id دارد، هیچ کلاسی
(مثل `.btn-danger` با قدرت (0, 1, 0)) نمی‌تواند رنگ آن را عوض کند. همکار به‌جای حل ریشه، روی هر علامت
یک `!important` یا یک انتخابگر قوی‌تر گذاشت و نتیجه:

- متن دکمه «حذف» هنوز آبی روی قرمز بود (فقط پس‌زمینه‌اش وصله شده بود)؛
- hover دکمه «حذف» کار نمی‌کرد، چون `background-color` با `!important` قفل شده بود؛
- برای دکمه «ویرایش» یک انتخابگر خیلی قوی با قدرت (1, 3, 1) لازم شده بود.

## تغییرات، یکی‌یکی

| # | قبل | بعد | قدرت قبل ← بعد | چرا |
| :---: | --- | --- | :---: | --- |
| ۱ | `#app` | `.app` | (1, 0, 0) ← (0, 1, 0) | HTML از قبل کلاس `app` داشت؛ id در CSS ممنوع است. |
| ۲ | `#app .app-header h1` | `.app-header h1` | (1, 1, 1) ← (0, 1, 1) | پیشوند id هیچ کاری جز بالا بردن قدرت نمی‌کرد. |
| ۳ | `#app .card` | `.card` | (1, 1, 0) ← (0, 1, 0) | همین. |
| ۴ | `#app .card h2` | `.card h2` | (1, 1, 1) ← (0, 1, 1) | همین. |
| ۵ | `#app .card a` | `a` | (1, 1, 1) ← (0, 0, 1) | **تغییر اصلی.** قانون لینک متنی باید ضعیف باشد تا کلاس `.btn` و انواعش برنده شوند. در این صفحه لینک متنی دیگری بیرون کارت نیست، پس `a` تنها کافی است. |
| ۶ | `.featured { … !important }` | `.card.featured` | (0, 1, 0)+important ← (0, 2, 0) | دو کلاس از `.card` قوی‌تر است؛ نیازی به `!important` نیست. |
| ۷ | `#app .card a.btn { text-decoration: none !important }` | حذف شد | — | با تغییر ۵، خود `.btn` زیرخط را برمی‌دارد. |
| ۸ | `.btn-primary { color: white !important }` | حذف شد | — | قانون اصلی `.btn-primary` حالا برنده است. |
| ۹ | `.btn-danger { background-color: … !important }` | حذف شد | — | با حذفش، `.btn-danger:hover` (0, 2, 0) دوباره کار می‌کند. |
| ۱۰ | `#app .card a.btn:first-child` | حذف شد | (1, 3, 1) ← — | `.btn` خودش رنگ تیره دارد و دیگر کسی با آن رقابت نمی‌کند. |

قوی‌ترین انتخابگر فایل نهایی `.btn:hover` / `.btn-primary:hover` / `.btn-danger:hover` / `.card.featured` با قدرت **(0, 2, 0)** است؛
یعنی کمتر از سقف (0, 2, 1).

## چرا ترتیب `.btn` و `.btn-primary` مهم است؟

`.btn` و `.btn-primary` هم‌قدرت‌اند (0, 1, 0). `.btn-primary` **بعد از** `.btn` نوشته شده، پس رنگ پس‌زمینه‌اش برنده است.
اگر کسی بعداً `.btn` را پایین فایل منتقل کند، همه دکمه‌ها خاکستری می‌شوند؛ برای همین بخش «دکمه‌ها» با ترتیب
«پایه، سپس انواع» نوشته شده است.

## راه‌حل جایگزین قابل قبول

اگر هنرجو بخواهد قانون لینک فقط مخصوص کارت بماند، این راه هم درست است:

```css
.card a { color: #1a5fb4; text-decoration: underline; }   /* (0, 1, 1) */
a.btn { … }                                               /* (0, 1, 1) — پایین‌تر، پس برنده */
a.btn-primary { … }                                       /* (0, 1, 1) */
a.btn-primary:hover { … }                                 /* (0, 2, 1) — درست روی سقف */
```

یا `.card .btn`، `.card .btn-primary` و … با قدرت (0, 2, 0). عیب این روش این است که دکمه‌های **بیرون** کارت
(مثل «بازگشت به داشبورد» در پانویس) قانون جداگانه می‌خواهند؛ پس اگر هنرجو این‌طور نوشته، باید دکمه پانویس هم درست باشد.
