# یادداشت تمیزکاری — پروژه ۵ (پاسخ استاد)

## ریشه مشکل

سه انتخابگر id در `base.css` (`#header a`، `#product p` و `#product a`) قدرت (1, 0, 1) داشتند. هر کلاسی که بعداً در `page.css` نوشته شد (0, 1, 0)
از آن‌ها باخت و برنامه‌نویس به جای درست کردن ریشه، `!important` گذاشت. بعد یک `!important` (پس‌زمینه دکمه) باعث شد `!important` بعدی (hover) هم لازم شود.

## تغییرات در base.css

| قبل | بعد | چرا |
| --- | --- | --- |
| `#header` و `#header a` | `.site-header` و `.site-header a` | HTML از قبل کلاس داشت؛ id لازم نبود. |
| `#product` و `#product p` | `.product` و `.product p` | قدرت از (1, 0, 1) به (0, 1, 1) آمد؛ حالا یک انتخابگر دوکلاسی کافی است تا از آن ببرد. |
| `#product a` | حذف | همان رنگ قانون `a` بود. |

## ده !important

| شماره | اعلان | لازم بود؟ | راه درست |
| :---: | --- | --- | --- |
| ۱ | `.nav-current` رنگ | بله، رقیب `#header a` | انتخابگر `.site-header .nav-current` (0,2,0) در برابر `.site-header a` (0,1,1) |
| ۲ | `.product-title` رنگ | نه | هیچ قانونی به `h1` رنگ نمی‌داد؛ فقط حذف |
| ۳ | `.badge` رنگ | نه | `#product p` به `p` رنگ می‌داد، نه به `span`؛ رنگ مستقیم `span` از رنگ ارثی می‌برد |
| ۴ | `.old-price` رنگ | بله، رقیب `#product p` | انتخابگر `.product .old-price` (0,2,0) در برابر `.product p` (0,1,1) |
| ۵ | `.price` رنگ | بله، رقیب `#product p` | انتخابگر `.product .price` (0,2,0)، مثل شماره ۴ |
| ۶ | `.price` اندازه | نه | هیچ رقیبی برای `font-size` نبود |
| ۷ | `.buy-btn` پس‌زمینه | نه | رقیبی نبود |
| ۸ | `.buy-btn` رنگ | بله، رقیب `#product a` | `#product a` را حذف کردیم؛ `.buy-btn` از `a` قوی‌تر است |
| ۹ | `.buy-btn` زیرخط | نه | زیرخط پیش‌فرض از CSS مرورگر است و هر قانون نویسنده از آن می‌برد |
| ۱۰ | `.buy-btn:hover` پس‌زمینه | فقط به خاطر شماره ۷ | بعد از حذف شماره ۷، `.buy-btn:hover` (0,2,0) خودش از `.buy-btn` (0,1,0) می‌برد |

## باگ ترتیب (بدون !important)

`.review-best` بالاتر از `.review` نوشته شده بود؛ هر دو (0,1,0) هستند، پس `.review` پس‌زمینه سفید و کادر خاکستری را برمی‌گرداند.
قاعده «اول عادی، بعد ویژه» را رعایت کردیم و `.review-best` را بعد از `.review` آوردیم.

## راه جایگزین قابل قبول

به جای بالا بردن قدرت `.price` و `.old-price`، می‌شد قدرت رقیب را کم کرد: `:where(.product) p` با قدرت (0, 0, 1).
آن‌وقت `.price` و `.old-price` ساده (0, 1, 0) خودشان می‌برند.

راه نادرست: منتقل کردن `color` از `.product p` به خود `.product`. این کار رنگ تیتر «مشخصات» و خانه‌های جدول را هم عوض می‌کند (که قبلاً رنگ `body` را داشتند)؛
یعنی ظاهر صفحه تغییر می‌کند.
