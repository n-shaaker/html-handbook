# سناریوی تدریس درس ۱: ترتیب قوانین در یک فایل (Order)

**صفحه جزوه:** [`pages/01-order.html`](../../pages/01-order.html)  
**پیش‌نیاز:** [انتخابگرها](../../../02-CSS-مقدماتی/تدریس/دروس/03-انتخابگرها.md)  
**مدت پیشنهادی:** حدود ۷۰ دقیقه  
**هدف جلسه:** دانشجو بفهمد **آبشار (Cascade)** وقتی چند قانون به یک عنصر می‌رسد چطور یکی را برمی‌گزیند؛ در حالت **قدرت برابر**، قانون **پایین‌تر در همان فایل** برای هر ویژگی مشترک برنده است — نه اینکه «قانون دوم همه‌چیز را پاک می‌کند».

**چرخه ثابت تدریس (در کل جلسه تکرار کن):**  
مسئله واقعی → دیالوگ → Live Coding → مشاهده مرورگر → سؤال کلاسی → اصلاح اشتباه

| موضوع | زمان |
|------|------|
| شروع: دو رنگ برای یک پاراگراف | ۱۲ دقیقه |
| ترتیب در یک `<style>` / یک فایل | ۱۸ دقیقه |
| جایگزینی **ویژگی‌به‌ویژگی** | ۱۵ دقیقه |
| DevTools و خط‌خورده (strikethrough) | ۱۵ دقیقه |
| پروژه mini + جمع‌بندی | ۱۰ دقیقه |
| **مجموع** | **۷۰ دقیقه** |

## ۱) شروع کلاس؛ مسئله واقعی

«بچه‌ها، فرض کنید روی پروژهٔ تیم کار می‌کنید. دیروز یکی `styles.css` را باز کرده و نوشته:

```css
p { color: gray; }
```

امروز همکار دیگر پایین همان فایل اضافه کرده:

```css
p { color: blue; }
```

صفحه را رفرش می‌کنید. **کدام رنگ روی همهٔ `<p>`ها می‌ماند؟** خاکستری؟ آبی؟ یا هر دو؟

و سؤال مهم‌تر: اگر روی یک پاراگراف کلاس `intro` هم باشد و جایی نوشته باشیم `.intro { color: black; }`، آیا هنوز «آخرین `p` در فایل» برنده است؟

تا اینجا فقط CSS مقدماتی بلد بودیم: انتخابگر، رنگ، فونت. حالا وارد **آبشاری بودن CSS** می‌شویم — یعنی وقتی چند قانون هم‌زمان به یک عنصر می‌رسند، مرورگر با قواعد ثابت تصمیم می‌گیرد **کدام مقدار نهایی** روی صفحه بماند.»

فایل Live پیشنهادی: `تدریس/live/04-order.html`

### مرحلهٔ اول Live — فقط HTML و یک رنگ

```html
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Live — ترتیب قوانین</title>
  <style>
    body {
      font-family: Tahoma, sans-serif;
      padding: 1.5rem;
      line-height: 1.7;
    }
  </style>
</head>
<body>
  <p>این یک پاراگراف آزمایشی است.</p>
  <p class="intro">این پاراگراف کلاس intro دارد.</p>
</body>
</html>
```

**در مرورگر:** هر دو پاراگراف رنگ پیش‌فرض مرورگر (معمولاً سیاه).

«هنوز هیچ رنگی تعریف نکردیم. حالا *دو بار* برای `p` رنگ می‌نویسیم — عمداً پشت سر هم.»

## ۲) دو قانون هم‌قدرت؛ پایین فایل برنده است

«وقتی **انتخابگر و قدرت (specificity) یکسان** باشند — مثلاً هر دو فقط `p` هستند — مرورگر stylesheet را از **بالا به پایین** می‌خواند. برای **همان ویژگی** (`color`)، مقدار **دیرتر** جایگزین مقدار قبلی می‌شود.»

### Live Coding مرحلهٔ دوم

```css
p { color: #64748b; }
p { color: #6366f1; }
```

در حین تایپ بگو:

«اول می‌گوییم خاکستری مایل به آبی… بعد دوباره همان `p` را هدف می‌گیریم و بنفش می‌گذاریم. مرورگر هر دو را می‌بیند؛ برای `color` فقط **یکی** می‌ماند.»

**در مرورگر:** هر دو پاراگراف بنفش (`#6366f1`).

### سؤال کلاسی

«اگر ترتیب دو خط را عوض کنیم — اول بنفش، بعد خاکستری — چه می‌شود؟»  
**پاسخ:** باز هم **آخرین** `color` در فایل برنده است؛ یعنی خاکستری.

«پس «اولین قانون همیشه اعمال می‌شود» درست نیست. در قدرت برابر، **آخرین مقدار همان ویژگی** در همان منبع (اینجا یک `<style>`) برنده است.»

---

## ۳) وقتی کلاس وارد می‌شود — ترتیب دیگر کافی نیست

«حالا پاراگراف دوم کلاس `intro` دارد. یک قانون برای کلاس اضافه می‌کنیم.»

```css
p { color: #64748b; }
p { color: #6366f1; }
.intro { color: #0f172a; }
```

**در مرورگر:**

- پاراگراف بدون کلاس → بنفش (دومین `p`).
- پاراگراف با `.intro` → خاکستری خیلی تیره (`#0f172a`).

«پس جواب سؤال اول کلاس این بود: **نه**، آخرین `p` روی `.intro` غلبه نمی‌کند، چون انتخابگر `.intro` **قدرت بیشتری** دارد (درس بعد جزئیاتش را می‌شماریم). امروز فقط می‌خواهیم بفهمیم: **ترتیب فقط بین قوانین هم‌قدرت** تعیین‌کننده است.»

### سؤال کلاسی

«دو بار `.btn { background: red; }` و `.btn { background: green; }` — کدام پس‌زمینه؟»  
**پاسخ:** سبز — همان منطق order.

«اگر یکی `.btn.primary` و دیگری `.btn` باشد؟»  
**پاسخ راهنما:** آن‌وقت دیگر purely order نیست؛ کلاس ترکیبی قوی‌تر است — در درس ۲.

## ۴) جایگزینی ویژگی‌به‌ویژگی (نه کل بلوک)

«اشتباه رایج این است که فکر کنیم قانون دوم **کل** قانون اول را حذف می‌کند. در CSS این‌طور نیست: برای **هر property جدا** تصمیم گرفته می‌شود.»

این بخش را **دقیقاً** مثل جزوه [`01-order.html`](../../pages/01-order.html) و فایل [`order.css`](../../css/demos/order.css) نشان بده:

```css
.demo-order .first {
  color: #c92a2a;
  font-size: 20px;
}

.demo-order .first {
  color: #0b6e4f;
}
```

HTML نتیجه:

```html
<div class="demo-order">
  <p class="first">متن نمونه</p>
</div>
```

**در مرورگر:**

- رنگ → سبز تیره (`#0b6e4f`) چون در قانون دوم `color` دوباره آمده و دیرتر است.
- `font-size: 20px` → **هنوز** از قانون اول می‌آید؛ قانون دوم اصلاً `font-size` ننوشته.

در حین نمایش بگو:

«پیشوند `.demo-order` فقط scope است تا استایل به کل صفحه نپاشد؛ **هر دو** قانون همان `.demo-order .first` را هدف می‌گیرند → قدرت برابر → برای `color` دومی برنده، برای `font-size` فقط اولی وجود دارد.»

### Live Coding — پس‌زمینه

```css
.demo-order .later-wins {
  background-color: #ffe0b2;
  padding: 10px;
  margin: 8px 0;
}

.demo-order .later-wins {
  background-color: #c3fae8;
}
```

**در مرورگر:** پس‌زمینه سبز روشن؛ `padding` و `margin` از بلوک اول باقی می‌مانند.

### سؤال کلاسی

«اگر قانون دوم فقط `background-color` داشته باشد، آیا `padding` اول صفر می‌شود؟»  
**پاسخ:** خیر — فقط ویژگی‌هایی که در قانون بعدی **دوباره** تعریف شده‌اند عوض می‌شوند.

## ۵) DevTools — دیدن cascade در عمل

«حالا F12 → Elements → پاراگراف را انتخاب کن → تب **Styles**. قوانینی که خط‌خورده‌اند (strikethrough) یعنی مرورگر آن مقدار را **محاسبه کرده** ولی در نتیجهٔ نهایی **بازنویسی** شده.»

**گام‌های مشاهده:**

1. روی `<p class="first">` در demo کلیک کن.
2. هر دو `.demo-order .first` را ببین؛ یکی `color` خط‌خورده.
3. در Computed → `color` و `font-size` را جدا بخوان.

«این همان آبشار است: جمع کردن همهٔ قوانین، بعد برای هر property برنده را انتخاب کردن. امروز فقط لایهٔ **order** را دیدیم؛ specificity و منبع (inline، فایل خارجی) بعداً اضافه می‌شوند.»

### سؤال کلاسی

«در Styles، چرا گاهی همان selector دو بار لیست می‌شود؟»  
**پاسخ:** چون در CSS واقعاً دو بار نوشته شده؛ DevTools منبع را نشان می‌دهد، نه اینکه خودش duplicate ساخته باشد.

## ۶) اشتباهات رایج — غلط در برابر درست

| اشتباه | چرا غلط است | درست |
|--------|-------------|------|
| «همیشه اولین rule اعمال می‌شود» | در قدرت برابر، **آخرین** مقدار همان property برنده است | دو `p { color }` → رنگ **پایین‌تر** |
| «rule دوم کل rule اول را delete می‌کند» | cascade per-property است | `color` عوض، `font-size` از rule اول |
| «پایین فایل = همیشه برنده» | اگر selector قوی‌تر بالا باشد، order کمکی نمی‌کند | `.intro` روی `<p>` قوی‌تر از `p` سوم |
| کپی کردن کل بلوک CSS برای تغییر یک رنگ | فایل شلوغ و bug در order | فقط property لازم را در rule جدید یا همان rule ویرایش کن |

**Live اصلاح:** دانشجو فکر می‌کند باید rule اول را پاک کند. نشان بده که می‌توان فقط یک خط `color` پایین اضافه کرد — یا rule اول را edit کرد — ولی **درک** order برای debug ضروری است.

## ۷) پروژهٔ mini جلسه — «کارت اعلان»

«یک کارت اعلان بسازیم؛ عمداً دو بار استایل می‌دهیم مثل legacy code.»

### HTML

```html
<div class="notice demo-order">
  <p class="first">به‌روزرسانی: کلاس فردا برگزار می‌شود.</p>
</div>
```

### CSS — مرحله‌به‌مرحله

۱) پایه:

```css
.notice {
  border-radius: 8px;
  max-width: 28rem;
}
```

۲) «نسخهٔ قدیمی تیم» (بالا):

```css
.demo-order .first {
  color: #c92a2a;
  font-size: 18px;
  padding: 12px;
  background: #fff5f5;
}
```

۳) «hotfix دیروز» (پایین — فقط رنگ):

```css
.demo-order .first {
  color: #0b6e4f;
}
```

**قبل از رفرش** از دانشجو بپرس: رنگ؟ اندازه فونت؟ padding؟  
**بعد از رفرش** با DevTools تأیید کن.

«این سناریوی واقعی است: کسی فقط رنگ را fix کرده؛ بقیهٔ استایل از rule قدیمی مانده — **چون** cascade per-property است.»

## ۸) جمع‌بندی مدرس و سؤالات پایانی

قبل از تمرین بپرس:

1. اگر دو قانون **کاملاً هم‌قدرت** باشند، چه چیزی برنده را مشخص می‌کند؟  
   **پاسخ:** ترتیب در همان stylesheet — قانون پایین‌تر برای property مشترک.

2. قانون دوم فقط `color` دارد؛ قانون اول `color` و `padding`. بعد از cascade چه چیزهایی از rule اول می‌مانند؟  
   **پاسخ:** `padding` (و هر property که rule دوم بازنویسی نکرده).

3. آیا می‌توانیم با «نوشتن rule پایین‌تر» یک `#id` را شکست دهیم؟  
   **پاسخ راهنما:** نه — id specificity بالاتر دارد (درس بعد).

**پیام پایانی:**

«Order ساده‌ترین لایهٔ cascade است. وقتی استایل «عجیب» شد، اول بپرس: آیا دو rule هم‌قدرت پشت سر هم دارم؟ DevTools strikethrough بهترین معلم امروز بود.»

## تمرین‌ها (ساده → چالشی)

### ساده
1. در `order.css` جای دو بلوک `.first` را عوض کن — رنگ قبل از پیش‌بینی، بعد تأیید در مرورگر.  
2. سه بار `h2 { color: ... }` با رنگ‌های مختلف — کدام می‌ماند؟

### متوسط
3. rule اول: `color` + `font-weight: bold`؛ rule دوم: فقط `color`. bold می‌ماند؟  
4. دو `.card` پشت سر هم با `background` متفاوت — `border-radius` فقط در اولی؛ نتیجه را بکش.

### چالشی
5. بدون حذف rule قدیمی، فقط با rule جدید پایین، `font-size` را به 16px برسان (rule اول 20px دارد).  
6. توضیح بده چرا «همهٔ استایل‌ها را در یک rule giant می‌نویسم تا order گیج نشود» راه‌حل خوب **نیست** (maintainability).
