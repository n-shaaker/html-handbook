## ۱) شروع کلاس؛ مسئله واقعی

«بچه‌ها، فرض کنید روی سایت خبری کار می‌کنید. در `main.css` نوشته‌اید:

```css
a { color: #2563eb; }
```

همهٔ لینک‌ها آبی شدند — خوب است.

بعد در `nav.css` اضافه می‌کنید:

```css
.nav a { color: #0f172a; }
```

لینک‌های منو تیره شدند — باز هم منطقی است.

اما یک روز کسی برای «فقط لینک ویژه» می‌نویسد:

```css
#main .nav a { color: #6366f1; }
```

و **پایین همان فایل** یک hotfix می‌آید:

```css
a { color: red !important; }  /* اشتباه — امروز !important را نمی‌خواهیم */
```

یا بدون important، فقط:

```css
a { color: red; }
```

«فکر می‌کنید لینک داخل `#main .nav` قرمز می‌شود چون **آخر فایل** است؟»

**مکث.** از کلاس بپرس. اگر گفت بله — امروز specificity را یاد می‌گیریم تا دیگر حدس نزنیم.»

فایل Live: `تدریس/live/04-specificity.html`

## ۲) وقتی order کافی نیست

«در درس قبل گفتیم: **قدرت برابر** → **ترتیب**. حالا قدرت **نامساوی** است.

- `a` → یک **نوع (type)** → در demo جزوه با پیشوند `.demo-spec` می‌شود `(0, 1, 1)` یعنی یک کلاس scope + یک `p` یا `a`.
- `.note` → `(0, 2, 0)` با پیشوند demo.
- `#special` → `(1, 1, 0)`.

**مهم:** سه عدد را **جمع نمی‌کنیم**. مثل نسخهٔ نرم‌افزار `(major, minor, patch)` از **چپ** مقایسه می‌کنیم.»

### Live Coding — دقیقاً مثل [`specificity.css`](../../css/demos/specificity.css)

```css
.demo-spec p {
  color: #c92a2a;
  font-size: 18px;
}

.demo-spec .note {
  color: #1a5fb4;
}

.demo-spec #special {
  color: #0b6e4f;
  font-weight: bold;
}
```

HTML:

```html
<div class="demo-spec">
  <p>فقط تگ p</p>
  <p class="note">با کلاس note</p>
  <p class="note" id="special">با id special</p>
</div>
```

**در مرورگر:**

- پاراگراف اول → قرمز (`p` rule).
- دوم → آبی (`.note` ستون class بیشتر).
- سوم → سبز (`#special` ستون id برنده).

در حین تایپ بگو:

«پیشوند `.demo-spec` فقط scope است؛ به **همه** انتخابگرها یک کلاس اضافه می‌کند تا روی کل صفحه نریزد — ولی **نسبت** قدرت بین `p`، `.note` و `#special` همان است که در جزوه توضیح داده شده.»

### سؤال کلاسی

«`div p` در مقابل `.text` — کدام برنده؟»  
**پاسخ راهنما:** `.text` → `(0, 1, 0)` در برابر `(0, 0, 2)` — ستون class برنده است.

«آیا `#id1 #id2 .x` همیشه خوب است؟»  
**پاسخ:** از نظر cascade قوی است؛ از نظر **نگهداری** معمولاً بد — specificity جنگ را سخت می‌کند.

## ۳) سه ستون قدرت — آنچه در جزوه می‌آید

جدول ذهنی (بدون اختراع قواعد جدید):

| ستون | چه چیزهایی می‌شمارد |
|------|---------------------|
| **اول — id** | `#special` |
| **دوم — class** | `.note`، `[type="text"]`، `:hover`، `:not()` **داخل** (طبق جزوه) |
| **سوم — type** | `p`، `::before` |

«`*` و combinator (فاصله، `>`، `+`) امتیاز نمی‌دهند — فقط ساختار انتخاب را مشخص می‌کنند.»

### Live — جعبه‌های راهنما

همان CSS جزوه برای `.score-tag`، `.score-class`، `.score-id` را نشان بده تا دانشجو رنگ‌ها را با ستون‌ها associate کند.

### سؤال کلاسی

«`.demo-spec p.note` چند class و چند type دارد؟»  
**پاسخ راهنما:** با پیشوند demo → `(0, 2, 1)` — دو class (demo + note)، یک type.

## ۴) ترتیب در فایل vs specificity — آزمایش

«عمداً rule ضعیف را **پایین** می‌گذاریم.»

```css
.demo-spec #special {
  color: #0b6e4f;
}

.demo-spec p {
  color: #c92a2a;
}
```

**در مرورگر:** عنصر `#special` همچنان **سبز** — چون `#special` قوی‌تر است، هرچند `p` پایین‌تر است.

«این همان پاسخ سؤال اول کلاس بود: **نه**، آخرین `a` همه را قرمز نمی‌کند اگر selector ضعیف‌تر باشد.»

---

## ۵) DevTools — specificity tooltip

**گام‌ها:**

1. Inspect روی `<p class="note" id="special">`.
2. در Styles کنار selector، specificity را ببین (Chrome: `(1, 1, 0)` style).
3. ruleهای خط‌خورده را با rule برنده مقایسه کن.

«وقتی debug می‌کنید، اول **برنده** را پیدا کنید، بعد بپرسید چرا rule من بازنده شد — order یا specificity یا منبع بعدی.»

### سؤال کلاسی

«دو rule هم specificity — کدام برنده؟»  
**پاسخ:** order (درس ۱).

## ۶) inline style — یک لایهٔ دیگر (سطح این ماژول)

«`style="color: blue"` روی عنصر از almost همهٔ ruleهای فایل **بدون** `!important` قوی‌تر است.

امروز فقط mention: در [`05-important.html`](../../pages/05-important.html) می‌بینید `!important` چطور بازی را عوض می‌کند. **اولویت:** selector درست بنویسید، نه inline و نه !important.»

**Live کوتاه:**

```html
<p class="note" id="special" style="color: purple;">...</p>
```

**در مرورگر:** بنفش — تا وقتی rule قوی‌تر یا !important نیاید.

---

## ۷) اشتباهات رایج

| غلط | درست |
|-----|------|
| جمع کردن id و class به یک عدد | ستون‌به‌ستون از چپ |
| chain کردن `#a #b #c` برای «برنده شدن» | specificity بالا + کد غیرقابل نگهداری |
| `.nav a` و فکر کردن «دو class» | یک class + یک type → `(0, 1, 1)` |
| copy-paste rule پایین فایل بدون تقویت selector | selector را دقیق‌تر یا ساختار HTML را ساده کن |

**مثال غلط vs درست:**

```css
/* غلط — امید به order */
a { color: red; }
#main .nav a { color: navy; }
a { color: red; }  /* فقط p ساده را می‌گیرد، نه همه */

/* درست — selector مناسب */
.nav a { color: navy; }
a { color: #2563eb; }
```

## ۸) پروژه mini — «نجات رنگ منو»

HTML:

```html
<nav class="demo-spec nav">
  <a href="#">خانه</a>
  <a href="#" class="note">ویژه</a>
</nav>
```

CSS مرحله‌ای:

1. ` .demo-spec a { color: #c92a2a; }`
2. ` .demo-spec .note { color: #1a5fb4; }`

**قبل از رفرش:** رنگ «ویژه»؟  
**بعد:** آبی — `.note` برنده.

از دانشجو بخواه specificity هر rule را روی تخته بنویسد.

## ۹) جمع‌بندی و سؤالات پایانی

1. `(1, 0, 0)` در برابر `(0, 99, 99)`؟  
   **پاسخ:** id برنده — ستون اول.

2. `div p` vs `.text`?  
   **پاسخ:** `.text`.

3. rule قوی بالا + rule ضعیف پایین — برنده؟  
   **پاسخ:** قوی — order فقط در تساوی.

## تمرین‌ها (ساده → چالشی)

### ساده
1. specificity سه selector از جزوه را روی کاغذ بنویس.  
2. در demo، `#special` را به `<span>` بدون id منتقل کن — چه رنگی؟

### متوسط
3. `.demo-spec p.note` vs `.demo-spec .note` — کدام برای `<p class="note">`؟  
4. rule پایین فایل با `p` — آیا `#special` را شکست می‌دهد؟

### چالشی
5. بدون id جدید، فقط با selector، لینک `.note` را سبز `#0b6e4f` کن در حالی که `.demo-spec a` قرمز است.  
6. چرا «specificity بالا» می‌تواند technical debt باشد؟
